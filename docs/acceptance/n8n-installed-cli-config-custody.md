# Installed n8n CLI/config custody

Tracker: [#8142](https://github.com/ubugeeei-prod/vize/issues/8142).
The paired issue decision is prepared locally; posting and remote delivery remain
with the release coordinator.

This standalone typed campaign runs the existing bounded n8n CLI/config contracts
against a genuinely npm-installed `vize` and its `vize/config` export. It does not
create a workspace build receipt, replace a native provider, add a release gate,
or establish full 51-rule, monorepo, performance or all-native adoption.

Both runners import the existing frozen oracle, projection, original-copy and

published evidence; it is outside this campaign.

## Installed authority

Supply the exact SHA-256 of a reviewed successful receipt from the existing
official public-install collector, together with its reviewed collector snapshot
digest. The adapter consumes `vize-public-registry-install-v1` and its full
`vize-public-registry-payload-files-v1` manifest. It requires the declared C/H/tag/R
tuple, exact version and public npm lock v3/SRI/provenance identities, then
rechecks every installed payload path, complete file set and file digest before
and after the campaign. It verifies the separately reviewed collector files,
CLI wrapper/dist, config export, Node executable and native/Corsa identities.
This reuses the collector's registry/archive evidence; JSON syntax alone does
not establish publication or replace the coordinator's reviewed receipt digest.

The existing official collector currently owns Darwin ARM64. This adapter
preserves that boundary; another platform needs its own genuine collector
evidence. Initial runtime/source overrides are rejected, including workspace
binding, native paths, version bypasses, Corsa routes and ambient preloads.

Only owned private settings and unchanged inputs/configs are written beneath a
fresh child of the public consumer directory. `vize/config` must resolve to the
actual installed package in the ancestor `node_modules`; no package dist is
copied or linked from the repository. CLI calls use the recorded Node executable
and installed CLI wrapper. The unchanged native observer delegates to Node's
original extension loader and records its actual successful return. A new
complete journal must authenticate the expected native path/digest, PID, CLI
argv, bundled Corsa route and process exit for every call. Lint exit 1 remains
valid only when the complete report contains errors.

Raw stdout/stderr, provider errors, command/argv, process status and the complete
native journal are retained before parsing or assertions. A failure cannot earn
execution credit or a successful summary. Successful campaigns recheck all
package/config/input bytes. Observer hashing and capture time are not adoption
performance measurements.
