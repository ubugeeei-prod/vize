## #13592 の修正候補

公開PRの先端は `0b1eed96e8cc0dd0e1f587ed22531c30f0ef0982`。幅1・カーソル1で Linux は27 → 28 ns（31組中26組で遅化）、順序を入れ替えても26 → 28 ns（28組で遅化）。既存のゲートが検出した。修正候補 `3602af9a875283b5c05cd9d971b97f1e22f4063e` はその直接の子。重複位置の妥当性を再利用し、単一位置、2〜4位置、長い入力のそれぞれで元の診断とUTF-8上の範囲を返す。 [Linux の失敗](https://github.com/ubugeeei-prod/vize/actions/runs/45299822296/job/138129237526) · [保存した差分](https://github.com/ubugeeei-prod/vize/compare/0b1eed96e8cc0dd0e1f587ed22531c30f0ef0982...3602af9a875283b5c05cd9d971b97f1e22f4063e)

macOS arm64 で同じ実装の中間版を、元の独立バイナリと入力16条件・各15組で比較した。幅1×カーソル1は31 → 28 ns、128×64は7,160 → 4,441 ns。保存版ではカーソル数2・3・5を追加した。**最終28条件の両環境での実測と、保存版の全コーパス再実行が残っている。** 既存の比較対象は6,311入力、うち5,448件を破損・復元し、43,216レコード、124,092カーソル一致。広い範囲に対するローカル Clippy は既存の `examples/profile/checks.rs` の `format!` 5件で終了し、後続のテストはその実行では開始されていない。

Kani 0.68.0 は最大7個の32ビット位置で、実装の473検査で失敗0、到達しない検査1、カバー6/6。10個の変異のうち7個が休止までに意図どおり失敗した。残る3個は単一カーソルの下端、挿入点、順位。全10個の変異を再現するスクリプトも保存した。 [モデル検査の再現](./handoff-2026-11-24/check-recovery-mutations.py)
