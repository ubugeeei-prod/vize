# Original primitive TS annotation receipts and linked native setup output

Tracked in [#6838](https://github.com/ubugeeei-prod/vize/issues/6838) and
[#6840](https://github.com/ubugeeei-prod/vize/issues/6840). The original strict
literal provider, Const setup and no-erasure TS consumers are actual merged
prerequisites. Private development starts from their genuine source and is
refreshed onto actual main before independent publication.

The existing sole variable walk classifies only original bigint, boolean,
null, number, string, symbol and undefined keyword annotation nodes attached
to direct Const/Let/Var primitive-literal declarations. It retains their
checked original colon-through-type spans and kinds in deferred File-owned
storage. Unannotated files allocate no annotation collection; ScriptUnit's
existing measured 48-byte layout remains unchanged. No caller supplies spans,
names, source replacement or an eligibility flag.

The sealed VueSetup capability exposes only same-unit annotation receipts
borrowed from the same complete original File. Original Program/source/profile,
default parser options, root scope, normal uninterrupted completion and strict
literal/binding checks remain mandatory. All non-keyword types, assertions,
declare/definite forms, nested/exported declarations, imports, nonprimitive
initializers and unavailable syntax retain their existing File issues and
typed refusal. Primitive annotations do not authorize Ref/unwrapping semantics.
The checker retains and copies the original TS Program unchanged.

Native JS setup emission omits only those genuine ordered annotation ranges
and links each remaining original source segment. The original complete SFC,
descriptor, Program, comments, diagnostics and File survive; map source content
and named binding coordinates still point to that complete source. Untyped JS
and TS output and all previous module/map fixtures must stay byte-exact. No
parse, source search, additional AST walk, serialization, pipeline stage,
legacy compiler or default replacement is introduced.

Meaningful source/profile/owner/interruption and unsupported-type laws,
actual source-built whole modules/maps, an independent pinned Vue 3.5.35 and
official TypeScript reference, and real native Vue execution are required.
The independent reference reproduces complete compiler bytes and maps with
Vue 3.5.35 and official TypeScript 6.0.3, and its real Vue renders pass. New
Rust laws, native modules/maps and native renders still require source-built
Actions execution. The existing first-tooling-shard native setup action also
runs on precisely affected PR source: its classifier forces a worker even
when ordinary tooling selection is empty. The protected merge-group capture
remains mandatory independently of that flag. Missing captures fail rather
than substituting fixture bytes. Actual generated native modules/maps will be
frozen before final acceptance; exact-head checks, full protected suites, all
100 unchanged instruction ceilings and actual merge remain required. With
the genuine predecessors merged, this successor is published independently.

Broader TS erasure, ordinary scripts, macros, nonprimitive bodies, remaining Vue
dialects/targets and compiler default migration remain unfinished. Compiler
history #6880 must close before replacing the default legacy product path.
