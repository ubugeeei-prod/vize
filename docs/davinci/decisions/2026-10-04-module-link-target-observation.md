## Approved bounded physical mechanism

The bounded no-symlink grant is easiest to make truthful on Unix with anchored directory handles: open/retain root and traverse normal parent components using directory-relative `openat` with `O_DIRECTORY | O_NOFOLLOW | O_CLOEXEC`; final open uses `O_NOFOLLOW | O_NONBLOCK | O_CLOEXEC`, then fstat/metadata checks regular-file kind. Nonblocking final open prevents a swapped FIFO from hanging a supposedly regular-file observation. Root opening must itself avoid following path-component symlinks; beginning from the filesystem root and walking actual root components is part of this policy. Merely applying O_NOFOLLOW to the final full pathname does not protect intermediate components.

All raw descriptor acquisition is converted once into owned File/OwnedFd with correct close-on-error and no double-close; any unsafe FFI is tiny and audited. Existing workspace `libc = =0.2.189` would be an explicit Unix target-specific normal dependency of Maestro, not a level->legacy edge or new dependency version. Root approved this pinned dependency and Unix-first policy for private implementation. Non-Unix initially returns a typed UnsupportedPlatform, with no unchecked metadata identity fallback. Portable filesystem metadata alone cannot prove replacement/ABA identity.

An owned observation retains the actual root pathname chain, root, source-parent/target-parent component handles, final target handle identities and requested relative path. Retain each traversed directory handle, not merely root/final inode fields; an equal hard link below a replaced parent must not bypass a per-component replacement check. Final recheck reopens the original root and the exact target through fresh no-follow traversal, comparing every actual directory-component identity and the final regular-file identity to their retained original handles. Original open handles prevent inode reuse while comparison occurs. This only proves the object reached by those actual bounded operations; it does not establish contents, parser semantics or arbitrary future path immutability. Retaining anchored old parents alone is insufficient: fresh path traversal must detect directory/root rename or replacement.

No file bytes are parsed/read as another Program. No second AST walk, copied literal/span table, serialization stage or source pipeline is added. Filesystem component traversal is its own genuinely missing external-observation provider, with explicit O(path depth) handles/work; do not call this an AST walk.
