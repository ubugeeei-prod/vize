## Existing genuine event and missing admission

`Walk::statement(ExportNamedDeclaration)` → `export_named` →
`declaration(actual declaration, true)` → `function(actual Function, true)`.
`export_named` owns the original `ExportNamedDeclaration.declaration` borrow;
no later search reconstructs an exported function.

Before annotation admission, `function` creates its actual parent-scope value

unit, name, original identifier span, `Namespace::Value`, and that actual
local BindingId. Source/local-reference/source-site fields stay unchanged.

formal parameters and body to the existing one traversal. Current untyped
export laws already prove original Unicode/nonzero SourceBlock, unit 7,
Function/Parameter declarations, resolved body read and unchanged AST/comment
allocation. These existing records supply the necessary authority.

Only the new keyword annotation paths currently exclude a direct exported
function: `exported` in the return guard and `!exported` in the parameter
predicate. A later original `export { f }` is already supported. The
exported flag is the event's direct declaration role, never a whole-program
export classifier. No new receipt, table, resolver or AST visitor is proposed.

## Exact bounded admission

non-definition/default ParseOptions and genuine completed ProgramInput/source.
Its existing supported body and every other envelope guard still apply.
Required parameters may have only the existing seven reference-free keywords:
bigint, boolean, null, number, string, symbol and undefined. Return annotations
may have those same seven keywords. Unannotated required parameters and
unannotated returns retain existing behavior; no implicit-any diagnostic is
filtered. Both annotation and inner type spans pass the existing authored
SourceBlock projection before use.

The smallest proposed production change is confined to the existing function
event in `lang/js/file/walk/functions.rs`:

1. Remove only `exported` from the supported keyword-return refusal.
2. Replace the required-parameter annotation predicate's `!exported` with
   `(!exported || !parameter.optional)`. Retain every profile/keyword/span
   predicate and the existing optional/default/rest/decorator/pattern guards.
3. Do not add a parameter pre-scan. Original parameters are inspected only
   during the existing child enumeration, then original statements are visited
   in their existing order. No type/value namespace reads or fabricated type
   binding are needed for a reference-free keyword.

The explicit second condition is essential: removing `!exported` outright
would silently admit optional exported parameters after the fifth provider.
Every direct optional export stays incomplete, annotated or unannotated;
nonexported optional functions and later optional export events remain exactly
as provided by the independent optional lane. Defaulted/decorated/readonly,
accessibility/override/rest/pattern parameters, generic/this/declare/async/
generator/nested functions and unsupported statements remain refused.
No SetupAnnotation, erasure or compiler/setup/ordinary visibility is granted.
