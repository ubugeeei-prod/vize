Thus even instantaneous JS/browser jobs would not make this measured required report finish within 120s.

## Source-built focused JS experiment

A push-only, non-required diagnostic used the exact #7150 synthetic merge source, the PR JS runner/setup/cache steps, `build:native:test`, and the binding's active test-preparation receipt. Its first two runs failed a Vite JSX configuration test even though the ordinary #7150 JS job ran and passed that same test. A third run with the ordinary job's `NODE_OPTIONS` and concurrency setting also failed. The checkout and environment therefore did not explain the discrepancy.

The full `test:js` sequence packs `npm/cli` before it tests `npm/builder/vite`. The Vite plugin lazily imports `vize/config` from `npm/cli/dist/config.mjs`; that generated file is absent before `vp pack`, and shared config resolution catches a failed import and falls back to defaults. The focused test had skipped this preparation dependency. With `vp run --filter './npm/cli' test` before the Vite command, [diagnostic run 36466937920](https://github.com/ubugeeei-prod/vize/actions/runs/36466937920) passed: 38 CLI tests, then 52 Vite plugin tests and 19 companion tests, with the source-built binding reused. Creation to aggregate completion was **88s** (18:41:10–18:42:38 UTC). The earlier isolated failure was a preparation error; the ordinary gate did not skip the JSX test, and this is not a legacy JSX behavior fix. Keep the CLI pack in every focused Vite route.

## Conservative T0/T1 split to implement and verify

For ordinary PRs whose *entire* changed-path set is audited SFC/L1 Rust library source plus inert Markdown, a focused T0 JS route may build the NAPI addon from the exact checkout, run the CLI pack/tests, and then run prepared Vite compiler tests with the active source receipt. A path outside that narrow allowlist, an unavailable comparison base, a deletion or rename, or a planning error selects the existing complete PR JS job. In particular, changes in `npm/**`, `playground/**`, Cargo manifests/lockfile, workflow/task configuration, `docs/davinci/plan/**`, generated ledgers, tooling tests, and unknown source paths remain on the complete PR route. The actual #7150 diff contains plan TSV and tooling-test inputs, so it is **not** eligible for the focused tier despite being the useful source fixture for the diagnostic.

For that same narrow source cohort, defer the complete browser run to the protected merge queue. Changes to playground, WASM build inputs, Vite plugin/package source, shared JS configuration, or unknown paths retain browser tests in the ordinary PR. The queue and main keep all 16 JS package filters, Fresco checks, source WASM, all 41 browser files/215 tests, and the existing VRT policy. The required aggregate must still await every selected T0 job and retain the complete T1 jobs on `merge_group`; no required context is removed.

The local prototype adds a fail-closed `js-browser-tier` output to the source planner and a focused JS command sequence to `pr-source-checks.yml`. A deletion or rename forces the complete tier; `merge_group` always selects complete JS and browser execution. Focused planner and workflow contract tests pass locally. Running the planner against the actual #7150 synthetic merge diff selects the **complete** tier (21 changed paths), as intended. This prototype is unpublished and has not run as an integrated ordinary PR check.

Before publishing, run an actual PR-like changed-path diagnostic with the integrated planner, exact source receipt, and CLI pack, then measure the complete required `test-report`. The 88s focused JS diagnostic is only one job's run. The observed 135s `check-vize-apps` path and report fan-in mean the user's ≤120s required PR target remains unmet. Its setup/cache and source CLI receipt need a separate measured reduction without dropping coverage or weakening ruleset parity.
