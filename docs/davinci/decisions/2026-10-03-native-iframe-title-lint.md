# Native L1 iframe title lint

Issue: [#6848](https://github.com/ubugeeei-prod/vize/issues/6848).
The fix-history gate [#6881](https://github.com/ubugeeei-prod/vize/issues/6881)
remains open. This is the next opt-in syntax rule after the actually merged
native image-alt consumer [#7489](https://github.com/ubugeeei-prod/vize/pull/7489).
The ordinary linter, presets and registry retain their current routes.

## Selected-owner admission

`NativeSyntaxLint::iframe_has_title` consumes one genuine same-owner
`NativeElement` from the existing Descriptor-selected `NativeTemplateComponent`.
The context retains the original selected owner and reads its actual recovery
and unsupported observations. Equal source bytes in another original owner
cannot grant element authority. Nothing reparses the source, walks child bodies,
fabricates a provider or invokes Relief/Croquis or a legacy semantic helper.

The existing image-alt token, attribute and directive checks move into one
private shared header module without broadening admission. Each rule validates
opening and any authentic closing tokens against the checked UTF-8 SourceBlock,
then processes every original same-owner attribute once. Missing or inconsistent
quote/value tokens, dynamic arguments, object bindings and unknown directive
heads remain refusals, including after an earlier known title. Original `v-pre`
flags preserve directive-looking attribute names as literal source.

## Exact rule behavior

The code is the existing registered `a11y/iframe-has-title`. As in that rule,
`iframe` and `title` are case-sensitive exact names. A static title must contain
at least one non-whitespace decoded Unicode scalar. A valueless, empty or
whitespace-only title does not satisfy the rule. The genuine public L1
`decode_one` in Attribute context supplies WHATWG named/numeric reference
semantics; decoded scalars are inspected without allocation. Invalid references
stay literal. This does not parse an expression or construct a decoded AST.

Typed static `:title`, `.title` and `v-bind:title` arguments, including their
original modifiers, satisfy title presence while keeping values opaque. Event
and model bindings, differently cased names and `data-title` do not satisfy it.
An admitted iframe without title returns a finished L0 Surface advisory Warning
and full catalog Help over the entire original element range, including its
closing tag. There are no secondary labels or fixes. The caller supplies the
actual L0 MessageLookup; diagnostic text is owned after the source arena drops.

## Validation and delivery

Ten new ordinary integration laws compare complete ordered diagnostics against
the unchanged actual IframeHasTitle-only registered legacy oracle. They cover
English/Japanese/Chinese text and full Help/ranges, valueless and Unicode/entity
whitespace, multi-scalar/unknown/numeric references, typed static arguments and
modifiers, case/event/model controls, verbatim headers, nested selected elements
and absolute Unicode offsets, later unresolved headers, foreign/recovered
owners, owned diagnostic lifetime and the empty selected template. The same
integration target retains every original image-alt input and assertion.

Only the exact new dev-only catalog caller/import is added to the existing
host-i18n registry; the unchanged boundary laws still reject other imports,
storage types and foreign/production paths. Native production uses only L0/L1.
The canonical Patina consumer witness is regenerated rather than hand-edited.

Fresh exact-head PR Actions and the actual protected merge-group full suites,
whole Patina Clippy and existing instruction ceilings are required, followed by
actual merge confirmation on fresh main. No manual duplicate full100 run is
added. Source gates and authored laws alone do not establish hosted acceptance.

Other syntax rules, unresolved dynamic/object admission, every Vue dialect,
semantic linting on L2/facts, autofix span edits, complete linter fix-history,
default route replacement and complete native Patina remain unfinished.
