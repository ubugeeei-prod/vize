## Complete values at the existing consumer boundary

Independent source review found an essential mismatch in the first local prototype: the public `CompatSink` intentionally forwards only the first scalar of `&fjlig;`, but its coordinate map describes complete `fj`. Armature consequently retained `f` before its parameter producer, leaving a later declaration one byte early. That source defect and the first prototype remain separate history, rather than a successful coordinate qualification.

The first published candidate used a private sink around the same `CompatSink`. Actions retained its authentic medium-parser instruction failure: 245,981 against the unchanged 243,340 ceiling; its exact parent measured 241,745. Forced inline forwarding reduced the candidate to 245,076 but still failed. The measured medium input is exactly the 2,238-byte root-template slice and contains no ampersand in either attributes or text; CSS ampersands are outside that slice. The compiler/code-generation cause remains unknown. Both complete raw measurements and all original ceilings remain evidence, rather than performance qualification.

The corrective source returns private tokenizer setup to its original `CompatSink<ParserCallbacks>` and `Lexer<Component|Document>` instantiation. The public `Callbacks` trait gains one provided, object-safe `on_attrib_entity_value(DecodedEntity, start, end)` method. Its default uses the existing shared first-scalar projection and the original character callback. Existing callback implementations keep the same default stream. `CompatSink` forwards the already-decoded borrowed event to that method; only private `ParserCallbacks` explicitly consumes complete attribute values at the same accumulation/flush boundary and authored span. Text values, other callbacks, errors, live v-pre polling and declaration defaults retain their old ownership.

The restored-sink successor retained another authentic instruction failure: 245,985 against the same 243,340 ceiling. All 104 original workloads and all 312 measured windows retain their exact input identities, methodology and ceilings; medium is the only failed workload. Its normalized exclusive delta against the same parent is `Lexer<Component, CompatSink<ParserCallbacks>>::run` +4,244 and `parse_inner` −4, with every other function unchanged. These profiles locate the cost but do not identify its machine-code cause.

The private complete-value handler now isolates actual attribute-entity work from normal byte and text callbacks. A named expansion already borrows valid UTF-8 from the existing entity table: it is appended once through the same accumulator, avoiding a scalar walk, repeated UTF-8 encoding and repeated no-op text flushes. An empty named expansion still does nothing; a numeric expansion uses the existing one-character handler. A nonempty expansion flushes pending text once, which has the same effect as the previous first-scalar flush because that method takes the pending value. The authored start/end are unchanged. The handler is marked cold because it is reached only after a successful attribute entity decode. This is a source-supported boundary hypothesis, with no instruction reduction or repaired budget claimed before fresh Actions qualification. Public default/text callbacks and the historical first-scalar owner stay exact.

This is an additive public Rust trait source surface, reexported through `vize_armature::tokenizer`, and must ship in a later MINOR genuinely containing this source. It is not described as an unchanged public API. No required trait method, associated constant, field, cache, retained state, decoder, scanner, pipeline stage, JavaScript parse or dependency is added. The nonempty-delimiter guard, arena-borrowed delimiter lifetime, document profile, experimental comments and legacy raw-interpolation capability stay exact. The physical mapper separately decodes authored bytes to calculate coordinates; it currently costs O(bindings × attribute bytes), with no measured performance claim.

The complete attribute behavior follows the [HTML named character references](https://html.spec.whatwg.org/multipage/named-characters.html): `fjlig;` has two letters, `acE;` and `NotEqualTilde;` have a base scalar plus a combining scalar, and `ThickSpace;` has two spaces. Vue's [pinned tokenizer](https://github.com/vuejs/core/blob/4ab865a848a1da3d10fb674f857e5fff13094644/packages/compiler-core/src/tokenizer.ts) forwards each entity code point with its authored span to [attribute accumulation](https://github.com/vuejs/core/blob/4ab865a848a1da3d10fb674f857e5fff13094644/packages/compiler-core/src/parser.ts). These read-only policy sources do not substitute for the original pinned compiler/runtime oracle or claim text parity.
