# Compiler history type closures

Tracked in [#6880](https://github.com/ubugeeei-prod/vize/issues/6880).
This supplements the [history audit](./2026-10-01-compiler-history-completion.md)
and [target capture record](./2026-10-01-compiler-target-history-next.md).

## Decision

Keep the three history layers independently executable and reviewable on
the actual merged provider tree. The foundation introduces the history
index and five original SFC captures; the second layer adds ten original
SSR/Vapor captures. The public compiler API helpers, manifests and actual
execution law first exist in the third layer. A final-top test inventory
does not prove that an earlier physical layer contains or executes them.

The third layer gives its fixture, original options, process attempt,
observation, complete result, build receipt and report explicit types.
The receipt type derives from the real shared observer builder. Existing
mixed TS/MJS imports resolve from their actual source bytes; no declaration
stub or type-error suppression stands in for a helper. The source checks
use the repository's strict NodeNext settings with JavaScript import
resolution. Existing unowned MJS bodies are a separate baseline and are
not claimed as strict JavaScript validation.

Caught failures retain an Error's message or the actual thrown value's
string representation. An empty failure message is still a failure:
explicit null checks preserve all five planned failed coordinates, a null
build receipt, the empty message, and zero native credit. A bounded law
checks this case. Invalid-packet tests continue to mutate clones of the
same pinned options and complete output fields.

## Preserved evidence

All original input, options, expected result, process archive, authored
witness, Rust observer and provenance bytes remain unchanged. Raw SSR and
Vapor template inputs must go through their original library API observer;
they are not wrapped in an SFC or given different options to fit a CLI.
The CLI's unsupported raw-template route remains separate unfinished work.

The replay preserves the entire incoming actual main tree outside owned
history paths, including every unrelated central decision paragraph and
the existing source-length limit. The original private history and native
SFC assembly snapshots remain immutable provenance, not publication parents.

## Bounded verification and remaining work

Each physical layer passes strict TypeScript 6.0.3 for its actual owned TS
roots and recursive mixed-source import closure. The first two layers each
have one owned TS root. The third has seven roots including the existing
tooling scope registry, two helpers, shared types, and both API tests.
The third-layer closure also contains the genuine shared observer builder
and two existing MJS helpers. Type-aware deny-warning lint and nine
comparator/failure laws pass for the repaired source. These laws use
synthetic comparator packets and real pinned artifacts; they do not build
or certify current product execution.

Separately enabling strict JavaScript body checks records 27 pre-existing
diagnostics in the unchanged shared manifest/acceptance MJS helpers and no
owned TS diagnostics. This baseline is not reported as a passed gate.

The pinned census remains 626 candidate subjects: 30 fixture-linked,
596 unlinked, and 124 without a changed witness-path candidate. Every
subject still needs semantic and target review; the semantic denominator
is unset. Current-head mandatory API captures remain 0/15, certified full
history closure remains zero, and native compiler credit remains zero.

Before publication and queue entry, preserve the original source refs,
verify exact Git tree/commit/parent/message identities, register and check
one GitHub native Stack, and run actual exact-head Actions. The final
consumer must retain all 15 complete original API observations, repeats
and source-built artifact receipts. The unchanged protected full suites
and all instruction-count ceilings still apply. Verify actual merge and
fresh main separately; this decision does not close #6880.
