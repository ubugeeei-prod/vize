# Declaration reference roles preserve existing editor behavior

Issue: [#3952](https://github.com/ubugeeei-prod/vize/issues/3952),
[#6883](https://github.com/ubugeeei-prod/vize/issues/6883).

The Nuxt ownership source `96ce07d217900f0817d0f02a4a8ea5c14b3af897`
passed its seven ownership laws, two real server hover/refusal cases and three
pure corpus/runtime-candidate laws in actual source-built Actions. The whole
Check run `37108488796` failed: seventeen jobs succeeded, two failed and five
were declared skips. Counts run `37108490403` succeeded with all three existing
100 measurements. These results remain bound to that source and its original
logs; they do not qualify this correction or close the original Matrix failures.

The original declaration create/delete and watched-change tests timed out
because diagnostics stopped referencing their Vue `GlobalComponents`
augmentations outside `include: ["src/**/*"]`. The original Element Plus badge
hover changed from `(parameter) value: any` to `(parameter) value: string`
because canonical hover newly referenced the component augmentation. Neither
the original declarations/configurations nor the original exact expectations
are changed. The original Volt source blob
`76ffa1bb83ee2056c60be853c7300db522bfb6c6`, authored `ref(['new'])` binding,
registry pin and `const tags: string[]` contract remain unchanged.

The correction collects declaration roles in the existing OXC declaration
visitor and caches them with the existing disk stamp or open-document revision.
There is one declaration parse/visitor on a cache miss, shared with tag names;
there is no second classification parse or pipeline stage. Actual direct value
declarations inside `declare global` supply canonical editor references only
after existing physical effective-project membership selection. Comments,
unrelated modules, type-only declarations and values confined to a nested
namespace do not supply this role. A whole file that also augments Vue
`GlobalComponents` is withheld from canonical hover, since importing that whole
file would change the established slot behavior. Projecting only its global
value declarations, and admitting other ambient declaration forms, remain TODOs.

Diagnostics retains ordinary membership-scoped references and the established
component-augmentation route. The latter receives only actual parser-classified
Vue or `@vue/runtime-core` `GlobalComponents` declarations. A configured source
must have one readable actual owner. Component declarations are either members
of that effective project or physical declarations below its configuration root
without a nearer different TypeScript configuration. Unowned, ambiguous,
missing, foreign and nested-project fallback candidates are refused. The
existing no-configuration physical workspace fallback remains. Path selection
does not classify declaration roles or mint native File authority. Configuration
is reread between calls; it is not an atomic filesystem snapshot.

A new reduced corpus retains the literal original Volt ambient declaration and
the existing watcher and badge component augmentations. Four new actual-parser
and revision-cache laws and four effective-project boundary laws are
source-authored and require fresh Actions. The pure corpus law checks its
literal source and original contracts. All original seven ownership laws, two
server cases, watcher inputs/diagnostic vectors, badge hover oracle, runtime
commands, defaults, budgets, dependency declarations and helper 68 remain exact.

This is a correction on the same temporary source branch. It has no new product
execution yet and requires one fresh exact-head whole Check, including all
existing watcher and Vue parity suites. No unchanged rerun, expected-value
refresh, timeout increase, skip, warning waiver, new job or extra stage is added.
Native routing, complete LSP history, the ecosystem Matrix and #6883 remain
unfinished. A public PR and protected acceptance are held until the correction
has actual full-suite evidence.
