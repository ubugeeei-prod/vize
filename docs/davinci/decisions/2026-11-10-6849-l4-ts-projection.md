# L4 type-check projection from L2

Tracked in [#6849](https://github.com/ubugeeei-prod/vize/issues/6849) (gate
`products.typechecker`). The fix-history fixtures come from
[#6879](https://github.com/ubugeeei-prod/vize/issues/6879). The inputs are
[#11554](https://github.com/ubugeeei-prod/vize/issues/11554) (JSX),
[#11555](https://github.com/ubugeeei-prod/vize/issues/11555) (TSX) and
[#6858](https://github.com/ubugeeei-prod/vize/issues/6858) (TSRX). JSX lowering
comes from [#6885](https://github.com/ubugeeei-prod/vize/issues/6885) and
script facts from [#6844](https://github.com/ubugeeei-prod/vize/issues/6844).

The 2026-09-27 decisions on #6849 still hold:

- Parity is measured on diagnostics, not virtual TS bytes.
- The target writes from L2 through the single writer.
- Writer span links are the projection mapping rows.
- Maestro's virtual code merges into this target.

This record fixes the shape of `vize_l4::targets::ts` and the order in which
it replaces the current projections.

## Principles

- **One implementation.** SFC templates, JSX/TSX and TSRX produce the same L2
  ops. The target branches on the op and its facts, never on the input kind.
  Vue template semantics come from the Vue dialect module, as data (the access
  rule below). Core modules never encode them.
- **TypeScript judges.** Rust writes only facts that are certain from the
  source: spans, names, scopes, op structure, macro calls and declarations. It
  never writes a type it resolved itself. A construct the target cannot project
  returns a typed refusal and no document.
- **More precise than vue-tsc, never weaker than today.** A check that the
  current projection makes stays, including the stricter-than-vue-tsc ones.
  Positions name the exact authored construct, such as the attribute rather
  than the tag. Intentional strictness goes on the type-checker compatibility
  page.
- **Cost.** A cold full check is never slower than today. This is measured in
  CPU-seconds, peak RSS and checker instantiations, with no caches.
  - Nothing is declared per usage or per file as a local generic alias. Those
    defeat instantiation caching.
  - Helpers are shared ambient declarations.
  - Spans are coarse: one link per contiguous verbatim run and one per
    expression. There are no per-line splits and no one-character delimiter
    links.

## Document shape

The document is a plain `.ts` module for every input, as the standing directive
for JSX virtual TS requires. Its parts, in order:

1. **Script, verbatim.** Each contiguous authored run is one linked run.
   - SFC: `<script>`, then `<script setup>`, in authored order, at module
     scope. With `generic`, the setup statements sit inside one generic
     function, and its exported types are hoisted.
   - JSX/TSX/TSRX: the whole module. Each outermost markup root is replaced in
     place by its projection, which is the reverse embedding. Markup inside an
     embedded expression is projected recursively.
2. **Render body (SFC only).** One function after the setup statements. It
   opens with the one context declaration described below.
3. **Export tail (SFC only).** The default export has the same public shape
   and markers as the current projection, because the helpers in other files
   read them. A parent projected by one route and a child projected by the
   other must still check correctly.

Markup in statement position (TSRX bodies) projects to statements. A root in
expression position (JSX) projects to one expression whose type follows the L2
execution model of #6885: re-render gives a VNode and run-once gives the
element or block. Until that fact exists in L2, such a root is refused.

## Name resolution

Template expressions are written through `vize_l4::expr::write_expression`,
the same writer the DOM target uses. The TS target supplies the
`AccessProvider`:

- **Template-local bindings stay verbatim.** These are `v-for` aliases, slot
  parameters and handler locals. Each L2 region becomes a TS block with the
  same declarations, so TypeScript resolves the name to the same binding L2
  chose.
- **Plain script bindings stay verbatim.** In JSX/TSX/TSRX, a name L2 binds to
  a lexical script declaration whose value is not transformed is not
  respelled.
- **Everything else is read through the context.** This covers Vue setup
  exposure (refs unwrap), props, instance members and names L2 leaves
  unresolved. They are spelled as a read from the context, and the identifier
  keeps its own link. An unknown name is therefore reported by TypeScript at
  the identifier, not refused or guessed by Rust.

The SFC context is declared once per file. It combines:

- `import('vue').ShallowUnwrapRef` over the template-visible setup bindings.
  These are value-namespace declarations from the #6844 binding rows, and the
  object type is written once per file.
- The props value.
- The public instance members.

Writes stay checked. An assignment in a template expression or handler is
written as an assignment, so TypeScript reports a const, readonly or non-lvalue
target. The slice that adds context writes pins the exact form against the
fix-history fixtures for model and handler writes.

Macro calls (`defineProps`, `withDefaults`, `defineEmits`, `defineModel`,
`defineSlots`, `defineExpose`) stay calls inside the verbatim setup:

- The callee is respelled at the callee span from the #6844 macro-call facts,
  to the shared ambient declarations (`__vize_defineProps`, …).
- Arguments and type arguments stay verbatim.
- A bare `defineProps` statement is captured into the props value with a
  generated prefix.

## Projection per L2 op

"Owner object" means the one props object literal of the element, component
or outlet that owns a binding. Each owner is checked by one shared helper
instantiation, which TypeScript caches across usages of the same component
type.

| L2 op                                          | TypeScript construct                                                                                                                                                                          | Links                            |
| ---------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------- |
| `ui.text`, `vue.once`, `vue.cloak`             | Nothing                                                                                                                                                                                       | None                             |
| `ui.comment`                                   | Nothing. A check comment (`@vue-ignore`, `@vue-expect-error`, `@vue-skip`) becomes a directive range on the next projected statement                                                          | Directive range to the comment   |
| `ui.interpolation`, `ui.jsx-child`             | One expression statement                                                                                                                                                                      | The expression                   |
| `ui.element`                                   | Owner object checked against the native element type through the existing native-element helpers. Children follow in order                                                                    | Tag anchor; each key and value   |
| `ui.component`                                 | Component value: the L2-resolved binding verbatim, or a registered component read through the context. Owner object holds static attributes as string props, plus bindings and slot callbacks | Tag name; each key and value     |
| `ui.bind`                                      | `name: value`, `[name]: value` or `...value` in the owner object. Modifiers decide the key spelling                                                                                           | Name and value                   |
| `ui.on`                                        | `onName: handler` in the owner object. An inline body becomes `($event) => { body }` around the original L2 handler body                                                                      | Event name; handler or body      |
| `ui.model`                                     | Value prop plus the update listener, which assigns to the authored target. Native elements are checked per element kind                                                                       | Argument; target                 |
| `ui.if`                                        | `if`/`else if`/`else` blocks around the regions. A conditional authored as script (`&&`, `?:`, TSRX `@if`) keeps its authored bytes around the projected regions                              | Conditions; authored script runs |
| `ui.for`                                       | `for (const [value, key, index] of __vForList(source)) { region }`                                                                                                                            | Source; each alias               |
| `ui.for` (original)                            | The authored loop or callback head verbatim (`.map(...)`, TSRX `@for`), with the region projected inside                                                                                      | Authored script runs             |
| `ui.slot`                                      | Owner object checked against the component's own declared slot payload. Fallback region after                                                                                                 | Name; each key and value         |
| `ui.slot-content`                              | `(params) => { region }` typed by the host component's slot payload through the existing slot helpers                                                                                         | Slot name; params pattern        |
| `ui.slots-object`                              | The object checked against the host component's slots                                                                                                                                         | The expression                   |
| `vue.directive`                                | The existing directive call helper with value, argument and modifiers                                                                                                                         | Name; value; argument            |
| `vue.show`, `vue.html`, `vue.text`, `vue.memo` | Expression statement. `v-html` and `v-text` are checked as the DOM prop they set                                                                                                              | The expression                   |
| `vue.css-bind`                                 | Expression statement in the render body                                                                                                                                                       | The expression                   |
| `vue.sync`, `vue.slot-scope`                   | Vue 2 forms of `ui.model` and `ui.slot-content`, under the Vue 2 dialect, after the Vue 3 families                                                                                            | As above                         |

## Span links and the Canon contract

The target returns three things:

- The `EmitDocument`.
- One role per link: script, expression, name, component tag, attribute,
  event, slot, directive or export.
- The directive ranges.

Canon converts this to its existing output contract without changing it: code,
`VizeMapping` rows (`crates/vize_canon/src/virtual_ts/mapping/rows.rs`) with
`ProjectionMeta`, and the directive ranges. The content mapper wire therefore
carries it unchanged. A name link nested in an expression link becomes a
sub-span of that row. Context reads also carry a semantic link to the
declaration span from the #6844 facts, for definition and rename.

Diagnostic mapping keeps the rule `targets::ts::mapping` already enforces. A
range maps only when it lies inside one link (or is a point at its end). It
never clamps across a boundary. Every generated construct that can carry a
diagnostic gets an anchor link to the authored construct that owns it; for
example, a missing required prop lands on the component tag name. The number
of unmapped diagnostics on the corpus must be zero.

The layout stays stable under edits: script runs first, then the render body.
The LSP can then send only the edited ranges to the checker, as decided on
#6849.

## Helpers

The target references helpers by name only, from two sources:

- The published ambient set, `npm/cli/virtual-ts-globals.d.ts` together with
  the hoisted shared preamble.
- Vue's public types, such as `import('vue').ShallowUnwrapRef`.

One const table in `targets::ts` lists every helper name the target writes. A
tooling test asserts that each name is declared in the published file. The
target never writes a helper declaration, so the helper assets, the helper-abi
chain and its frozen hashes stay untouched.

- **Helper not yet published.** A projection that needs one is refused. The
  helper is added by a separate helper-asset change from its owner, sequenced
  through the orchestrator.
- **JSX `Ctx<Emits, Slots>`.** The current JSX path declares it per file. The
  L4 projection keeps exactly today's declaration bytes, which is not a
  regression, and moving it into the shared ambient set is an owed asset
  change.
- **Standalone content-mapper route.** This route has no ambient file. It stays
  on the current projection until its helper delivery is decided with its
  owner.

## Canon seams

Each switch is a per-file opt-in and is off by default. Each wiring change goes
to the Canon perf owner with exact files before it is opened.

- **JSX/TSX (`vize check`).** `build_jsx_registered_file` in
  `crates/vize_canon/src/batch/virtual_project/jsx_build.rs` consumes
  `GeneratedJsxFile { code, mappings, diagnostics }`. The L4 adapter produces
  the same struct.
- **SFC (`vize check`).** `generate_vue_virtual_ts` in
  `crates/vize_canon/src/batch/virtual_project/vue_codegen.rs` returns
  `GeneratedVueFile`. `crates/vize_canon/src/typecheck_service.rs` serves
  batch checks and `crates/vize_canon/src/sfc_typecheck/runner.rs` serves
  single files.
- **LSP.** `crates/vize_maestro/src/ide/corsa_support/canonical/` and
  `crates/vize_maestro/src/ide/diagnostics/corsa/virtual_ts.rs`.

A refusal keeps that file on the current route. That is routing, not a
fallback: the file counts as not native in every acceptance rate and never
passes a gate. The checker host move into an L4 `host` feature (2026-09-27)
comes after the default switch.

## Differential oracle

The differential runs one build and one checker on one project configuration,
over two routes: the current projection and the L4 opt-in. It compares the
mapped authored diagnostics: file, start, end, code, category and message.

- **Inputs.**
  - Every #6879 pack under `tests/_fixtures/differential/typechecker/` and
    `tests/_fixtures/differential/typecheck/`. The native adapter of the
    harness (`tests/differential/typechecker.ts`, today `native: null`) is this
    route.
  - The public corpora that the type-check corpus pair measures.
- **Classes.** Every row that is not identical is classified with evidence;
  there is no unclassified row.
  - _Identical._
  - _L4-only:_ correct from the authored code, so Vize is more precise and the
    row is recorded, or else a defect.
  - _Current-only:_ a missed check, which is a defect, unless the current row
    is a false positive with evidence.
  - _Position-only:_ L4 must be at least as narrow.
- **Where it runs.** A separate lane in `typecheck-corpus-pair.yml` or its own
  dispatch workflow. It is outside the required checks until a default switch,
  and it reports the cost numbers above beside the diagnostics.

## Rollout

The order follows where L4 replaces the most legacy code. The JSX/TSX path is
a textual lowering through `vize_atelier_jsx`.

1. **This record.**
2. **Target core.** The output type (document, link roles, directive ranges),
   the context access provider and the helper table with its tooling test. Then
   the JSX/TSX module projection for each L2 JSX family as #6885 delivers it.
   Real TypeScript tests in `vize_l4` follow the existing program projection
   tests.
3. **JSX/TSX seam and lane.** The opt-in JSX/TSX seam (wiring PR), the
   differential lane, and the native adapter enabled for the JSX packs.
4. **TSRX.** With the TSRX compiler lane: a component declaration becomes a
   function, and statement markup becomes statements.
5. **SFC templates.** Verbatim setup with macro respelling, the render body and
   the context first. Then the component, slot and model families. The Options
   API (#6844 S7) and Vue 2 come last.
6. **Default switch, per input family.** It happens only when three conditions
   hold:
   - every fix-history fixture of that family passes natively;
   - the differential has no unclassified row and no current-only true
     positive;
   - cold CPU and RSS are at or below the current route.

   The current projection for that family is deleted after the switch (#6828).
