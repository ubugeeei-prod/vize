# Directed queries over original frontend IR

Experimental implementation behind the `graph-queries` feature and the independently selected [resident provider](../../../crates/vize_incremental/providers/graph/Cargo.toml).

An editor can move a whole template by inserting an emoji in an earlier script. Its DOM dependencies still connect the same template operations, while every file-absolute byte and UTF-16 location may change. A formatter needs the exact original spelling even during a half-written edit. A compiler needs to know whether the operation and its dependencies are complete. Giving these consumers the same mutable, absolute-positioned tree makes them repeat parsing, traversal and invalidation.

## Representation and ownership

| Layer | Owns                                                                                                        | Failure and reuse                                                                                                                                |
| ----- | ----------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| L1IR  | The immutable source, ordered container segments, trivia, embedded-language boundaries and parser recovery. | Every byte of a UTF-8 input belongs to one source segment. A broken file still has a source view.                                                |
| L2IR  | The completed native file with its scoped bindings, references and root region.                             | A native observation exposes the complete file only after admission. Partial syntax and diagnostics stay accessible on the original observation. |
| L3IR  | The scheduled operations and explicit DOM-order, effect-order and data-dependency edges.                    | A query names a start, a direction and a set of edge kinds. Locally issued IDs belong to one original graph.                                     |

The native file API names these views `L1Ir`, `L2Ir` and `L3Ir`. Existing callers can keep their type spellings. Original containment has an order and a lossless text interpretation. References, captures, dependencies and effects can cross containment boundaries or form cycles. Linking those relations through explicit owners lets the formatter recover exact text while semantic consumers traverse only their selected edges.

Roslyn's green nodes store immutable, position-independent structure. A red view supplies parent and position information at use time. Roslyn's workspace and language server also maintain document and solution context across requests. rust-analyzer separates syntax from semantic queries and uses a coarser item representation to avoid invalidating unrelated name resolution after body edits. Davinci applies this distinction at the block boundary. A resident query reads relative content and its expression language. A borrowed document view supplies the current start offset at publication. The present implementation re-lowers a changed block. Subtree-level reparsing remains a separate obligation. [Roslyn syntax design](https://github.com/dotnet/roslyn/blob/main/docs/compilers/Design/Red-Green%20Trees.md), [Roslyn language server](https://github.com/dotnet/roslyn/blob/main/src/LanguageServer/roslyn-language-server/README.md), [rust-analyzer architecture](https://rust-analyzer.github.io/book/contributing/architecture.html).

## Query meaning and cost

Direct incidence scans the original edge slice with zero auxiliary allocation. Repeated requests can build forward and reverse adjacency in one reverse-order pass. Each node and each original edge adds two 32-bit adjacency links. Dense IDs directly index node positions. Sparse IDs use a sorted position table. Construction rejects duplicate IDs and dangling endpoints, including endpoints outside the requested closure. A parallel edge retains its own ordinal and optional effect identity. An isolated start has a zero-length path to itself.

Reachability returns each reachable endpoint once in breadth-first order. The selected edge order deterministically breaks traversal ties. A callback can compute region/effect rows and source spans during that same walk. A proof row gives the original edge ordinal that first justified the endpoint. The independent checker accepts any valid witness order. It checks each parent was already seen and then scans all selected original edges for an omitted successor. For dense IDs the walk visits reachable nodes and their incident edges, while verification also reads the complete graph. A resident materialization copies the relevant original rows exactly once, keeps the index for other starts and caches the checked result of each query.

Cypher gives nodes, relationship identity, direction and relationship types distinct roles. Its path-pattern and row multiplicity matter when a query enumerates alternative paths. Davinci keeps one witness per reachable endpoint in `reach_with`. A two-edge pattern in `visit_two_hop` returns one row per distinct pair of original relationship ordinals. Two parallel edges can return to the same operation in two different ways. This follows Cypher's relationship uniqueness within a path pattern. Davinci additionally specifies lexicographic ordinal order so independent passes and editor requests see the same sequence. [Francis et al., SIGMOD 2018](https://www.research.ed.ac.uk/en/publications/cypher-an-evolving-query-language-for-property-graphs/).

LLVM groups passes at the same IR level to preserve locality, and its analysis manager tracks what a pass preserves. MLIR scopes analyses and nested pass pipelines to operation owners. GCC's Tree SSA pipeline exposes control-flow and value edges after lowering. Cranelift's e-graph work documents the difficulty of preserving side effects while selecting among equivalent expressions. Davinci therefore shares a physical pass when the requested consumers read the same owner and edge selection, retains explicit effect edges and keeps representation conversion outside individual consumers. [LLVM new pass manager](https://llvm.org/docs/NewPassManager.html), [MLIR pass management](https://mlir.llvm.org/docs/PassManagement/), [GCC Tree SSA passes](https://gcc.gnu.org/onlinedocs/gccint/Tree-SSA-passes.html), [Fallin on Cranelift's e-graphs](https://cfallin.org/blog/2023/01/20/cranelift-egraph/).

The cyclic graph of source and operation relationships is independent of the database's evaluation dependencies. The standalone resident provider runs on the existing Salsa database through its opt-in `resident-providers` interface. Its own Cargo workspace and lock keep graph dependencies out of the stock build. A resident query reads its tracked block source and language. Other starts share the lowering and adjacency index. A sibling edit can change an absolute location and preserve the memoized relative result. An equal-length edit still revalidates changed content. A clean recomputation checks the transitions into and out of a syntax error. This is the demand-driven distinction described in Adapton and in rustc's red–green dependency checking. [Hammer et al., PLDI 2014](https://www.cs.umd.edu/~mwh/papers/hammer13adapton.html), [rustc incremental evaluation](https://rustc-dev-guide.rust-lang.org/queries/incremental-compilation-in-detail.html).

## Verification and its scope

| Check      | Question answered                                                                                                                                                                                                                                   |
| ---------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Lean       | For any relation, including on an infinite type, does a finite rooted list with earlier witnesses and closure contain exactly the reachable vertices? The kernel checks the theorem without additional axioms.                                      |
| Alloy      | With up to five operations, six first-class edges and five ranks, can reachability disagree with a valid answer? Satisfiable examples exercise reverse traversal, parallel edges, a cycle, a missed successor and a disconnected unsupported cycle. |
| TLA+ / TLC | With two document identities, three bodies, two offsets and three revisions, can an older completed request publish into a newer snapshot? Disabling the publication check must yield a counterexample.                                             |
| Kani       | Do the actual local Rust rules justify a full-width endpoint, and does every accepted answer agree with transitive closure on all three-node labelled graphs in either direction?                                                                   |
| Creusot    | Do the Rust witness and closure predicates implement their mathematical contracts for every Boolean input and 32-bit endpoint? The proof workspace shares the shipped source.                                                                       |

The checker validates a particular answer against the original L3 rows. The graph specification assumes the selected relation represents the intended language behavior. A compiler correctness result additionally needs source and target semantics and a simulation across lowering. Diagnostics need rule-specific soundness and range checks, a typechecker needs a typing derivation, a formatter needs preservation and idempotence for its admitted grammar, and an LSP response needs current document identity, revision and coordinate encoding. Keep those claims specific to each product and continue using the established differential oracles for every adoption decision. [Necula, Proof-Carrying Code](https://doi.org/10.1145/263699.263712), [CompCert's semantics and simulation proofs](https://compcert.org/doc/).

## Many starting operations in a resident document

The single-query cache uses a Salsa LRU capacity of 128, matching the existing resident interface summary capacity. Cold answers leave the cache when a document revision advances. An all-start scan can visit every suffix of a chain in one revision, producing a quadratic number of rows. The batch reader retains the verified graph and returns one independently checked answer at a time. Dropping that answer releases its rows. A caller that collects every answer owns the corresponding storage.

On Apple arm64 a 256-sibling scan visited 32,896 rows. Memoizing each start and reading through the batch produced identical results. The additional peak fell from 936,224 to 5,376 bytes, allocation calls from 5,010 to 3,847 and elapsed time from 629,709 to 534,708 ns. A subsequent prefix-only edit reused the graph and rechecked the 128 evicted answers. The time control on the regular compiler/editor benchmark pools two additional measurement windows if the initial median slows down. The final median must still meet the original threshold.

On Linux x86-64 the same 32,896 results took 485,824 ns with memoization at every start and 379,985 ns with the batch reader. Peak bytes fell from 940,472 to 5,376 and allocation calls from 5,046 to 3,847. [Linux measurement and corpus checks](https://github.com/ubugeeei-prod/vize/actions/runs/45029702414/job/137230353875)

## Typed two-edge patterns

Both legs choose a direction and edge kinds. The shared adjacency lists yield the intermediate operation, then its eligible second edges, in original row order. A consumer can stop on its first match. A complete response can be independently checked against the Cartesian product of the original relationship rows, including unmatched or malformed endpoints. The checker is for qualification or consumers requiring certification. Enumerating matches only needs the adjacency index and constant additional space.

In the resident provider, the Salsa dependency is the template's content and language. A two-edge request borrows that graph and resolves only the source positions the consumer requests against the current block. An edit before the template moves these positions. An edit inside the template can invalidate the whole graph or return the original parser's holes. This applies red-green dependency tracking to the particular inputs that determine each answer. [Salsa algorithm](https://salsa-rs.github.io/salsa/reference/algorithm.html).

`tests/formal/ir-graph/Reach.lean` proves ordered list equality for arbitrary finite edge tables, assuming each adjacency bucket preserves the original edge order. `Trail.als` compares bounded index results to a separate relation over raw directed edges. Positive examples cover returning on parallel relationships, two self-loops, and a single reversed relationship excluded by the uniqueness rule. The Rust corpus checks both indexes and every reported intermediate and final operation against the authored L3 table.
