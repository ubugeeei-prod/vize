# Leading line-comment directive fixed points

The [paired #7924 decision](https://github.com/ubugeeei-prod/vize/issues/7924#issuecomment-6010464167) retains the full original `Min.vue` and its reported `--write --no-config` command. Its 70-byte value begins with a line comment on the opening quote; the continuation must converge at attribute depth plus one level instead of accumulating another SFC indent on each pass.

The leading-comment branch now calls the existing `reanchor_continuation_lines` helper with authored HTML representation. It does not send comments through the standalone expression formatter. The helper retains #3346 common/relative continuation depth and raw literal ownership; a blank first line still returns verbatim, preserving #6694 own-line comment and quote placement. No parser, script formatter, pipeline stage or provider changes.

The independently authored complete 72-byte reference keeps `x` at six spaces. Public Rust tests require whole first/second/third output bytes, first-pass `changed`, both later `changed=false` and unchanged options. LF/CRLF, event comments, relative block depth, raw template lines and own-line quote controls remain complete inputs and references. The original `Min.vue` stays as reported; the existing differential CLI's `App.vue` transport is a byte-identical copy. All twelve prior manifest cases, references and global capture contracts are preserved.

The public CLI test requires a non-writing failed check of the original, three writes and a successful final check. It compares complete files, stdout/stderr and exit statuses both without project config and with an authored config ignored by `--no-config`. Exact-source Actions, the existing whole differential formatter artifact, protected unchanged instruction budgets/full suites, actual signed merge and installed release replay are still pending. These controls grant no native formatter, default migration or performance acceptance.
