# One JSX lowering on the shared levels

Tracked in [#6885](https://github.com/ubugeeei-prod/vize/issues/6885), for the
gates `levels.jsx`, `inputs.jsx` ([#11554](https://github.com/ubugeeei-prod/vize/issues/11554))
and `inputs.tsx` ([#11555](https://github.com/ubugeeei-prod/vize/issues/11555)).
It implements the 2026-09-27 [JSX decisions](./2026-09-27-level-restructure-designs.md#jsx-semantics);
this page fixes the op mapping, the dialect compositions, every observable
change and the delivery order.

## Pipeline

|       | SFC template                   | JSX / TSX                                                                                               |
| ----- | ------------------------------ | ------------------------------------------------------------------------------------------------------- |
| L1    | `vize_l1::markup` surface tree | the oxc `Program` from `vize_l1::embed::syntax::program::parse_program_once` (`jsx: true`), parsed once |
| L1→L2 | `vize_l1_to_l2::lower`         | `vize_l1_to_l2::framework::vue::jsx`, one walk per render root                                          |
| L2    | `ArtifactParts`                | the same `ArtifactParts`, one per render root                                                           |
| L3/L4 | `run_transform`, DOM/Vapor/SSR | the same calls, with no JSX parameter                                                                   |

Today JSX goes oxc → `vize_atelier_jsx::lower` (a Relief `RootNode`) →
`vize_atelier_core` transforms → legacy codegen, and `vize_atelier_jsx::l2`
projects that Relief tree back into L2 for the VDOM subset and the linter.
Both Relief hops go away. The new lowering reads the oxc AST and retains its
expressions (`JsExpr::from_retained_in`), with no reparse.

## One per-file shape

```rust
pub struct ComponentDef<'a> {
    pub name: Option<&'a str>,
    pub exec: Exec,       // ReRender | RunOnce
    pub scope: Scope,     // Lexical | Instance
    pub span: Span,
    pub body: ArtifactParts<'a>,
}
```

`ComponentDef` lives in `vize_l2` (it is not JSX-specific). A JSX file lowers
to one `ComponentDef` per outermost render root, in authored order. An SFC
lowers to one, with `exec: RunOnce` for a Vapor component and `ReRender`
otherwise. Products (compiler, linter, type checker, LSP) read this list and
never ask which input produced it.

- `exec` comes from the nearest enclosing function's `"use vue:vapor"` /
  `"use vue:vdom"` prologue, else the configured default. It selects the L4
  target: `ReRender` → DOM, `RunOnce` → Vapor; SSR accepts both. An explicitly
  requested target that contradicts `exec` is an error diagnostic.
- `scope` is where a free identifier resolves. A JSX render body is
  `Lexical`: identifiers are bare, as today. A template is `Instance`: the
  `_ctx.` / setup-binding rules apply. This replaces the Vapor "closure mode"
  switch (`VaporGenerateOptions::jsx_closure`).

## Dialects

A dialect is resolved once per file and is a const composition of features
under `framework/vue/jsx/`. The interpretation depth only chooses which ops
the lowering builds; the meaning of the built ops comes from `exec`.

| Dialect const   | Depth           | `exec`   | Selected by                                 | Reference               |
| --------------- | --------------- | -------- | ------------------------------------------- | ----------------------- |
| `VIZE`          | Structural      | either   | default                                     | today's Vize output     |
| `BABEL`         | Opaque          | ReRender | `compiler.jsxCompat: "babel"`               | `@vue/babel-plugin-jsx` |
| `VUE_JSX_VAPOR` | Reactive getter | RunOnce  | `compiler.jsxCompat: "vue-jsx-vapor"` (new) | `vue-jsx-vapor`         |

Opaque and reactive-getter build the same expression ops. They differ only
in `exec`, which is why the table has no other cells. `BABEL` with Vapor and
`VUE_JSX_VAPOR` with VDOM stay diagnostics, as `compat.rs` already reports
for Babel.

| Feature                                                  | `VIZE` | `BABEL`             | `VUE_JSX_VAPOR` |
| -------------------------------------------------------- | ------ | ------------------- | --------------- |
| structural `&&` / `?:` / `.map`                          | yes    | no                  | no              |
| `onXCapture` / `Once` / `Passive` names                  | yes    | yes                 | no              |
| `_` modifiers on directives (`v-x:a_m`)                  | yes    | yes                 | yes             |
| `_` modifiers on events (`onClick_stop`)                 | yes    | no                  | yes             |
| `v-model` array / `v-models`                             | yes    | yes                 | yes             |
| `v-slots`                                                | yes    | yes                 | yes             |
| object-child slots                                       | yes    | `enableObjectSlots` | yes             |
| `mergeProps`, `transformOn`, `isCustomElement`, `pragma` | –      | options             | –               |

## Op mapping

Every row produces the same op the equivalent template produces, unless the
runtime meaning differs; then the op differs.

### Names

| JSX                                         | L2                                          |
| ------------------------------------------- | ------------------------------------------- |
| lowercase intrinsic (`div`, `svg`, `x-foo`) | `ui.element` (namespace from the tag path)  |
| capitalized or member (`Foo`, `ui.Button`)  | `ui.component`                              |
| `<component is={X}>`                        | `ui.component` with `is` (dynamic)          |
| `<Teleport>`, `<KeepAlive>`, …              | `ui.component`; built-in resolution is L3's |
| `<template v-slot:x>` under a component     | `ui.element` + `ui.slot-content`            |
| `<style scoped>` inside a render root       | no op; an L1 style block                    |

### Attributes

| JSX                                                         | L2                                                                |
| ----------------------------------------------------------- | ----------------------------------------------------------------- |
| `a="x"`, `a`, `a={}`                                        | `Attribute`                                                       |
| `a={e}`                                                     | `ui.bind a`                                                       |
| `{...e}`                                                    | `ui.bind` with no name, in authored order (`mergeProps`)          |
| `onClick={e}`                                               | `ui.on click`, handler `Value(e)`                                 |
| `onClickCapture={e}` (`Once`, `Passive`)                    | `ui.on click [capture]`, handler `Value(e)`                       |
| `onClick_stop={e}`                                          | `ui.on click [stop]`, only when every segment is a known modifier |
| `key={e}`, `ref={e}`                                        | `ui.bind key` / `ui.bind ref`                                     |
| `v-model={x}`, `v-model:a_m={x}`                            | `ui.model` (argument, modifiers)                                  |
| `v-model={[x, 'a', ['m']]}`                                 | `ui.model` (argument `a`, modifier `m`)                           |
| `v-models={[[x, 'a'], …]}`                                  | one `ui.model` per entry                                          |
| `v-show`, `v-html`, `v-text`, `v-once`, `v-memo`, `v-cloak` | the template's `vue.*` op                                         |
| `v-if` / `v-else-if` / `v-else`, `v-for`                    | `ui.if` / `ui.for`, as templates                                  |
| `v-name:a_m={e}`, `v-name={[e, 'a', ['m']]}`                | `vue.directive` (argument, modifiers)                             |
| `v-slots={e}`                                               | `ui.slots-object`                                                 |

`Value(e)` is a new `OnHandlerRef` variant: the value of `e` is the listener.
A template `@click="e"` keeps its classified handler (method path, function
or inline statement). A template `:onClick="e"` and a JSX object spread stay
`ui.bind`.

### Children

| JSX                             | L2                                                                       |
| ------------------------------- | ------------------------------------------------------------------------ |
| text                            | `ui.text`, cleaned by the Babel JSX whitespace rule                      |
| `{'s'}`                         | `ui.text`                                                                |
| `{}`, `{/* c */}`               | nothing                                                                  |
| `{e}`, alone or mixed with text | `ui.jsx-child` (renderer-normalized value), never `ui.interpolation`     |
| `<>…</>` in child position      | its children, spliced                                                    |
| `{...e}`                        | `ui.child-spread` (new)                                                  |
| other JSX inside an expression  | `ui.render-expr { expr, regions }` (new); the nested JSX are its regions |

### Control flow (`VIZE` only; `BABEL` and `VUE_JSX_VAPOR` build `ui.render-expr`)

| JSX                                 | L2                                                                                             |
| ----------------------------------- | ---------------------------------------------------------------------------------------------- |
| `c && <A/>`, `c` provably boolean   | `ui.if` with one branch                                                                        |
| `c && <A/>`, otherwise              | `ui.and { left: c, right }` (new): `c` evaluated once, falsy values render as a JSX child      |
| `c ? <A/> : <B/>`, nested ternaries | `ui.if` with else-if branches; a non-JSX arm is a `ui.jsx-child`                               |
| `xs.map((x, i) => <A/>)`            | `ui.for` (value `x`, index `i`)                                                                |
| `xs.map(x => { return <A/>; })`     | `ui.for`, only when the body is exactly that one `return` and there are at most two parameters |
| any other shape                     | `ui.render-expr` or `ui.jsx-child`                                                             |

`ui.and` replaces today's synthetic scoped `For` around an `If`, which the
Relief projection already refuses. `ui.for` iterates with `renderList`, so a
non-array `xs` (an object, or a value with its own `map`) behaves as `v-for`,
not as the JS call. That is the `VIZE` reading today and stays documented here.

### Component children

| JSX                                  | L2                                                          |
| ------------------------------------ | ----------------------------------------------------------- |
| elements / text                      | implicit default `ui.slot-content`, as templates            |
| `{(p) => …}` sole child              | default `ui.slot-content` with parameter `p`                |
| `{{ name: (p) => … }}` sole child    | one `ui.slot-content` per property                          |
| any other sole object or value child | `ui.slots-object`                                           |
| slot function returning a value      | its body lowers as a render root: `ui.jsx-child` for values |

## Source facts for products

The type checker projects authored script verbatim and replaces each JSX root
in place ([#12478](https://github.com/ubugeeei-prod/vize/pull/12478)), so the
lowering keeps these facts beside the ops:

- each `ComponentDef` has the authored span of its root;
- an `ExprRef` (child, attribute value, spread, `ui.render-expr`) that
  contains JSX lists its nested roots by span, each with its region;
- `ui.component` names resolve through the File's reference rows to their
  script declaration;
- structural ops keep their authored spans: the `&&` operator and both
  operands for `ui.and` / `ui.if`, the test and arms for a ternary, and the
  callee and callback head (parameters) for `.map`, as `ui.for` does for an
  original `v-for` head;
- slot functions keep their parameter pattern span.

## L3 and L4

Neither reads the dialect. The two file-wide JSX flags they read today are
resolved as follows:

- `OpFamily::JsxChild` is derived from the presence of `ui.jsx-child` ops and
  stays: raw child values disable DOM block tracking whatever the input.
- `OpFamily::JsxClass` is not an encoding choice. A lone JSX `class={e}` follows
  `createVNode`'s rule, so falsy non-strings reach `patchClass` unchanged,
  while a template `:class` always goes through `normalizeClass` (row
  `props/dynamic-class-value`). The rule therefore moves onto the binding:
  `ui.bind class` records `class_rule: Runtime | Normalized`, and the
  file-wide bit is deleted.

## Observable changes

Native Vize output stays byte-identical to today's, except for these fixes.
Each lands with its slice, a failing oracle row turned equivalent and a
release note.

| Change                                                                      | Issue  |
| --------------------------------------------------------------------------- | ------ |
| mixed-text `{e}` and slot return values render as JSX children              | #12322 |
| `.map` callbacks with statements or a third parameter stay JSX child values | #12477 |
| Vapor function `ref` calls the function                                     | #12311 |
| Vapor honors `v-once`                                                       | #12312 |
| `_` modifiers on events and custom directives                               | #12313 |
| Vapor capture/once/passive listeners pass the value through                 | #12323 |
| Babel `mergeProps: false`, `modelValueModifiers`, non-object spread         | #12324 |
| Babel children under VDOM blocks are normalized                             | #12334 |

Differences that remain between `VIZE` with `RunOnce` and `vue-jsx-vapor` are
by design. Each produces an `Info` diagnostic on the L1→L2 channel, with the
oracle row that pins it:

| Diagnostic              | Meaning                                                   | Oracle row                                    |
| ----------------------- | --------------------------------------------------------- | --------------------------------------------- |
| `jsx/structural-and`    | the branch instance survives truthy-to-truthy updates     | `children/logical-and`                        |
| `jsx/structural-map`    | keyed items are reused by key                             | `control-flow/keyed-map-list`                 |
| `jsx/on-option-suffix`  | `onClickCapture` registers a capture listener for `click` | `events/capture-suffix`, `events/once-suffix` |
| `jsx/dynamic-component` | `<component is>` resolves dynamically                     | `components/dynamic-component`                |

`VUE_JSX_VAPOR` emits none of them, because it does not lower structurally.

## Delivery

One PR per step. Each keeps the Relief path for whatever the new lowering does
not admit yet, and proves the admitted part with three checks: the new L2 dump
equals the Relief projection's dump on every JSX corpus row it admits, apart
from the remappings on this page (`on*` props, the class rule, mixed text);
native output is byte-identical over both oracles' corpora, apart from the
fixes above; the JSX differential corpus records zero fallback for the
admitted rows.

1. `ComponentDef`, the dialect consts, names, attributes, text and
   `ui.jsx-child`.
2. Structural control flow, including `ui.and` and the `.map` fix (#12477).
3. Models and directives, with the `_` modifiers (#12313).
4. Component children and slots (#12322).
5. `ui.child-spread` and `ui.render-expr`.
6. `BABEL` through the same ops (#12324, #12334).
7. `RunOnce` roots on the native Vapor target (#12311, #12312, #12323), then
   `VUE_JSX_VAPOR`.
8. SSR from the same L2.
9. Products read `ComponentDef`s; `vize_atelier_jsx::lower`, `::l2` and the
   Relief dependency are deleted.
