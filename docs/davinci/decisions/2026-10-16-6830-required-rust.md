# Require Rust tests and Clippy before every merge

Issue: [#6830](https://github.com/ubugeeei-prod/vize/issues/6830).

The maintainer requires Rust tests and Clippy on every PR, with auto-merge
unable to accept either failing. This tightens the original affected-only
iteration policy, including documentation and JavaScript-only changes.

## Execution policy

- Every PR runs Clippy, ordinary Rust tests through cargo-nextest, and Cargo
  doctests. Changed crates and their full reverse dependency closure select
  the packages. Shared, deleted, or unknown inputs conservatively select the
  whole workspace.
- When no Rust crate is affected, run the actual `vize_relief` library tests,
  Clippy, and doctests. This small baseline exercises template AST, binding,
  diagnostic, and recovery behavior without pulling in compiler-wide test
  oracles. Missing baseline metadata is an error, never a successful skip.
- The merge queue runs Clippy and the full ordinary test profile for every
  workspace crate on the actual merge candidate, plus doctests and all Rust
  differential lanes. It catches failures outside the PR's narrowed closure
  before auto-merge can complete. Existing feature/runtime checks remain.
- Keep the original affected closure for JavaScript and native runtime
  selection. Mandatory Rust acceptance must not turn a documentation change
  into unrelated browser and package builds.

Reuse the trusted `nextest-ci` target snapshot, parallelize Clippy and four
test shards, and preserve the queue's source-bound archive and observations.
The optimization changes scheduling and compilation reuse, never a failed
test's exit status. A small shard may be empty; all four shards and Clippy must
still succeed for the selected nonempty package plan.

## Merge contract

The workflow always enables Rust checks. The Rust report refuses a disabled,
missing, or malformed plan and requires successful Clippy/doctest and test
jobs. The queue additionally requires the archive producer and differential
jobs. Failure, cancellation, an absent result, or a skipped required job cannot
be converted to success by an aggregate report.

The existing dependency chain ends in required `test-report`:
Rust jobs → Rust source report → PR source report → `test-report`.
The active main rulesets require this context and an ALLGREEN merge queue.
This change does not grant or use an administrative bypass.

Focused selector tests cover documentation, JavaScript, leaf-crate, unknown
input and merge-candidate cases. Gate tests inject failed, cancelled, skipped,
missing and malformed results. PR #9198 records Actions validation of the
final implementation and timings; earlier measurements remain observations
of their recorded commits, not proof of a later head.
