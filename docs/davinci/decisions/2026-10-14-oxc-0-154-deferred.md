# The OXC 0.154 upgrade waits until after Vue Fes Japan

Issue: [#8987](https://github.com/ubugeeei-prod/vize/issues/8987).

## Decision

Vize stays on OXC 0.142 until 2026-11-01. The upgrade to 0.154 then lands as
one pull request, prepared on the branch `chore/oxc-0.154`, while the merge
queue is quiet.

## Reason

OXC 0.154 is not a version bump that compiles with renames. Its AST changed
shape in four places: export declarations split into three node kinds, arrow
bodies became an enum without a statement list for expression bodies,
TypeScript module declarations split into namespace and global declarations,
and interface heritage now holds a type name instead of an expression. About
250 sites in twelve crates need a semantic rewrite. A walk over an arrow's
statements, for example, has to become a walk over its expression when the
arrow has an expression body.

Every one of those rewrites can change legacy output, which must stay
byte-exact, and the twelve crates are the ones other lanes are changing every
day. Doing it ten days before the talk would put correctness at risk and
conflict with nearly every open pull request.

## Rejected alternative

A compatibility view in the level crates, presenting the old node shapes over
the new AST, would have kept consumer diffs small. It adds a translation stage
between OXC and the levels, which the level restructure forbids, and it would
have to be removed again once consumers migrate.

## What is already done

The branch carries a script that rebases the vendored parser and formatter
forks onto a new OXC revision with a three-way merge
(`tools/support/dependencies/rebase-oxc-fork.ts`). Both forks are rebased onto
0.154 with their conflicts resolved and compile. The L1, L2 and Relief call
sites are migrated. `vize_croquis` and the crates that depend on it remain.
