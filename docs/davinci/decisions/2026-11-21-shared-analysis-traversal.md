# Sharing traversals and preserving authored source

Compiler backends, the formatter, lint rules and editor requests often inspect the same file. A rename needs the original binding and edit range. Formatting needs the original parentheses and comments. Code generation needs the lowered meaning. Sharing an AST that has already discarded a required distinction forces the next tool to parse the file again.

## What four compiler infrastructures teach us

**LLVM.** An inner pass that triggers a module-wide scan for each function can make analysis time quadratic. LLVM limits an inner pass to cached, immutable outer analyses. Grouping function passes at the function boundary also improves locality. Davinci can apply both ideas by declaring the requested fact families up front and passing each original Program event to the observers that requested it. The paired observer retains separate checkpoints and rolls them back in reverse order if construction fails. [LLVM New Pass Manager](https://llvm.org/docs/NewPassManager.html) · [Davinci Program observer](../../../davinci/vize_l2/src/lang/js/file/observer/pair.rs)

**MLIR.** A lowering may encounter operations it cannot legalize yet. MLIR gives each conversion target explicit legality rules. Partial conversion can retain unknown operations, analysis conversion can report what would succeed, and full conversion requires every operation to be legal. Davinci's analogous distinction is observable at the query boundary. A missing observer, incomplete file and successful empty result have different meanings to a linter or editor. Keeping those outcomes distinct lets a consumer decide whether it can publish its answer. [MLIR dialect conversion](https://mlir.llvm.org/docs/DialectConversion/) · [Davinci Vue query results](../../../davinci/vize_l2/src/query/vue.rs)

**Cranelift.** A frontend encounters variable uses before it knows all the predecessors of a loop block. Cranelift records the unresolved work during translation and finishes it when the frontend seals the block. This permits SSA construction alongside the original traversal. The corresponding boundary in Davinci is completion of one observed File. The producer gathers selected facts during that walk, and the model verifies File identity when attaching those facts. This transfers the ownership and completion discipline to source tooling. [Cranelift SSA builder](https://github.com/bytecodealliance/wasmtime/blob/40e0d780e4bfa34325d342db5bcf492bea227e07/cranelift/frontend/src/ssa.rs) · [Davinci File producer](../../../davinci/vize_l2/src/query/vue/producer.rs)

**GCC.** Tree SSA gave different frontends a common representation for analysis. GCC's early GIMPLE implementation reused the full frontend tree representation, whose generality exceeded the needs of the restricted IR. The gimplifier also illustrates the cost of an extra intermediate walk when the downstream consumer already needs the lowered form. Davinci keeps the authored L1 source available for editing and printing, while L2 owns binding and scope facts. Where printing needs a different parse profile, it can borrow the existing semantic observation and parse the original bytes once with the printer's options. [GCC Tree SSA project](https://gcc.gnu.org/projects/tree-ssa/) · [GCC GIMPLE internals](https://gcc.gnu.org/onlinedocs/gccint/GIMPLE.html) · [Davinci script profiles](../../../davinci/vize_l1/src/embed/syntax/snapshot.rs)

## Checking a claim of pass fusion

The L2 transform plan groups `hoist-static` and `template-complexity` as fusable. At revision `1ffbbd4b060`, the transform dispatcher still calls a recursive static-fact traversal and a separate recursive complexity traversal. The planner's group count describes the schedule. Counting visits to the actual operations would measure the work a combined implementation removes. [Transform dispatcher](https://github.com/ubugeeei-prod/vize/blob/1ffbbd4b060d944ddb94b5b59d5c5cffe41d2c21/davinci/vize_l1_to_l2/src/pass.rs) · [Static-fact traversal](../../../davinci/vize_l2/src/analysis/static_facts/lattice.rs) · [Complexity traversal](../../../davinci/vize_l2/src/analysis/template_complexity/regions.rs)

The Vue binding and contract observers provide a worked comparison. The same requested facts were checked against independently run observers, including partially admitted files. Each timed interval includes constructing and dropping the File owners. Each half creates its shared arena and parses the script before the timer starts, then drops the arena after the timer stops. A resident position index has a different cost profile, so its construction and repeated lookups are measured separately. Small inputs and single queries expose costs that a repeated large-file workload can hide. [Vue observer parity and timings](https://github.com/ubugeeei-prod/vize/pull/13438) · [Position-index qualification](https://github.com/ubugeeei-prod/vize/pull/13433)
