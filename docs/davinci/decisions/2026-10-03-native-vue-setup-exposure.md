## Genuine declaration events

The existing Program statement/declaration traversal records whether a
declaration occurred directly in the original Program body. A matching scope
alone cannot prove this: block-nested `var` has different Vue exposure semantics.
Only actual same-File, same-unit, direct top-level Value Let/Var declarations
pass the binding query. Foreign File handles, parameters, local declarations,
imports, type-only declarations, const and functions are typed refusals.

The existing retained reference walker records a private script-call bit before
the diagnostic callback. Any script call is conservatively unsupported here,
including a shadowed `defineProps` call in a neutral File that otherwise
completes with `NoObserver`. This is script-call/macro refusal, not complete
macro recognition or scope semantics. The existing statement event similarly
records setup exports, including `export {}`, which are refused.

Actual direct Value declarations named `__proto__`, `__isScriptSetup`,
`__returned__`, `__props` or `__expose` refuse view construction even when unused.
The names come from original semantic identifiers, including escaped spellings.
The pinned Vue 3.5.35 compiler audit establishes the prototype/marker and
generated-module boundaries. Ordinary `_ctx`, `$setup`, `_toDisplayString`,
escaped nonreserved identifiers and Unicode names are not guessed collisions.
No initializer syntax grants a ref, constant, access or purity classification.
