Andrei Elkin (`AndreyYolkin`). Original source was based on signed main
`6a75086cf305ea576117cc48ec68d1ad6a6f2cdd`; the controlled delivery source rebases
onto actual signed main `953e49e690d2534a9f8cb72664cc3d25dad53c81`.
Publication is required to complete delivery.

## Problem

The addon toolbar only exposes built-in canvas controls. Projects cannot apply brand,
component theme, locale or direction to every variant without injecting code into the top
window. Detached iframe realms make the workaround fragile across SPA navigation.

## Decision

- Add `MuseaOptions.toolbar`, an optional declarative array of select or two-option toggle
  controls. Validate ids, option values, labels and exact default membership once when the
  plugin is created. Finite string, number and boolean values retain their types.
- Export `MuseaPreviewContext`, `MuseaGlobals`, `MuseaGlobalValue`, `MuseaToolbarControl`
  and `MuseaToolbarOption`. Configured previews receive a stable Vue ref through
  `previewSetup(app, { globals })`. Existing one-argument hooks keep working.
- Keep canvas backgrounds independent of project component themes. Render project controls
  in a Vue SFC with native labeled selects and explicitly pressed toggle buttons.
- Own the values in the gallery realm. Each real preview iframe registers directly with a
  Vue directive and unregisters on unmount. A change visits only registered frames and
  sends one validated message per frame; it never scans the DOM or reloads previews.
- Read initial values from each preview URL before setup runs, then accept only messages
  from that iframe's same-origin parent. Repeated identical values do not replace the ref.
  Preserve the current ref when Props controls remount an app.
- Carry state through router navigation and serialize `museaGlobals` into the gallery URL.
  Scope optional local-storage persistence by gallery base path. Explicit URL state wins
  over storage. Unknown keys are omitted; invalid values fall back to declared defaults.
  Unavailable storage does not prevent updates, navigation or reproducible URLs.
- Propagate controls through dev/source/prebuilt gallery configuration, props-preview
  generation, virtual preview modules and static gallery emission. Reuse the existing safe
  script serializer for inline gallery configuration. Configured globals require Vue 3
  or Vue 2.7; earlier Vue preview paths remain unchanged when no toolbar is configured.
- Remove the existing VariantPreview message listener on component unmount so navigation
  does not accumulate detached-frame listeners.

## Compatibility and performance

The unconfigured default and props-preview modules must remain byte-exact against whole
modules generated by actual base main. These retained differential fixtures accompany the
new runtime regression laws. No public compiler output, pipeline stage, native dependency,
global parser, repeated full-tree search or cross-request cache is introduced.

Toolbar validation runs once per plugin construction. Registered-frame delivery and URL
serialization occur only on genuine value changes; initial preview URL reads do not subscribe
iframe source computations to global updates. The existing preview setup remains responsible
for releasing external watchers when an app unmounts; the working Vue example demonstrates this.

## Scope and delivery

English and Japanese guides include a brand/component-theme/locale configuration and a
reactive `vue-i18n` setup example. `examples/vite-musea` has a separate `gallery:globals`
command so the existing example's ordinary gallery configuration and screenshots are retained.

Automatic VRT capture over a Cartesian product of globals is optional in the original request
and is not implemented. Existing VRT uses configured defaults. This limitation is explicit in
the public guides and must not be presented as completed.
