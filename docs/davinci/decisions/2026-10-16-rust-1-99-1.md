# Rust 1.99.1 production builds with reproducible 1.99.0 measurements

The official [Rust 1.99.1 release](https://blog.rust-lang.org/2026/10/15/Rust-1.99.1/)
fixes x86_64 FFI bool return values, direct macOS rust-lld invocation, and missing
wcslen fallback symbols. Development and active source/build/seed/preview/release
workflow pins advance from 1.99.0 to 1.99.1. Existing stable installer inputs
already resolve the patch release; Cargo uses the exact repository pin.

The workspace MSRV remains 1.99.0. The Nix package and SemVer lane retain that
compiler. Only rust-overlay advances in flake.lock; the development shell reads
the contributor toolchain, while unrelated Nix inputs stay unchanged.

## Measurement authority

`rust-measurement-toolchain.toml` retains the complete old contributor manifest,
byte for byte. Instruction and paired-memory collectors explicitly select its
Rust 1.99.0 compiler. The reusable instruction workflow also exports
RUSTUP_TOOLCHAIN=1.99.0 so its harness tests and cache preparation use that compiler.
Every existing instruction/compiler build identity, input, window, allocation
budget, and numeric ceiling remains unchanged. This is no new calibration or
compiler-methodology transition.

The collectors fall back to rust-toolchain.toml only for historical sources
that predate the measurement manifest. An explicit malformed or unsupported
measurement manifest refuses execution. The paired-memory source judge verifies
each selected manifest against its complete committed Git blob and compares the
complete selected bytes between arms, as well as the existing exact Cargo/rustc
images. This permits a historical 1.99.0 source and current 1.99.1 development
source to run the same 1.99.0 measurement recipe. It does not permit mixed compiler
builds or measurement-pin drift. Original historical captures, receipts, and
compiler-specific source experiments retain their literal toolchains.

## Production receipts

The active Rust archive producer and workers advance together. Their receipt
validator obtains the compiler authority from the exact committed source pin,
accepts only reviewed 1.99.0/1.99.1 sources, and rejects a different actual compiler,
including the other patch release. Working-tree pin edits cannot change that
source authority. Fixed historical archive diagnostics retain their 1.99.0
source and remain reproducible. Source-bound typechecker receipts likewise admit
the exact new committed patch without accepting an old compiler for new source.

## Qualification

Regression laws cover the independent measurement pin, historical memory source
fallback, changed measurement/compiler refusal, both archive patch versions,
uncommitted pin substitutions, unsupported sources, and source-bound typechecker
compiler refusal. Source-law tests establish validation behavior only; fresh
Actions compilation, native/runtime/corpus checks, protected instruction ceilings,
and public release qualification remain required before delivery claims.
