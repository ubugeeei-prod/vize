# Model-checking the unsafe islands

The fleet rule admits `unsafe` when every block states its `// SAFETY:` argument and a differential test exercises it. This record adds a machine-checked layer where the argument is about memory or UTF-8 that Kani can decide on the shipped code. It also lists every remaining site with the oracle that holds it. `tests/tooling/unsafe-inventory.test.ts` holds the list. It walks the module tree of every `crates/*/src` and `davinci/*/src` crate root and skips `#[cfg(test)]`, `#[cfg(kani)]` and `#[cfg(creusot)]` modules, including inline ones. Comments and literals are blanked, and the test counts the `unsafe` tokens in each product file. The per-file counts must equal the sums of the rows below. A new `unsafe` therefore fails CI until it has a row, a class and a verifier. Every `kani` reference must name a `#[kani::proof]` with `kani::cover!` checks, and a Davinci Kani job must run it with its kernel in the workflow paths. Every `creusot` reference must name a function in the row's own file, that file must be a module of a `tests/formal/creusot` package, and the Davinci Creusot workflow must watch it.

Sites fall into three classes. **(a)** Pure memory or UTF-8 reasoning over values the code builds itself. **(b)** FFI and operating-system contracts: libc, Win32, N-API and the mimalloc option store. Kani has no model of the foreign side, so these rows name the platform contract and the test that runs it. **(c)** Lifetime widening and arena or traversal pointer dereferences. Their argument is about who keeps a borrow alive or who holds the only mutable path. Kani has no aliasing model, so these rows name the Miri lane or the tests that walk the real trees.

## How the harnesses run

Each harness is a `kani.rs` module next to its kernel. The kernel declares it with `#[cfg(test)] mod kani;` and every item in it is `#[cfg(kani)]`, as in the position-index harnesses. A product build never compiles the module, so these declarations cannot change product code. The kernels use `CompactString`, the oxc-backed arena or other crate items, so a standalone `kani file.rs` root cannot include them. Instead `cargo kani --manifest-path <crate>/Cargo.toml --lib --tests --harness <name>` compiles the crate unchanged with the harness added. Davinci Kani runs one job per crate.

Kani is for small models here. Every harness is checked on the smallest piece that carries its SAFETY claim. It must pass locally under the fleet runner's limits: one CBMC at a time, 4 GB resident and 10 minutes. Kani checks bounds, pointer validity and liveness, frees and every assertion. The harnesses assert each SAFETY comment's premise as a property. The bytes `fill` reports must equal a prefix of whole `&str` pieces, which makes them valid UTF-8 and proves every one was written. Kani gives an unwritten `MaybeUninit` byte every value, so an unwritten byte fails the comparison. Parked references must read back their values after the vector relocates. The allocator wrapper must hand back writable, prefix-preserving blocks.

## Proved deductively

Some claims are about an index or a byte sequence of any length, which is past what CBMC can bound. Creusot proves these on the shipped source instead (see [the Creusot record](./2026-11-17-creusot.md)).

- **`ScopeChain`'s current row.** Kani's smallest model passed 4.8 GB because `Scope`'s tables and data variants dominate it. The index law does not depend on `Scope`, so the rows and the current index now live in a generic kernel, `scope/chain/rows.rs` (`Rows<T>`), whose fields only its own methods can touch. Its type invariant is `current < rows.len()`. Creusot assumes the invariant of every table a method receives and proves it of every table a method returns or leaves behind through `&mut`. In `Rows::current` and `Rows::current_mut` it discharges the `requires` that creusot-std 0.14 gives `<[T]>::get_unchecked` and `get_unchecked_mut` (`ix.in_bounds`). No `Rows` method has a precondition, so the proof holds for any caller in the crate: a panic is a failing goal in Creusot, so `select` reports a missing row and `ScopeChain::set_current` panics on it as before. `the_current_row_exists_after_every_transition_sequence` in `scope/chain/creusot.rs` restates the law for every table and every sequence of appends, selections and reservations. The package is `tests/formal/creusot/scope-chain`. Creusot treats a panic as unreachable, so it proves the invariant on return but not across unwinding, where a caught panic leaves the table in use. `push_selected` therefore selects the new row only after `Vec::push` returns. The test `a_failed_push_keeps_the_current_row_in_bounds` catches the capacity-overflow panic and checks that the previous row is still selected. The first version of this kernel set `current` before the push, and every Creusot goal still passed; main's earlier `ScopeChain` pushed first.
- **The recovery cursor window.** `vize_resident_graph` matches each retained recovery record to the caller's sorted cursors with two binary searches in `recovery/positions/window.rs`. `partition_point` has no creusot-std 0.14 spec, and a safe rewrite that Creusot could prove was 10 to 25% slower, so `skip_below` keeps the search `partition_point` runs and reads with `get_unchecked`. Its loop invariant `base + size <= positions.len()` (with `size >= 1`) discharges the `requires` that creusot-std gives `get_unchecked` (`ix.in_bounds`) at both reads. The invariant does not depend on the cursors being sorted, so the reads are in bounds for any input the crate passes. With sorted cursors, `window_matches_each_requested_cursor` in `recovery/positions/creusot.rs` proves the window for every length and every `u32` endpoint: it starts after exactly the cursors before the record and holds exactly the cursors the record covers. That replaces the Kani harness, which stopped at five cursors. The package is `tests/formal/creusot/recovery-positions`.

## Not model-checked, and why

**CBMC model too large.** These models exceeded the runner's 4 GB or 10-minute limit even at their smallest useful bounds, so they were dropped:

- `rebuild_source` end to end: `CompactString`'s heap representation passed 8 GB, an arbitrary `char` per part passed 12 GB, and one part of each kind around two fixed scalars passed 10 minutes. `fill` carries the claim instead (above). `CompactString`'s `spare_capacity_mut` and `set_len` rest on `compact_str`'s contract and the `text_rebuild` fuzz target. **Deleting the `unsafe` costs instructions, so it stays.** A safe spelling has to build either through `CompactString::push_str` or through a heap `TextBuf`, and the inline case is the one interpolation-heavy templates hit. Retired instructions per call (local aarch64 `release`, 20,000 calls, minimum of 7 rounds, result dropped): a 12-byte inline rebuild costs 448 today, 664 with `push_str`, 882 through `TextBuf` and 542 with a stack buffer and a checked `from_utf8` for the inline case. A 43-byte heap rebuild costs 1,130 today, 1,477 with `push_str` and 1,100 through `TextBuf`; a 103-byte one costs 1,262, 1,653 and 1,214. Only the heap case breaks even, so every safe spelling regresses the inline one by 21% or more.

**Decoder boundary.** `read_to_string` reduces its claim to `decode_utf8`. Below 64 bytes that is `core::str::from_utf8`. Above 64 bytes it is simdutf8, whose runtime CPU dispatch Kani cannot compile. Its differential tests against the standard decoder are the oracle. Deleting this `unsafe` costs a second decode: simdutf8 only lends a `&str`, so a checked owned string means either `String::from_utf8`, which revalidates with the standard decoder (627,973 instead of 314,411 instructions over the repository's 970,143 bytes of `.vue` files, aarch64 release), or a copy of the buffer. The row stays owed.

## UTF-8 composition laws

Every `from_utf8_unchecked` row below makes one of two claims: its buffer is a concatenation of well-formed pieces and ASCII bytes, or it copied a range of a well-formed source whose ends sit at ASCII bytes. CBMC could not carry either claim through a whole builder. The general step of both is now proved for sequences of every length, and the predicate it is stated over is tied to the standard library's decoder.

- **The predicate.** `davinci/vize_l0/src/source_io/utf8.rs` transcribes Unicode Table 3-7 (chapter 3, D92) as the Pearlite functions `scalar` and `well_formed_range`. creusot-std 0.14 models `str` as an opaque `Seq<char>` and gives `str::as_bytes` no specification, so the laws use this predicate rather than creusot-std's.
- **Tied to the decoder.** `is_well_formed` reads the definition scalar by scalar. Creusot proves it decides `well_formed`. The standalone Kani root `source_io/kani.rs` checks `the_well_formed_check_agrees_with_the_standard_decoder`: on every sequence of up to four bytes, the longest scalar encoding, `is_well_formed` accepts exactly what `core::str::from_utf8` accepts (213 checks, 5/5 covers; 37 to 76 s of CBMC time on the loaded fleet machine, 0.5 GB peak). A mutant that accepts surrogates (`ED A0..BF`) fails the agreement assertion.
- **The laws** (Creusot package `tests/formal/creusot/utf8`, root `source_io/creusot.rs`): `well_formed_sequences_concatenate`, `appending_an_ascii_byte_keeps_a_sequence_well_formed`, `an_ascii_byte_is_a_whole_scalar`, `an_ascii_byte_splits_a_well_formed_range`, `dropping_a_trailing_ascii_byte_keeps_a_sequence_well_formed` and `a_range_between_ascii_boundaries_is_well_formed`.
- **Where the laws still apply.** Each builder's own step, that every byte it appends is one of those pieces, was never machine-checked: the builders appended the bytes of `&str` values, Creusot cannot read those bytes (`str::as_bytes` has no specification), and the scanners that picked the copy ranges go through `memchr` and `char_indices`. Every such builder row has since been deleted instead (below). The laws remain the general step of `rebuild_source`, whose `fill` premise Kani checks.
- **Deleted instead.** A builder whose every append is already a `&str`, a `char` or a checked `str` slice needs no law: it can append to a string type, and rustc's type checker proves the result. The script-setup compilers (function mode, the inline body and its props declaration) now append to `vize_l0::string_builder::TextBuf`, a heap `String` whose appends take only `&str` and `char` and which moves into a `CompactString` without a copy. `apply_scoped_css` and the v-bind transform append to the arena `StringBuilder` and freeze it in place. The SFC formatter, its observed-template entry, the template formatter and its whitespace-preserving variant append to `TextBuf` too; their source copies are `str::get` ranges that start and end at ASCII delimiters, and the text run and output-line width checks read `&str` instead of revalidating bytes. Their eleven `from_utf8_unchecked` sites and rows are gone.

## Findings

- `reborrow_markup` (`crates/vize_patina/src/markup.rs`) and the `jsx_*_ref` accessors in `markup/jsx_names.rs` were safe functions that widen a borrow or dereference any raw pointer they are given. They are now `unsafe fn` with a `# Safety` section, and every caller states its `SAFETY:` argument. No undefined behavior was reachable: every caller kept the program and header alive.
- `reborrow_markup` widened a stack `L2Markup` header to the lint context's lifetime because `MarkupContext<'_, 'a>` ties elements to the `'a` of an invariant `&mut LintContext<'a>`, and the header was built in a frame shorter than that context. It is deleted. `lint_markup_l2` creates its own context, so it now takes `&'a L2Markup<'a>` and the caller's borrows shrink to one lifetime. The SFC facade dispatch builds the header into a slot that `run_template_rules` declares before the context, so the header outlives it and the document borrows it for `'a`. The borrow checker proves both.
- The markup facade stored its OXC JSX nodes as raw pointers because oxc's `Visit<'a>` lends each node for its callback only, so a JSX element found by a walk could not be kept at the program's `'a`. The facade now stores `&'a` references, so the borrow checker proves every read, and the `jsx_*_ref` accessors and their 41 call sites are gone. The one remaining widening is in `crates/vize_patina/src/lent_walk.rs`: a private visitor that only entry points taking an `&'a` root can drive, with one cast per lent node type (JSX element, JSX fragment, call expression). The component-options collector, which widened its own call-expression borrow, uses the same walk. oxc's `Visit::alloc` makes the same cast for `AstKind`; calling it instead would only hide the obligation in the dependency. The Miri lane's `patina-lent-walk` job runs `lent_walk::tests`, which keep every lent element, fragment and call past the walk and read them back, so Miri checks each widened reference under the aliasing model.
- **Upstream note (not filed).** oxc could remove the cast at its source. If the generated `Visit<'a>` took `it: &'a T<'a>` and each `walk_*` took `&'a` too, the signature would state what every walk already does: it descends through fields and arena boxes of a tree borrowed for `'a`. `Visit::alloc` and its transmute would go, and `lent_walk.rs` would shrink to plain `Visit` impls with no `unsafe`. The breaking change is for callers that walk a `Program` they own on the stack: they would borrow it for the walk. `VisitMut` cannot follow, because a `&'a mut` node would forbid reborrowing its children.
- The template transform kept raw cursors in its context: a `ParentNode` pointer to the parent whose children it was walking and a `current_node` pointer to the child slot it was visiting. `v-if` and `v-for` replaced the slot through the pointer, and `v-else` reached back through the parent pointer to the `v-if` before it, while the walk still held the slot. The context now holds no cursor. `traverse_children` takes the children `Vec` by `&mut` and splits it at each child into the siblings before it and the slot (`split_at_mut_checked`). It lends both to the structural transforms, so `v-else` joins the earlier `v-if` through the `before` half while the slot stays borrowed, and the borrow checker proves the two borrows are disjoint. The 4 sites (`children_mut`, `replace_node`, `take_current_node`, `traverse_node_guarded`) are gone, and so are the public `replace_node`, `take_current_node` and `remove_node_at`, which only made sense with a cursor. The Miri lane still runs the transform suites, now as a check of safe code.
- The shared script parse kept 4 sites in `crates/vize_croquis/src/script_parser/shared.rs`: a lifetime-erasing transmute (2 sites), an owned `NonNull<Source>` deref and a hand-ordered drop. Readers found the parse through an ambient thread-local list, `PARSES`, and a thread-local holds only `'static` data, so each parse erased its borrow of the boxed text and arena it lived beside. The cache is now an explicit handle, `ScriptParses<'p>`. It borrows an `Allocator` its caller owns, copies each text into it and caches `ParserReturn<'p>` values in a `RefCell<Vec<..>>`. `vize_canon`'s `generate_vue_virtual_ts` creates it and passes `Option<&ScriptParses<'_>>` to every reader; `None` parses privately, as reading outside a scope did. The borrow checker proves the four claims, and the 4 sites are gone. Entries that callers outside the projection reach keep their signatures and pass `None` (`generate_virtual_ts_with_offsets_and_checks`, `validate_script_setup_semantics_located`, `resolve_type_world_with_sources`). The Miri lane's `croquis-shared-parse` job still runs `script_parser::shared::tests`, now as a check of safe code.
- `ScopeChain::get_scope_unchecked` had no caller in the repository and is deleted.
- `apply_scoped_css` compared `c as u8` with the open quote inside strings, so a non-ASCII scalar whose low byte is `"` or `'` (for example U+0122 `Ģ`) closed a CSS string early. That was a scoping-behavior bug, not a memory one: the output still copied whole scalars. Fixed: both scoped CSS scanners now take the string-body step in `css/string_body.rs`, which Kani checks against CSS Syntax for every scalar.
- Product unsafe blocks without a `SAFETY:` comment (`preserved_text.rs`, `raw_mode/unix.rs` `emergency_restore_raw_mode`, `corsa_session/paths/store.rs` and the N-API helpers in `js_value/raw.rs`) now carry one each. The `GlobalAlloc` methods rely on their impl comment. (`errno.rs`, whose `unsafe fn` declarations relied on their module comment, has since been deleted.)

## FFI surface

Patina's session-owner liveness check uses Nix's safe libc-backed signal-zero probe. PID zero and values above `i32::MAX` are refused as before, `EPERM` keeps an owner live, and the non-Unix branch is unchanged. The locked Nix version already occurs in benchmark dependencies. This alternative preserves the original libc call path; it still needs exact-source functional and performance qualification.

Class (b) sites cannot be proved, because their contract lives on the foreign side. They are kept few and small instead. Each remaining site is one foreign call in a private function behind a typed safe wrapper, and its `// SAFETY:` comment names the platform contract it relies on. A site is deleted when std or a crate already in the graph offers the same call safely; no crate is added to hide one.

- **Fresco's terminal lifecycle (60 → 19 sites).** `isatty`, `fcntl(F_DUPFD_CLOEXEC)`, `tcgetattr`, `tcsetattr`, `cfmakeraw` and the panic hook's `write` go through rustix's safe `termios`, `io` and `stdio` wrappers. The `/dev/tty` open goes through `std::fs::OpenOptions`, and the snapshot holds its descriptor as an `OwnedFd`, so `close` is its drop. The per-libc errno accessor (15 sites) and the signal handler's raw errno read and write are replaced by the `errno` crate's `errno` and `set_errno`. Both crates were already linked on Unix: crossterm depends on rustix with these features, and signal-hook-registry on errno. `sigaction` copies are plain `Copy` reads, and the default-disposition path reuses `replace_action` and `std::process::abort`. The Windows `GetStdHandle`, `GetConsoleMode`, `SetConsoleMode` and `WriteFile` calls that raw mode and the panic hook each declared are folded into `lifecycle/windows_console.rs`, and the console-control routine is a safe `extern "system" fn`. One edge changes: a Unix target outside the old accessor's list no longer gets `UnsupportedPlatform` from the signal hook, because the `errno` crate covers every Unix target the crate builds on. Linux and macOS behave as before.
- **What stays, and why.** The signal module keeps the `sigaction` query and install, `raise` and the two handler-ABI casts; no crate in the graph exposes them safely, and `raise` signals the calling thread where `kill(getpid())` would signal the process. The two lock-free cells, the termios snapshot and the previous-action table, stay `UnsafeCell`s with an `unsafe impl Sync`. A panic hook or signal handler reads them, so they may not lock or allocate, and std has no lock-free cell for a non-atomic C struct. Their argument is the publication protocol written on each accessor.
- **The language server's descriptor walks (10 → 1 site).** `openat` in the module-target walk, and `inotify_init1`, `inotify_add_watch`, `read`, `inotify_rm_watch` and `statfs` in root discovery, go through rustix's safe `fs` and `io` wrappers, which tempfile already linked. Each takes a borrowed descriptor and returns an `OwnedFd`, a count or a `StatFs` value, so the two `from_raw_fd` wrappers and the `statfs` `assume_init` go too. The flags, the mask and the error handling are unchanged. `getdents64` stays a raw system call: rustix offers it only through `RawDir`, which hides the per-call byte counts that the `fs.getdents64.*` counters report.

## FFI surface

Class (b) sites cannot be proved, because their contract lives on the foreign side. They are kept few and small instead. Each remaining site is one foreign call in a private function behind a typed safe wrapper, and its `// SAFETY:` comment names the platform contract it relies on. A site is deleted when std or a crate already in the graph offers the same call safely; no crate is added to hide one.

- **The native config normalizer (25 → 0 sites).** `js_value/raw.rs` calls napi's safe `Env`, `JsValue` and `JsObjectValue` methods, which issue the same N-API calls the helpers made by hand.
