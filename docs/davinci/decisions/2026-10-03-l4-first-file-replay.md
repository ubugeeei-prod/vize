# L4 on the first genuine File provider (2026-10-03)

Issue: [#6840](https://github.com/ubugeeei-prod/vize/issues/6840).

## Decision

Replay only the native File DOM encoder, its ownership laws, and the retained
property-layout codec onto the actual Shared → Pending → File → L3 provider
chain. The L4 production API remains `emit_file(&NativeFileAnalysis)`. It
derives source, artifact, resolutions and lexical scopes from that sole owner;
there is no conversion to bare analysis, caller runtime classifier, upper
normal dependency, context fallback, additional walk or serialization.

The first lower File provider exposes `FileProducer`, completed Program units,
explicit `ProgramScope`, and `TemplateScope`. Its genuine upper native
component diagnostic constructor can populate those real factory rows. It
does not expose the earlier private Vue facade or certify complete original
template custody. Development fixtures therefore use actual module/nested
Program units and explicit root/last-unit template scopes. Their private
visibility policy grants lexical resolution only. It grants no Vue role,
runtime class, declaration exposure or native product acceptance.

References remain typed refusals, even when a same-file declaration has a
literal initializer. Shadowing laws now assert actual unit scopes, binding
identities, authored declaration spans and foreign-owner rejection. They do
not label neutral nested Program units as authenticated setup declarations.
Literal expression rows retain the original native AST, decoded window,
authored projection, File owner and mint-time lexical scope.

## Current source-bound validation

The bounded recipe compiles complete registered L3/L4 source on this actual
provider closure, using hash-authenticated matching lower File, upper native
diagnostic and Shared L1 libraries. It preserves the pinned Vue 3.5.35 sources,
options, complete template modules and raw reference maps unchanged.

Fifty-two L4 unit laws, four File integration laws, the seven-input property
integration law, compile-fail privacy and strict whole-production L4 Clippy
pass. Eight static/literal modules match every reference byte and execute in
the actual Vue runtime under sixteen contexts. Fourteen property modules
(seven bare resolver fixtures and seven File literals) match all bytes and
twenty-eight additional runtime contexts. Recorded/NoLinks text and helper
order agree, actual source links remain checked, and the preceding property
codec fails the retained-whitespace complete-module regression.

The prior private Vue-facade File proof and its frozen source remain separate.
This new result authenticates the current diagnostic construction route; it
does not upgrade its custody, replace those earlier proofs, or establish
whole upstream map equivalence. Original upstream maps are retained and
regenerated without filtering native maps or names.

## Remaining work

Authenticated declaration membership and original native template custody are
separate provider capabilities. External SetupLet reads require the genuine
L2 exposure view and sealed L3 read decisions before an additive L4 consumer.
Neither diagnostic visibility nor FileDependent values authorize `$setup` or
`_ctx`. Current File If/For, broad Vue directives/dialects, full maps and
performance remain unfinished.

Current whole-workspace Cargo, hosted Actions, no_std, protected instruction
gates, native Stack/queue and terminal merge are separate delivery checks.
Native product acceptance remains zero and no product route changes. Compiler
history [#6880](https://github.com/ubugeeei-prod/vize/issues/6880) and #6840 stay
open. The final callable source packet records the exact provider head,
library/source hashes and finite commands; publication remains root-owned.
