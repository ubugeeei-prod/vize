## Concrete problem and resulting behavior

The previous opt-in native `textDocument/linkedEditingRange` route compared
rename/nativeLinkedEditing booleans and Vue configuration values after await.
Disabling and re-enabling a setting could therefore let a response captured
under the old configuration pass as current. Its unconditional Names-cache
drain could also retire a compatible newly enabled original owner.

The standard handler now classifies Disabled, Legacy or Native under one
actual-state read gate. Native carries a privately minted configuration ticket
directly into the existing endpoint; it never captures settings a second time
before await. Disabled and Legacy retain their existing complete outputs.
The feature gate and explicit nativeLinkedEditing initialization option remain.
No new flag, capability, custom request, URI or configuration wire is added.

The public `NativeNavigationProject::linked_editing` remains an independent
parser-only provider API. Its existing original laws use ServerState::new with
the transport opt-in false and retain those exact options. The standard endpoint
uses a separate private parser-and-route ticket. An actual route change returns
the existing -32801/"Content modified" envelope; parser supersession retains
-32801/"Native Vue configuration superseded". Neither substitutes a legacy query.

## Actual state, identities and complete setters

One feature-only server-state RwLock holds private retained Arc identities for
parser and linked-route settings. Existing fields remain authoritative. Reads
copy actual settings while holding this gate; no duplicated settings cache,
syntax row, parser index or source revision is introduced. Each retained Arc
keeps its allocation alive, so a pending request cannot confuse a later equal
configuration or equal foreign state with its original identity.

The parser identity changes only when actual Vue version, configured dialect,
patterned flag or effective legacy setting changes. The linked identity changes
when either actual nativeLinkedEditing or rename changes, even while their
combined route is disabled. No-op updates preserve identity.

Real `set_dialect_config` and initialization options enter a write transaction.
Both actual config loaders apply feature flags, the LSP section and dialect
within one transaction using private already-locked helpers. File loading,
parsing, other configs, cache invalidation and logging remain outside the gate.
The before/after comparison happens after every inner field guard has dropped.
No setter enters a worker map or document store while holding this gate.
didChangeConfiguration retains its current editor-restart behavior.
