## Registry and observable contract

Register the six existing, actually merged Canon history packs through the
existing `vize.differential.manifest` and `vize.differential.result` v1 helper.
The registry fixes all 17 production projects, all 67 exact source/configuration
carriers, original regression identities and fixture-pack SHA-256 values.
Expected diagnostics remain in their original immutable `cases.json` packs.
No expected diagnostic, fixture input or product implementation changes.
The new serialized adapter identity is `batch-typechecker-fixture-v1`.
The historical Canon JUnit class remains the actual legacy receipt interface.

Compare the original authored diagnostic projection in its returned order:
project-relative file, one-based authored UTF-16 start, code, exact message and
severity. This public API has no end, related information or raw backend
response. Those fields remain explicitly unavailable; they are neither
reconstructed nor credited. These witnesses are a partial batch-start contract.
The actual public result additionally exposes `exit_code`, `success` and each
diagnostic's optional `block_type`. Retain all of them beside the unchanged
projection, explicitly observed but unbaselined. Missing public fields fail.
Public diagnostic paths and zero-based starts remain as actually returned;
the captured project root ties them to the original relative/one-based oracle.
`projectRoot` belongs to each runtime capture case; immutable fixture-pack
cases retain only their original input and diagnostic fields.
Only `batch-start-diagnostics-v1` is matched to the original fixture oracle;
the complete public result cannot earn full-match credit before fresh actual
captures are frozen and independently checked.

The provider validates missing/extra/reordered case identities, every diagnostic
field, unexpected child-file rows, input bytes, fixture/executable/build receipt
identity and successful JUnit identities. Four-worker reconciliation requires
one occurrence of every planned body, the same source tree, transferred archive
receipt and actual test executable. A duplicate, missing, stale, failed or
skipped observation cannot become a passing fixture row.

Native type checking is explicitly unsupported. All 17 planned rows stay in
the registered-fixture denominator, with zero native handled/equivalent rows
and no paired legacy/native comparison. Registration does not establish a
native implementation or whole-history coverage.
