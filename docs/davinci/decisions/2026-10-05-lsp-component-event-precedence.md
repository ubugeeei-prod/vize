# Prefer declared component listeners in completion

Decision for [#8005](https://github.com/ubugeeei-prod/vize/issues/8005).

The existing template providers concatenate generic Vue events and component
surface declarations. A component declaring change/click consequently publishes
two equivalent insertion candidates. At the three existing assembly sites,
remove only generic EVENT candidates with the same declared EVENT label,
insertion text/format, text edit, additional edits and command. Append the
complete declaration unchanged, retaining its type, docs, data and order.
Distinct completion kinds, snippets, modifier names and acceptance actions stay
available. Props, global/native attributes, handler expression paths and native
completion-resolve ownership keep their existing providers. No new stage,
parser, resolver call, shared helper or cache is introduced.

The complete original App/MySwitch/config inputs and all whole expected objects
are a current-product corpus. The mandatory source-built stdio test checks 43
complete completion arrays and two exact typed native hovers in seven sessions.
Controls cover Vue JS/TS, native button/input/global attributes, LF/CRLF, astral
prefix edits, distinct modifiers and unsaved child declarations/restore.
Independently selected expected candidates do not call the production union;
only authored request ranges replace fixture placeholders. Entire protocol
messages and original diagnostic publications persist before assertions in the
existing Rust shard artifact, with executable hashes and source/archive identity.
The original omitted required prop's diagnostics remain observed rather than a
new diagnostics oracle. Runtime bootstrap supplies the real native dependency
and frozen Playground Vue; unavailable dependencies fail instead of skipping.

Source review and lightweight formatting/inventory checks precede public source
Actions. Native execution, unchanged protected instruction ceilings/full suites,
actual signed merge and release remain pending. This bounded current-product
repair does not close the LSP fix-history gate, claim native-level eligibility,
complete generic completion #8015, or claim a latency/speed target.
