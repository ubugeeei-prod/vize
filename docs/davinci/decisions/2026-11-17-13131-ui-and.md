# `ui.and`: a child `left && <region>` that renders a falsy `left`

Issue: [#13131](https://github.com/ubugeeei-prod/vize/issues/13131) (TSRX DOM
refusals, part of [#6858](https://github.com/ubugeeei-prod/vize/issues/6858)).
Planned by the [JSX lowering](./2026-11-10-6885-jsx-l2-lowering.md) as
`ui.and { left: c, right }`.

## Op

`vize_l2::op::AndOp` (`Op::And`, mnemonic `ui.and`) holds `left`, the region a
truthy `left` renders, and the span of the whole `left && right`. `left` is
evaluated once. A falsy `left` is the child itself and renders as a
renderer-normalized child value, as a `ui.jsx-child` does: `0`, `NaN` and `''`
as text, `false`, `null` and `undefined` as nothing. A `ui.if` cannot express
that, because its test is only a condition. A provably boolean `left` keeps
lowering to a one-branch `ui.if`.

The op is framework-neutral. The builder observes the `JsxChild` family for it,
because a raw child value needs complete child patching on every target. The
folio line is `ui.and <expr> @s:e` with the region beneath it.

## Producers and targets

- TSRX (`vize_l2::lang::tsrx::nested`): `{n && <A />}` when `n` is not provably
  boolean. The JSX lowering does not build it yet.
- DOM (`vize_l4` `vif::emit_and`): `(left) && <region root>`. JavaScript yields
  `left` when it is falsy and Vue's `normalizeVNode` renders it, which matches
  the reference's `setNodes` for every falsy primitive. The region root takes
  the next branch key, like a one-branch `ui.if`, and is emitted as a `ui.if`
  branch is: a region without a single root is one keyed fragment, and an
  empty region is refused (`IfBranchShape`).
- No other target emits it yet. L2→L3 carries it as an `If` without branch
  operands, which native Vapor admission refuses; the SSR string plan reports it
  as an unsupported client child value; the JSX module type-check target refuses
  it. TSRX refuses the SSR and Vapor targets.
- Lint presents it as a one-branch conditional over its region.

## Differences from the reference

Node identity follows [#13176](https://github.com/ubugeeei-prod/vize/issues/13176)
option A: when `left` changes from one truthy value to another, Vize keeps the
region's nodes, the reference (`vue-jsx-vapor` `setNodes`) re-creates them.
Mount row `and/recount` stays an expected difference.
