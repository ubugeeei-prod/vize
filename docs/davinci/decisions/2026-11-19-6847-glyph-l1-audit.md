# Glyph on L1: residue audit and closing slices

Tracked in [#6847](https://github.com/ubugeeei-prod/vize/issues/6847)
(`products.formatter`: "Glyph formats from L1 only"). Plan task
[P4-12b](../plan/phase-4-tasks-last.md#p4-12b--glyph-on-l1) owns the template
rewrite; [P4-12d](../plan/phase-4-tasks-last.md#p4-12d--lossless-script-and-jsx-l1)
owns the formatter parse profile for scripts. This record measures what is left
at `1cdd5410f8` and fixes the order in which it closes.

## What is already on the levels

- **Dependencies.** Glyph's normal dependencies are `vize_l0` and `vize_l1`.
  Its product allowlist is empty and its source names no legacy crate
  ([dependency gate](./2026-10-21-glyph-product-dependency-gate.md)).
- **SFC blocks.** `formatter/blocks.rs` takes every block, opening tag,
  attribute and location from the L1 container (`observe_template_only`,
  `split_blocks`). Block languages come from `vize_l1::container::lang`.
- **Directive grammar.** Attribute sorting, shorthand normalization and the
  expression-surface choice decompose names with `VueDirectives` and classify
  them with `vize_l1::dialect::vue3::DirectiveKind` (history #6882, closed).
  Entity decoding uses `vize_l1::markup::entity`.
- **TSRX.** `tsrx/` lays out the L1 `markup::tsrx` tree.

## What is not

Each residue below is a place where Glyph recognizes source syntax itself.

| Residue               | Where                                                                                                                                       | What it does                                                                                                                                       | Slice |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- | ----- |
| Script parse          | `script/format.rs`, `script/block_identity.rs`                                                                                              | `oxc_formatter::parse_for_format` of a whole script block                                                                                          | F2    |
| Expression parse      | `script/expression.rs`                                                                                                                      | the same parse of a `void (…)` wrapper, once per directive value or interpolation                                                                  | F2    |
| Literal reparse       | `template/literal_spans.rs`                                                                                                                 | a second, private OXC parse of a multi-line value to find the lines that start inside a string or template literal                                 | F3    |
| Template byte scanner | `template/formatter.rs` and `template/formatter/{tags,interpolation,whitespace_significant,preserved_text,suppression,child_width,text}.rs` | finds tags, attributes, comments, interpolation delimiters, raw-text elements and pragma comments by scanning bytes (`memchr`, hand-written loops) | F4    |
| Post-print relex      | `formatter/template_indent.rs`, `formatter/raw_mask.rs`                                                                                     | rescans Glyph's own template output for quotes, `<`, `v-pre` and literal lines to decide which lines receive SFC indentation                       | F4    |

The `memchr` calls that measure Glyph's own output buffer (the column of the
last emitted line, a tab in it) are printer arithmetic, not parsing. They stay
with the printer; they move out of `template/` only because P4-12b's acceptance
greps that directory.

## The second template route

`native_doc/` (5.8k lines, plus 21k lines of tests) is an L1 route with its own
Doc IR and printer. It consumes `NativeTemplateComponent`, typed directive heads
and retained expressions, and refuses everything else: today it admits only
script-less, style-less Vue 3 SFCs, and formats only conditional and static
binding values. No product calls it; only Glyph's own tests do. Its output is a
different layout (authored attribute order, verbatim content) from the default
route. Whether it is promoted or deleted is a maintainer decision (F5); the
measurements for that decision are in its PR and issue comment, not here.

## Slices

1. **F2 — formatter parse profile.** `vize_l1::embed::syntax::format` parses a
   Program with exactly the options `format_program` requires: no retained
   parentheses, no regular expression parse, and JSX for every JavaScript
   source type. The compiler profile hands out `EmbedSyntax`, never a bare
   parser result, so the two parses cannot be confused. The script,
   block-identity and expression formatters parse through it and still refuse
   any parse with a diagnostic.
2. **F3 — literal ownership from L1.** The lines a multi-line value owns as
   runtime literal bytes come from an L1 provider, computed once per value
   instead of once per helper that asks. Glyph then needs no parser of its own,
   and its `oxc_parser` dependency goes.
3. **F4 — template on the L1 surface, by construct family.** Each PR replaces one
   scanner family with the L1 template surface that is built once per template,
   and deletes the scanner. Order: opening and closing tags with their
   attributes; comments, interpolations and text runs; raw-text and `v-pre`
   elements with suppression pragmas; then the post-print relex, which goes
   away once the printer emits SFC indentation directly from the tree. No PR
   may add a second L1 parse of the same bytes.
4. **F5 — `native_doc`.** Promote it as the F4 printer, or delete it.
5. **F6 — close #6847** with the gate evidence below.

## Acceptance for every slice

- Formatted output is byte-identical on every formatter fixture (the formatter
  differential pack and its fix-history packs) and on every `.vue` file in this
  repository, base against head.
- The glyph test suite and the differential CLI gate
  (`tests/tooling/differential-formatter-cli.test.mjs`) pass.
- Every row of `docs/davinci/plan/formatter-instruction-budgets.toml` and every
  formatter row of `level-instruction-counts.yml` is at or below base, measured
  base, head, base twin, head twin. `PR performance observation` shows no wall,
  CPU, RSS or binary-size regression.

## Script formatting and "L1 only"

An OXC formatter printing a Program that L1 parsed under its formatter profile
counts as formatting from L1: the parse and its profile identity are owned by
L1, and Glyph no longer parses. P4-12d's lossless script tree (tokens, gaps,
structural recovery) is not a precondition for this gate; the printer never
sees recovered syntax.
