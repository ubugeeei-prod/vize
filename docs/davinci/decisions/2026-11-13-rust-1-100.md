# Rust 1.100.0 development, production and measurement toolchain

The maintainer requests the latest stable Rust. Rust 1.100.0 was released on
November 12, 2026; its compiler identifies as `rustc 1.100.0 (0ef1bc386 2026-11-09)`.
This record follows [one Rust toolchain](./2026-10-20-single-rust-toolchain.md)
and [the MSRV follows the pinned toolchain](./2026-10-13-rust-msrv-1-99.md).
Tracking issue: [#6830](https://github.com/ubugeeei-prod/vize/issues/6830).

## Pins

`rust-toolchain.toml` moves from 1.99.1 to 1.100.0, and so do the workspace
`rust-version`, the Nix package toolchain, the release SemVer lane and the
contributing guides in every locale. Every workflow and composite action that
builds the current checkout installs 1.100.0, including the compiler assertions
of the n8n custody job, whose current-source phase cannot build on 1.99.0 once
the MSRV is 1.100.0. Source-bound typechecker receipts admit a committed
1.100.0 pin.

Jobs that rebuild only a fixed historical source keep that source's compiler:
the Canon helper native baseline (`1d1bb26a`, asserted binary size), the
normal-codegen recovery replay (two pinned commits), the frozen
`typecheck-vs-vue-tsc` cohort, and the baseline jobs of the native SFC runtime
options and plain-script import pairs. Those checkouts pin 1.99.1 themselves.
Historical decision records, receipts and fixtures keep their literal compilers.

Rust 1.100.0 still emits rustdoc JSON format v61, so the SemVer lane keeps
cargo-semver-checks 0.51.0. A local 0.51.0 run on 1.100.0 output reports a
removed public function as a major change.

rust-overlay advances alone in `flake.lock`, to
`8bbfc858c7b85f5e6ed6d6cc201ffcee1bb08a9b` (2026-11-12), whose stable
manifests include 1.100.0. `nix develop` now provides rustc,
Cargo, Clippy and rustfmt 1.100.0. The host `origin` Cargo launcher keeps its
own overlay and still stops at 1.98.1.

## Compiler and Clippy findings

Clippy 1.100.0 applies `allow-*-in-tests` to library code under the workspace
`tests/` directory. The `clippy::panic` expectation on the Davinci test-support
corpus module is therefore unfulfilled and is removed; the corpus gate still
panics with its diagnostic. Two functions now return their final `matches!` or
call result directly instead of an `if` that returns `true` followed by `false`.
rustfmt 1.11 moves one long test string literal to its own line.

The CI Clippy run also stopped on two findings that reached main without a PR
Clippy run, not on new lints: `script_unused::analyze` had eight parameters after
#12939, and its only caller always passed `apply_template = true`, so the
parameter is removed with identical logic; the profiling-only content-mapper
allocation report wrote `Value::to_string()`, a disallowed method, and now
writes `serde_json::to_vec` bytes, which are identical. Cargo 1.100.0 also warns
about unused dependencies and members without lint inheritance; those manifest
warnings do not fail any gate and are left for their owners.

## Instruction re-baseline

The level (101 rows) and formatter (4 rows) registries move their compiler
identity to 1.100.0 and their evidence to source
`aa9ab054fd272578f142dfd2c789d0e1869c7b86`, run
[43351845175](https://github.com/ubugeeei-prod/vize/actions/runs/43351845175).
The same-source 1.99.1 control is main `db73bca412884b963f26ab0178fb0d64ac4466cd`,
run [43352512122](https://github.com/ubugeeei-prod/vize/actions/runs/43352512122).
The two sources differ only in toolchain pins, measurement tooling and the
behavior-preserving lint fixes above. All three executions on each compiler are
identical, and rows, inputs, windows and non-rustc method fields are unchanged.

On the level rows, 10 counts are unchanged, 61 rise and 30 fall; the total moves
from 88,380,440 to 89,378,531 instructions (+1.13%). The largest moves are
`s1_to_s2_emit_p2_11_dom_surface` (+6.47%), `atelier_vapor_generate_stress-interp`
(+6.03%), `s1_to_s2_emit_helper_rich_large` (+4.03%) and
`atelier_dom_codegen_medium` (−0.74%). The formatter total moves by +0.001%;
`formatter_template_complex` keeps 40 instructions of headroom.

Three level rows hold their caps on 1.99.1 and cross them only on 1.100.0:

| Row                          |       Cap |    1.99.1 |   1.100.0 |
| ---------------------------- | --------: | --------: | --------: |
| `armature_parse_medium`      |   243,340 |   242,975 |   244,853 |
| `croquis_analyze_full_large` | 2,786,473 | 2,783,082 | 2,789,255 |
| `harness-selfcheck`          |    15,476 |    15,476 |    15,481 |

`harness-selfcheck` is the synthetic 1024-element fill, which no source change
can recover. The contributing guide forbids loosening only caps the compiler
change does not explain, and these three are explained by the paired control.
They rise to exactly their measured 1.100.0 counts. Every other cap is unchanged.

The ratchet admits exactly this 1.99.1 to 1.100.0 step: the authenticated 1.99.1
registry, the same rows and input identities, caps that stay or tighten, and the
three listed raises to at most their reviewed counts. A raise is admitted by no
other step and, once the registry is on 1.100.0, the ordinary downward ratchet
applies to it. The complete 1.99.1 registries and the 1.100.0 three-run packets
are retained as fixtures beside the earlier transition controls.
