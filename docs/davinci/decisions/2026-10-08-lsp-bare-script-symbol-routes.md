# Bare-script read-only symbol routes

Related: [#8010](https://github.com/ubugeeei-prod/vize/issues/8010),
[#3952](https://github.com/ubugeeei-prod/vize/issues/3952),
[#3957](https://github.com/ubugeeei-prod/vize/issues/3957).
The [paired issue decision](https://github.com/ubugeeei-prod/vize/issues/8010#issuecomment-6049621944)
records the same bounded scope and remaining TODOs.

Plain JS/TS and declaration documents have no SFC block. The standard definition
and references handlers previously delegated them to an SFC service whose block
dispatch returned no answer before reaching the native checker. The historical
H probe retains the complete original `plain.ts`, `ordinary.d.ts` and authored
`src/lib.dom.d.ts` inputs and independently authored positive rename expectations.
Its null responses remain a failed/unsupported baseline, not passing coverage.

Route only existing `is_plain_script_path` documents to a small read-only native
service. Reuse the existing canonical script opener, configured project, retained
source catalog and revision-keyed dirty overlays. Definition opens the existing
script project; references also use its existing workspace synchronization to
retain incoming Vue importers. Both methods map the cursor through the existing
projection and make their existing native query. They add no parser, pipeline
stage, transport API or product replacement.

Every raw native location must map through the existing canonical mapper. A
single private, unknown or unmappable location refuses the complete answer;
filtering that member out would claim an incomplete set as successful. Preserve
the native location order, ranges and multiplicity. Empty native answers remain
null; a single definition is a scalar location and several definitions an array.
The outer native request wrapper continues to check the complete document and
environment revisions after the existing open/query/map transaction.

Existing SFC services, the opted-in JSX/TSX dispatcher and its disabled gate,
prepare-rename, rename and their writer ownership checks stay unchanged.
`isDefaultLibrary: false` attests a non-default member of the current native
Program; it does not attest physical authored-file ownership. Bare rename and
preparation therefore remain whole refusals until that ownership is proved.
Read-only library navigation does not grant writer authority. Do not infer it
from a basename, root path, catalog retention or projection alone.

The independent stdio corpus retains the three original H source blocks and
requires complete definition/reference vectors, declaration inclusion, Unicode
UTF16 and LF/CRLF positions, dirty overlays and restored/reopened disk snapshots.
It records bare writer nulls and unchanged full disk bytes separately from the
still-unfulfilled historical positive rename vectors. Existing JSX/TSX opt-in
controls remain distinct. An actual stock-native TS2322 break/repair witness and
the existing admitted Vue diagnostic route prevent empty reports from serving
as a correctness oracle for unsupported bare diagnostics.

The new CLI integration target is discovered by the existing full workspace
suite and appended to the existing source native qualifier command. All original
targets, commands, fixtures, response vectors and instruction ceilings remain
required. Exact-source Actions, fresh protected full/native suites and actual
signed merge qualify this slice; historical H or previous-source results do not.
