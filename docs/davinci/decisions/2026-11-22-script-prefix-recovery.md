# Retaining local type information during an incomplete script edit

When a user deletes the initializer after `let second: string =`, asking for the type of an earlier binding should still work. Reusing an old program wholesale would also preserve the obsolete initializer. Accepting text up to the last newline would be wrong for JavaScript expressions that can continue on the next line. A multi-declarator statement creates the same problem at its commas.

## What the editor can recover

The optional index starts with a successfully parsed TypeScript program and a checked list of primitive initializer judgments. It retains original ranges and a byte boundary for each eligible binding. The parser arena can then be released. A boundary comes from a complete top-level statement whose final source byte is its semicolon. A declaration using automatic semicolon insertion can share a later qualifying boundary once the next token and its enclosing statement have also been established. A trailing declaration that depends on end of input has no such witness. These conditions use the original AST statement boundaries and include comments, whitespace and all preceding bytes in each comparison. [ECMAScript rules for automatic semicolon insertion](https://tc39.es/ecma262/multipage/ecmascript-language-lexical-grammar.html#sec-rules-of-automatic-semicolon-insertion)

On a subsequent edit, the editor obtains the current script role from the original Vue descriptor, checks its grammar and compares the actual script bytes. A lookup returns the types of the original binding and initializer inside the confirmed prefix. The editor maps its range through the current rope and checks the open document revision before publishing. The answer carries the precise range of coverage. Consumers requiring a complete program, all writes to a binding, or a complete diagnostic set still require their own successful queries.

The byte comparison scans up to the first difference or last indexed boundary. A second scan checks the unparsed suffix for potential diagnostic directives. A binary search selects retained bindings and locates a cursor within the result. The index owns one entry per retained initializer. Grammar changes and raw diagnostic directives in the unparsed suffix refuse recovery.

## Opening a file that is already broken

The first-open query parses the original script without requiring a prior document. If the full parse reports a syntax error, the earliest parser label limits the search for a preceding semicolon. A semicolon inside a quoted string, a comment, a nested block or a JSX expression can also be found. Each proposed prefix therefore passes through the ordinary program parser and the independent assignment verifier. Only complete top-level statements can contribute to the index. Cursor publication rechecks the whole current script's suffix for diagnostic directives. Unsupported container frames continue to report their existing refusal.

After a failed prefix parse the next search stops at the earlier of its first diagnostic and half the failed prefix length. For a block of N bytes the total input supplied to parsers is at most 3N, including the initial whole-file parse. Each failed parse drops its arena before trying the next cut. This bound can return a shorter prefix when a broken nested block contains many semicolons. The response gives the actual coverage in current document coordinates. A complete earlier version, when available, can supply a longer boundary without these probes.

## Prior work and design choices

Wagner and Graham's incremental parsing work identifies the parser context and lookahead needed to reuse prior structure. Their history-based error isolation work studies how to preserve reliable context around broken input. Here the history is one checked program and the context is a byte-identical prefix with a known ending. This deliberately limits the damage that one missing delimiter can conceal. [Efficient and Flexible Incremental Parsing](https://harmonia.cs.berkeley.edu/papers/twagner-parsing.pdf), [Isolating Errors](https://harmonia.cs.berkeley.edu/papers/twagner-er.pdf)

Roslyn checks parsing context when reusing immutable syntax. Lezer's account of contextual tokenization explains why a token's unchanged spelling may be insufficient after an earlier edit. Biome retains trivia and represents recovered syntax explicitly so its formatter and analyzer can reason about the extent of an error. In Davinci the source remains lossless at L1, the local type judgment belongs to L2, and the editor owns the current coordinate system. These responsibilities permit reuse after a Vue tag moves while keeping the source evidence inspectable. [Roslyn incremental parser](https://github.com/dotnet/roslyn/blob/main/docs/compilers/Design/Incremental%20Parser.md), [Lezer system guide](https://lezer.codemirror.net/docs/guide/), [Biome architecture](https://biomejs.dev/internals/architecture/)

## Evidence

The reference comparison parses the entire new, deliberately malformed script with TypeScript. It checks that the reference parser reports a syntax error, then validates the number of usable bindings, all three original spans, primitive types and assignability inside the announced coverage. The first-open corpus also reads original TypeScript compiler and conformance fixtures whose reference syntactic diagnostics are nonempty. Separate editor tests apply actual document changes, including CRLF, astral characters, tag relocation and an edit to the first binding. Kani checks that transferring every valid 32-bit source interval preserves its width, order and inverse mapping. A second harness checks the first-open resource invariant on the supported input domain. Spending the current prefix length and reserving twice the next limit always fits within twice the current length.

On the repository and generated edit corpus, TypeScript agreed with 1,530 retained judgments and 1,521 first-open judgments across the same 2,457 broken texts. Both paths identified 744 incompatible initializers. Among 12,397 UTF-8 files at the pinned TypeScript revision, its compiler reported syntactic diagnostics in 1,002 untouched files. The first-open query withheld three for diagnostic directives. Of the remaining 999, 998 yielded no judgment. The one local result was the numeric annotation and initializer in the historical octal-literal test. TypeScript also reports a syntax error in that file. The query exposes local binding information alongside such errors.
