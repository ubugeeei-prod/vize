# Expression whitespace safety (#8186)

The two original `js_ts_expression` slow units from Fuzz run [37612059560](https://github.com/ubugeeei-prod/vize/actions/runs/37612059560) are preserved byte for byte in the existing regression corpus. Their SHA-256 digests are `94471c1713309f60403603d9f407823e73b7a603072aa0f3c4fda7eed826e38a` (23,424 bytes) and `6914c3b2e778e7d8c084a94a82dcd61a037bbe8c3fb7be5c35e084f937ed2957` (23,436 bytes). The official seed recipe already includes this directory.

The shared L0 expression scanner treated vertical tab and form feed as invalid tokens instead of ECMAScript whitespace. That changed the regex goal after a prefix operator. In the original inputs, a backtick inside a regex then appeared to start a template literal, hiding more than 17,000 live brackets from the depth guard. The unchanged parser subsequently traversed those brackets recursively.

Preserve the existing lexical state across these two ASCII whitespace characters in both the nesting and prefix-operator scanners. Keep every nesting and operator budget unchanged. No parser, pipeline, feature flag, or timeout changes are needed. Regression laws exercise the complete original inputs, all six ASCII whitespace characters, a regex containing deep delimiters, postfix non-null division into a template, and the existing operator-depth boundary.

A bounded local probe used the unchanged actual `486c390d` parser and byte-identical guard sources with Rust 1.98 release mode on macOS ARM64, without ASAN. Before the correction, the guard admitted both inputs at depth 3 in 40–42 microseconds; parsing returned errors in 179–225 milliseconds. With the correction, both are rejected before parsing in 98–110 microseconds. These local measurements identify the guard error; they do not substitute for the original Linux sanitizer harness.

Actions must run the new laws and existing regressions on the published source head, then replay the committed full corpus through the existing Fuzz workflow with unchanged sanitizer and resource limits. Close #8186 only after the corrected source actually merges and the specific original inputs have been covered by that replay. Publication verification remains part of the release task.
