# Immutable release source native recipes

Decision for [#6830](https://github.com/ubugeeei-prod/vize/issues/6830): ordinary
pull requests keep the current complete native step, including all nine
declared CLI targets, including the actual incoming bare-script navigation control. An authenticated immutable release source uses the whole
original step from its source commit, which must equal its genuine cut's
workflow. There is no target discovery, command filtering or fallback after
failed source authentication.

The restored 0.436.0 source H339 has parent C6d and only 37 generated version
changes. The current base workflow adds `check_tsconfig_types_extends_cli`, which
does not exist in H. Source native job 113122220570 in run 37718958562 exits 101
before running any target. Its original seven-target command and every later
command, flag, mandatory native guard and receipt are retained in the selected
complete script. The new tsconfig-types capture is explicitly unavailable for
this source; no current-case credit is invented.

Selection requires the official repository, same-repository open draft release
PR, maintain/admin author permission, unique immutable markers, unchanged remote
head and durable pin's exact parent/tree/message. H must have exactly parent C,
C must be an ancestor of the freshly fetched main, and every generated metadata
byte must match the existing `pr_pin_metadata.rs` field rewrite. The complete
eligible-file scan rejects omitted version pins as well as non-version edits,
file additions/removals, renamed files and mode changes. Node mirrors the
existing transformation because frozen H cannot contain the new helper.

The workflow fetches its full `GITHUB_WORKFLOW_SHA`, copies both helper blobs
outside the source checkout and authenticates those complete bytes before
selection. Existing source-custody guards remain mandatory. The original script
runs with the existing Bash error/pipefail semantics, its original environment,
and a full recipe/source/pin/workflow receipt. No release source, cut, publisher,
shipping catalog, compiler pipeline or numerical gate is changed.

The frozen C/H full-blob control preserves all 38 inputs under fixed gzip and
decompressed hashes. Real disposable-Git controls cover exact source selection,
unchanged current inline commands, helper provenance, foreign/partial/malformed
identities, permissions, durable pin, merges, omitted metadata, product edits,
dependency edits, target/flag mutations and file modes. Fresh Actions and actual
protected delivery remain required.

Rerunning an old run retains its original workflow snapshot. After actual helper
delivery, any qualification of H must use a new pull-request event against the
new base workflow, coordinated with the release operator while preserving H and
all immutable pins. The protected-main dispatch guard remains unchanged and
does not accept an unmerged release H. There is no blind release-branch dispatch.
Source SSR's separate 44366/44367 cardinality failure remains independent and
unresolved; this recipe fix does not alter its original catalog or denominator.

Initial source head 6599 passes formatter/apps and starts the actual current
native recipe, but hosted check-js rejects all six unawaited test registrations.
The successor awaits these registrations, following the original custody test
pattern, without changing any body, input or expectation. The zero-warning gate
and all fresh source/native/protected obligations remain mandatory.

Future version-only cuts may themselves contain this wrapper. Unique declared
inline boundaries select every source-owned command exactly once; the complete
source step and executed script receive separate SHA-256 receipts. Only the
recognized wrapper prefix/suffix may surround these boundaries, so extra
commands, missing/duplicate boundaries and malformed wrappers are refused.
Unwrapped H339 still executes its whole original seven-target script byte for
byte. The current complete nine-target script is unchanged inside the boundaries.

The source's declared capture environment is preserved, including the newer
tsconfig capture when present. The bootstrap's symbolic GitHub-token entry is
retained as source metadata, excluded from execution-environment validation, and
the actual token is unset before Bash execution; no actual token is serialized.
The future-cut real-Git control checks both hashes, all original inline bytes,
non-recursion, Bash syntax, capture preservation and wrong-cut/flag/target refusals.
The same PR requires fresh Actions after this correction; previous native success
on 0ac remains historical evidence and does not qualify the successor.
