# Preserve whole original App check answers

**Issue:** [#6879](https://github.com/ubugeeei-prod/vize/issues/6879)

The original five baseline failures discarded parts of the public program report
before snapshot serialization; VueFes failed its unchanged count assertion before
retaining the complete answer. Without the original raw and parsed packets,
a diagnostic-count match could not establish source or configuration equivalence.

The independent test child retains exact stdout, unmodified parsed JSON, argv and
cwd immediately after the existing JSON parse, before each original assertion or
serializer. Its opt-in helper retains whole authored config chains and source
identity, with physical generated-config candidates clearly distinguished from
proved native selection. It does not run another compiler, edit config fields,
change diagnostic order, deadlines, expected snapshots or selected program roots.
Without the capture environment variable, the helper has no filesystem effect.

The dedicated immutable qualifier enables retention only for its original full
App row and shares the existing native build. A packet law checks that nested
program, diagnostic and unknown fields survive unchanged. The TypeScript config
reader uses a bound callback under the original zero-warning lint requirement.

Actual producer repairs, their full legacy corpus and required native controls
belong to the preceding native completion layer. The partition preserves all
original source, author/message objects and failed Actions in custody. Native
configuration and package-read authority omitted by the public API remain
unproved; captured candidates never substitute for them. One later composed
qualifier with the generic-prop repair and genuine Nuxt fixture preparation
remains required before release readiness.
