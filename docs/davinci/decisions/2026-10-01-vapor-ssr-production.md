# Vapor and SSR production acceptance

For [#6100](https://github.com/ubugeeei-prod/vize/issues/6100), production
acceptance covers both compiler backends. Passing development runtime tests
alone does not establish production compatibility.

The first repair preserves Vue's input-model comparisons in both the SSR
string-plan emitter and compatibility walker. Bound `value` expressions and
checkbox `true-value` use Vue's loose comparisons; dynamically typed inputs
pass their value to the server-renderer helper. The registered
`tests/_fixtures/ssr-input-models.json` corpus covers 57 root, inline and merged
attribute cases through the production Vue 3.5 server renderer. The
feature-enabled suite also compares the two emitters' generated bytes. The
inline model lookup selects the first authored static or bound value, as
Vue's `findProp` does; merged routes consume the final props object. Both
static-before-bound and bound-before-static orders are registered fixtures.
Merged prop objects likewise retain the first ordinary static key, as Vue
does; class/style/listeners still combine and computed keys remain dynamic.
The merge-queue instruction gate caught a quadratic scan of retained keys on
wide prop objects. Objects of at most eight entries keep a bounded scan. Wider
objects borrow static keys into a pre-sized hash set before moving any entries;
only duplicate ordinary indices are retained for removal. Wide objects without
class/style/listeners retain their input vector. Source order and first-entry
spans are preserved without raising instruction or allocation budgets.

Vue 3.5's merged `ssrGetDynamicModelProps` helper ignores checkbox `true-value`
and can check a nonmatching truthy model. The input corpus mounts official
client output to verify the checked state. Only a checked-attribute correction
may differ from the server oracle, and only when that client agrees; all other
attributes and content still match. Inline inputs omit true/false-value
attributes, matching the official compiler.

Array checkbox models use membership of the input value even when true-value
is present. Scalar models use true-value equality. Vue 3.5's inline SSR
transform instead prioritizes true-value over array membership; the same
official mounted client oracle verifies this corrected checked state.

The full Check and merge queue rerun the mounted official Vapor parity and
SFC runtime contract suites with `VIZE_VUE_RUNTIME_PRODUCTION=1`. Runtime dev
branches are removed, the runtime is minified, and SFC output uses production
inline templates as Vite does. Dedicated fixture cases retain explicit
ref/computed/event, keyed slot/scoped-style, native model, component model and
disposal expectations alongside DOM comparisons. Ordinary PR checks retain
development coverage and run the dedicated production cases.

Production Vapor script-setup output is normalized to an inline template in
the shared SFC compiler. The native APIs default to separate templates in
development; relying only on Vite to select inline output left those production
callers with bindings that the runtime cannot expose. The reactive-event
fixture also mounts a production request using that native default. DOM, SSR
and normal-script output retain their requested module shape.

Production SFC fixture inputs live in their owning crate's
`tests/fixtures/vapor-production/` and are registered by the SFC runtime suite.
They do not expand the generic L3 optimization-remarks fixture pack.

Remaining acceptance work: obtain terminal exact-head full corpus, real-project
and merge-queue evidence and fix every reproduced failure. This change does not
promote an experimental backend or close the compiler fix-history gate (#6880).
