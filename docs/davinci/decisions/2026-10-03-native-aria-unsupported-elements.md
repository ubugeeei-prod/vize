consumer of the [original selected header Fact provider](./2026-10-03-native-header-facts.md).

original-header admission runs before tables exist; unresolved dynamic/object
bindings, malformed modifiers, duplicate static names, lexical holes, recovery,
foreign owners and ambiguous pre retain typed refusals. Nothing is reparsed or
walked by the consumer and no legacy semantic helper is called.

## Error authority and diagnostics

The consumer reads only its declared original header, attribute and derived
counterexample groups. For each stored counterexample it constructs the genuine
three-link causal chain using actual original ordinals and absolute tag/full-
attribute ranges. The real SDK verifier re-reads every group/key/span/verdict
through the same owner-bound fact view. Every chain is verified before any
message lookup or result generation. Missing evidence, SDK facts and failed
witnesses remain distinct typed failures; no synthetic authority is substituted.

Only after verification does `Diagnostic::proven` emit `Stage::Surface` and
exact Error severity. The existing rule code, complete original attribute
range, owned message and owned full Help are retained, with no labels or fix.
Catalog substitution is portable through `MessageLookup` and matches the real
host's ordered tag-then-attribute replacement, including repeated placeholders
and opaque attribute spelling. Empty or exempt tables never use the catalog.
Finished diagnostics and their concrete witness chains can outlive the owner,
arena and catalog after verification; authority construction remains sealed and
original-owner-bound. No legacy exemption, warning downgrade or default switch
is added.
