## Authority and source semantics

`NativeElement::names()` accepts no caller source, span, raw Element, namespace
or profile. The projection already came from the original Component's sealed
child iterator. The provider checks its actual direct parent/ordinal slot and
original Element pointer, source-buffer identity and present delimiters.
The returned non-cloneable private `NativeElementNames` borrows that complete
Component, Element and parent/ordinal identity. `accepts` rejoins only that real
element; independent equal-buffer parses or equal coordinates do not suffice.

Opening name bytes are the original `<name` token after its one-byte delimiter.
Only actual `ElementClose::Present` supplies a closing name. The existing builder
matched that closing event using its own policy, which preserves byte length.
The close token retains `</`, any originally accepted gap, then that name.
Its name is the suffix of the authentic token with the opening name's byte
length, projected through the same original SourceBlock. This excludes framing
and gap bytes without a source scan or a new matching/case/namespace policy.
Both names keep their actual authored spelling and half-open UTF-8 spans in
the full source. UTF-16 conversion belongs to the later consumer.

The original close outcome stays typed: Present, Missing, Implicit,
SelfClosing, or Void. Void here means the original builder chose NotExpected
without an authored slash; it is not new DOM namespace classification.
Missing/Implicit provide no second name. Recovered/unsupported components,
missing required delimiters and source identity failures return typed refusals.
Verbatim original CST may supply lexical names without expression/semantic
admission. This API supplies no Descriptor selection, File/runtime completion,
whole-body certificate or changed dialect eligibility.

The provider reads existing fields at the caller's original child visit. It
does not parse, walk an AST/tree, scan source, allocate, store names on every
node, add an index/pipeline stage or serialize between levels. Receipts can
outlive the temporary child projection but cannot outlive the actual owner.
No core builder/token layout or L1→L2/body/factory source is changed.
