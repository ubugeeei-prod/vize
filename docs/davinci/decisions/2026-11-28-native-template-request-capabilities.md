# Original listener and lexical products on open editor revisions

The base open-buffer template product request continues to use its original
native File admission. Two additional explicit requests connect existing native
producer capabilities to the same checker/editor product and publication path:

- `run_native_listener_template_products`: static named method-reference events
  and authored same-name bindings through the existing listener producer.
- `run_native_lexical_template_products`: the existing supported arrow initializer
  scopes and captures, together with the listener family.

Both construct the actual original File inside the request arena. They retain
the original call/invocation, parameter, dynamic-event and inline-handler
refusals. Neither selects an LSP endpoint nor grants native runtime setup
emission. The shared SourceQuery guards still reject stale or cancelled work
when the caller publishes the complete owned products.

The native template workflow compares base, listener and lexical admission on
the same exact tracked-source manifest. Every admitted input compares complete
checker documents, ordered expressions, public script bytes, URIs and mappings
against the existing separate checker/editor oracle. A later capability must
preserve every earlier admission. Marginal original paths are retained in
`native-admission.json`.

Refusal counts include nested Vue role issues, underlying L2 issues and native
template holes. Counts represent files with each typed reason and overlap; they
must not be summed into an admission percentage. Each reason retains owned
source witness paths. Macro/reactivity call spellings alone are not evidence of
actual refusal classes or supported coverage.

Prepared listener and lexical product pairs use the same serialized allocation,
peak-memory and paired-time protocol as the base family at four expression
densities. Initial File construction stays outside these timed regions. Exact-head
Actions results must establish the actual coverage gains and measured resource
results before this slice is accepted. Full real-project/default qualification
and the zero-fallback stability period remain outstanding.
