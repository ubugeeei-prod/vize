## Original construction and profile

The Vue 1 component parse retains escaped-text observations during its existing
original lexer visit. A Vue 1 local sink forwards the original callbacks into
the unchanged Vue 1 policy and shared scope sink; no shared lexer, tree builder,
modern Vue policy or legacy product route changes. The original native
construction produces both optional CST projections once.

Each eligible original escaped callback prepares its complete content once with
the existing HTML text decoder, then checks historical framing before ECMAScript
trim. The trimmed checked source goes to the existing `parse_once` provider with
`Grammar { shape: Expr, lang: Js }` and the retained compiler Module JS profile.
No generated Vue runtime string becomes parser input. These are original syntax
artifacts; they do not prove historical runtime evaluation or legacy JS semantics.

The intrinsic component owns its callback observations in an ordinary `Vec` so
the original parser's owned diagnostics are dropped normally. Actual source,
decode maps and ASTs keep their arena/root lifetimes. The exact reviewed storage
changes are `allocVec 1/4` in Vue 1 surface and `1/2` in its local sink, both
`analysis`; the existing surface `arenaVec 1/4` is unchanged. No other inventory
or ceiling change is intended.

## Original source, tree and occurrence join

There is no public constructor pairing existing syntax with a supplied source,
offset, interpolation or tree. The component's sealed `TextChildren` iterator
produces only its own original direct children and their actual parent/ordinal.
Nested children can only be projected from a sealed original element. Optional
authored children come from that same original construction, only when actual
interactive repair required the existing optional alternative. That repair
witness keeps original membership for inspection but always refuses body
admission; requesting authored syntax never creates another wellformed tree.
Read-only raw CST
access remains available; a public lookalike node cannot produce a sealed view.

`text_for` checks actual component identity, original block/token pointer spans,
callback content bytes and complete escaped delimiters. It finds an observation
by the monotonically ordered callback start, with no source/tree/AST traversal,
decoding or parse at lookup. This admits a short original callback/CST/expression
`TextView`, preserving the same actual parser root. Repeated identical bytes
have different original offsets and ASTs. A different component over the same
byte buffer is refused; moving the original component and obtaining fresh views
retains its original arena AST. Raw observation/AST inspection alone grants no
original CST occurrence authority.

Recovery propagates through the caller's same child traversal using constant
direct-token checks. Surface errors, missing/implicit ancestor extents and
verbatim parents cannot produce expression views. No new header/body/AST walk,
pipeline stage, neutral tuple serialization or legacy normal dependency is added.

## Explicit boundaries

Raw HTML, once-only syntax, missing delimiters, empty expressions and every
authored or decoded pipe are typed refusals. The entire pipe family includes
logical `||` and pipes inside literals: it deliberately waits for Vue 1's actual
space-separated filter grammar instead of borrowing Vue 2's scanner. Native
language holes retain source, comments and original diagnostic records.

Historical dot framing rejects every CR, including CRLF, and U+2028/U+2029 in
the complete decoded window before trim. Once-only detection tests the first
decoded character before trim; leading-space `*` remains a native syntax hole.
Entity-produced braces inside callback content explicitly refuse framing.
Outside callbacks the original entity callbacks retain full-file encoded-brace
boundaries; such a component is conservatively refused for text views. Literal
`v-pre` suppresses callbacks using its unchanged original scope policy.
Double-encoded input is decoded once, retaining its exact native source map.
