# Native scoped class lists from retained original CSS syntax

The dependent native consumer uses SimpleClassListStyle from the original L1
StyleSyntax owner. It lends every insertion from an actual classname token end
in the same complete cssparser qualified rule. No additional parse, copied
stylesheet, raw selector scanner or legacy style helper supplies authority.
The single-class receipt and its escaped-name family remain unchanged.
Original quoted-token binding/comment-marker refusals apply to list values too;
the native path never drops descriptor CSS-variable semantics from those values.

The list family contains at least two literal simple classes separated by real
comma tokens. Whitespace after a comma and before the opening brace remains
authored; pre-comma whitespace, comments between selectors, escaped names,
mixed selectors and other unproven profiles remain typed source-linked refusals.
These boundaries preserve the insertion-only output contract proven against
pinned Vue 3.5.35, rather than guessing its normalization. Actual parser errors
and the complete original descriptor/script/template/File survive refusal.

The consumer inserts the same validated component scope attribute at each
receipt position. Every remaining original byte retains a whole-SFC source
span. Generated scope attributes and existing block-join newlines are unlinked.
Optional CSS, trim, original block order, default filename scope identity and
whole module attachment remain the existing native result contract. A failure
in any style returns no partial CSS or complete module success.

Three authored whole-SFC/full-module/CSS fixtures cover a two-class list,
Unicode/CRLF/comment trivia with internal whitespace and original setup with
the actual default scope identity. Separate complete ordinaryCss fixtures retain
the dev-only ordinary printer's comma-space join and selector trimming. Native
and pinned Vue output preserve every original byte around the insertions;
neither result is normalized or compared only for semantic equivalence.

Rust laws compare every complete result, original source custody across moves,
recording-disabled output and independent full-source Source Map v3 coordinates.
They prove that all emitted non-generated CSS bytes exactly cover the original
style and that the only map gaps are the two scope attributes. Separate trim and
typed-refusal laws preserve the same obligations. No production allocation is
added for collecting insertion offsets.

The existing protected tooling-shard-1 scoped action captures current-source Rust
whole modules/CSS/maps for both the original four single-class fixtures and all
three list fixtures. The class-list Node harness requires those exact captures
when the action sets its environment, then mounts those fresh complete modules
through real Vue in HappyDOM. Each class alternative is tested independently,
including actual computed CSS, scope attributes, exclusion outside the component,
setup update and unmount. Source and runtime captures remain action artifacts.
Local committed-fixture execution is not current-source Rust capture proof.

This bounded slice requires exact-head Actions and protected full/all100 queue
acceptance, including the fresh class-list Rust/Vue captures, before delivery.
Broader selectors, multiple rules, nested/functions/binding
values, Modules/preprocessors/external/custom sources, SSR scoped output and
whole-product/history gates remain unfinished. Ordinary routes, output oracles,
history gates and instruction budgets remain unchanged.
