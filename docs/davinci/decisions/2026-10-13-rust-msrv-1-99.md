# The minimum supported Rust version follows the pinned toolchain

## Decision

`[workspace.package].rust-version` is `1.99.0`, the same release that
`rust-toolchain.toml` pins. When the pinned toolchain moves to a new stable
release, `rust-version` moves with it in the same change.

## Scope

The workspace manifest, the release SemVer job in `check.yml`, the Nix package
toolchain in `tools/nix/pkgs.nix` and the contributing guides. The vendored
OXC crates keep the `rust-version` of their upstream source.

## Reason

Vize ships as prebuilt binaries: the CLI archives, the N-API packages and the
WebAssembly package. Users do not compile it. The crates on crates.io are
published for those builds and for tooling in this repository; no external
consumer that builds them with an older compiler is known.

The previous value, `1.95.0`, was declared but not built by any pull request
check; only the release SemVer job and the Nix package used it. A declared
minimum that CI does not build is a claim nobody verifies.

Keeping the declaration four releases behind also had costs:

- resolver 3 prefers dependency versions whose own `rust-version` fits the
  workspace value, so `cargo update` held dependencies back;
- Clippy does not suggest APIs newer than the declared minimum, which hid
  lints for APIs stabilized in 1.96 through 1.99;
- code could not use those APIs without contradicting the manifest.

## Tradeoff

A downstream crate that builds Vize from source needs Rust 1.99.0 or newer.
No such consumer is known, and the published binaries are unaffected.
