The existing Linux public acceptance materializes one fresh npm consumer from
the authenticated frozen release source H. It retains the C/H/R, registry,
archive and provider guards, the original native cases, gallery globals and
all 65 browser frames. This observer adds mandatory VRT observations in that
same installation. It grants no publication, signed-source or installed
success until the actual next official release campaign completes.

## Source and custody

The observer lives in eight `vrt_*.ts` modules under
`tools/support/release/public_acceptance/`. Preparation copies their whole
sources alongside the unchanged original consumer harness. It separately
copies normal raw H blobs for both `snapshot-collision/{left,right}/Button.art.vue`
inputs and the `gallery-vrt-options.json`, `hosted-audits.json` and
`vrt-report-ownership.json` contracts. Both original Art SHA256 values remain
mandatory. The original example, setup, package manifest and collector bytes
are preserved. A mutable `vrt-workspace` has its own runtime configuration,
Arts, reports and snapshots; sealed inputs remain outside that directory.

There is one exact public npm installation and one installed native provider.
The VRT entry rejects overrides and authenticates the Linux provider before
product imports and after all observations. Sealing requires native, original
Musea and VRT receipts to agree on every package record and loaded provider.
A missing, failed, unsupported or mismatched VRT observation fails acceptance.
There is no capability skip, second installation or workspace native fallback.

Whole authored/configuration bytes, generated static manifest and physical dist
files, HTTP bodies, gallery documents and their hashes accompany the raw API
responses and CLI streams. The HTTP host serves emitted files only. Original
audit compiler substitutions are not imported. Page and console errors must
be empty before deliberate negative controls; errors from those controls are
retained honestly. No later colon-binding, literal-key or loopback service
successor is required by this input selection.

Every acquired page, dev server, HTTP server and browser has cleanup. Cleanup
attempts each remaining operation even if a preceding close or evidence write
fails, records all failures and fails the campaign. Failed runs retain whole
available response bodies, documents and the physical mutable project without
writing a success receipt.

## Preparation status and review boundary

Before this change, the workflow had no installed VRT step and its seal had no
VRT receipt. This integration adds one independent step using the
already installed consumer and makes the seal require its receipt. Original
native/browser commands, deadlines, source snapshots, conditions and release
authority remain unchanged. The existing strict `success()` seal condition
also rejects a failed VRT step.

The VRT6 prerequisite is actual delivered main
`b2ed3149cedc4b937ce651089bb5c9b513a02bd4`. Preparation began on isolated
`test/musea-installed-vrt` from main77ed and incorporated that exact delivered
prerequisite once before this narrow integration; no old0.441 campaign evidence transfers
to this observer. Source syntax, formatting and guard laws are preparation
checks only. Official next-cut C/H/R inputs and a real Linux installed run are
still pending. PR, queue and dispatch admission remain with the root owner.
