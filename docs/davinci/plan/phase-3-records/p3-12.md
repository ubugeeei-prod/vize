# P3-12 - Mounted backend behavior

The first TS-30 slice compiles templates with both Vize backends and mounts
their emitted functions with the pinned Vue 3.6 beta runtime in Happy DOM.
The runner bundles Vue's published ESM entry with Vite+, so its scheduler,
reactivity, event delegation, slot handling, and component lifetimes execute
without substituted runtime helpers. Each backend runs in a fresh process.

`crates/vize_atelier_vapor/tests/davinci_mounted_behavior.rs` covers:

- Initial button markup, reactive text/disabled updates, delegated clicks,
  and complete unmount.
- Conditional removal/restoration beside a slot fallback, in both source orders.
- Empty-element `v-text`, nested `v-text`, multiple updates in one effect,
  and transitions through string, null, and numeric values.
- IME composition with intermediate Japanese input and commit, `.lazy` change
  timing, combined `.trim.number` conversion, checkbox array membership, and
  select-multiple reconciliation after user input and external state updates.
- Member and computed `v-model` bindings, including replacement of the parent
  state object. A code-generation regression checks both identifier-prefix modes.

Observations preserve element order, text, attributes, and live form properties.
Only implementation-specific anchor comments and adjacent text-node boundaries
are normalized. Runtime warnings/errors and missing interaction targets fail
the run. Cross-backend equality is supplemented by concrete expected outputs.
The ordinary Cargo suite and Davinci Lean workflow both run the mounted gate.

The first run exposed two Vapor defects: `v-text` addressed a nonexistent
child Text node, and a slot was inserted before a preceding conditional.
`SetTextIRNode::is_element` now distinguishes whole-element text updates from
Text-node updates in both inline and multiline effects. Dynamic children and
structural children now lower in source order. The TS-28 control/slot ordering
exception is removed; its reference comparison is exact.

Combining the child traversals also reduces the pinned Vapor visits from
25/102/127/256/4/3102 to 23/82/118/203/4/3002 on the six-fixture ladder.
The traversal ratchet and its record are updated; this is a node-visit result,
not a wall-clock performance claim.

The model scripts exposed another Vapor defect: already-prefixed model
expressions received a second `_ctx.` prefix and crashed when mounted.
Model getters and setters now use the existing directive expression resolver,
including retained member/computed expressions, instead of adding a raw prefix.
The runner also observes selected option state and applies explicit selection
steps before dispatching native change events.

Nested event coverage exposed a separate delegation defect: only the root
block registered event names, so listeners inside conditions, loops and slots
could be emitted without installing their delegated event type. Registration
now happens when the listener itself is emitted, using the existing shared
deduplicated/sorted set and no additional traversal. Code-generation tests cover
branches, loops, fallback/default/named slots and direct-listener exclusions.
Mounted traces verify disabled/enabled conditional activation, removal/remount,
keyed single-item replacement, slot fallback delivery and experimental root
`v-match` arm switching through both runtimes.
These do not claim the broader keyed reorder/focus/identity contract complete.

The dynamic-button case now shares its complete script and structured output
artifact with the [P3-4 stateful Lean reference](./p3-4.md). Its twelve observations
are compared in full by both mounted backends and the independent S3 interpreter.
An explicit `activate: "button"` step calls the native element's `click()`;
disabled activation leaves the event history unchanged before and after
reactive updates. Existing `event` steps retain their synthetic dispatch
semantics. The runner rejects ambiguous activation fields, unsupported targets,
and missing or multiple buttons. This does not model trusted input or keyboard
and focus behavior.

The control/slot case now shares one authored template, one scenario and ten
complete observations with Lean, including repeated conditional removal and
restoration beside reactive fallback text. Rust verifies both the graph and
value Folios against that exact input. A corrupted expected root element fails
both the mounted comparison and the independent reference comparison.

The SFC runtime contract gate in
`crates/vize_atelier_sfc/tests/vapor_runtime_contracts.rs` compiles complete SFCs
through the adapter API and mounts parent/child components in both backends.
It covers nested scoped attributes, conditional and loop descendants, namespaces,
raw text and `v-html` boundaries, leading/middle/adjacent component insertion,
supplied default slots, lazy inline component handlers, handler references and
bound callback factories. Keyed component reorders retain the actual DOM nodes,
update props and event payloads, and do not leak reserved `key` attributes.
Unmount removes all nodes and detached children cannot emit further events.
The scoped-style loader metadata is supplied explicitly; compiler-generated
render expressions and runtime helpers are not replaced.
Namespace URIs are compared alongside the SFC trees. MathML is exercised in
`playground/e2e/vapor-scoped-namespaces.test.ts` with Chromium, because Happy
DOM's template parser assigns HTML namespaces to MathML even without a compiler.

This gate exposed missing insertion anchors, root-only scoped-style rewriting,
eager inline handlers, reserved-key fallthrough, and a default-slot call that
omitted the name required by the pinned runtime. Scope attributes now enter
template generation during lowering, and dynamic children use authored anchors.
These SFC cases are mounted VDOM/Vapor comparisons, not new Lean reference
coverage or an SSR hydration completion claim.

P3-12 remains open for broader keyed list/interaction scripts. Both
Rust-lowered template fixtures share full observations with Lean. The
[P3-4](./p3-4.md) model and supplied-slot references now give the scripted
model/IME and slot surfaces stateful reference equality. The remaining ad hoc
mounted cases here are cross-backend only.

The 2026-09-20 [array-loop slice](./p3-11.md) adds complete reference equality
for keyed, unkeyed and nested native loops. Mounted observations assign lifetime
numbers to actual DOM objects, check removed nodes are disconnected, and compare
every authored tree/event/identity observation with the same Lean artifact.
Replaced/reordered item handlers must deliver the current label exactly once.
This exposed and fixed an extra lambda wrapper in native Vapor event generation.
Broader keyed component interactions, model/IME and supplied-slot reference
semantics, hydration and focus acceptance remain open; P3-12 is not complete.

## Keyed model interactions (2026-09-22)

The model reference now executes controls inside a single array loop. Each
control instance reads through its loop scope. A write through the value alias
lands in the source element at the instance's current index, as Vue's reactive
item proxy does. Live DOM state stays keyed by element identity.
`model-loop-reference.*.jsonl` holds four Rust-lowered cases: keyed and
positional text rows, and keyed and positional checkbox rows. They type,
reorder rows while an IME composition is in flight, commit, remove and insert.
Lean, VDOM and Vapor agree on every tree, live form property and element
lifetime. The IME commit reaches the item that owns the composing element when
keyed, and the row now occupying its position when positional. Assigning an
index alias, nested looped controls, identity-free observation of looped
controls and missing keyed targets fail closed.

## Status

_Closed 2026-09-22:_ every scripted surface in the acceptance has trace equality
across both mounted backends and against the independent Lean reference:

| acceptance surface                                                     | reference-backed gate                                 |
| ---------------------------------------------------------------------- | ----------------------------------------------------- |
| scripted prop/interaction traces, activation, disabled buttons         | `rust-lowered-static-dynamic` / `-control-slots`      |
| IME `compositionstart` → intermediate input → `compositionend`         | `model-reference` `text-ime`, `model-loop-reference`  |
| `.lazy` / `.number` / `.trim`                                          | `model-reference` `text-lazy`, `text-trim(-number)`   |
| checkbox arrays, select-multiple (plus boolean, radio, numeric select) | `model-reference` `checkbox-*`, `radio-*`, `select-*` |
| keyed interactions: reorder, insert, delete, clicks, toggles           | TS-29 `ivm-matrix` (32 cases), `rust-lowered-loop-*`  |
| keyed interactions with live model state                               | `model-loop-reference` (4 cases)                      |
| supplied and fallback slots                                            | `slot-reference` (8 cases)                            |

The remaining ad hoc mounted scripts and the SFC runtime contract gate stay as
cross-backend supplements. They exercise components, `v-html`, namespaces and
member/computed model expressions, which the S3 reference subset does not
model. The only pinned divergence is the upstream `runtime-vapor` unkeyed-object
key-alias defect recorded by [P3-11](./p3-11.md). Hydration belongs to SSR
(P3-8). Focus and trusted-input semantics are not part of this acceptance;
Vapor behavioral parity against upstream (TS-33) is a Phase 3 exit gate.
