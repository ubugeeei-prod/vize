# P6-3 — In-process wasmtime hosting lane

**Landed 2026-09-22.** `vize_extension_host` hosts contract guests under
wasmtime in process and out of process with the same guest binary, stops a
guest at its fuel and memory limits with exact errors in both modes, and
wasmtime is reachable only through the `extension-host` feature.

## What landed

- In-process hosting (`wasm::WasmGuest`) and the out-of-process child
  (`vize-extension-host serve`) already shared one engine path and the WIT
  contract since P6-1a; TS-48 runs the same echo guest binary through both.
- **Per-guest limits** (`GuestLimits`, default one billion units of fuel per
  call and 128 MiB of linear memory): every call gets a fresh fuel budget
  (`Config::consume_fuel`), and a `ResourceLimiter` denies memory growth past
  the ceiling and records the denial, so the trap that follows is reported as
  the limit. The errors are `GuestError::OutOfFuel { budget }` and
  `GuestError::MemoryLimit { limit }`; the child process takes the same limits
  as `--fuel` / `--memory` and returns the same errors over the wire.
- **Dependency isolation** (`tests/tooling/davinci-extension-host-deps.test.ts`):
  with default features no workspace crate — the `vize` CLI included —
  reaches wasmtime (it is absent from the resolved graph); with
  `vize_extension_host/extension-host` on, `vize_extension_host` is the only
  workspace crate that does.

## Acceptance evidence

- `cargo test -p vize_extension_host --features extension-host --test guest_limits`:
  under 5,000,000 fuel and 16 MiB, the echo guest's `<!-- spin -->` probe is
  stopped with
  `guest stopped: it used up its fuel budget of 5000000 per call` and its
  `<!-- hoard -->` probe with
  `guest stopped: it tried to grow its memory past 16777216 bytes`, in both
  modes; every golden block still passes under the same limits; the defaults
  are pinned.
- TS-48 (`--test wit_golden`) passes in both hosting modes with the same guest.
- `node --test tests/tooling/davinci-extension-host-deps.test.ts`: the two
  isolation checks above, and the check **fails with the exact message on an
  injected wasmtime edge** into the `vize` CLI.
- `cargo audit --deny warnings` over the lockfile: clean locally against the
  RustSec database of 2026-09-22 (wasmtime `=48.0.2` and its transitive
  crates, plus the SDK's `wit-bindgen`); the `security-audit` CI job holds it.

## Remaining

- The `vize` CLI does not host external dialects yet: wiring an
  `extension-host` feature into the CLI (routing a block whose `lang` a
  configured guest declares) is the next step, and the isolation test already
  names the edge it must add only behind that feature.
