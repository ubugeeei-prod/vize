# P6-1b — Expression-dialect WIT world

**Landed 2026-09-22.** `crates/vize_extension_sdk/wit/expression-dialect.wit` defines the
expression world — one block's expressions and the bindings in scope in,
analysis facts and a checkable projection with span links out — and TS-48
exchanges it with a stub guest in both hosting modes, byte for byte.

## What landed

- **World** (`vize:contracts@0.1.1`, additive over 0.1.0): interface
  `expression-analysis` with one coarse-grained call,
  `analyze(expression-batch) -> analysis`. The batch carries every expression
  of a block (`id`, authored `source`, file-absolute `span`) and the
  environment (`name`, `BindingType`-spelled `kind`); the analysis carries two
  pages and diagnostics. The world exports `handshake` and
  `expression-analysis` and imports only the types-only `types` interface.
- **Facts as a P4-2 α page** (`facts-page@1`): the new fact group
  `expression-facts` (`vize_davinci::fact::ExpressionFacts`, analysis id 12,
  α schema 1) holds P2-5b's capability duties per expression id: referenced
  bindings, whether that enumeration is exact, and const-ness. Its α export
  is registered in `ALPHA_GROUPS` and [fact-alpha-schemas.md](../fact-alpha-schemas.md);
  import unions the section keys with pessimal defaults.
- **Projection as P4-5a rows** (`projection-page@1`,
  [folio-format-projection.md](../folio-format-projection.md)): each row is a
  `ProjectionMapping` entry — generated and authored ranges, sub-spans,
  `ProjectionSpanKind`, `ProjectionFeatures` — and the generated text.
- **Host** (`vize_extension_host::expression`): `ExpressionSession`
  negotiates with the world's own required features (`negotiate_for`) and
  accepts the answer as untrusted input: pages at readable schema versions,
  parsed and canonical; exactly one fact per batch id; exact references
  inside the environment; rows inside the generated text and one
  expression's span; sub-spans inside their row; diagnostics inside an
  expression. Both hosting modes serve it: `WasmExpressionGuest` in process
  and `vize-extension-host serve --world expression-dialect` out of process
  (wire `analyze` / `analysis`), with the P6-3 limits.
- **Released surface**: `crates/vize_extension_sdk/versions/vize-contracts@0.1.1.json`
  (policy: additive, patch bump, protocol version unchanged); the Rust SDK
  and `@vizejs/extension-sdk` carry the WIT, the TypeScript mirror of the new
  records and `ExpressionAnalysis`, and the world's page schemas and required
  features.

## Acceptance evidence

- TS-48, expression world
  (`cargo test -p vize_extension_host --features extension-host --test wit_golden_expression`):
  the stub guest (`tests/guests/expression-echo`, on the SDK runtime)
  negotiates protocol 1 with no ignored features in both modes, returns the
  committed `probe.facts.folio` and `probe.projection.folio` byte-equal, the
  host accepts both into the expected α document and projection, an unknown
  batch traps with the exact message, and the component imports only
  `vize:contracts/types@0.1.1`.
- `cargo test -p vize_extension_host --test expression_contract`: the goldens
  are the canonical probe pages, the rows convert into a P4-5a
  `ProjectionMapping` that maps both ways exactly, and nine tampered analyses
  and seven malformed projection pages are refused with exact messages.
- `cargo test -p vize_extension_host --test contract_surface`: the released
  history 0.1.0 → 0.1.1 passes the P6-8 policy and 0.1.1 is the WIT today.
- `node --test tests/tooling/davinci-extension-sdk.test.ts`: the TypeScript
  declarations mirror all 15 surface types and the three exported interfaces.

## Remaining

- The Rust SDK binds only the input-dialect world; an expression guest uses
  `wit-bindgen` over the SDK's WIT with the SDK runtime. SDK bindings and
  writers for the expression pages join with P6-4b, its first real consumer.
- No compiled-in expression dialect answers the world yet (P6-4b).
