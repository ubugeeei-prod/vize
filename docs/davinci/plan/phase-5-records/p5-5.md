# P5-5 — Snapshot tree under salsa

Contract: [phase-5-tasks.md](../phase-5-tasks.md#p5-5--snapshot-tree-under-salsa).
Landed 2026-09-22.

## What landed

`vize_resident::snapshot` — Lean's snapshot-tree incrementality at an SFC's
natural joints, one reuse rule (**old syntax ≡ new syntax ⇒ adopt the old
subtree**), below the salsa tier's block firewall:

| Joint  | Syntax compared                                               | On equal                        | On change                                         |
| ------ | ------------------------------------------------------------- | ------------------------------- | ------------------------------------------------- |
| header | block layout (kind, ordinal, header attributes) + config      | adopt the file's block tasks    | restart: cancel the whole old tree, adopt nothing |
| block  | `BlockSource` (content + its P5-1a S0 key), wherever it moved | adopt S1 + S2 artifacts, shared | cancel the old task, compute a new one            |
| region | a template root region's bytes                                | adopt its lowering, spans moved | cancel the old task, lower the region             |

- **Regions.** `snapshot::region::split_regions` splits a template's root
  children into regions when the template is decomposable: elements
  separated only by newline whitespace (the runs root condensing drops),
  an `if` chain kept in one region. Each region lowers against the block
  frame; the page is the concatenation — ops, then every tokenizer finding,
  then every lowering diagnostic, the whole-block order. Anything else at the
  root lowers the block whole.
- **Moved regions.** A region with the same bytes at a new offset is adopted
  with its spans shifted (`snapshot::shift`, exhaustive over every op,
  binding and expression variant, no `_` arm) — no parse, no lowering.
- **Cancellation.** Every task has a `CancelToken` parented to its task in
  the _current_ tree: tokens live in tree entries, not in the shared
  snapshots, so an adopted subtree gets fresh tokens and cancelling a file
  cascades to everything it serves. A replaced task is cancelled (cascading to
  its old regions); an update polls between units of stage work and stops
  with `Cancelled`, leaving the previous tree valid.
- **Isolation.** `snapshot::isolate` runs file updates on scoped worker
  threads under `catch_unwind`. A panicking stage returns
  `FileOutcome::Degraded("internal error in a stage task: …")`; that file
  keeps its previous tree and every other file's update completes.
- **Sharing.** Snapshots are immutable and shared (`Arc`, behind one allowed
  alias with its reason), so adoption is a pointer copy.

## TS-46, measured

`cargo test -p vize_resident --test snapshot` (5 tests), every state also
compared with the clean path:

| Update (fixture: script, 3-region template, style) | header a/c/x | blocks a/c/x | regions a/c/x |
| -------------------------------------------------- | ------------ | ------------ | ------------- |
| open                                               | 0/1/0        | 0/3/0        | 0/3/0         |
| edit inside the last region                        | 1/0/0        | 2/1/1        | 2/1/1         |
| grow the first region (the others move)            | 1/0/0        | 2/1/1        | 2/1/1         |
| script edit (template and style move)              | 1/0/0        | 2/1/1        | 0/0/0         |
| header change (`<style scoped>`)                   | 0/1/1        | 0/3/0        | 0/3/0         |
| project config change (Vue 2)                      | 0/1/1        | 0/3/0        | 0/3/0         |

(a = adopted, c = computed, x = cancelled.) The cancellation tests pin the
task tokens in document order: after the last-region edit the old tree reads
`[file live, script live, template + its 3 regions cancelled, style live]`,
the new tree is all live, cancelling the new file token cancels all seven
(adopted subtrees included), and a header restart cancels every task of the
previous tree. An update cancelled mid-template stops after exactly one
region lowering and leaves the previous tree's artifacts unchanged. The
isolation scenario runs three files on two workers with the middle one
panicking: `[ready, degraded, ready]`, the degraded file still answering from
its previous tree.

## Under TS-42

`EquivalenceReport` now runs the snapshot tree beside the salsa database on
every state and compares both with the clean path (P5-9's harness). On the
committed `_projects` plane: 0 mismatches, and the snapshot accounting pinned
exactly — header 1953/201/134, blocks 2476/2194/1762, regions 156/1524/1158
(adopted/computed/cancelled). The seeded stale-cache build now reports 627
stale states (347 from the database, 280 from the snapshot tree, whose block
joint compares the same `BlockSource`). A region probe over all 343 committed
templates found 262 decomposable (41 with more than one region) and zero
cases where region assembly differed from whole-block lowering.

## Limits, honestly

- The region joint is the template **root**. Most templates have a single
  root element, so a keystroke inside it re-lowers the whole block; nested
  regions need a lowering entry that accepts parent context (namespace,
  `pre`, component slot context) and are the next step, not claimed here.
- The tree runs beside the database, not inside a salsa query yet: wiring
  it into `s2_page` as a content-keyed memo is part of the Maestro migration
  (P5-6a), where the per-file worker loop lives.
