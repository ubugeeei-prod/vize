# P5-1a — Stage artifact keys

Contract: [phase-5-tasks.md](../phase-5-tasks.md#p5-1a--stage-artifact-keys).
Landed 2026-09-22.

## What landed

`vize_davinci::key` is the shared cache identity for stage artifacts, in the
shape of Doctor's `cache_identity` (domain-separated, versioned, explicit):

- **`ArtifactKey { stage, schema_version, hash: [u8; 16] }`** — `Copy`,
  totally ordered, printed as `s2.v1:<32 hex>`. Fields are private: a key
  only comes out of a `KeySink`, so no caller can hand-assemble one that
  skips the domain prefix.
- **`KeySink`** — the one encoder. Every hash starts with a fixed domain tag,
  the stage's physical id and the recipe version, so equal pages of
  different stages or versions never collide. After the prefix a keyer feeds
  either raw folio text (the `fmt::Write` impl) or typed fields
  (length-prefixed strings, little-endian `u32`s, rebased spans).
- **`KeyedArtifact`** — `const STAGE`, `const SCHEMA_VERSION`, `feed_key`.
  `ArtifactKey::of(&artifact, block_start)` is the only entry point.
- **`key::schema`** — one recipe version per keyed artifact (`SOURCE_BLOCK`,
  `S1_SURFACE`, `S2_PAGE`, all `1`). A grammar or recipe change bumps its
  entry; the golden fails otherwise.
- **`rebase(span, block_start)`** — the single rebasing rule. A span reaching
  before its block has no relative form; it is fed absolute under its own
  marker instead of letting `Span::to_block_relative` saturate two spans
  onto one.

The hash is XXH3-128 through the new `vize_s0::hash::StableHasher128`: the
digest is defined over bytes by the XXH3 specification, so it does not
depend on endianness, pointer width or SIMD path, and 128 bits is the rustc
`Fingerprint` width. It lives in S0 beside the existing XXH3-64 helpers, so
`vize_davinci`'s direct dependency ledger (`vize_s0`, `vize_davinci_derive`)
is unchanged. Unit tests pin the streaming digest against the one-shot
function and the reference empty-input vector.

## Where each keyer lives, and why

| Artifact        | Keyer                                               | Page the hash walks                                                                                                           |
| --------------- | --------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| S0 source block | `vize_davinci::key::source_block_key`               | kind, header attributes as a sorted set, content bytes — all length-prefixed                                                  |
| S1 surface page | `vize_s1_to_s2::key::SurfacePage` (`KeyedArtifact`) | the lossless render: every token slice, `Missing` holes as empty pieces, each length-prefixed (token segmentation is covered) |
| S2 page         | `impl KeyedArtifact for S2Folio` in `vize_s2`       | the Disegno folio `Full` form, every `@s:e` rebased to the block start                                                        |

- **S2** streams its own printer into the sink. The printer's `mode`
  parameter became a private `Style { mode, base }`; the public `Folio`
  print always passes base `0`, so every committed page and the TS-16 laws
  are byte-unchanged, and the key feed passes the block start. There is one
  printer, so the key cannot drift from the folio.
- **S1** cannot name `vize_davinci`: the stage-dependency table keeps S1 on
  S0 alone. Its keyed view lives in the conversion crate, the one place that
  already joins S1 and the shared infrastructure. S1's page is its render
  (the P2-18 precedent: the S1 page _is_ the lossless render); token slices
  carry no offsets, so the page is block-relative by construction.
- **S0 blocks** have no stage parse yet, so their key is the block itself.
  Header attributes are a set — `<script setup lang="ts">` and
  `<script lang="ts" setup>` are one block — because identity excludes
  presentation. The block's position is never an input; it is the S0 side
  table beside the key.

## TS-43, measured

`cargo test -p vize_davinci --test artifact_keys` (3 tests) plus 6 unit
tests in `key::tests`:

1. **Golden keys, two platforms.** `tests/fixtures/keys/base.keys` pins the
   seven keys of `base.vue` (template S0/S1/S2, `script setup`, two
   `<style scoped>` blocks, one `<i18n>`). `.github/workflows/davinci-incremental.yml`
   runs the test with `--nocapture` on `blacksmith-32vcpu-ubuntu-2404` and
   `blacksmith-12vcpu-macos-15`; both print the listing and compare it with
   the one golden, so equality across the two platforms is checked on every
   PR touching a keyer.
2. **Edit locality, exact changed sets.** Ten cases, each asserting the
   edited file differs from the base and naming exactly the keys it changes:

   | Edit                                                | Changed keys                                |
   | --------------------------------------------------- | ------------------------------------------- |
   | insert above every block (outside any block)        | none                                        |
   | insert inside the `script setup` above the template | `script-setup s0`                           |
   | insert inside the template                          | `template s0`, `template s1`, `template s2` |
   | insert inside the `<i18n>` block below              | `i18n[0] s0`                                |
   | reorder blocks (template first)                     | none                                        |
   | whitespace between blocks                           | none                                        |
   | whitespace inside the template                      | `template s0`, `template s1`, `template s2` |
   | header attribute order                              | none                                        |
   | header attribute of the second style                | `style[1] s0`                               |
   | whitespace inside the first style                   | `style[0] s0`                               |

3. **Offset independence.** The two byte-identical `<style scoped>` blocks
   key identically at different offsets; the template lowered with
   file-absolute spans (`lower_source_block`) keys exactly like the same
   block lowered as its own root (`SourceRoot::whole_block`, base-zero
   spans) — S1 and S2 both.

The unit tests pin the display spelling exactly, relative-span equality at
two offsets, the out-of-block marker (the saturating collision it prevents),
stage/version domain separation, length-prefix separation, and the
attribute-set rule.

  (folio laws unchanged), `cargo clippy` on the four touched crates.
- TS-24: the key module is `no_std + alloc` like the rest of the crate; the
  wasm32-wasip2 lane builds it (CI-owned, `check.yml`).
- TS-13: the new tests use exact `assert_eq!`/`assert_ne!` only.

## Not in this task

- Ambient inputs (tsconfig, toolchain/Corsa versions, feature flags,
  platform) are P5-1b's `KeyManifest`, folded into these keys.
- No cache consumes a key yet; the resident tier is P5-4a, projection reuse
  P5-7, Corsa sessions P5-8.
- Diagnostics and lowering side tables are not part of the S2 page key:
  they are separate artifacts derived from the same block, keyed by their
  own recipes when a cache first stores them.
