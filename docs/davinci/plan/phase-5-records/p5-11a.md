# P5-11a — Resident resource baselines and methodology (TS-44)

**Status:** landed. `budgets.toml [resource]` pins the
reference-runner preset from a recorded CI measurement; the gate runs in
`.github/workflows/davinci-resource-budgets.yml`. Enforcement on the large
corpus projects is P5-11b (gated on P5-6c).

## What is measured

`rust-script tools/commands/davinci/resource-budgets.rs --measure` drives the
real `vize lsp` over stdio through one scripted session per run, in a fresh
copy of the TS-45 fixture workspace (`editors/vscode/test-fixtures/extension-host/real-vue`,
document `src/Scenario.vue`; lint, type check, editor and ecosystem on):

| Metric                 | Sampler                                                                                                           | Statistic                                          |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------- | -------------------------------------------------- |
| `cold_start_ms`        | process spawn → `initialize` response, monotonic clock                                                            | median over runs                                   |
| `first_diagnostics_ms` | `didOpen` → first publish carrying the TS 2322 diagnostic                                                         | median over runs                                   |
| `keystroke_p95_ms`     | `didChange` → publish for that version carrying that edit's TS 2322 message (the edit alternates two type errors) | nearest-rank p95 over every keystroke of every run |
| `rss_peak_mib`         | `/proc/<pid>/stat` RSS summed over the server's process tree (the Corsa/tsgo children included), every 50 ms      | maximum over runs                                  |
| `rss_idle_mib`         | the same tree RSS at the end of the idle window                                                                   | maximum over runs                                  |
| `idle_cpu_pct`         | utime+stime+cutime+cstime of the tree across a 60 s idle window after the last publish, ÷ wall time               | maximum over runs                                  |
| `server_binary_mib`    | size of the measured server binary                                                                                | file size                                          |

The keystroke oracle is exact: each edit's latency ends at the publish whose
`version` is that edit's and whose diagnostics contain that edit's own type
error, so an early lint-only publish or a stale type result never ends the
clock.

## Ratchet

Every metric entry records `baseline` (the measurement), `ceiling` (the
gate), `headroom` and `ceiling <= ceil(baseline × (1 + headroom))`, plus its
unit, statistic and sampler; every preset's `methodology` table records machine, project, server
build, the exact command, run count, date and the Actions run it came from.
`--validate` rejects a bare number or a missing methodology field, `--ratchet
<base>` rejects a raised ceiling or headroom and a dropped metric or preset,
and `--check --measurement <json>` fails on any pinned metric over its ceiling
or not measured. `tests/tooling/davinci-resource-budgets.test.ts` proves each
rejection on injected mutations of the committed file.

## Numbers

Recorded on the reference runner (`blacksmith-32vcpu-ubuntu-2404`) by
[Actions run 35640713079](https://github.com/ubugeeei-prod/vize/actions/runs/35640713079)
(3 runs × 20 keystrokes, 60 s idle window, `ci-opt` server); pinned in
`[resource.linux-x64-ci]` of [`budgets.toml`](../budgets.toml):

| Metric                 | Per-run samples        | Baseline | Headroom | Ceiling |
| ---------------------- | ---------------------- | -------- | -------- | ------- |
| `cold_start_ms`        | 4.1, 4.1, 3.1          | 4.1      | 1.0      | 9       |
| `first_diagnostics_ms` | 1119.6, 1118.4, 1118.0 | 1118.4   | 0.25     | 1398    |
| `keystroke_p95_ms`     | 60 samples, 22.3–31.8  | 30.1     | 0.5      | 46      |
| `rss_peak_mib`         | 281.9, 277.4, 292.3    | 292.3    | 0.15     | 337     |
| `rss_idle_mib`         | 271.2, 274.5, 258.3    | 274.5    | 0.15     | 316     |
| `idle_cpu_pct`         | 0.117, 0.100, 0.217    | 0.217    | 1.0      | 1       |
| `server_binary_mib`    | 56.0                   | 56.0     | 0.05     | 59      |

Observations the numbers carry: the resident tree is three processes (the
server and its Corsa/tsgo children) holding ~260–290 MiB for a nine-file
project; the first type diagnostics take ~1.1 s in all three runs
(Corsa start-up dominates, see P5-8); a keystroke's type-checked publish
lands in 22–32 ms; idle CPU stays near 0.1–0.2 %. The measurement JSON is
the `resource-linux-x64-ci` artifact of that run.
