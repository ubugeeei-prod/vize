# P4-1a — Fact API core

**`vize_davinci::fact` lands the one typed query surface of charter #5/#8:
fact groups as const data, static demand declarations, a stratified registry
checked at compile time, a `FactManager` that computes exactly the demanded
closure once per artifact, and the TS-35 undeclared-access detector.
Landed 2026-09-22.**

## Boundary

The API exists and is proven by fixtures; nothing in the tree consumes it
yet (TS-11 empty by construction). Tracker migrations are P4-3a…P4-3f,
α/β serialization is P4-2, and invalidation after a pass plus the
recompute-and-compare mode are P4-1b.

## Decisions

| subject        | decision                                                                                                                                                                                                                                     |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Identity       | `FactGroup::ID` is a pass-manager `AnalysisId`; `Demand` is the same 64-bit mask shape as `Preserved`, so `Demand::surviving(Preserved)` is the P4-1b bridge. One identity space, capped by `MAX_ANALYSES` and its assertion.                |
| Group shape    | `trait FactGroup: Sized + 'static { ID, NAME, STRATUM, DEPENDS, Key: Ord, Value; DESC }`; `NAME` added over the contract so errors and dumps name groups.                                                                                    |
| Stratification | `check_strata(&[GroupDesc]) -> Result<(), StrataError>` is a `const fn`; `FactRegistry::new` panics on any error, so a `const` registry that breaks it is E0080. Self-, same- and upward edges are all `NotStrictlyLower`.                   |
| Producers      | `FactProducer<A>::produce(&A, &FactView) -> FactTable<Self>`; the registry stores one function pointer per group (per pipeline, never per node — guardrail 1). A producer's view is declared with its own `DEPENDS`.                         |
| Manager        | Closure to a fixpoint, unregistered demand refused before anything runs, stratum order with registration order inside a stratum, each group at most once per manager (= per artifact). Tables are `Send + Sync` erased boxes.                |
| Tables         | `FactTable<G>` is a key-sorted `Vec` (binary-search reads, key-ordered iteration for folio/α, no hashing); `FactTableBuilder` keeps the last insert per key. Registered in the storage ledger as `analysis`.                                 |
| Detector       | Debug builds: `FactView` carries consumer name + demand; an undeclared read returns `FactError::Undeclared { consumer, group }` and bumps `undeclared_accesses()` even when the table exists. Release: `Declared` is a ZST (const-asserted). |
| Counters       | Process-global `produced_count(AnalysisId)` and `undeclared_accesses()` (`AtomicU64`, `no_std`); tests that read them serialize on a fixture lock.                                                                                           |
| Errors         | `FactError::{Undeclared, Unregistered, NotComputed, TypeMismatch}`, each naming the group, so every test compares the exact value.                                                                                                           |

## Mechanical witnesses

- `cargo test -p vize_davinci --test fact_demand --test fact_manager` (TS-35
  is the first: zero undeclared accesses for declared consumers, the exact
  refusal for a consumer and for a producer reading outside `DEPENDS`, and
  the exact `StrataError` for every violation class)
- `cargo test -p vize_davinci --doc` — the two `compile_fail,E0080`
  stratification doctests on `FactRegistry` (same-stratum edge; the upward
  half of a would-be cycle) plus the passing registry example on `fact`
- `cargo test -p vize_davinci` (TS-1); `rust-script tools/commands/davinci/assertion-lint.rs` (TS-13)
- `cargo build -p vize_davinci --lib --target wasm32-wasip2` with and without
  `--no-default-features` (TS-24); `cargo build --release -p vize_davinci --lib`
  evaluates the release ZST assertion
- `node --test tests/tooling/davinci-storage-policy.test.ts tests/tooling/davinci-module-layout.test.ts tests/tooling/davinci-portability-lane.test.ts tests/tooling/davinci-phase4-contract-status.test.ts`

## Follow-up

P4-1b wires the manager to the pass manager (`after_pass` invalidation,
named preservation groups, the verify observer and its bench pair). P4-2
adds the α form beside `FactTable`. P4-3 waves register real producers and
switch consumers from struct-field reads to demands.
