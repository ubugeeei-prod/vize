# P4-6a — Precision tiers and the error-witness law as types

**`vize_davinci::diagnostic` makes `assurance.md`'s verdict rules types: an
error diagnostic is constructible only with a non-empty witness chain or a
declared, counted exemption; a heuristic rule declaring error severity does
not compile; and the exemption inventory is derived from the source and can
only shrink. Landed 2026-09-22.**

## Boundary

The law is enforced by construction for every producer of the unified
channel. Nothing re-checks a witness yet (P4-6b's verifier), Patina is not on
the channel yet (P4-6c), and no renderer shows witnesses yet (P4-14c). The
one producer on the channel today, `vize_s1_to_s2`, reports its compile
errors under five declared exemptions; no diagnostic changed a byte of
message, span or stage.

## Decisions

| subject       | decision                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| ------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Error law     | `Diagnostic`'s `severity` and `witness` are private. `Diagnostic::new` takes `Advisory { Warning, Info, Hint }`; `Severity::Error` is reachable only through `Diagnostic::proven(stage, span, message, WitnessChain)` or `Diagnostic::legacy_error(&'static Exemption, ..)`. Readers use `severity()`, `witness()`, `witness_chain()`, `exemption()`.                                                                                    |
| Retired       | P2-1's `satisfies_witness_law()` predicate: the law now holds by construction, and `exemption()` is what a runtime inventory counts.                                                                                                                                                                                                                                                                                                     |
| Witness       | `Witness::{Proven(WitnessChain), LegacyExempt(&'static Exemption)}`. `WitnessChain` is a boxed slice of `WitnessLink { group: AnalysisId, span, key: WitnessKey }` whose constructors take a first link or refuse an empty list, so an empty proof is unrepresentable.                                                                                                                                                                   |
| Keys          | `WitnessKey::{Artifact, Node(NodeId), Index(u32), Name(String)}` erases a fact group's typed key; `WitnessKeyed` round-trips `()`, `NodeId`, `u32` and `String` (the P4-6b verifier reads a link back into the group's key).                                                                                                                                                                                                             |
| Size          | `Diagnostic` stays 88 bytes and `Option<Witness>` 24 (const-asserted): a boxed-slice chain is 16 bytes and an exemption is one `&'static` pointer — the P2-1 note's "boxed rather than inlined" honoured.                                                                                                                                                                                                                                |
| Tiers         | `Tier { Exact, Sound, Complete, Heuristic }` with stable spellings, `admits(Severity)`, `no_false_positives()`/`no_false_negatives()`. `Domain::new(&'static str)` rejects an empty statement. `RuleContract::new(tier, domain, severity)` is a `const fn` that panics on a heuristic error, so a `const`/`static` contract fails with E0080.                                                                                            |
| Configuration | `RuleContract::clamp(configured)` returns `Warning` for a severity the tier does not admit: user configuration cannot promote a heuristic finding into a proof (the P4-6c adoption path).                                                                                                                                                                                                                                                |
| Verdict axis  | P3-2's `Verdict { Proven, Refuted, Unknown }` moved from `vize_impeto::lattice` to `vize_davinci::diagnostic::Verdict`; the lattice re-exports it with its folio spellings unchanged, so the lattice and the witness verifier share one axis.                                                                                                                                                                                            |
| Exemptions    | `Exemption::new(producer, code)` is a `const fn` over `[a-z0-9_./-]` names, neither `Clone` nor `Copy`, used by `&'static` reference to a named `static`.                                                                                                                                                                                                                                                                                |
| Inventory     | `witness-exemptions.tsv` (`producer`, `code`, `exempt`) is derived mechanically: every `Exemption::new` in `crates/*/src` must be a named static whose producer is its crate, and `exempt` counts its `&NAME` construction sites. The checker fails on drift, on an unused declaration, and on any count rising against the base revision.                                                                                               |
| Onboarding    | A producer absent from the base inventory may enter with its legacy errors (P4-6c's Patina rows); a producer already on the channel cannot gain a code. The phase-4 exit gate is the inventory at zero rows.                                                                                                                                                                                                                             |
| Extension ABI | P6-1a's WIT 0.1 mirror (`vize_extension_host`) carries an error's exemption as `legacy-exempt("producer/code")`; a declared in-tree exemption converts back to the same `static`, so the built-in Vue guest round-trips exactly (its `recovery` golden gains the four witness lines), and any other guest error reports under `vize_extension_host/guest-error`. A proof chain has no WIT 0.1 shape yet and crosses without its witness. |

## The canaries

- `compile_fail` on `vize_davinci::diagnostic`: `Diagnostic::new(Severity::Error, ..)` (the provisional "error-on-unknown fails to compile"), and a struct literal forging `severity: Severity::Error, witness: None`.
- `compile_fail` on `vize_davinci::diagnostic::tier`: `static CANARY: RuleContract = RuleContract::new(Tier::Heuristic, .., Severity::Error)`.
- Stable rustdoc does not check a `compile_fail` error code, so each canary has a passing twin doctest identical but for the violating token. Flipping each canary to its twin was run locally and made both doctests fail as "compiled successfully" — the failure is pinned to the intended construct.

## Mechanical witnesses

- `cargo test -p vize_davinci --test witness_law --test witness_tiers` — constructors, accessors, chain non-emptiness, key round trips, and the exact tier × severity, clamp and spelling tables; runtime panics of the const assertions pinned to their exact messages
- `cargo test -p vize_davinci --doc` — the three `compile_fail` canaries and their passing twins
- `cargo test -p vize_davinci -p vize_s1_to_s2 -p vize_impeto` (TS-1); the cached `assertion-lint` build (TS-13)
- `cargo build -p vize_davinci -p vize_s1 -p vize_s2 -p vize_impeto -p vize_s1_to_s2 -p vize_s2_to_s3 --lib --target wasm32-wasip2`, with and without `--no-default-features` (TS-24)
- `node --test tests/tooling/davinci-witness-exemptions.test.ts` — the committed inventory equals the derived one; no count rises against the base revision; an injected increase (and a new code for a known producer) is rejected with the exact violation, both as a pure comparison and against a real base commit in a scratch repository
- `node --test tests/tooling/davinci-storage-policy.test.ts tests/tooling/davinci-phase4-contract-status.test.ts`

## Follow-up

P4-6b adds `vize_davinci::witness::verify` over the fact API (`WitnessLink::of::<G: FactGroup>` sugar belongs there, beside P4-1a's `FactGroup`), the forged-witness fixtures and the TS-36 command. P4-6c puts Patina on the channel: `rule_contracts.rs` declares one `RuleContract` per rule, error-default rules without witnesses enter this inventory as Patina's onboarding rows, and output spans move onto the S0 frame (FP-1).
