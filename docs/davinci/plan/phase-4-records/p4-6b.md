# P4-6b — Witness verifier

**`vize_davinci::witness::verify` re-checks every link of a diagnostic's
witness chain against the fact base through the producer's own fact view,
and `WitnessAudit` runs it over every diagnostic a producer emits in debug
and CI builds (a zero-sized no-op in release). Every forged-witness fixture
is rejected with its exact `WitnessError`; every valid witness verifies.
Landed 2026-09-22.**

## Boundary

The verifier and its observer are complete and proven on fixtures. No
producer emits a `Diagnostic::proven` chain yet — the one producer on the
channel (`vize_s1_to_s2`) reports under exemptions, and Patina joins in
P4-6c without chains — so TS-36 over the TS-9 lint fixtures holds **vacuously**
today (zero chains, zero unverifiable). It becomes load-bearing when the
P4-8 waves emit the first rule witnesses; the phase-4 exit gate's TS-36 line
is evaluated then.

## Decisions

| subject     | decision                                                                                                                                                                                                                                                                |
| ----------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Entry point | `verify(&Diagnostic, &FactView, &WitnessChecks)`: the view is the **producer's**, so a witness citing a group outside its producer's demand trips the TS-35 detector. `verify_as::<C>(&Diagnostic, &FactManager, &WitnessChecks)` is the contract's `FactManager` form. |
| Link law    | A link verifies when its group has a registered check, the view reads the group, the key has the group's shape, a fact is stored under it, the fact's span equals the link's, and the fact's verdict is proven — in that order; the first failure is the result.        |
| Capability  | `trait WitnessGroup: FactGroup<Key: WitnessKeyed> { fn fact_span(&Key, &Value) -> Span; fn verdict(&Value) -> Verdict { Proven } }`: a group backs witnesses only by stating where each fact is and whether it is proved.                                               |
| Registry    | `WitnessChecks::new(&'static [WitnessCheck])` is const and rejects a repeated group at compile time (a `compile_fail` doctest with a passing twin); dispatch is one monomorphized function pointer per link.                                                            |
| Errors      | `WitnessError::{UnknownGroup, Fact(FactError), KeyShape, MissingKey, SpanMismatch, NotProven}`, each carrying the link index and the disagreeing values.                                                                                                                |
| Chains only | A legacy-exempt error has no chain and verifies trivially — the inventory counts it; an advisory's "why" chain is checked like a proof.                                                                                                                                 |
| Observer    | `WitnessAudit::audit(&[Diagnostic], &FactView, &WitnessChecks)` keeps observed/verified/exempt counts and exact failures (with the diagnostic's ordinal) and bumps the process-global `unverifiable_witnesses()`; in release it is a ZST (const-asserted) and a no-op.  |
| Typed links | `WitnessLink::of::<G>(&G::Key, span)` builds a link from a group's typed key, so id and key shape cannot disagree with the cited table.                                                                                                                                 |

## Forged-witness fixtures

`crates/vize_davinci/tests/witness_verify/`, over a `str` artifact with four
witness-capable groups (`words`, `repeats`, `sentence`, `hidden`) and one
that is not (`lengths`):

| forgery                                     | exact error                                                                              |
| ------------------------------------------- | ---------------------------------------------------------------------------------------- |
| a group that cannot back a witness          | `UnknownGroup { link: 0, group: lengths }`                                               |
| the repeat fact cited under the words group | `KeyShape { link: 0, group: words, key: Name("the") }`                                   |
| the first `the` cited at the second's span  | `SpanMismatch { link: 0, group: words, fact: 0..3, witness: 12..15 }`                    |
| a word index past the sentence              | `MissingKey { link: 0, group: words, key: Index(99) }`                                   |
| a single word cited as a repeat             | `MissingKey { link: 0, group: repeats, key: Name("cat") }`                               |
| a maybe cited as a proof                    | `NotProven { link: 0, group: words, verdict: Unknown }`                                  |
| a group outside the producer's demand       | `Fact(Undeclared { consumer: "repeated-word", group: hidden })` (release: `NotComputed`) |
| a view taken before the run computed        | `Fact(NotComputed { group: words })`                                                     |
| a valid chain plus a wrong-span fourth link | `SpanMismatch { link: 3, group: sentence, .. }`                                          |

The fixture rule fires on proof only (a repeat whose first occurrence is a
maybe stays silent) and its one error's three-link witness verifies, through
the view and through `verify_as`.
