# P2-8 — S1→S2 Vue lowering

**The total lowering function, with provenance and a fuzz lane. Landed
2026-08-21; every locally-evaluable acceptance clause met, the
corpus-widened lane run read-only against the main checkout's hydrated
fixtures (12,215/12,215, zero failures — honest label below), and one
machine constraint (cargo-fuzz cannot run here) split explicitly into
what ran locally versus what CI covers.**

## The home: `vize_s1_to_s2`, a conversion crate (the decision)

The contract left the home open — `vize_s2`? a module in
`vize_sinopia`? a new crate? — to be decided by dependency direction.
What landed is **`crates/vize_s1_to_s2/`** (a _ricalco_ is the tracing
that transfers a drawing onto a new surface), `publish = false`,
experimental, `no_std + alloc`, depending downward on both stages plus
`vize_carton`/`vize_davinci`/`oxc_ast`. The MLIR conversion-library
shape, chosen against both alternatives on the direction rule:

- **Not in `vize_s2`:** the neutral pivot would depend on the Vue
  S1 surface — exactly "S2 depending on S1's internals needlessly" —
  and drag `vize_armature` + `vize_relief` into the **required** TS-24
  wasm lane, which is pinned to exactly the two claim crates
  (`tests/tooling/davinci-portability-lane.test.ts`). JSX (P2-16) and
  pug (phase 4) lower into the same family; per-dialect conversions
  stay outside the pivot.
- **Not in `vize_sinopia`:** the lossless record crate would grow
  semantic decisions and an oxc-parser edge; P2-7's whole design is
  that S1 records what was written and nothing else.

**The TS-11 reading, stated rather than assumed:** with the lowering
landed, `cargo tree -i vize_s2` and `-i vize_sinopia` are no
longer bare — each lists exactly `vize_s1_to_s2`, and
`cargo tree -i vize_s1_to_s2` lists only itself. Every crate in those
inverse trees is `publish = false` experimental, so no shipped compile
path can observe any of this and no output byte can move; the corpus
diff is empty by the same mechanical argument every additive Davinci
task has used. The release gate's rule (published crates cannot depend
on deferred ones) is untouched: nothing published gained an edge.

## Totality: what "S2 or a diagnostic" means concretely

`lower(allocator, &tree, &errors) -> Lowered` never panics, never
rolls back, and populates four channels on every input: the op tree
(kept fragments included), diagnostics, provenance, hygiene scopes.

- **Structure lowered:** elements/components (component iff
  `!is_native_tag`, the carton table), text and interpolations
  (verbatim; the total P2-5b admission per expression position), `v-if`
  sibling chains grouped into one region-owning `ui.if` at lowering
  (the sibling mutation the region design exists to end), `v-for` as
  `ui.for` (below), `<slot>` outlets with the implicit name normalized
  to `"default"`, `v-model` to the `ui.model` contract (read and write
  share the authored payload; element kind, static argument and
  modifiers ride as synthesized attributes carrying the binding's
  span), custom directives as `vue.directive` verbatim.
- **Unmappable is a diagnostic plus a kept fragment, never a new op**
  (the canary is P2-9's to break): `v-bind`/`v-on`/`v-html`/`v-text`/
  `v-show`/`v-cloak`/`v-once`/`v-memo`/`v-pre`, `v-slot` grouping,
  slot props, and `v-model` with a dynamic argument each defer with an
  **`Info`** diagnostic and a `defer.*` provenance record. Info, not
  error, by the no-error-on-maybe doctrine: the input is not wrong —
  the stage is younger than the construct, and the message says which
  task closes the gap (P2-9).
- **Grammar violations are `Error`s with relief's exact message
  text** (`ErrorCode::message`, so the two channels never drift on
  wording): orphan `v-else`/`v-else-if`, missing `v-if`/`v-for`/
  `v-model` expressions, malformed `v-for`, custom directives on slot
  outlets. The fragment is still lowered — an orphan `v-else` keeps
  its element, a malformed `v-for` keeps its op and region.
- **The P2-7 hand-off, both halves:** the tokenizer's `SurfaceError`s
  enter the unified channel as `Stage::Surface` errors (code message,
  zero-width span at the reported offset), and — a finding, not a
  plan item — **the tokenizer never reports a missing end tag** (tag
  matching is tree construction, not lexing), so `<div><span>x</div>`
  arrived with zero diagnostics. The lowering therefore renders the
  `ElementClose::Missing` hole into the channel itself
  (`Cx::report_missing_close`, relief's exact `MissingEndTag` text,
  span on the open tag), at one chokepoint per lowered element plus
  the two template-unwrap sites. EOF-in-tag inputs now carry both the
  tokenizer's EOF error and the missing-end-tag — over-reporting
  accepted and recorded, silence not.
- **Dropping is never silent:** comments, processing instructions,
  `Unexpected` holes, chain gaps, and attributes on an unwrapped
  `<template>` wrapper each leave a `drop.*` provenance record (the
  wrapper attributes additionally an Info diagnostic); CDATA lowers
  its inner bytes as `ui.text` (the foreign-namespace reading). No
  _new_ diagnostic accompanies drops the tokenizer already reported.

## The admission-rule deviation (owned)

P2-5b's `expr/js.rs` docs said "Lowerings (P2-8) never parse — they
receive armature's retained ASTs". That expectation predates P2-7's
measurement: the S1 that actually landed is **token-level** and
retains no ASTs. So the lowering is where a template expression first
parses on the Davinci lane — through `ExprRef::parse_js_in`, the one
shared home of the guard → parse → whole-coverage rule, never a
private variant. The js.rs docs are amended in this PR. The counter
decision goes with it: `parse_in` still does not increment
`davinci.expr.parses` — the P1-5 law is a statement about the shipped
compile path, this lane runs beside it (counting would double-count
any file both see), and the lane's counter story lands when the lane
_becomes_ the compile path (P2-12b). TS-26 is untouched;
`vize_armature`'s pin still passes.

## v-for: consuming the P2-5b decision

The split is Vue's text grammar — the shipped splitter's
`find_for_separator` / strict `split_for_aliases` ported into
`lower/vfor.rs` (strict only; the `template_syntax_quirks` compat path
deliberately not offered) — applied **before** any parse, then each
sub-slice admitted through the shared rule. `a in b in c` is pinned:
alias `js("a")`, source `js("b in c")` — the retained-AST reading
`(a in b) in c` never happens because no whole-value parse exists.

`OpaqueReason::ForValue` gets its two producers, both pessimal:

- **The unsplittable whole** (`v-for="items"`): the value rides whole
  as `opaque(for-value)` in the source position, a zero-width escape
  in the value position, `Error` beside it, op and region kept.
- **The absent alias** (`v-for=" in xs"` — valid Vue): the value
  position exists grammatically with no authored text; a zero-width
  `opaque(for-value)` at the alias's location.

One divergence was caught by measurement during landing and fixed:
the first cut trimmed the value before splitting, which made
`v-for=" in xs"` _malformed_ — the shipped splitter runs over the
**untrimmed** value, where the leading whitespace makes the separator
viable and the alias legitimately empty. The landed split runs
untrimmed, matching both the shipped splitter and upstream's
`forAliasRE`. `MultiStatement` and `Compound` have **no P2-8
producer**: v-on bodies land with `ui.on` (P2-9) and compound
text-merging with `transform_text`'s port (P2-9); the reasons stay
reachable only through the folio spellings until then.

## Hygiene scope tags (design, and what P2-8 does not synthesize)

`vize_s2::scope` — neutral S2 vocabulary, shared by every later
dialect lowering: `ScopeTag` (dense per artifact, minted by the
lowering), `ScopeBinding { name, origin }` with
`ScopeOrigin::{Authored{span}, Synthesized{rule}}`, in a
`SideTable<ScopeFacts>` keyed by the introducing op's page-order
`NodeId`. Identity is `(name, tag)`; a later pass minting a name must
mint a fresh tag and record `Synthesized` — the discipline that makes
capture impossible is written at the type, and the
"synthesized-never-equals-authored" law is pinned by test.

Two honest boundaries, both recorded rather than smoothed over:

1. **P2-8's own lowering synthesizes no names.** The contract's
   examples (slot props, v-for scopes) are introduction _sites_; at
   this stage their names are authored or absent, and inventing one
   for an absent alias would be realization, not semantics — the
   absent position is the zero-width `ForValue` escape instead. The
   `Synthesized` origin is exercised at the type level and waits for
   its first real producer (P2-9's slot normalization).
2. **Pattern names are not enumerated.** A destructuring alias
   (`({ a, b }, i) in xs`) records the scope, the tag, and the simple
   identifiers only (`i`); the names inside the pattern wait for the
   one identifier-extraction home,
   `ExprDialect::enumerate_bindings` (#4365) — a second ad-hoc scanner
   here would recreate the P1-8 split that waiver exists to end.

Slot-props scopes are recorded today even though the grouping op is
deferred: `#head="props"` mints a tag on the carrying element's op
with the `props` binding (pinned), so the LSP has the fact before the
op family can express the region.

## Provenance (the survival law, materialized)

`vize_s2::provenance::ProvenanceRecord { rule, node, before,
after, span }` — owned, `'static`-asserted like `Diagnostic`, one per
decision in decision order. The survival law holds in both directions:
a decision that produced no op is still a record (`node: None`, empty
`after` — deferrals, drops, orphan directives), and on error the
produced fragments keep their records with live `node` links. The
rule vocabulary is closed and pinned by the suites: `lower.*` (nine
producers), `defer.*` (twelve), `drop.*` (six), `error.*` (six).
P2-8 materializes fully — every decision, owned text — and the
ring-buffer/off decision for the fused walk stays P2-12b's, as the
P2-3 record already scoped.

## Page-order ids: the accounting law

The arena ops carry no id field; identity is positional
(`folio-format.md` "Node numbering"). `Cx::mint_op` therefore mints in
**print order** during the walk — op line, attached bindings, then
children; a `ui.for` wrap before the element it wraps — and the law
`Lowered::op_count == DisegnoFolio::of(root).op_count()` is asserted
on every input every suite touches, so scope and provenance keys
resolve by construction (`verify_table` empty is part of the oracle).
Id exhaustion is a diagnostic, not a panic, per the `NodeId` contract.

## v1 scope, recorded (each a deliberate non-goal here)

- **No whitespace condensing, no entity decoding**: text and attribute
  values lower verbatim; both are `transform_text`/element-transform
  ports (P2-9). Entity-bearing expression text can therefore land as
  `Opaque(ParseRejected)` — total, pessimal, and honest until the
  decode moves in.
- **No implied-end-tag reconciliation**: `<li>a<li>b` lowers nested,
  exactly as S1 records it (the battery's `sibling_li_nests_v1` pin);
  reconciling against the shipping parser's tree is the differential
  lane's job when a comparator exists (P2-9/P2-11).
- **Namespace by inheritance only**: `svg`/`math` enter, the
  integration points (`foreignObject`/`desc`/`title`;
  `mi`/`mo`/`mn`/`ms`/`mtext`) return children to HTML; the full HTML
  tree-construction rules are not replicated.
- Duplicate attributes are kept (the tokenizer already diagnosed);
  `v-else` values are ignored; extra v-for aliases beyond three are
  ignored; `.prop`-shorthand deferral does not inject a `prop`
  modifier; a second structural directive on one element is ignored
  under `drop.structural-duplicate` + Info.
