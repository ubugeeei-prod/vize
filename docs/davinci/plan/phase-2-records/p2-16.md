# P2-16 — JSX lowering re-targets S2

**Completed 2026-09-08** through
[#5927](https://github.com/ubugeeei-prod/vize/pull/5927). This record closes
the task-level ledger now that the admitted JSX VDOM path is S2-first and the
fallback cases are explicit.

## What Landed

- `lower_source` now returns each `LoweredRoot` with an authoritative
  `s2: Result<JsxS2Root, S2Refusal>` beside the legacy `RootNode`.
- `compile_root_to_vdom` attempts `try_emit_s2_vdom` before the Relief
  transform/codegen path, so admitted JSX VDOM roots use S2. The legacy root
  remains for Patina, source-map requests, Babel-specific compatibility
  options, and explicit S2 refusals.
- The admitted S2 family covers elements, fragments, text, interpolations,
  dynamic binds/spreads, event bindings/modifiers, components, dynamic
  components, default/paramless/scoped slots, `v-show`, `v-html`, `v-text`, TSX
  roots, component `v-model`, native input/textarea/select model families,
  model modifiers, control-flow children, and scoped styles.
- Babel-compat options that intentionally change VDOM semantics keep fallback
  tests instead of pretending S2 covers them.

## Decisions

- The `MarkupDocument::from_jsx` bypass does not disappear in P2-16, because
  the mode-aware JSX compiler already has a lower-level root path. The fairness
  measurement is that VDOM no longer re-enters Relief for admitted roots; it is
  not the deletion of every Relief consumer.
- Keeping `LoweredRoot::root` is deliberate. Patina still consumes Relief until
  phase 4, and unsupported Babel/source-map cases need explicit fallback rather
  than silent partial S2 lowering.

## Left Open
