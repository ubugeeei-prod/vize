# P2-2 — Pass manager

**Pass manager. Landed 2026-08-19; every acceptance clause met, both laws
enforced as compile errors and both proven by compiling a violation.**

### Guardrail 1 is what shapes the design

`architecture.md`'s first performance guardrail is that dispatch is resolved
**per pipeline, never per node**. That rules out the obvious design — a
registry of `Box<dyn Pass>` looked up while walking — so a pass is a
`PassDesc`: a 32-byte `Copy` struct of one `&'static str`, two one-byte tags
and an 8-byte preserved mask. A `Pipeline` is that plus a `&'static
[PassDesc]`. Nothing allocates, nothing is dynamically dispatched.

The consequence worth stating twice: **every planning query is a `const fn`** —
`group_count`, `group`, `group_of_pass`, `is_fully_serialized`,
`Preserved::intersect`. A fusion plan can therefore be pinned in a `const`
item, which makes a grouping regression a compile error rather than a runtime
surprise nobody notices. The fixture pipeline's boundaries are pinned exactly
that way.

### The two laws, and proving them

**Law 1 — a mandatory pass is an unfusable barrier.** `PassDesc::new` is a
`const fn` that asserts it. Descriptions are declared as `const DESC` items, so
the illegal combination cannot be written. Compiling
`PassDesc::new("bad", PassKind::MandatoryLowering, Fusability::Fusable,
Preserved::NONE)` gives:

```text
error[E0080]: evaluation panicked: a mandatory pass must be a barrier: it
either needs whole-tree facts or establishes an invariant the next pass reads,
and fusion breaks both
```

**Law 2 — only a mandatory pass canonicalizes.** `Canonical`'s field is
private and its only constructor is `produce::<P>`, which forces
`MandatoryCheck::<P>::PROOF`, an associated `const` whose body asserts
`P::DESC.kind.is_mandatory()`. Associated consts are evaluated per
monomorphization, so an optional pass calling `produce` is a compile error.
Compiling it gives:

```text
error[E0080]: evaluation panicked: only a mandatory pass may perform the raw ->
canonical transition
note: the above error was encountered while instantiating
`fn Canonical::<u8>::produce::<Optimizer>`
```

Both were **compiled, not assumed** (the P0-7 rule). Neither is a standing
regression test, because the workspace has no compile-fail harness — there is
no `trybuild` dependency anywhere in it. Adding one is a workspace-wide
decision rather than this task's, so the gap is named in `canonical.rs`'s own
comment and here, and the exact rustc output is recorded above so a future
change to either message is visibly a change.

**Why a marker type rather than a `MandatoryPass` trait.** A trait would be one
more thing to implement correctly, and an incorrect implementation would only
be caught if something happened to use it. With the check hanging off a private
marker there is nothing to implement: every pass that reaches the transition is
checked by reaching it.

### Fusion grouping

Walk the passes and start a new group when either the current pass or the
previous one is a barrier — so a barrier always sits alone, joining neither the
run before it nor the run after it. "A mandatory pass never joins a fusion
group" is then a **consequence** of law 1 plus that rule, rather than a second
check that could disagree with the first. The canary proves it over five
arrangements (barrier first, middle, last, two barriers, one barrier alone)
rather than one, so a rule that only held in the middle of a pipeline would
fail.

A group's preserved set is the **intersection** of its members': fusing cannot
preserve more than the least-preserving member does. Passes declare what they
**preserve**, never what they invalidate, because the safe default has to be
the conservative one — a pass that says nothing preserves nothing, so
forgetting to update a declaration costs a recomputation, never a stale fact.
`Preserved` is a `u64` mask over `AnalysisId`s that their owning crates
declare; `MAX_ANALYSES = 64` is asserted against `u64::BITS`, so widening it is
a compile error rather than a silent truncation.

### The pipeline grammar

`s2(normalize,fold),s2-to-s3(lower)` — lowercase kebab-case identifiers, **no
whitespace anywhere**. That is not terseness: with optional whitespace,
`print(parse(s)) == s` would hold for one spelling and fail for the others, and
the round-trip law would have to be stated over an equivalence class instead of
over bytes. An empty pass list (`s2()`) is legal, because a bisecting
`--pipeline` needs to be able to say it.

Ten rejections are documented as a table in the module docs and asserted on
their **full rendered message and variant** — no substring matching (assurance
§4, TS-13). The whitespace cases are pinned by variant and offset too, not by
`is_err()`: which production rejects the space is part of the contract, and a
rejection that moved to a different rule would still pass a bare `is_err()`.

Parsing yields `PipelineSpec` — borrowed stage and pass **names**, not
`PassDesc`s. Resolving a name to a description needs a catalogue of the passes
that exist, and none exist until P2-9, so binding is the caller's step and
`davinci-opt --pipeline` (P2-4) is where the two meet.

### Naming, and TS-13 at the source

`Preserved::preserves(analysis)`, not `contains`. The set is named for what it
keeps, so `preserves` is the question callers actually ask — and it clears
TS-13's `contains` finding **at the source**, which is the only acceptable
resolution: the allowlist's own header says new test code must never be added
to it. The same reasoning renamed P2-1's `SideTable::contains_id`.
