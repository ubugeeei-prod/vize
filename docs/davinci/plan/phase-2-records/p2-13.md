# P2-13 — Folio-after-change, `vize repro`, timing JSON

**The ICE policy made real (charter #30) plus the per-pass dump controls.
Landed 2026-08-20; every acceptance clause met, with the honesty decisions
and profile constraints itemized below.**

## What a crash is now, on the compile path

A panic during a batch build **fails that file and writes its reproducer** —
`{output}/{stem}.repro.folio` — while every other file compiles and emits
normally; charter #26's no-auto-fallback rule holds because the ICE'd file
emits nothing but its repro. The guard wraps the per-file compile
(`build/runner/compile.rs`), so the property is per-file by construction,
and TS-23 pins it as an **exact file set**: a three-file batch with one
injected panic produces exactly `{a.js, b.repro.folio, c.js}`.

The repro is a new hand-written folio page (`[repro]`,
`crates/vize_davinci/src/folio/repro.rs`, grammar in
[`folio-format.md`](../folio-format.md) § "The repro page"): pipeline string
(validated against the P2-2 grammar at parse time), replay config as a
sorted map, the recorded failure, and the last-good stage dump in a
**verbatim, terminal** artifact section — the only way to embed an
arbitrary dump without an escaping scheme, and the semantic decision that
keeps this page off the derive. Until P2-12b routes the compile path
through the pass manager, the last good stage **is the authored source**
(`artifact-stage=source`), and the page says so instead of pretending an
S2 dump exists.

## Attribution: exact or stated-unknown, never guessed

The TS-23 injection (`vize build --davinci-inject-panic <stem>:<pass>`,
hidden flag, validated against the plan so an injection that could never
fire is an argument error) drives the legacy-plan pipeline through
`run_pipeline` with a step that records the stage and pass it is entering
before it can panic — so the caught failure names the pass exactly. A panic
in the **real** compile is not attributable (the real stages do not run
through the driver yet) and is recorded with an empty `failed-pass`,
rendered `template.?: …`. One formatter (`repro::failure_text`) renders
every failure everywhere, so "the same failure" is the same bytes.

`vize repro <file>` is the new command the re-cut promised
(`crates/vize/src/commands/repro.rs`, `Repro` variant, module declaration).
It replays — an injected repro re-drives the pipeline and re-derives the
panic from the injection spec (not from the recorded text, which would be
circular); a real-ICE repro re-compiles the embedded source under the
recorded mode — and compares replayed against recorded by **exact
equality on (stage, pass, reason)**, inside the tool: exit 0 reproduced,
1 diverged or completed, 2 malformed. TS-23 pins all four verdicts with
exact output.

## The dump flags, and where they are honest

`--folio-dir <dir>` / `--folio-after-change` exist on both surfaces the
contract names, with different truth values today:

- **`davinci-opt --pipeline`** dumps real pages: the artifact's canonical
  `Full` text after every pass (`{seq:03}-{stage}.{pass}.folio`), hash-gated
  by `--folio-after-change` to passes whose hash changed — with no-op
  bodies, provably zero pages, and the gate seeds from the input so the
  first pass is compared rather than dumped unconditionally. The mechanism
  (`folio::dump::FolioDump`) is IO-free `no_std + alloc` and hashes the
  canonical text, which the Folio equality laws make interchangeable with
  the value.
- **`vize build`** accepts the same flags, but the compile path has no
  folio-printable stage artifact until P2-12b — so the pinned behavior is
  "directory created, zero pages", asserted by
  `davinci_repro_cli::the_build_folio_dir_is_created_and_stays_empty_until_p2_12b`.
  The P2-14 rule about decorative flags applies: the vacuity is **measured**,
  and P2-12b inherits a flag whose contract already has a test.

## Timing JSON: one producer, one validator

`davinci-opt --timing-json <path>` enables the global profiler, attaches
`Pair<TimingObserver, BudgetObserver>` (one span per fused walk, attributed
`{stage, lead pass}` — the P2-3 law), and writes
`vize_carton::profiler::export_report(...).to_json()` — the P0-11 export
wholesale, `command: "davinci-opt"`, `allocation: null`. Validation reuses
the strict TS-15 subset validator through the normal `davinci_test_support`
dependency. `crates/vize_davinci/tests/davinci_opt_dumps.rs` is only its
consumer, so the tree still has exactly one producer and one validator of
`profile-export.schema.json` documents. The deterministic structure is
pinned exactly: one span, key `davinci.pass.walk`, count 1, attribution
`{stage: "s2", pass: "alpha"}`, empty counters, zero truncation.

## Deviations and recorded constraints

- **`panic = "abort"` in the release profile stands.** Catching is live in
  every unwind build (dev, test, CI — where TS-23 runs); a release binary
  still aborts on panic. Trading the shipped profile's abort strategy for
  ICE recovery is a program decision this task records and does not make.
  The panic-hook silencing is gated on `cfg!(panic = "unwind")` so abort
  builds keep their only report.
- **`--format stats` compiles are not guarded**: they emit no artifacts to
  protect, and the file-scoped property is about emitted files. Status quo
  (a panic aborts the batch) preserved there, stated rather than implied.
- **Repro naming** is `{stem}.repro.folio` under the output dir: two files
  with the same stem in different subdirectories would overwrite; accepted
  until the S2 path gives the repro writer the planned relative path.
- **Real-ICE replay compiles with mode defaults**, not the full build
  settings — the config section captures `mode` and `inject-panic` today.
  Fidelity grows with the config the S2 path actually consumes.
- **`davinci-opt`'s usage string second line grew** the three new flags
  (first line still byte-identical to P0-10); the `davinci_opt_cli.rs` pin
  was updated to match — the same contract-forced shape P2-4 recorded.
- **`vize` now depends on `vize_davinci` normally** — the first CLI
  consumer. Legal where `vize_atelier_core` was not: both crates are
  `publish = false`, so no release graph widens
  (`moonbit-publish-crates` green).
- **TS-23's registry row** named no concrete command ("injected-panic
  test"); the command cell now reads
  `cargo test -p vize --test davinci_repro_cli` per this phase's
  registry-maintenance rule. _From_ and oracle were already correct.
- The wasm32-wasip2 build was **not** re-run here: the lane does not exist
  until P2-14, and the two new library modules are `alloc`-only by
  construction (IO stays in the binaries). P2-4's lane note stands.
