# P2-6 — S2 verifier v1

**The between-pass verifier and the TS-18 invalid-fixture set. Landed
2026-08-20; every acceptance clause met, with the P2-5b liveness seam and
four design decisions the contract left open recorded below.**

## The catalogue, and what "local" bought

Six codes, one page-order walk (`crates/vize_s2/src/verify/walk.rs`),
each check a line plus the facts it and its owner already declare — the
GHC `-dcore-lint` import, no global inference, no fixpoint, no second
traversal per invariant. The catalogue and its exact message shapes are
documented in [`folio-format.md`](../folio-format.md) ("S2 verifier
invariants"), because the format doc is where "canonical" is written down:

- **S2V001/S2V002 (structural)** — span order and region nesting. Spans
  are the redundant declared facts that make region nesting _locally_
  checkable: every nested line (child op, `branch`, binding, `attr`) must
  sit inside its immediate owner's span.
- **S2V003 (structural)** — id resolution. S2 ids are dense and
  page-ordered (`attr`/`branch` lines carry no id), so "every `NodeId` a
  side table references resolves" is a range check against the artifact's
  op count by construction. P2-8's lowering mints ids in this order; the
  rule is now written down for it.
- **S2V004–S2V006 (canonical)** — the `ui.if` form invariants the op type
  deliberately does not encode (`op/control.rs`): at least one branch, a
  conditional leading branch, unconditional only trailing. This is the
  whole canonical set today **on purpose**: an invariant lands with the
  pass that establishes it (P2-9), the same rule the op family applies to
  ops.

**Canonical-form per `PassKind` is rigor tracking, not a per-kind list**:
`Rigor::Raw` until the first `MandatoryLowering` pass — the only kind that
canonicalizes (P2-2's type-level law) — then `Rigor::Canonical` for the
rest of the run; diagnostic and optional passes never change it. Pinned
through a real `run_pipeline` run and through `Pair` composition.

## Liveness: the mechanism reused, and the P2-5b seam

`VerifyObserver::check_live` delegates to `Allocator::assert_stamp_current`
— the P1-11 arena-generation stamp — and stays that mechanism's panic on
purpose; no second liveness mechanism, no re-rendered message. One
artifact-level stamp covers the whole tree today because `ExprSlot` is
zero-sized: there is no per-expression identity to validate. **The seam
for P2-5b (in flight in parallel):** when `ExprRef` gives expression
positions identity (and possibly per-value stamps crossing side tables),
the per-position walk lands inside `check_live`, whose signature —
event, allocator, stamp — already carries what pass attribution needs.
No test here constrains `ExprRef`'s shape.

## "Through the P2-3 observer", applied to hooks that carry no artifact

P2-3's hooks deliberately do not carry the stage artifact, so the verifier
follows the `FolioObserver` precedent exactly: the `PassObserver` impl
does the rigor bookkeeping (`after_pass` → `note`), and the checks
(`check`, `check_table`, `check_live`) are methods the artifact holder
calls — after each pass, or at `is_group_exit` minimum ("after each fused
group minimum", the GHC import). `note` is public because `run_pipeline`
mutably borrows its observer for the whole run: a step body wiring
verification in-line calls `note` then `check` on a verifier it holds
itself, and the trait impl keeps the same object composable through
`Pair` when a future driver passes artifacts through hooks.

Failure is a panic with the aggregated page-order report headed by the
offending pass (`` S2 verifier: {n} violation(s) after `{stage}.{pass}` ``),
asserted on the **whole payload** via `catch_unwind` — not `should_panic`
substring matching — for the tree and table lanes.

## Decisions the contract left open

1. **The walk runs over the owned model** (`DisegnoFolio`), not the arena
   tree: it is the single surface the fixture set and a live tree (via
   `DisegnoFolio::of`, which the folio observer's dump already needs)
   share, and a parallel arena walk is exactly the drift the P1-8 scanner
   split taught. The arena side is covered by the liveness stamp.
2. **`Violation` is not a `Diagnostic`.** The unified channel carries what
   the user must see about their source; a verifier finding is a
   compiler-bug report about an artifact no user wrote ("checks the
   compiler's sanity, not yours") — and it needs the `code` field the
   diagnostic deliberately does not have.
3. **The release-shape assertion reuses the P2-3 bench rather than adding
   one.** The cfg shape is const-asserted in both profiles (debug: 1 byte
   of rigor; release: ZST — `cargo build -p vize_s2 --release`
   compiles the release assert) and the check bodies are cfg-empty, so the
   release observer _is_ the `NoObserver` shape whose zero cost P2-3
   measured alloc-identical. A dedicated bench would need `vize_davinci`
   to dev-depend on `vize_s2` — the dependency arrow backwards.
4. **Two invariant lanes are pinned in code, not page text.** Id
   resolution needs a side table and liveness needs an arena; neither is
   expressible in a committed `.folio`. Both carry the same exact-oracle
   discipline in `tests/verifier_observer.rs` (whole panic payload for the
   table lane; the one committed stamp message for liveness, asserted the
   way `vize_carton`'s own stamp tests assert it).

## The fixture set

15 grammar-valid, semantically invalid pages in
`crates/vize_s2/tests/fixtures/invalid/`, each beside its `.expected`
rendering (`{code} @{start}:{end} {message}` per line, canonical `en`),
compared **whole-file** — TS-18's no-partial-matching oracle. Coverage is
per owner lane, not per specimen: backwards span at root; child/attr/
binding escaping an element; a `ui.model`'s attr escaping the model;
child escaping a component; branch escaping its `ui.if`; child escaping
its branch; region escaping `ui.for`; fallback escaping `ui.slot`;
empty `ui.if`; leading else (two spellings: first-of-two and only-branch);
mid-chain else; and one compound page pinning aggregation order
(S2V001 → S2V002 → S2V004). The harness pins the fixture count (15), the
canonical spelling of every page (round-trip byte-identity, so fixture rot
is loud), and the rigor split: the four canonical-only pages verify clean
at `Rigor::Raw`.
