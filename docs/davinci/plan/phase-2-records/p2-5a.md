# P2-5a — `vize_s2` S2 op and type family

**The S2 crate and its ops. Landed 2026-08-20; every acceptance clause
met, one contract step satisfied through its own written escape (the folio
page is hand-written under the P2-4 boundary), and the two design
decisions the contract left open are recorded below.**

## Two enums, and why the split is the design

The contract lists nine ops; the crate lands them as **two** closed enums
(`crates/vize_s2/src/op.rs`): `Op` for region positions (`ui.element`
/ `ui.component` / `ui.text` / `ui.interpolation` / `ui.if` / `ui.for` /
`ui.slot`) and `BindingOp` for attached positions (`ui.model` /
`vue.directive`). A binding belongs to exactly one element or component
and can never stand in a child list, so the split makes a floating
`ui.model` **unrepresentable** instead of a P2-6 verifier rule — the same
move P2-1 made with `NonZeroU32`. Every payload is boxed into the arena
(the `vize_relief::TemplateChildNode` shape), so both enums are 16 bytes.

**Regions are owned by their op**, per the contract's rationale: `ui.if`
owns its branches and each branch owns its region, `ui.for` and the
`ui.slot` fallback own theirs, elements own their children. The enter/exit
sibling mutation this kills is real and located: the shipped
`v-else`/`v-else-if` transform removes the taken element and pushes it
into the previous sibling's branch list on the **parent's** child list
mid-traversal (`crates/vize_atelier_core/src/lane/structural.rs`,
the `children_mut()` splices around lines 286–403) — precisely the
re-visit source a region-owning `ui.if` never needs.

**The dialect family holds exactly one op** (`vue.directive`, custom
directives only — built-ins normalize into `ui.*` at lowering). `ui.bind`
and `ui.on` are deliberately absent: an op lands with the transform that
needs it (P2-9), and the canary makes their arrival loud.

## `ui.model`: the contract pair, with the flow law on the pair

`ModelOp` carries `BindingContract { read, write }` plus attributes
(element kind, dialect modifiers) and a span — never realization
(`crates/vize_s2/src/op/model.rs` restates the charter #40 boundary:
IME, checkbox arrays and `.lazy` are runtime-owned by declaration).

**Recorded decision:** the contract names three carried things — what is
read, what is written, the value-type flow — and the landed type carries
two fields, with the flow as the pair's **documented law**: the type of
what is read is the type of what is written, one declared value type
flowing view-ward through `read` and model-ward through `write`. Any flow
_data_ representable today would be either a one-variant enum or a
speculation on type-system structure that belongs to the projection; the
moment P2-5b gives the slots identity, the law is checkable on them
directly. If review wants the flow reified, the slot for it is
`BindingContract` and the change is additive.

## The expression slot

`ExprSlot` (`crates/vize_s2/src/expr.rs`) is a zero-sized marker:
present/absent (via `Option<ExprSlot>`) is the only information an op
carries about an expression, its folio spelling is `?expr`, and its docs
forbid branching on it or growing it. P2-5b replaces it with `ExprRef<'a>`
— the node-size figures are expected to move then, which is what the
assertions are for.

## The folio boundary, applied again

The contract step says "S2 folio page from birth via the P2-4 derive";
what landed is a **hand-written owned page** (`DisegnoFolio`), which is
the escape the P2-4 record defined and this record re-measures rather than
assumes: the derived grammar is flat by construction — header scalars plus
one-level list/map sections, computable from the type shape — while the S2
artifact is region-nested _by the crate's central design decision_.
Flattening the tree into `FolioValue` lines was considered and rejected
because it moves structure validation (indentation, which op may own what)
outside `parse`, stripping its 1-based line numbers. The derive stays the
right tool for any flat S2 side artifact a later task adds; nothing in
this crate is flat yet, so the derive is unused here.

Two grammar decisions worth naming (full grammar:
[`folio-format.md`](../folio-format.md) "Disegno page"):

- **`ops=` is computed, not carried.** Croquis carries its header counts
  verbatim because they are the renderer's statement about an analysis the
  folio cannot see; the disegno tree is fully present in its own page, so
  a count that can never lie is printed and a stale one is normalized by
  the first print (parse validates the integer and discards it).
- **The grouping is grammar, not leniency.** Under an element the order
  attributes → bindings → children is canonical _and_ enforced on parse
  with exact rejections (`attribute after a binding`,
  `attribute after a child`, `binding after a child`), because print can
  never emit the interleaved form — there is nothing to be lenient toward.

The owned mirror types (`folio/owned.rs`) reuse every lifetime-free op
type (`Span`, `ExprSlot`, `Namespace`, `ForBinding`, `BindingContract`)
and mirror only the lifetime-carrying ones; `DisegnoFolio::of` bridges a
live arena tree into the owned model, and its exhaustive matches are part
of the canary surface.

## The canary, proved by injection

Per the P0-7 staleness rule the canary was proven, not assumed, in two
stages on this tree:

1. A `CanaryProof(Box<TextOp>)` variant injected into `Op` broke the
   **crate's own** exhaustive matches first: E0004 in `folio/owned.rs`
   (`of`) and `op.rs` (`mnemonic`).
2. With those two patched to handle the variant, the build failed again —
   this time only in the canary test itself
   (`tests/op_family.rs`, `op_keyword`, E0004) — proving the test catches
   a variant the crate already handles everywhere else.

The injection was then removed; the committed tree carries no trace of it.
`tests/op_family.rs` matches `Op`, `BindingOp`, `Namespace` and
`DynamicName` with no `_` arm anywhere.

## Sizes, pinned

All 64-bit, guarded on pointer width (the wasm32-wasip2 lane is 32-bit;
`crates/vize_relief/src/relief/elements.rs:31-36` rationale): `Op` and
`BindingOp` 16, `Region` 24, `ElementOp` 104, `ComponentOp` 96,
`TextOp` 24, `InterpolationOp` 8, `IfOp` 32, `IfBranch` 40, `ForOp` 40,
`ForBinding` 2, `SlotOp` 48, `DynamicName` 16, `ModelOp` 32,
`BindingContract` 0, `VueDirectiveOp` 80, `Attribute` 40. Drop-freedom is
additionally restated as `!needs_drop` const asserts on the three
composite roots, beside the container-level enforcement P1-10 measured.

## Left open, with owners

- Slot-content grouping on components (children → named slot regions) and
  forwarded slot props on outlets: both need `ui.bind`-class ops and land
  with the lowering/transforms that need them (P2-8/P2-9). `ComponentOp`
  docs say so at the field.
- The flow-law reification question above, if P2-5b's review wants it.
- The wasip2 lane still builds against the P2-4 sysroot overlay
  (`rust-std-1.95.0-wasm32-wasip2`, commit `59807616e`); the proper CI
  install stays P2-14's.
