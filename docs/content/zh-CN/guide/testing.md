# 测试与反馈

Vize正处于其**真实世界测试**阶段：重点是正确性，而真实世界的项目则是
测试套间。本页面向测试人员——如何检查 Vize 的功能，去哪里查看，如何操作
报告发现、如何衡量绩效，以及如何将项目作为试验平台。

## 与游乐场一起检查

游乐场附带一个**检查器**，并列显示官方Vue SFC编译器
输出、Vize编译器输出、生成的虚拟TS、VIR以及用于本地的跨文件图
批量。这是最快查看 Vize 在某一特定情况下与 Vue 意见一致或反对的途径
`.vue`档案。

- <https://vizejs.dev/play/?tab=inspector>开门。
- 请参阅[编译器检查器](./compiler-inspector.md)指南，了解每个曲面的含义。

游乐场检查器链接是很好的修复复制品。

## 阅读测试案例

Vize经过严格测试，采用多种方式——编译器配置与官方版本的对比
Vue编译器、类型校验与`vue-tsc`、lint 和格式化器快照、SSR 代码生成
快照、模糊线束和真实应用夹具。在提交报告之前，通常会
帮助浏览现有案例：

- 编译器和SFC的奇偶校验夹具及快照，`tests/`及每个箱子的`src/snapshots/`。
- `tests/_fixtures/`下的真实应用夹具（例如 Elk、Misskey、Nuxt UI，
  Reka UI和VOICEVOX驱动端对端和VRT。

如果缺少案例或结果看起来不对，这正是该阶段所需要的反馈。

## 报告发现

- **纯文本即可。**清晰描述你做了什么，你期待什么，以及发生了什么
  已经很有价值了。
- **如果可以的话，在GitHub追踪器上附上最小的复制品**——最小的`.vue`文件（或
  小项目）这仍然显示了问题所在。使用游乐场检查员链接非常有效。
- 修复报告、复制品、基准测试结果和兼容性发现均有帮助。参见
  [贡献](../contributing.md)导游和
  [支持](https://github.com/ubugeeei-prod/vize/blob/main/SUPPORT.md)。

## 绩效衡量

Vize内置了**画像模式**，你可以测量时间流向，而不是猜测。

- 在本地开发中，工具链揭示了解析器、编译器、分析和
  类型检查阶段。
- CLI也有：`vize check --profile`通过**vize_curator**进行检查并打印
  各阶段剖析报告。用它来捕捉并分享你自己的绩效数据
  代码库。

## 将你的项目作为试验平台

真正庞大的代码库能发现合成示例永远找不到的失败。**许可证在哪里
允许的话，项目可以添加到Vize的灯具中，成为端对端/VRT目标**，所以未来
回归会自动被发现。

如果你维护（或知道）某个Vue应用、库、框架或工具可能会用到，这点
太好了，请告诉我们——发起修正请求或联系我们。代码库越大越真实，
信号更有用。
