Documentos de referência são ótimos para responder "como uso isso?" Eles são muito piores em responder perguntas como:

- Por que esse recurso foi adicionado?
- Qual troca levou a essa arquitetura?
- Quais experimentos são promissores, mas ainda não estáveis?
- O que o projeto está tentando aprender a seguir?

Por isso a documentação agora inclui uma faixa separada **de Anotações** .

## O que pertence aqui

As notas são intencionalmente irregulares. Uma postagem pode ser:

- Um devlog após uma semana de trabalho com compiladores
- Um resumo de arquitetura para uma nova caixa
- uma nota de design sobre o Musea, o LSP ou a integração com o Vite
- Uma atualização curta de projeto que é útil, mas não está atrelada a uma tag de versão

## Por que não colocar tudo nas notas de lançamento

As notas de lançamento são otimizadas para mudanças de lançamento. Eles devem permanecer afastados e acionáveis.

As notas abrem espaço para uma narrativa mais ampla: o contexto por trás de uma matéria, a forma do roteiro e o pensamento que ajuda os leitores a entender o projeto ao longo do tempo.

## Direção de Roteiro

Em caso de dúvida:

- use **as Notas de Lançamento** se a postagem anunciar que algo foi enviado
- use **Notas** se o post explicar pensamento, progresso ou experimentos
