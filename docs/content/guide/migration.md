# Migrate existing tools

Start with the Vite plugin, build your app, then enable checks. Keep existing
custom rules and editor tooling until you have compared results on your project.
Vize is actively developed; this guide does not claim complete option or diagnostic parity.

## Choose what to replace

| Source | Target | Effect | Install |
| --- | --- | --- | --- |
| `@vitejs/plugin-vue` | Vize compiler | Vue 3 SFC compilation in Vite | `@vizejs/vite-plugin` |
| `vue-tsc` script | `tsc --runExternalCode --noEmit` | TypeScript 7.1 content mapper | `vize` and `typescript@beta` |
| Vue lint scripts | `vp run lint` | Vize Vue rules plus Oxlint | Same integration |
| Vue format scripts | `vp run fmt` | Vize for Vue; Oxfmt for other files | Same integration |

[tsrs](https://github.com/oxc-project/tsrs) is a drop-in of that typecheck: `tsrs --runExternalCode --noEmit` on the same `tsconfig.json`. The lint and format commands are generated by the [Vite+ helper](./vite-plus.md). They are custom tasks, distinct from built-in `vp lint`, `vp fmt`, and `vp check`. `vp run typecheck` remains the packaged checker. The mapper setup is in [Type Checking](./type-checking.md).

## Vite+ project

Install Vize into an existing Vue/Vite+ project:

```bash
vp install -D @vizejs/vite-plugin
```

Change `vite.config.ts`:

```ts annotate="remove:1,2,6;add:3,7"
import { defineConfig } from "vite-plus";
import vue from "@vitejs/plugin-vue";
import { defineConfig } from "@vizejs/vite-plugin/vite-plus";

export default defineConfig({
  plugins: [vue()],
  compiler: {},
  server: { port: 3000 },
});
```

The helper registers the Vize compiler and native tasks. Preserve unrelated
plugins, aliases, server settings, and tests. An empty `compiler` object uses
the defaults; you can also omit it.

Move supported plugin options to `compiler`, rather than retaining two Vue compilers:

```ts annotate="remove:1;add:2"
  plugins: [vue({ template: { compilerOptions: { whitespace: "preserve" } } })],
  compiler: { whitespace: "preserve" },
```

Check [plugin option coverage](./vite-plugin.md#drop-in-scope) before moving
other options. Vue 2 compatibility modes and experimental bundlers have a different scope.

Run a production build, type-check with the content mapper, and compare lint and format. Add the mapper to `tsconfig.json` first. tsrs runs the same file:

```bash
vp build
tsc --runExternalCode --noEmit -p tsconfig.json
tsrs --runExternalCode --noEmit -p tsconfig.json
vp run lint
vp run fmt:check
```

`vp run typecheck` and `vp run check` run the packaged checker.

Generated task names avoid existing package scripts. If `check` already exists,
run `vp run vize:check`; explicit `run.tasks` definitions also take precedence.
See [task names](./vite-plus.md#tasks) before replacing a CI command.

## Ordinary Vite: replace only the compiler

Keep `defineConfig` from `vite` and replace the plugin:

```ts annotate="remove:2,6;add:3,7"
import { defineConfig } from "vite";
import vue from "@vitejs/plugin-vue";
import vize from "@vizejs/vite-plugin";

export default defineConfig({
  plugins: [vue()],
  plugins: [vize()],
});
```

```bash
vp install -D @vizejs/vite-plugin
vp exec vite build
```

Your lint, formatter, and type-checking commands continue to use their existing
tools. [Vite plugin options](./vite-plugin.md#compiler-options) live directly in
`vize({ ... })`. Adopt the Vite+ helper later if you want combined tasks.

## Replace a check command after comparing output

Replace `vue-tsc` with the content mapper. Lint and format opt into the native
tasks. Test each change independently:

```json annotate="remove:1,3,5;add:2,4,6"
  "typecheck": "vue-tsc --noEmit",
  "typecheck": "tsc --runExternalCode --noEmit",
  "lint": "eslint src",
  "lint": "vp run vize:lint",
  "format": "prettier --write src",
  "format": "vp run fmt"
```

An existing `lint` script makes the helper generate `vize:lint`. **Use that
collision-safe name in the actual replacement.** tsrs is the same typecheck
script with `tsrs` in place of `tsc`. `vp run vize:typecheck` remains the
packaged checker.

```json
{
  "scripts": {
    "typecheck": "tsc --runExternalCode --noEmit",
    "lint": "vp run vize:lint",
    "format": "vp run fmt"
  }
}
```

Keep custom ESLint rules that have no equivalent, compare type diagnostics, and
review the formatter diff before changing CI. Formatting writes files;
`vp run fmt:check` checks first without writing.

## Without Vite+: swap one command at a time

You can replace one script and keep the rest:

| You run today                              | Replace with                               | Read first                                                       |
| ------------------------------------------ | ------------------------------------------ | ---------------------------------------------------------------- |
| `vue-tsc --noEmit`                         | `tsc --runExternalCode --noEmit`           | [Coming from vue-tsc](./type-checking.md#coming-from-vue-tsc)    |
| `eslint` with `eslint-plugin-vue`          | `vize lint src`                            | [ESLint rule migration map](../rules/migration.md)               |
| `prettier --write` on `.vue` files         | `vize fmt --preset prettier --write src`   | [Coming from Prettier](./formatter.md#coming-from-prettier)      |
| Vue - Official diagnostics                 | `vize lsp`                                 | [Language Server](./language-server.md)                          |

```json
{
  "scripts": {
    "typecheck": "tsc --runExternalCode --noEmit",
    "lint:vue": "vize lint src",
    "format:vue": "vize fmt --preset prettier --write src"
  }
}
```

tsrs is that typecheck script with the executable swapped to `tsrs --runExternalCode --noEmit`. Add the `contentMappers` entry first. `vize check` remains the packaged checker.

Keep ESLint for rules Vize does not implement yet, or run Vize's rules inside Oxlint with the
[Oxlint plugin](./oxlint.md). Run the old and new command side by side on the same commit and
compare the results before you remove the old one.

## Migrate standalone config into Vite+

Move native settings from `vize.config.*` or top-level `vize:` to `vue:` in your
existing Vite configuration. Keep TypeScript strictness and `vueCompilerOptions`
in `tsconfig.json`, including standard `extends` and `references`.

```ts
import { defineConfig } from "@vizejs/vite-plugin/vite-plus";

const vpConfig = { server: { port: 3000 } };

export default defineConfig(vpConfig).withVue({
  linter: { preset: "essential" },
  formatter: { printWidth: 100 },
});
```

The CLI and editor read the same Vite and TypeScript project settings. Remove the
old dedicated file after verifying the migration; dedicated files and Vize-specific
`extends` are no longer supported. See [Configuration](./configuration.md).
