# ファイル間の複雑さ

Vize のファイル間の複雑さレポートは、Croquis が作るプロジェクト グラフの要約です。レポート自体は診断
ルールではありません。レポートや Playground、将来のしきい値ベースのチェックに表示できる、説明可能な
スコアです。

モデルは Vue に対して 3 つの複雑さのシグナルを扱います。

- テンプレートのパス数: 各コンポーネント自身のサイクロマティック複雑度です。Davinci の S2
  `template-complexity` 解析で計算します。`v-if` / `v-else-if` の条件、`v-for`、そしてテンプレートが
  評価する式に含まれる `&&`、`||`、`??`、`?:` を 1 つずつ数えます。
- ネストした制御フロー: 各コンポーネント自身の認知的複雑度です。分岐やループは、`v-if`、`v-for`、
  スコープ付きスロットの内側に深くネストするほどコストが高くなります。
- コンポーネント境界のデータフロー: props、provide/inject、リアクティブなエッジは、1 ファイルに
  平坦化せず、境界を越えるシグナルとして残します。

メトリクスの定義とコーパスから決めたしきい値は
[`complexity-metrics.md`](https://github.com/ubugeeei-prod/vize/blob/main/davinci-road/plan/complexity-metrics.md)
にあります。

## スコア

レポートは生のシグナルと派生スコアの両方を公開します。

| フィールド        | 意味                                                                                                                                   |
| ----------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `cyclomaticScore` | 全コンポーネント自身のテンプレート サイクロマティック複雑度の合計。                                                                    |
| `cognitiveScore`  | 全コンポーネント自身のテンプレート認知的複雑度の合計。                                                                                 |
| `totalScore`      | ディメンション スコアの合計: テンプレート フロー、スロット、props のバケツリレー、グローバル状態、provide/inject、フォールスルー属性、リアクティブ グラフ。 |
| `band`            | 人向けの区分: `low`、`moderate`、`high`、`extreme`。                                                                                   |

生の入力には、スコアの根拠となる次の数値も含まれます。

| シグナル                                                        | 重要な理由                                                                                           |
| --------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| `templateCyclomatic` と `templateCognitive`                     | コンポーネント自身のテンプレート スコアを全コンポーネントで合計した値。                              |
| `templateMaxNesting`                                            | 1 つのテンプレート内で分岐・ループ・スコープ付きスロットが最も深くネストした段数。                   |
| `templateScopedSlotCount`                                       | スコープ付きスロットは親子のテンプレートを結合するため、通常のスロットとは別に数えます。             |
| `templateUnknown`                                               | AST を持たない式 (複数文のハンドラーなど) の数。どちらのスコアにも加算しません。                     |
| `propDrillingEdgeCount`                                         | props のエッジは境界を越えるデータフローを示します。                                                 |
| `provideInjectMaxDepth` と `provideInjectReferenceCount`        | 深い、または広い DI ツリーは、所有関係をローカルに確認しにくくします。                               |
| `reactiveNodeCount`、`reactiveEdgeCount`、`reactiveCycleCount`  | リアクティブ グラフは、宣言レベルの状態・エフェクト・リアクティビティを失いやすい循環を捉えます。   |

## コンポーネントの境界

テンプレートの複雑さには 2 つの見方があり、どちらも同じファクトから計算します。

- **自身 (own)** の複雑さは、そのコンポーネントのテンプレートだけを見た値です。lint ルール
  `vue/max-template-complexity` はこちらを判定します。分岐を子コンポーネントに切り出せば、
  親のスコアは必ず下がります。
- **描画 (rendered)** の複雑さは、自身のスコアに、描画する個々のコンポーネントの自身のスコアを
  重複なく足した値です。Croquis が import を通して解決するコンポーネント使用グラフをたどります。
  2 か所から描画される子は 1 回だけ数えます。再帰するコンポーネントや、互いを描画し合う
  コンポーネント群も 1 回だけ数えます。

`CrossFileResult.templateComplexity` は、両方の見方を全コンポーネントについて、描画ツリーの複雑さが
大きい順に並べます。各コンポーネントについて、複雑さを生んでいる構文を行・列つきで返します。

そのため、見た目が浅いコンポーネントでも、スコープ付きスロットを転送したり、props をバケツリレー
したり、深い provide/inject のパスに依存したりすると、高いスコアになることがあります。Playground の
Cross-file モードでは診断の横にスコアを表示するので、フィクスチャを編集しながらこれらのシグナルを
確認できます。

## lint ルールと Doctor の検出

`vue/max-template-complexity` は `opinionated` プリセットに含まれ、`warning` として報告します。
コンポーネント自身のテンプレートのサイクロマティック複雑度が 11 を超えるか、認知的複雑度が 16 を
超えると警告します。この上限は、Vize の実世界コーパス 40,724 テンプレートの p95 です。警告は
`<template>` タグを指し、複雑さを最も増やしている 5 つの構文にラベルを付けます。

`vize doctor` は、コンポーネントの描画の複雑さがコーパスの p95 (サイクロマティック 106、認知的
139) を超えると、テンプレート複雑度のホットスポットを notice として報告します。

サイクロマティック複雑度は、判断 1 つにつき 1 を加えます (`v-if` / `v-else-if` の条件、`v-for`、
論理演算子、`?:`)。認知的複雑度は次のように数えます。

- `v-if` と `v-for` は 1 とネストの深さを加えます。
- `v-else-if` と `v-else` はそれぞれ 1 を加えます。
- 同じ種類の `&&`・`||`・`??` の連続 1 つにつき 1 を加えます。
- `?:` は 1 とネストの深さを加えます。
- スコープ付きスロットの本体は 1 段深いネストとして数えます。

## ホットスポット

レポートは順位付けしたホットスポットも公開します。そのため、ツールはプロジェクト全体の数値 1 つ
ではなく、スコアを生んでいるファイルやコンポーネントを示せます。各ホットスポットには、ローカルの
スコア入力、ディメンション スコア、合計スコア、主要なディメンションが含まれます。
`dominantDimension` で高い理由を説明し、`input` でそれを生んだ生のシグナルを示してください。

## 現在の公開面

公開 JSON は、WASM のファイル間解析バインディングから `CrossFileResult.complexityReport`、
`CrossFileResult.complexityHotspots`、`CrossFileResult.templateComplexity` として利用できます。
CLI はまだこのスコアでビルドを失敗させません。まずは探索的なシグナルとして使い、プロジェクト固有の
ベースラインができてから安定したしきい値に昇格させてください。
