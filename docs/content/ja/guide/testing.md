# テストとフィードバック

Vue プロジェクトで、コンパイル結果、型エラー、lint の警告や実行速度に違和感があるときの手順を説明します。
小さな再現例と実行したコマンドを共有すると、同じ問題を調べやすくなります。

まず[コンパイラインスペクタのガイド](./compiler-inspector.md)で、問題が起きる `.vue` ファイルを開く方法を確認してください。
出力を調べ、期待する結果と再現例を報告します。
性能の測定結果を共有したり、回帰テスト用のプロジェクトを提案したりすることもできます。

## プレイグラウンドで検査する

[プレイグラウンドのコンパイラインスペクタ](https://vizejs.dev/play/?tab=inspector)を開き、
問題が再現する最小の `.vue` ファイルを使ってください。
公式 Vue SFC コンパイラと Vize の出力を比較し、同じ例をほかの人が開けるようにパーマリンクをコピーします。

インスペクタでは、生成された仮想 TypeScript、VIR、ローカルの複数ファイルにまたがるグラフも確認できます。
各表示の意味、DOM/SSR の切り替え、ローカルプロジェクトの読み込み方は
[コンパイラインスペクタのガイド](./compiler-inspector.md)を参照してください。

## 調査結果を報告する

何を実行し、何が起きて、どのような結果を期待していたかを書いてください。プレーンテキストで構いません。
Vize と Vue のバージョン、実行したコマンドまたはエディタ上の操作、関連するエラーメッセージを添えます。

インスペクタのパーマリンクか、問題が再現する小さなプロジェクトを添付してください。
速度の問題では、下で説明する測定結果とプロファイルの出力も共有すると調べやすくなります。
修正への参加方法は[コントリビュートのガイド](../contributing.md)、
質問や問題の報告先は[サポートのガイド](https://github.com/ubugeeei-prod/vize/blob/main/SUPPORT.md)にまとめています。

## テストケースを読む

似た問題の例を探したいときや、回帰テストを追加したいときは、既存のテストを参照できます。
コンパイラのテストでは公式 Vue コンパイラと出力を比較し、型チェックでは `vue-tsc` と診断結果を比較します。
lint、フォーマッタ、SSR のテストでは期待する結果をスナップショットに記録しています。
ファズテストや実際のアプリケーションを使ったテストでも、さまざまな入力や操作を確認しています。

- コンパイラや SFC の比較用の入力とスナップショットは、`tests/` と各クレートの `src/snapshots/` にあります。
- 実際のアプリケーションの入力は `tests/_fixtures/` にあります。Elk、Misskey、Nuxt UI、Reka UI、
  VOICEVOX などを使い、一連の操作や表示の変化を確認します。

不足している例があれば、報告に添えてください。修正後の挙動を守るための回帰テストにできます。

## パフォーマンスを測定する

速度が気になるプロジェクトで `vize check --profile` を実行すると、処理ごとにかかった時間を確認できます。
実行したコマンドと出力をそのまま共有し、Vize のバージョン、プロジェクトの規模、実際の実行時間も添えてください。

繰り返し比較できる測定方法は[型チェックの性能測定ガイド（英語）](/guide/check-performance)で説明しています。
ローカルの開発ツールでも、構文解析、コンパイル、解析、型チェックの処理時間を確認できます。

## プロジェクトをテストベッドとして提供する

Vue アプリケーション、ライブラリ、フレームワークやツールを保守している場合は、テスト用のプロジェクトとして提案できます。
プロジェクトのリンクとライセンス、インストールと起動に必要なコマンドを添え、Vize で確認してほしい操作を説明してください。

許可を得られ、ライセンス上も利用できるプロジェクトは、一連の操作や表示の変化を確認するテストにできます。
変更のたびに実行することで、同じ問題がほかの利用者に届く前に検出しやすくなります。
