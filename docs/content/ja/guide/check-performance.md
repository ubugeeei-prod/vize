# 型チェックのパフォーマンス

型チェックに時間がかかる場合や、ワーカー数を調整したい場合に使うガイドです。
まずは既定のワーカー数で実行し、処理時間の内訳を確認してください。ワーカー数を増やすと、診断の結果が変わることがあります。
対象プロジェクトの指定やその他のオプションは、[CLI の型チェック](./cli.md#check)を参照してください。

型チェックエンジン（Corsa）の各プロセスで使う、ワーカーの数を指定します。

```sh
vpx vize check --checkers 4 --servers 1
```

`--checkers` は正の整数を受け取り、環境変数 `VIZE_CHECKERS` より優先されます。
どちらも指定しない場合、Vize はワーカーを一つ使います。
`--servers` は別々に起動する Corsa プロセスの数です。プロセス数を自動で決める場合は、各プロセス内のワーカー数も考慮します。

ワーカーを一つにする既定値は、[#3905](https://github.com/ubugeeei-prod/vize/issues/3905)で確認した診断の動作を維持するためのものです。
その比較では、Corsa のワーカー数を増やすと、診断の一部が出なくなったり、異なる診断が出たりしました。
その違いを許容できる用途で、必要に応じてワーカー数を増やしてください。

Rust から呼び出す場合は、`BatchTypeChecker::set_checker_count(Some(4))` または `CorsaExecutor::set_checker_count(Some(4))` を使えます。
プロセス全体の環境変数を変更する必要はありません。`None` を渡すと、環境変数または既定値から選ぶ動作に戻ります。

どの処理に時間がかかっているかを確認するには、次のように実行します。

```sh
vpx vize check --profile
```

パスエイリアス経由の依存関係を集める際は、Vue を含まない依存関係の集合について、その実行中に得た結果を再利用します。
次に依存関係を集める際には、変更された内容を読み直します。
