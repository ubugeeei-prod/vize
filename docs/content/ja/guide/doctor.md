# Doctor による診断

`vize doctor` は、Vue コンポーネントとスクリプトモジュールを横断して、アプリケーションの健全性を調べます。
依存性注入の不一致、循環 import、サーバーとクライアントの境界、コンポーネント間の props 契約などの問題を、
判断の根拠となるソースの位置とともに報告します。まずターミナルでレポートを読み、該当するコードを確認してください。
変更後に同じコマンドを実行すると、診断の変化を確かめられます。

CLI のインストールは[はじめに](../getting-started.md)、ほかのコマンドは
[CLI ガイド](cli.md#doctor)を参照してください。

<span id="run-your-first-report"></span>

## 最初のレポートを読む

プロジェクトのディレクトリで、解析するソースのディレクトリを指定します。

```bash
vize doctor src
```

`src` は、アプリケーションのソースがあるディレクトリに置き換えてください。
パスを指定せずに `vize doctor` を実行すると、現在のワークスペースを調べます。
共有コードも含めるには、複数のディレクトリを指定します。

```bash
vize doctor src packages/shared
```

このコマンドは Vue SFC とスクリプトモジュールを読み取り、ファイルを書き換えません。
テキスト形式のレポートには、最初にワークスペース、100 点満点の健全性スコア、エラー・警告・通知の件数が表示されます。
それぞれの診断には、診断コード、メッセージ、ソースの位置が含まれます。コードを変更する前に、
示された位置をたどり、問題とされた関係を確認してください。その後、同じコマンドで結果を確かめます。

診断がないレポートは、現在の解析機能が対象のソースから問題を見つけなかったことを意味します。
アプリケーションのすべての動作を検証したという意味ではありません。
確実または高い確信度のエラーがある場合の終了コードは `1`、探索・解析・レポート出力に失敗した場合は `2` です。
警告や確信度の低い診断は、デフォルトでは実行を失敗にしません。
詳しい方針は[スコアと終了コード](#scoring-and-exit-status)で説明します。

<span id="save-a-report-for-ci"></span>

## CI 用のレポートを保存する

ほかのツールで診断を扱う場合は、JSON 形式で出力します。

```bash
vize doctor src --format json > doctor-report.json
```

JSON レポートには、診断の識別情報、根拠、スコア計算の情報が保持されます。
出力をファイルにリダイレクトしても、コマンドの終了コードは変わりません。
Doctor の診断を CI の失敗条件に使う場合は、その終了コードをそのまま使ってください。
ほかのシステムが失敗条件を決める場合に限り、`--exit-zero` を使います。
レポートを読むツールを作る前に、[自動化で使う際の契約](#automation-contract)を確認してください。

<span id="narrow-the-findings"></span>

## 診断を絞り込む

特定のカテゴリ、重大度、ルール、変更したソースに注目するには、フィルターを追加します。
フィルターは解析後の診断を選びます。実行する解析機能を減らすものではありません。
まずレポート全体を読み、関連するコンポーネント間の関係を確認してから、必要なオプションを使ってください。

`vize doctor` はアプリケーションを一度解析し、変更されないレポートから、
読者、CI、エディター、AI 連携が必要とする診断を選びます。
フィルターは解析機能の選択や根拠をつなぐグラフを書き換えません。
解析後の診断を選び、スコアを計算し直したレポートを作ります。

<span id="filter-algebra"></span>

## フィルターを組み合わせる

同じフィルターを繰り返すと、複数の値を指定できます。
カテゴリ、重大度、確信度では、カンマ区切りの値も使えます。
同じ項目に指定した値は OR、値を指定した異なる項目の間は AND で組み合わせます。

```bash
vize doctor src \
  --category correctness,security \
  --severity error \
  --confidence certain,high \
  --rule 'VIZE_DOCTOR_CF_*' \
  --path 'packages/**/src/*.vue' \
  --changed-file 'packages/account/**'
```

この例では、値を指定したすべての項目に一致する診断だけを残します。
値を指定しない項目は、すべてに一致します。
そのため、`--rule` を繰り返すとルールの選択範囲が広がり、
`--severity` を追加すると別の条件によって結果が絞られます。

| オプション       | 一致する対象                                                                                          |
| ---------------- | ----------------------------------------------------------------------------------------------------- |
| `--category`     | `correctness`、`accessibility`、`performance`、`maintainability`、`security`、`production-readiness` |
| `--severity`     | `error`、`warning`、`notice`                                                                         |
| `--confidence`   | `certain`、`high`、`medium`、`low`                                                                   |
| `--target`       | 解析機能が付けた対象の識別子                                                                           |
| `--rule`         | 安定した診断コード                                                                                    |
| `--path`         | 主なソース位置の、ワークスペースからの相対パスだけ                                                        |
| `--route`        | 解析機能が付けたルートの識別子                                                                         |
| `--environment`  | 解析機能が付けた実行環境                                                                               |
| `--package`      | 解析機能が付けたワークスペース内のパッケージ                                                             |
| `--changed-file` | 根拠をつなぐグラフ全体に含まれる、影響を受けるソース                                                      |

識別子とパスのフィルターには、大文字と小文字を区別するシェル形式の glob を使います。
`*`、`?`、文字クラス、再帰的な `**` に対応しています。
パスは、どのプラットフォームでも `/` を区切り文字として比較します。
不正なパターンや空のパターンがある場合は、解析結果を出力する前に終了コード `2` で失敗し、
どの項目のパターンが不正かを診断に示します。

<span id="changed-file-semantics"></span>

## 変更ファイルによる絞り込み

`--changed-file` は、`--path` より広い範囲を調べます。
次のいずれかの入力がパターンに一致すると、その診断を残します。

- 主なソース位置、または関連するソース位置
- 入れ子になった根拠が示すソース位置
- 提案された修正に含まれるソースの編集箇所
- 変更された場合に解析のやり直しが必要になる、判断の根拠に含まれる入力

これにより、診断が直接指している位置に変更がなくても、判断の根拠となる共有コンポーネント、
生成された契約、関連する宣言に変更があれば、その診断を保持できます。
ファイルをまたぐ因果関係を失わずに、プルリクエストへの診断表示にも使えます。

<span id="scoring-and-exit-status"></span>

## スコアと終了コード

絞り込み後のレポートも、同じ入力から同じ結果が得られる、通常の順位付けとスコア計算で組み立て直します。
件数、カテゴリごとの健全性、全体のスコア、実行を失敗にするエラーの有無は、表示される診断だけを対象にします。
最後に残った、実行を失敗にする診断をフィルターで除外すると、終了コードは `1` から `0` に変わります。

| 終了コード | 意味                                                                 |
| ---------: | -------------------------------------------------------------------- |
|        `0` | 表示されるレポートに、確実または高い確信度のエラーがない                 |
|        `1` | 表示される診断に、実行を失敗にするエラーが一つ以上ある                   |
|        `2` | 探索、解析、フィルターのコンパイル、シリアライズ、出力のいずれかに失敗した |

レポートを参考情報として使い、ほかのシステムが失敗条件を決める場合は、`--exit-zero` を使います。
このオプションが変えるのはプロセスの終了コードだけです。
レポート内の、実行を失敗にするエラーがあるという状態は書き換えません。

<span id="automation-contract"></span>

## 自動化で使う際の契約

CI、エディター、ダッシュボード、特定のプロバイダーに依存しない AI 連携では、`--format json` を使ってください。
JSON には、形式とスコア計算のバージョン、安定したルールコード、正規化されたパス、確信度、影響、
根拠、修正を利用できるかどうか、解析の判断に使った情報が含まれます。
JSON から診断だけを削除するのではなく、CLI またはライブラリの `vize_doctor::DoctorFilterSpec` を使って絞り込んでください。
それにより、診断から求められる健全性の情報と、終了コードの方針を一致させられます。

フィルターは一度コンパイルされます。レポートの絞り込みでは診断を一回走査し、
`--changed-file` が指定されている場合にだけ、追加の根拠をつなぐグラフをたどります。
出力機能は、絞り込み後の変更されないレポートを受け取ります。
そのため、テキスト、JSON、SARIF、TUI、今後の AI プロバイダーによる出力でも、同じ選択の方針を共有できます。
