# 安定性

Vize は v1 アルファ版に向けて進んでいます。アルファ コントラクトは、安定した v1 よりも意図的に狭くなっています。
規約: 初期採用者が使用できるようにする余地を残しつつ、サーフェスに名前を付けます。
内部構造と実験的な統合を迅速に変更します。プロジェクト全体はまだ完全には完成していません
本番環境に対応したツールチェーン。リリースの決定には、
[実稼働準備チェックリスト](https://github.com/ubugeeei-prod/vize/blob/main/docs/release/production-readiness.md)。
非推奨期間、SemVer ルール、およびリリースラインのサポートについては、
[サポートポリシー](https://github.com/ubugeeei-prod/vize/blob/main/docs/release/support-policy.md)。

## バージョニング契約

v1 が安定する前のプレリリースには重大な変更が含まれる可能性があります。 Vize は依然として重大な変更を次のように扱います
リリースノート資料、特にパッケージのエントリポイント、CLI フラグ、設定フィールドに影響を与える場合
診断コード、または生成された出力。

v1 アルファ行では次のルールが使用されます。

| 表面                                         | アルファの期待値                                                                            |
| -------------------------------------------- | ------------------------------------------------------------------------------------------- |
| 公開されたパッケージ名                       | 引き続き利用可能であるか、移行メモが同梱されている必要があります。                          |
| 文書化された CLI コマンドとフラグ            | サイレント動作の変更は避けるべきです                                                        |
| 文書化された構成フィールド                   | リリース ノートで変更が指示されない限り、名前と値の形状は安定したままにする必要があります。 |
| 診断コードはドキュメントにリストされています | 抑制と修正レポートが有用であり続けるように、認識可能な状態を維持する必要があります。        |
| 公開された Rust クレート API                 | 以下のクレートごとの階層と非推奨契約に従ってください。                                      |
| 未エクスポートの Rust クレート内部           | v1 が安定する前に移行サポートがなければ変更される可能性があります                           |
| 生成されたコードと仮想 TS 出力               | 正確性、互換性、パフォーマンス、または診断のために必要に応じて変更される可能性があります。  |

## ランタイムサポート

パブリック npm ランタイム パッケージのデフォルトの Node.js フロアはノード 22 です。
`oxlint-plugin-vize`。 Oxlint プラグインは `^22 || >= 24` を宣言するため、ノード 22 およびノード 24 以降は
ノード 23 がテスト済みの互換性マトリックスの外にある間は許可されます。

リリース ワークフローでは、x64 と arm64 にわたる macOS、Linux、および Windows のネイティブ パッケージを構築します

現在のプロジェクトのノードのバージョン。

完全な新規インストールスモークマトリックス (`.github/workflows/native-smoke.yml`) は毎週実行されます。
すべての PR プッシュではなく、リズムとオンデマンドです。公開されたパッケージのインストール パスを実行します。
GitHub でホストされている linux-x64-gnu、linux-arm64-gnu、darwin-arm64、win32-x64-msvc 用のランナー。の
残りの darwin-x64 および win32-arm64-msvc ターゲットは、アーキテクチャ固有のホスト ランナー上に残ります。
マトリックスはノード 22 とノード 24 に対して実行されます。リリース タグはリリース ワークフローによってブロックされたままです。
tarball は、npm パッケージを公開する前にスモークをインストールします。ランタイムスモークチェック `vize --version`、
`vize check`、`@vizejs/native`、`require` と `import` の両方、および
インストールされた tarball からの `@vizejs/vite-plugin` `vite build`。

宣言された 2 つの Linux musl ターゲットは、ホストされた新規インストール ランナーによって現在実行されていません。
これらは、プラットフォームごとのビルド アーティファクトと `@vizejs/native-*` によってカバーされます。

| ---------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------- |

`[workspace.package].rust-version`。 `rust-toolchain.toml` によって固定された開発ツールチェーン
同じバージョンかそれ以降のバージョンである可能性があります。 v1 が安定する前に、MSRV はプレリリースで前進する可能性があります。

### SemVer ゲートの解釈

`cargo-semver-checks` は、解決可能なレジストリを持つリリース発行者のクレートに対して実行されます
ベースライン。最初のパブリッシュを待機しているクレート、または最初のパブリッシュでブロックされているクレートは、パブリッシュが完了するとそのマトリックスに参加します。
ベースラインが利用可能です。それまでは、メタデータ/テーブル/リリースリストのチェックが引き続き適用されます。

| 階層                                  | CIの解釈                                                                                                                   |
| ------------------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| アルファ版サポート / 互換性プレビュー | API ブレークは修正するか、サポート ポリシーの非推奨期間に従い、従来のブレーク マーカーを保持する必要があります。           |
| 実験的                                | ゲートは偶発的なドリフトをキャッチします。意図的な中断では、非推奨ウィンドウなしで中断マーカーが使用される場合があります。 |
| 孵化中                                | 同じ検出が適用されますが、API またはクレート全体がどのリリースでも置き換えまたは削除される可能性があります。               |

CI で認識されるブレーク マーカーは、従来の変更タイトルの `!` または
`BREAKING CHANGE:` フッター。いずれかのマーカーでゲートを通過しても、非推奨は免除されません
アルファサポートまたは互換性プレビュークレートのウィンドウ。

## アルファ版にとって十分に安定しているものとは何か

パッケージまたはコマンドは、次の場合にアルファ サポート層に移行できます。

- インストールおよび使用パスの文書化
- パッケージのビルド、インストール、サポートされるノード ランタイムの CI カバレッジ
- 公開されたエントリポイントのスモークカバレッジをリリースします
- リグレッションと互換性レポートの明確な所有者
- 既知のサポートされていない動作は関連ガイドに記載されています

## まだ約束されていないこと

アルファ版は、すべての Vue コンパイラ エッジ ケース、すべてのパッケージとの完全な互換性を保証するものではありません
マネージャーのレイアウト、すべてのエディター機能、またはすべてのフレームワーク統合。 Vize が同意しない場合
公式 Vue ツール。Vize ガイドでない限り、公式出力を互換性ベースラインとして扱います。
異なる動作を明示的に文書化します。リリースブロッキングコンパイラ、型チェック、ランタイム、
Vite ビルド サーフェスの名前は
[Vue パリティ行列](https://github.com/ubugeeei-prod/vize/blob/main/docs/release/vue-parity-matrix.md)。

セキュリティの処理については、リポジトリ `SECURITY.md` を参照してください。貢献と修正のワークフローについては、を参照してください。
