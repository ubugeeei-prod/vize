## Context

The `css_parse` fuzz target found two crash classes (#3276, #3280) that reproduce inside upstream crates, not in Vize code, and both still reproduce on the latest released versions (lightningcss 1.0.0-alpha.72, cssparser-color 0.5.0):

1. **`Percentage::parse` `unreachable!()`** (`lightningcss/src/values/percentage.rs:30`) — a math function in a percentage-typed slot whose calc tree does not constant-fold to a plain percentage. Reproduces in every build profile (production crash). Empirical matrix (percentage slots = hsl S/L, hwb W/B, lab/lch/oklab/oklch L/C, rgb %, alpha, `opacity`):
   - `sign(-50%)`, `abs(-50%)` — panic (single % argument; `abs(-50%)` is *valid* CSS)
   - `mod`/`rem`/`round`/`min`/`max`/`clamp`/`hypot` with mixed %/number arguments — panic
   - nested forms: `calc(sign(-50%))`, `abs(sign(-50%))`, `min(abs(-50%), 60%)` — panic
   - same-type argument lists (`mod(50%, 7%)`, `min(10%, 20%)`) and %-typed products (`calc(10% * sign(-50%))`) — parse fine
2. **`hsl_to_rgb` `debug_assert!((0.0..=1.0).contains(&hue))`** (`cssparser-color/lib.rs`) — a hue that becomes non-finite: literals above `f32::MAX` (`hsl(1e40 0 0)`) or calc overflow (`hsl(calc(1e20 * 1e20) 0 0)`). Fires only with debug assertions (fuzz builds); release builds compute garbage silently.

Byte-level pre-guarding cannot express "calc type algebra resolves to a percentage" without over-rejecting working CSS (`min(10%, 20%)`, `calc(100% - 20%)`), so Vize hardens the boundary instead:

- `vize_atelier_sfc` wraps every lightningcss entry point in `catch_unwind` and reports `CSS parse error: the CSS engine hit an internal defect ...` instead of crashing the process (all Vize profiles unwind; no `panic = "abort"`).
- the `css_parse` fuzz target skips inputs matching the two known upstream shapes so fuzzing keeps hunting new bugs without re-reporting these.

## Retirement criteria

- [ ] Upstream fix for the `Percentage::parse` `unreachable!()` (math functions in percentage context) released in lightningcss.
- [ ] Upstream fix for non-finite hue handling released in cssparser-color/lightningcss.
- [ ] Bump the pinned versions, drop the fuzz-target skip-list, and replay the #3276/#3280 artifacts + the regression suite to confirm clean parses.
- [ ] Keep the `catch_unwind` boundary only if maintainers decide process-crash isolation from upstream parser defects is worth keeping permanently; otherwise remove it and let the regression tests assert clean error returns.

The panic-matrix regression tests added with the boundary (`css_engine_panic_boundary.rs`) must keep passing through the migration: shapes that panic today must parse or error cleanly after the bump.
