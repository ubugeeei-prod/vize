## Summary

When the editor has a document open already and then opens an SFC that imports a `.vue` file from a package linked into `node_modules` (what npm / pnpm / yarn workspaces create), `vize lsp` writes two generated files next to the **real** source of the imported SFC:

- `UiButton.vue.ts` ("Virtual TypeScript for Vue SFC Type Checking / Generated by vize")
- `UiButton.d.vue.ts` (`export { default } from "./UiButton.vue.ts";`)

They stay after `shutdown` / `exit`. In a monorepo they show up as untracked files in the shared UI package (one pair per SFC the import graph reaches, e.g. every component a barrel `index.ts` re-exports), where file watchers and `git status` see them.

`vize check` on the same project writes nothing into the source tree.

Same symptom as #2010 (closed), different trigger: no percent-encoded characters in the path here; the external file is reached through a `node_modules` symlink that lives inside the project directory.

## Environment

- vize 0.432.0 (npm)
- macOS 26.4.1 arm64, Node v26.10.0, npm 11.19.1
- typescript 7.0.2, vue 3.5.43 (also with vue 3.6.0-rc.10)

## Reproduction

```sh
mkdir repro && cd repro
echo '{ "private": true, "type": "module" }' > package.json
npm i -D vize@0.432.0 typescript@7.0.2 vue@3.5.43

# a workspace package, linked into the app the way a workspace install links it
mkdir -p ui app/node_modules
echo '{ "name": "ui", "private": true, "type": "module" }' > ui/package.json
printf '<template>\n  <button type="button" />\n</template>\n' > ui/UiButton.vue
ln -s ../../ui app/node_modules/ui

printf '{\n  "compilerOptions": { "module": "ESNext", "moduleResolution": "Bundler", "strict": true, "noEmit": true }\n}\n' > app/tsconfig.json
printf '<template>\n  <div />\n</template>\n' > app/Other.vue
printf '<script setup lang="ts">\nimport UiButton from "ui/UiButton.vue";\n</script>\n\n<template>\n  <UiButton />\n</template>\n' > app/App.vue

# lsp.mjs below: open the folder `app`, open Other.vue then App.vue, wait 15 s, shutdown + exit
node lsp.mjs app app/Other.vue app/App.vue
ls ui
```

<details><summary>lsp.mjs (minimal stdio client)</summary>

```js
// node lsp.mjs <workspace-root> <file>... : opens the files in order in `vize lsp`, waits 15 s, shuts down.
import { spawn } from "node:child_process";
import { readFileSync } from "node:fs";
import { resolve } from "node:path";
import { pathToFileURL } from "node:url";

const [root, ...files] = process.argv.slice(2).map((p) => resolve(p));
const server = spawn(resolve("node_modules/.bin/vize"), ["lsp", "--stdio"], { cwd: root, stdio: ["pipe", "pipe", "ignore"] });
const write = (msg) => {
  const body = JSON.stringify({ jsonrpc: "2.0", ...msg });
  server.stdin.write(`Content-Length: ${Buffer.byteLength(body)}\r\n\r\n${body}`);
};
const pending = new Map();
let nextId = 0;
let buffer = Buffer.alloc(0);
server.stdout.on("data", (chunk) => {
  buffer = Buffer.concat([buffer, chunk]);
  for (let end; (end = buffer.indexOf("\r\n\r\n")) >= 0; ) {
    const length = Number(/Content-Length: (\d+)/i.exec(buffer.subarray(0, end))[1]);
    if (buffer.length < end + 4 + length) break;
    const msg = JSON.parse(buffer.subarray(end + 4, end + 4 + length));
    buffer = buffer.subarray(end + 4 + length);
    if (msg.method && msg.id !== undefined) write({ id: msg.id, result: null }); // server -> client request
    else if (msg.id !== undefined) pending.get(msg.id)?.(msg);
  }
});
const request = (method, params) => new Promise((done) => { pending.set(++nextId, done); write({ id: nextId, method, params }); });
const notify = (method, params) => write({ method, params });
const sleep = (ms) => new Promise((r) => setTimeout(r, ms));

await request("initialize", { processId: process.pid, rootUri: pathToFileURL(root).href, capabilities: {} });
notify("initialized", {});
for (const file of files) {
  notify("textDocument/didOpen", { textDocument: { uri: pathToFileURL(file).href, languageId: "vue", version: 1, text: readFileSync(file, "utf8") } });
}
await sleep(15000);
await request("shutdown", null);
notify("exit", null);
```

## Actual

```
$ ls ui
UiButton.d.vue.ts  UiButton.vue  UiButton.vue.ts  package.json
```

3 out of 3 runs. The files appear within about a second of the `didOpen` and remain after the server exits.

- Opening only `App.vue` (`node lsp.mjs app app/App.vue`) writes nothing (0 out of 2), so it takes another document being open first, as in any real editor session.
- With `"include": ["**/*.vue"]` the result is the same. When the app's files are under `src/` with `"include": ["src/**/*.vue"]`, nothing is written.

## Expected

Nothing is written into the source tree: the virtual files for external SFCs go to the editor session directory (`$TMPDIR/vize-canon/editor/sessions/...`) or `node_modules/.vize/`, as they do for the project's own SFCs and as `vize check` does.
