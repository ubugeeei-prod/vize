# Complete local-alias transactions

These supplemental sources qualify the local-alias forms described in
[#8011](https://github.com/ubugeeei-prod/vize/issues/8011). The original report,
`../E.vue.txt`, and the six delivered alias sessions remain unchanged.

`E-defaults.vue.txt` defaults `tone` through `withDefaults`. Its public property
has three owned locations: the alias member, the defaults key, and the bare
template use. `E-partial.vue.txt` adds an optional `html` member and destructures
only `html`, retaining both `hidden` and `tone` as independent bare template
props. This isolates the reported partial-destructure form from renaming a
destructured local value. The original plain component remains the control.

The six `*-hidden.vue.txt` and `*-tone.vue.txt` files are independently authored
complete repairs. They are loaded before provider queries and are never
constructed from returned edits. LF and CRLF sessions use the same authored
content with only the line endings changed.

`lsp_type_alias_original_transactions_cli.rs` requires 26 complete rename
transactions and six definition sessions. Every rename origin has a whole
references and WorkspaceEdit expectation. Actual returned edits are applied to
the file and disk, with complete version-2 diagnostics; the independent golden
is then installed for a separate version-3 diagnostic observation. Every owned
declaration, default key, and template origin must define the exact alias
member. Each fresh session retains an actual native TS2322 guard and clean
repair before any property query.

The existing strict ES2022/Bundler pinned-Vue project helper is reused unchanged.
These are finite configured public-CLI contracts. They do not establish imported
or complex aliases, destructured-local rename parity, or universal native
provider-entry authority. No product fix is claimed until authentic source
execution demonstrates a defect and qualifies its correction.
