# Configured original HTML operation controls

This new corpus qualifies the private selection-and-execution operation for
[#7903](https://github.com/ubugeeei-prod/vize/issues/7903). It is independently
authored reported-shape HTML, not the issue's literal original Vue reproduction.
The older original HTML producer's 45 cases/90 observations, literal Vue replay,
original standalone transport snapshot and licensed n8n 83/73 packets are not
changed or regenerated.

`cases.json` declares 55 whole original-path/configuration cases, each intended
for both immutable host profiles. `expected-packets.json` contains 11 complete
ordered native Patina diagnostic packets authored before executing the new
operation. Expectations retain severity, message, exact original byte offsets,
full optional help, labels, fixes and both counts. These are native packets, not
invented Oxlint report metadata or output fragments. Source spans are the literal
attribute ranges in the independently authored files. The Unicode/CRLF case
also retains existing engine order: the duplicate-attribute diagnostic precedes
the earlier-in-source raw-HTML diagnostic.

The positive corpus includes genuine clean, warning, error, script-bearing and
Unicode/CRLF standalone HTML, same basenames in two directories, existing
directive suppression, independently retained mixed Vue/HTML roles, all three
VCS/configuration/CLI exclusions together and alone, explicit/discovered targets
and no-ignore. VCS policy remains active under no-ignore. The explicit VCS root
differs between the pinned 1.78 and 1.86 profiles; expectations preserve this
difference rather than forcing a common selected set.

Configuration cases retain authored off/warn/error and numeric severities,
missing/empty rule sets, actual opposite attribute-hyphenation options,
incremental option replacement, essential preset gating, Japanese/full help,
no-help/showHelp, and denyWarnings. The root snapshot retains foreign/core
configuration unchanged. A `debugger` inside scripted HTML remains host-owned;
this operation does not claim to run core Oxlint or import JavaScript plugins.
Configuration identity, duplicate keys, malformed JSON, active native type-aware
settings/rules, unsupported authored values and invalid original UTF-8 refuse
without a completed partial-success packet. An excluded invalid original is not
decoded or linted.

`sources.json` freezes every source's SHA-256 and identifies two exact copies:

- `OriginalAppPanel.vue.txt` is the immutable original issue reproduction from
  `../oxlint-original-ignore-7903/AppPanel.vue.txt`.
- `OriginalStandalone.html.txt` is the immutable input from
  `../oxlint-script-safe-carrier-7903/Standalone.html.txt`. Running the explicitly
  authored no-v-html rule on this copy does not replace its original root,
  argv or expected one-error Stylish transport packet.

`mutation-case.json` is a separate law. During the first callback to the actual
existing HTML engine, the test overwrites its owned root JSON and both physical
HTML inputs. The complete original callback packets and diagnostic expectations
must still match the two retained original sources, exactly once per original.
The malformed replacement root prevents a second root decode from passing
silently; the replacement clean sources prevent a second read from preserving
the expected warnings. Only these three authored mutations may occur. This
witness proves internal use of retained data, not general concurrent-filesystem
admission or unchanged external disk authority.

Every observation uses genuine owned `git init -q` setup, records its entire
process packet before checking success, and sets its owned info-exclude source
to authored empty bytes. Tests preserve the complete native operation/refusal
before any custody postread or assertion. Ordinary cases compare the complete
owned tree, including all `.git` files, before and after. Mutation evidence is
separate from ordinary custody. Receipts use the existing
`target/nextest/${NEXTEST_PROFILE}/oxlint-html-operation` artifact path and retain
the existing compiled archive receipt when available; no new CI or release gate
is introduced.

The immutable profiles are Oxlint 1.78.0 source
`c42d6397eab5b2d5bb2bd6746c57bc2a9cad21bd` and 1.86.0 source
`2ae2939bb2fd98796393658b21556b2a2467e047`. Selection reuses the actual locked
ignore 0.4.33 producer. Qualification still needs exact-source hosted execution;
authored expectations or local source inspection are not a successful receipt.
This private corpus grants no additive export, renderer, whole host validation,
public wrapper, public installation, release or broad n8n adoption credit.
