Three more template shapes where `printWidth` is not honoured (vize 0.432.0, `vize fmt --write --no-config`, default `printWidth: 100`). In the first two cases vize also joins input that was already broken the Prettier/Oxfmt way, so a Prettier-formatted file gets longer lines.

**1. A pre-broken attribute value is joined without accounting for the indent / attribute prefix**

```vue
<template>
  <section>
    <ul>
      <li>
        <span
          class="label"
          :title="
            buildTooltipText(currentItem.primaryValue, currentItem.secondaryValue, currentItem.extra)
          "
        />
      </li>
    </ul>
  </section>
</template>
```

becomes a single 108-column line:

```vue
          :title="buildTooltipText(currentItem.primaryValue, currentItem.secondaryValue, currentItem.extra)"
```

The expression seems to be formatted standalone with the full `print_width` (`script.rs`, `format_js_expression_with_quote_style`) and no column offset.

**2. A start tag that fits is put on one line together with its inline children**

```vue
<template>
  <div>
    <div>
      <MyButton
        v-if="visible"
        data-testid="submit-button"
        @click="$emit('submit')"
        >{{ $t("actions.submitTheCurrentForm") }}</MyButton
      >
    </div>
  </div>
</template>
```

becomes one 135-column line:

```vue
      <MyButton v-if="visible" data-testid="submit-button" @click="$emit('submit')">{{ $t("actions.submitTheCurrentForm") }}</MyButton>
```

`should_use_multiline_attrs` (`template/attributes.rs`) measures indent + tag + attributes + `>`, but not the children that are appended to the same line.

**3. A hugged multi-line `{{ }}` is indented one level too deep**

Oxfmt's output for case 2:

```vue
      <MyButton v-if="visible" data-testid="submit-button" @click="$emit('submit')">{{
        $t("actions.submitTheCurrentForm")
      }}</MyButton>
```

is re-indented by vize to

```vue
      <MyButton v-if="visible" data-testid="submit-button" @click="$emit('submit')">{{
          $t("actions.submitTheCurrentForm")
        }}</MyButton>
```

(stable, but `}}` ends up deeper than the opening tag; vize's own breaks inside `<p>{{ … }}</p>` come out the same way). `write_multiline_interpolation` appears to get the child depth even when the interpolation is hugged to the start tag.
