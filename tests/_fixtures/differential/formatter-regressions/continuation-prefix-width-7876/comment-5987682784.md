One more case of the same gap, the other way round: when the attribute value is already in Prettier's "expression on its own lines inside the quotes" layout, `vize fmt` (0.432.0) rewrites it into a hugged form instead of keeping it.

`vize.config.json`: `{ "formatter": { "printWidth": 80, "semi": true, "singleQuote": false, "trailingComma": "none", "arrowParens": "avoid", "sortAttributes": false } }`

`Edit.vue` (Oxfmt 0.60.0 with the same options leaves it unchanged)

```vue
<script setup lang="ts">
const guard = (allowed: () => void, denied: () => void): void =>
  Math.random() > 0.5 ? allowed() : denied();
const openEditor = (): void => {};
const openNotice = (): void => {};
</script>

<template>
  <button
    type="button"
    @click="
      guard(
        () => openEditor(),
        () => openNotice()
      )
    "
  >
    Edit
  </button>
</template>
```

`vize fmt --write Edit.vue`:

```diff
-    @click="
-      guard(
-        () => openEditor(),
-        () => openNotice()
-      )
-    "
+    @click="guard(
+      () => openEditor(),
+      () => openNotice()
+    )"
```

In a ~450-SFC app formatted with Oxfmt this accounts for 121 of the template hunks `vize fmt --check` reports. Expected: the Prettier layout is kept (and produced, as in the expected output above).
