# Operational diagnostic documentation

These authored inputs isolate the three operational IDs whose report URLs were
sent through the ordinary rule slug generator. The unused comment, an installed
application with an unmatched injection, and an explicitly missing type-aware
runtime exercise different producers. An ordinary missing-key diagnostic is a
negative control for the unchanged reference-page route.

`cases.json` records complete invocation inputs and the documentation-only
contract. Its Actions links establish the original report failure class, not an
execution of these new reductions. Existing source inputs and report oracles are
unchanged. This is a pinned, source-inspected input registration; it does not
claim a native adapter result or admit operational IDs into the rule catalogue.

`reports/` contains the current documentation expectations for three existing
whole-report cases. Each is the original immutable snapshot body with only its
reviewed documentation URL tokens changed. The historical snapshots and their
oracle-index hashes remain unchanged; the current Rust consumer compares the
entire report against these separate expectations.
