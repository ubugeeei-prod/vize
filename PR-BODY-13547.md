## What

A Vue file's source map now maps a component's render code back to its
template, so devtools, error overlays, and coverage land on the authored
`<template>` lines instead of the generated render function. The render map
the template compiler records is composed into the component's module map:

- the client render block and the SSR / Vapor render block are both placed in
  the composed map at the offset where the SFC assembly writes them;
- inline (`<script setup>`) renders carry the template parts they copy into
  `setup`, so their reads map to the template too;
- a setup-binding component read (`_push(_ssrRenderComponent($setup.Foo, ...))`,
  `_createBlock($setup.Foo)`) maps to its tag, `v-for` aliases map to the
  alias the loop authored, and static member reads of a rewritten expression
  map to their authored columns.

A map is additive: the module bytes never depend on whether a map was
requested. When the compatibility generator that supplies a mapped template's
links would emit a different module than the selected L2 emitter, the module
is kept and goes unmapped.

## Zero cost for compiles without a map

The links above are recorded only by generated copies of the compilers, in
their own crates:

- `vize_atelier_core_composed`, `vize_atelier_dom_composed` and
  `vize_atelier_ssr_composed` are generated by
  `tools/commands/generate/composed-crates.ts` from the plain crates' sources.
  Each plain crate has a copy macro (`render_map_copy!`, `dom_map_copy!`,
  `sfc_map_copy!`) whose `plain` tokens the plain crate keeps and whose
  `composed` tokens the copy keeps. Every generated file carries a
  do-not-edit header, and `check-js` runs `composed-crates.ts --check`, so a
  stale copy fails the PR.
- `vize_atelier_sfc` calls a composed crate only when a map is requested.
- The plain crates compile to main's code. A copy in the same crate was not
  enough: shared generic instantiations gain callers from the copy and LLVM
  inlines differently even where the copy is unreachable, so each copy is a
  separate crate.

The copies share the plain crates' option, context and result types
(`vize_atelier_ssr::shared`, `vize_atelier_core::codegen::context::result`,
`lane::ScriptTables`, `vize_atelier_dom::options`) and the differential lane
state, so a host hands both compiles the same values.
