# Davinci — Next-Generation Compiler Infrastructure

> [!WARNING]
> Davinci is a **rearchitecture program in its design phase**. Nothing on these pages
> is implemented, scheduled, or promised. These documents exist so the intended shape
> of the next-generation infrastructure is written down and reviewable before any
> code moves. Every decision recorded here may be revisited.

Davinci is the project name — and the name of the resulting infrastructure — for
rearchitecting Vize's compiler core around a **multi-stage IR**, in the spirit of
MLIR: many inputs, many outputs, one shared, progressively-lowered representation
in the middle, with no performance regression at any step.

- **Inputs (planned surface)** — Vue 3 SFC, Vue 2 (existing `legacy` dialect),
  JSX/TSX, alternate template languages (pug), and foreign expression languages
  (MoonBit and others) through a published dialect contract.
- **Outputs (planned surface)** — VDOM / Vapor / SSR JavaScript, virtual TypeScript
  for type checking, `.d.ts`, lint-facing semantic views, formatter-facing surface
  trees, and non-JS host targets (the Volt/Elixir pattern) through a published
  target contract.

## Why now

The current pipeline has one shared parse AST (`vize_relief`) and no shared IR
after it. The costs are concrete and measured, not hypothetical: template
expressions are re-parsed by oxc dozens of times per compile into throwaway
arenas, the Vapor backend runs the entire VDOM transform and then discards it,
three independent parsers read the same `.vue` text, and two independent virtual
TypeScript generators disagree about source mapping. The full evidence list, with
file paths, is in [Motivation](./motivation.md).

Davinci is therefore **also a performance project**. The rearchitecture removes
work the current design forces us to repeat, so "Be Fast Above All"
(`ubugeeei-redundancy.md`) is an argument for it, not against it.

| 20  | Editor neutrality                  | **Strict LSP conformance** — full function on Neovim, Helix, Zed, Emacs, not just VS Code; conformance and multi-client smoke tests gate the LSP phase.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| 21  | Assurance creed                    | **Never fail; edge cases must not exist; no false positives, no false negatives; never regress; every conceivable pattern is tested; tests are strict — nothing passes on partial matching.** Translated into mechanism in [assurance.md](./assurance.md): impossibility by construction; elimination by enumeration (construct matrices, property/metamorphic/differential tiers); verdicts-are-proofs diagnostics (three-valued facts with fire-on-proven policy, witness-carrying errors, precision tiers, seeded-defect recall as the FN oracle, suppression telemetry as the FP oracle); one-way ratchets and every-bug-becomes-a-test for regressions; exact-equality-only oracles with a mechanically enforced banned-assertion list; oracle-truth review; and mutation testing as the measure of strictness.                                                                                                                                                                                                                                                                                                   |
| 22  | Priority order                     | **Performance and correctness are co-equal and supreme. Size and extensibility come second. Implementation simplicity is explicitly not a goal** — difficult is fine. "Performance" includes memory (peak and steady-state) as one budget family. Trade-off resolution: performance/correctness never yield; size holds its budgets (#19) against performance's appetite (monomorphization bloat is watched, not banned); extensibility never taxes the hot path (#15's two tiers exist for this); and a simpler implementation loses to all of the above. Complexity is unbounded _inside the disciplines_ — contracts, verifiers, Folio inspectability — which is how this coexists with `ubugeeei-redundancy.md`'s "do not accumulate hacks as architecture": hard code with a verifier and a dump is engineering; hard code without them is a hack.                                                                                                                                                                                                                                                                |
| 23  | Compatibility policy (per surface) | **Vize-internal interfaces: not a goal during Davinci** — vize is experimental; crate APIs, CLI internals, dump/cache formats may break freely until contracts GA (phase 6); deprecation aliases are courtesy. **The compiler: compatibility is paramount, tiered by backend** — **VDOM and SSR hold the hard byte-parity bar**: the _gate_ is corpus byte-identity of emitted output (behavioral identity with Vue semantics is the _reason_ the bar exists, not a second oracle); waivers get the strictest review; **Vapor is an experimental surface** — upstream Vapor is itself fluid, so Vapor holds behavior-level compatibility (observable DOM results, reactivity semantics — sprout-style behavioral oracles) with maximal freedom in emitted shape. **Linter / type checker / semantic analysis: correctness and robustness outrank compatibility** — no bug-for-bug parity chasing with vue-tsc or eslint-plugin-vue; where upstream is wrong, Vize is right and the divergence is documented with its justification.                                                                                    |
| 24  | v1 gating                          | **Davinci completion is the precondition for v1 alpha.** The foundation is not built twice: every roadmap phase culminates in the v1 go/no-go (`docs/release/v1-alpha-go-no-go.md`), and v1 ships on the Davinci substrate.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| 25  | Implementation regime              | **AI agents implement; the maintainer reviews.** Roadmap items are written as agent-executable tasks with **machine-checkable acceptance criteria** (gates, budgets, oracles — not prose intent), sized for reviewable PRs.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| 26  | Migration fallback                 | **In-phase flag fallback only.** While a phase is live, the replaced lane stays behind a flag for emergency escape; at phase exit the old lane is physically deleted and the policy becomes fix-forward. No auto-fallback on internal errors — dual lanes must not fossilize.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| 27  | Surface freeze                     | During Davinci, **Fresco and Marquette are feature-frozen** (parity maintenance only). Musea and Doctor remain live surfaces and migrate on schedule (phase 4 / continuous).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| 28  | MoonBit timing                     | The MoonBit expression dialect lands **in phase 6** with the contracts GA. `ExprRef::Foreign` exists as a type from phase 2 but stays unimplemented until then — accepting the recorded risk that the expression-dialect abstraction is validated by a second implementation only late.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| 29  | JS plugin tier                     | **Users write plugins and custom rules in JavaScript** — a third extension tier alongside compiled-in Rust and WASM dialects, spanning **four hook families: custom lint rules + autofix, custom fact providers, compile transform hooks, and formatter/output hooks**. All families share the constraints: JS runs **outside the fused walks** in batched passes over the napi/vitrine bridge; transform hooks attach at one designated pre-canonical S2 point (never after canonicalization, never inside fusion) and are deterministic, sandboxed to declared inputs, and content-key cached with the plugin's own version in the key; **the synchronization boundary is explicit** — the compile joins user JS at that single point, per-block batches, and nowhere else ("the hot path never waits" governs every other stage, and a cache hit skips the join entirely); transformed output passes the same gates — **a JS transform cannot exempt its output from the parity bar or the verifiers**. Per-plugin cost attribution makes a slow plugin visible, never hidden. The hot path never waits on user JS. |
| 30  | ICE policy                         | An internal compiler error is a **file-scoped failure with an automatic reproducer** — the build reports that file as failed (other files continue), emits a repro package (last-good Folio + pipeline string + config) replayable via `vize repro`, and never silently degrades to possibly-wrong output.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| 31  | Corpus growth                      | The corpus is **expanded substantially and re-reviewed every phase**. Phase 0 audits construct coverage against the matrices and adds real projects for the surfaces Davinci first-classes (pug, JSX, Vapor, petite-vue); each subsequent phase re-audits for the surfaces it touches.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| 32  | AI loop autonomy                   | The AI optimization loop may **auto-merge optimization PRs when every gate passes** (corpus parity, bench + memory + size budgets, mutation score, assurance suites) — gate trust is the stated premise, which is itself an argument for gate strictness. Changes touching contracts, semantics, or public behavior remain maintainer-reviewed per #25.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| 33  | Parallelism                        | **Design for parallelism, implement file-parallel.** Stage data is `Send`/immutable-by-stage from birth (avoiding the rustc retrofit years); execution stays per-file rayon until measurements justify intra-file parallelism (block-parallel, Lean-style summary-first).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| 34  | Release operations                 | **High-frequency 0.x releases continue through Davinci** — strangler increments ship in normal releases so Real World Testing feedback arrives per-increment, not per-phase.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| 35  | Completion metrics                 | Davinci declares its own success with **relative targets recorded here and pinned to numbers once phase-0 baselines exist**: compile throughput and peak memory improved (not merely held), keystroke→diagnostics p95 halved, fact-adoption in the linter raised from 26/345 to the neutral-core majority, source maps on all backends, and the consumption/rule-parity matrices with no orphans. v1 go/no-go (#24) is the external gate; these are the internal ones.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| 36  | Formal methods                     | **Surgical formal verification where the domain is small and the guarantee load-bearing** ([assurance.md](./assurance.md#formal-methods--surgical-not-total)): an executable S3 reference semantics in Lean (spec + differential oracle + proof substrate), lattice/effect-grouping/IVM-linearity theorems, an independent Lean folio checker (Lean4Lean discipline), and provably-total decidable checkers (HTML content model). Formalism as a scalpel, never a lifestyle (the Effekt retreat).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| 37  | Croquis migration depth            | **Phase 1 rewrites croquis's input layer wholesale** (expression access, identifier enumeration, the fast/slow scanner — all onto retained oxc ASTs); tracker internals migrate incrementally as they become fact groups in phase 4. Risk spread over two phases instead of one big-bang rewrite.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| 38  | Vapor runtime                      | Vapor-generated code **calls upstream `@vue/runtime-vapor` public APIs** — emitted shape is free (per #23's experimental tier), the runtime surface is shared. Vize-bundled vapor helpers are off the table unless phase 3 measurements reopen the question.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| 39  | Dependency policy                  | **Runtime dependencies are strictly curated** (pin + audit + feature isolation — wasmtime only behind resident/extension features; salsa resident-tier only; oxc-style rev-pinning), **CI-only tooling is admitted leniently** (cargo-mutants, the Lean toolchain) under a separate supply-chain lane.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| 40  | v-model semantics                  | **Contract vs realization, confirmed.** `ui.model` carries only the binding contract in the neutral core (reads, writes, value-type flow; element kind and modifiers as attributes); realization — IME composition guards, checkbox arrays, `.lazy` — is **runtime-owned by declaration**, selected per target at S4 lowering, never expanded in S2 and never reimplemented by the compiler. Pinned by behavioral tests with IME event scripts.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| 41  | Formatter redesign                 | Glyph's phase-4 reimplementation on S1 **redesigns the output style intentionally at the same time**. The oracle is _not_ byte-compatibility with old Glyph: the four corpus properties (idempotence, parse-preservation, lint-agreement, pug) remain the exact invariant gates, plus a **written style specification** whose fixtures pin every intentional decision; churn against old output is reported for review, not gated. The style direction itself is a **blank-slate phase-4 discussion** — no direction is pre-committed.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| 42  | Diagnostics UX                     | **rustc/Elm-grade structured diagnostics as a first-class goal**: span labels, help text, fix suggestions, and witness-derived "why" expansion (#21's witnesses double as the explanation data), with **i18n (en/ja/zh) extended to all diagnostics** on the unified channel.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| 43  | Browser type checking              | **Deferred beyond phase 6.** Projection emission stays wasm-capable (consistent with #18), but in-browser check execution waits on the tsgo-in-wasm landscape; the playground shows projections without executing the checker.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| 44  | Memory vs latency default          | **Latency-first inside a hard RSS ceiling.** Every execution form carries an RSS cap (machine-scale presets, user-configurable); within the cap, spend memory for latency freely; at the cap, LRU eviction — never cap-less growth, never adaptive heuristics that make behavior unreproducible.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| 45  | Communications                     | Davinci stays **repository-internal for now** — no site publication, no blog announcement. Revisit when the maintainer chooses; nothing in the docs assumes public visibility.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |

## Relationship to the mission

`ubugeeei-redundancy.md` requires: performance as a product requirement, Vue
toolchain scope, "clear data ownership, explicit phases, narrow contracts,
deterministic behavior, testable outputs", and VoidZero assets as infrastructure.
Davinci is the structural answer to the third requirement — explicit phases and
narrow contracts _are_ the multi-stage IR — while decision 1 preserves the second
and the performance gates in the roadmap enforce the first.
