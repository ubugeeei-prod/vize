# P5-6b — Maestro diagnostics wave

Contract: [phase-5-tasks.md](../phase-5-tasks.md#p5-6b--maestro-diagnostics-wave).
Landed 2026-09-22.

## What landed

The diagnostics request path reads the resident SFC parse and the P4-5a
post-pass. It no longer calls `parse_sfc`.

- **Memoized rejection.** `vize_resident::sfc_descriptor` now returns
  `ParsedSfc`: the shared descriptor, or the parser error (message, code,
  line/column). A failed buffer is one revision, same as a successful one.
  `ResidentDocuments::descriptor` is still `Option` and drops the error for
  hover, completion and definition. Diagnostics call `parsed` /
  `ServerState::sfc_parsed` and publish that one `vize/sfc` diagnostic, then
  skip dependent diagnostics — the same short-circuit as before.
- **Request path.** `DiagnosticService::descriptor_for_collect` replaced
  `parse_sfc_for_collect`. `collect`, `collect_lint_only` and the native
  script-syntax check all read it. Art and inline-art virtual TypeScript
  take the descriptor from that memo instead of parsing again. Corsa
  diagnostics are still assembled only by
  `vize_canon::projection::assemble_diagnostics` in
  `ide/diagnostics/corsa/collect_virtual.rs`. No second assembler.
- **Not this wave.** Semantic tokens, inlay hints and `with_content` stay on
  `parse_sfc` (P5-6c). Projection reuse is P5-7.

## Ceiling

`tests/tooling/davinci-maestro-parse-sfc-ceiling.test.ts` pins
`parse_sfc(` on non-comment lines of `crates/vize_maestro/src` at exactly
**47** (50 after P5-6a, 81 before it). The three request-path sites removed
are `ide/diagnostics/collectors.rs` and the art / inline-art virtual
TypeScript generators. The diagnostics tree has none left. A new site
fails; a removed one fails until the ceiling is lowered.
