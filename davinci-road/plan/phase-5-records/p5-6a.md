# P5-6a — Maestro hover, completion and definition wave

Contract: [phase-5-tasks.md](../phase-5-tasks.md#p5-6a--maestro-hover-completion-and-definition-wave).
Landed 2026-09-22.

## What landed

The wave's request paths read the SFC descriptor from the resident tier
instead of calling `parse_sfc` per request — one parse per buffer revision,
shared by every request until the next keystroke.

- **`vize_resident::descriptor`.** `sfc_descriptor` is a salsa query over a
  `SourceFile` input (path = filename, text = buffer); its value is a
  `SharedDescriptor`, the owned descriptor behind a shared pointer, equal
  exactly when filename and source are equal (`parse_sfc` is a pure
  function of both, so salsa's backdating is sound). `ResidentDocuments`
  keys documents by the client's identity (a URI, or a path for a component
  read from disk): a lookup whose text equals the stored buffer starts no
  revision and reads the memo; a different text is one `set` and one
  re-execution. `close` empties the buffer and recomputes the memo, so a
  closed document's descriptor is released. Salsa's event records are
  drained on every lookup — nothing accumulates in a long-lived process.
- **Maestro.** `ServerState` owns one `ResidentCache` (a `parking_lot`
  mutex held only for the lookup, never across an `.await`), released on
  `didClose`. `IdeContext::descriptor()` fetches the document's descriptor
  once per context (a `OnceLock`); the context's own block detection reads
  the same value, so a request pays at most one lookup for its document.
  Components read from disk (props, slots, events, imported component
  hover, completion metadata) go through `ServerState::component_descriptor`.
- **Sites removed (30 in the wave + the context's own parse).** hover 8
  (`declaration_keyword`, `corsa` ×2, `component_prop`, `component_import`,
  `script`, `template`, `component_tag`), completion 3 (`script/context`,
  `template/bindings`, `template/component_meta`), definition 12 (`script`
  ×3, `template` ×4, `slot` ×2, `service`, `art`, `component_event`),
  template scope 3 (`analysis`, `v_for`, `v_slot`), references 4
  (`canonical`, `script`, `structural/style`, `structural/template`), plus
  `IdeContext` construction. The contract's counts (hover 7, definition 6, …
  of 71) predate sites added since the re-cut; every site under the five
  wave paths is gone.

## Ceiling

`tests/tooling/davinci-maestro-parse-sfc-ceiling.test.ts` pins the
`parse_sfc(` call sites on non-comment lines of `crates/vize_maestro/src`
at exactly **50** (81 on the base) and asserts the five wave paths have
none. A new site fails; a removed one fails until the ceiling is lowered,
so the count only falls. An injected-call case proves the scan counts code
and skips comments. P5-6b and P5-6c take it to 0.

## Exact accounting

`crates/vize_maestro/src/server/state/resident/tests.rs` drives the real
services (`HoverService::hover`, `CompletionService::complete` through the
completion context, `DefinitionService::definition`) and reads the
resident tier's counts after every keystroke:

| Scenario                                     | Lookups | Parses |
| -------------------------------------------- | ------: | -----: |
| one keystroke, then hover + completion + def |       3 |      1 |
| the same three requests, buffer unchanged    |       3 |      0 |
| `didClose`, then the three requests again    |       3 |      1 |

Six consecutive keystrokes each give exactly `3 / 1`, and every served
descriptor equals the clean parse of that keystroke's text. Before this
change each of those requests parsed the buffer in its context
construction and again in every wave site it reached.
`crates/vize_resident/tests/descriptor.rs` proves the query in isolation:
lookups between two edits share one parse, an edit to one document leaves
the others' memos validated (not re-run), the filename is part of the
descriptor, and a reopened document parses again — every served
descriptor's full debug print equal to the clean parse's.

## Keystroke cost

`cargo run --release -p vize_maestro --example keystroke_wave -- playground/src
tools/benchmarks/crates/davinci_harness/fixtures/large.vue --keystrokes 40`:
20 SFCs with an interpolation (the playground project plus the benchmark
harness's 30 KB `large.vue`; 5 files without one skipped), 40 keystrokes
each, then one hover, one completion and one definition at the first
interpolation, each timed from its context's construction to its response
(800 samples per feature). Base (`9f2e1434d`) and branch binaries ran
alternately on one developer machine (Apple silicon, shared with other
builds), nearest-rank p95 in µs:

| Feature    | Round 1 base → branch | Round 2 base → branch | Round 3 base → branch |
| ---------- | --------------------- | --------------------- | --------------------- |
| hover      | 766 → 679             | 658 → 649             | 846 → 822             |
| completion | 657 → 530             | 564 → 517             | 657 → 631             |
| definition | 1045 → 837            | 953 → 833             | 1312 → 1041           |
| whole wave | 2360 → 2020           | 2105 → 1997           | 2943 → 2507           |

The branch's p95 is lower for every feature in every round. Medians moved
less (whole wave 527 → 432, 440 → 429; round 3's branch run met a load
spike — 37 ms maximum — and its median rose, 438 → 551): `parse_sfc` is a
zero-copy block split, tens of microseconds on these files, so the wave's
remaining cost is the analysis each request runs, which P5-6b/P5-6c and
P5-7 address. The TS-44 gate (`davinci-resource-budgets.yml`,
keystroke → diagnostics p95 against the P5-11a ceiling of 46 ms, baseline
30.1 ms) runs on every change under `crates/vize_maestro/**`.
