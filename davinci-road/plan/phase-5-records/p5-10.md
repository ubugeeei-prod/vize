# P5-10 — Fault-tolerant analysis

Contract: [phase-5-tasks-later.md](../phase-5-tasks-later.md#p5-10--fault-tolerant-analysis).
Landed 2026-09-22.

## What landed

S1 `Unexpected` and `Missing` holes already survive the P2-8 lowering as
kept S2 ops. `vize_s1_to_s2::partial` names those fragments and the holes
beside them, then `FactManager` computes three groups:

| stratum | group             | what it is                                                                 |
| ------- | ----------------- | -------------------------------------------------------------------------- |
| 0       | `partial-holes`   | `Unexpected` byte ranges and `Missing` tokens / end tags                   |
| 0       | `partial-regions` | kept ops a non-empty `Unexpected` hole does not cover                     |
| 1       | `partial-scopes`  | simple-identifier scope names of those regions                            |

A cursor inside an `Unexpected` hole reads no scope fact. A `v-for` or
slot alias is a fact only when the lowering already recorded it — a
malformed `v-for` expression is not re-parsed (the non-goal: no error
recovery inside expressions). A sibling that did parse still has its
names. Slot-prop names are visible across the owner element, not only
on the attribute.

Maestro's hover and completion paths were not edited. They already
answer in the well-formed region of a file that has a parse hole
elsewhere; the partial facts are the analysis those features can read
when a later consumer needs the fact API instead of a second parse.
