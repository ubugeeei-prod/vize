## The harness

`vize_resident::equivalence::EquivalenceReport::check_file` opens a file in
one long-lived `ResidentDatabase` and runs every edit script against it. After
the open and after **every** step it reads every artifact the tier serves —
each block's identity, position (`start`), S0 key, S1 key and tokenizer
findings, S2 page and its diagnostics — and compares the whole list, exactly,
with `compute_file_artifacts` run from scratch on the same text and
configuration. A mismatch records the file, script, step and the first
differing block and field.

**Scope proof.** Files, script runs, applied steps, skipped operations,
comparisons and compared blocks are counted. `verdict()` fails a run with no
file, no applied step or no compared block exactly as it fails a mismatch;
`a_run_that_compares_nothing_fails` pins both the empty run and a file opened
without any edit.

## The edit scripts

Six committed scripts in `tools/commands/davinci/incremental-equivalence/scripts/`,
block-relative so they apply to any SFC (an operation whose target block is
absent is counted as skipped, never silently dropped):

| Script                   | What it exercises                                                     |
| ------------------------ | --------------------------------------------------------------------- |
| `01-template-keystrokes` | one step per character inside the template: every partial element     |
| `02-above-blocks`        | inserts above every block: positions move, no content changes         |
| `03-script-edits`        | script and `script setup` edits above the template                    |
| `04-style-edits`         | a `v-bind()` rule reaching the style's S2 page, then a letter change  |
| `05-length-preserving`   | letter bumps in template, script, style: same length, different bytes |
| `06-config-changes`      | Vue 2 ↔ Vue 3 project config interleaved with template edits          |

## The seeded defect

The `seeded-stale-cache` feature (never on in a real build) weakens the
firewall's `BlockSource` equality to kind, header and content **length** — a
key covering less than its input, the exact bug class the assurance rule
names. TS-42 must catch it: only the length-preserving and config scripts can,
and they do.

## CI

`.github/workflows/davinci-incremental.yml`, job `incremental-equivalence`,
runs on every PR and push touching `crates/vize_resident/**` (and the stage
crates, the SFC splitter, the harness and its scripts):

1. hydrate the corpus shard;
2. `cargo test -p vize_resident` — the firewall accounting and the committed
   plane above;
3. `rust-script tools/commands/davinci/incremental-equivalence.rs
--corpus-shard --fixtures tests/_fixtures/_projects --fixtures
tests/_fixtures/vue-language-tools` — TS-42 on the shard (exit 1 on any
   mismatch or an empty scope);
4. the seeded run: the `equivalence` test under `seeded-stale-cache`, and the
   driver with `--seeded`, which passes only when the defect is caught.

`tests/tooling/davinci-incremental-workflow.test.ts` pins the job's commands,
the trigger paths, the shard (driver and workflow agree) and the script set.
Making the check branch-protection-required is a repository setting; the
workflow runs on every such PR and auto-merge waits on it.
