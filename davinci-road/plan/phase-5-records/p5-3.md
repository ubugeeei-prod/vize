# P5-3 — Global summary

Contract: [phase-5-tasks.md](../phase-5-tasks.md#p5-3--global-summary).
Landed 2026-09-23.

## What landed

`vize_davinci::summary::GlobalSummary` holds the orphan facts no single SFC
owns. Global components are the P4-3b project group (`COMPONENT_USAGES`).
App-level provide/inject is the P4-3f project group (`PROVIDE_INJECT`).
Dialect-wide directives sit in the same summary. Each fact is fingerprinted
alone, under `vize.davinci.global-summary`, which is not the per-file
domain. An `SfcSummary` declaration with the same name and contract does
not share that fingerprint.

A file records the project facts it resolves, including a name the summary
does not export yet (stored with no fingerprint). `GlobalSummary::invalidated`
returns exactly the files for which one of those fingerprints is missing or
different. A file that did not resolve the new fact stays fresh.

## Evidence

`cargo test -p vize_davinci --test global_summary` — 2 tests, exit 0:

- adding `AppDialog` invalidates exactly `host.vue` and `page.vue`. `app.vue`
  resolves nothing and `nav.vue` resolves only `RouterLink`, whose fingerprint
  is unchanged. A later `AppToast`, `theme` provide, and `focus` directive
  invalidate nobody who already re-recorded `AppDialog`;
- a duplicate global component name is refused.
