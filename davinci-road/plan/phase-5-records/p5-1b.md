# P5-1b — Ambient key manifests

Contract: [phase-5-tasks.md](../phase-5-tasks.md#p5-1b--ambient-key-manifests).
Landed 2026-09-22.

## What landed

`vize_davinci::key::manifest` declares, for every cached artifact, which
**ambient** inputs — everything that is not the artifact's own content — its
cache key must cover, and folds their values into the key:

- **`AmbientInput`** — `project-identity`, `tsconfig-content`,
  `project-config`, `toolchain-version`, `corsa-version`, `feature-flags`,
  `platform`: the contract's five plus the two the Corsa session and the S2
  lowering need (the project's identity; the Vize configuration that selects
  the Vue line).
- **`CachedArtifact`** — `s0.source-block`, `s1.surface-page`, `s2.page`,
  `projection.virtual-ts` (P5-7) and `corsa.session` (P5-8), each with its
  `inputs()` and the stages its content key may come from.
- **`KeyManifest`** — the values, one per input, kept sorted so insertion
  order can never reach the hash.
- **The fold** — `ArtifactKey::with_manifest(artifact, &manifest)` keeps the
  content key's stage and recipe version and re-hashes under a separate
  domain tag (`vize.davinci.key-manifest`), over the content digest, the
  artifact name and the manifest entries. `KeyManifest::fingerprint` is the
  same fold without a content key, for the Corsa session. Both **refuse** a
  manifest that does not set exactly the artifact's declared inputs
  (`ManifestError::Undeclared { missing, extra }`) or a content key of a
  stage the artifact cannot be keyed by (`ManifestError::WrongStage`): a
  missing input is the corruption bug, an extra one is an input nobody
  declared, and neither is silently accepted.

[key-manifests.md](../key-manifests.md) is the human form of both tables,
with the reasoning per row.

## Evidence

`cargo test -p vize_davinci --test key_manifests` (5 tests), run by both
TS-43 lanes of `davinci-incremental.yml`:

- every declared input of every artifact changes its key, and the flipped
  keys are pairwise distinct (22 flips over the five artifacts);
- nothing else does: reversed insertion order and re-setting a value to the
  same thing keep the key;
- a manifest missing `project-config` for `s2.page`, or adding `platform`
  to it, is refused with the exact `missing`/`extra` lists; an S0 key cannot
  fold as an `s2.page`, and a fold keeps stage and version;
- the doc test reads `key-manifests.md` with `include_str!` and compares both
  tables with the code exactly — the input list in order, and per artifact
  its name, content stages and inputs.

TS-43's goldens are unchanged: the manifest never touches a content key.

## Not in this task

- Consuming the manifest: P5-8 widens `CorsaSessionKey` to
  `corsa.session`'s row; P5-7 keys projection segments; P5-13 adds the JS
  plugin cache's row when that cache exists.
- The resident tier keeps in-memory caches whose ambient inputs cannot
  change within a process except `project-config`, which is a salsa input;
  a persisted resident cache would fold these manifests.
