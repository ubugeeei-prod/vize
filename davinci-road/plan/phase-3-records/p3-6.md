# P3-6 - Vapor S3 generation contract

The native generation slice now consumes the S3 artifact instead of accepting
and discarding it. The generic graph verifier, aligned partition facts, and a
backend admission check produce a private `VaporS3Artifact`. Its checked payload
is projected to the shared generator IR without consulting the legacy template
AST. Earlier S1/S2 storage is dropped before generation.

P3-6 remains open. This is a bounded production route, not full Vapor parity or
permission to delete the legacy lane. Full semantic context, the remaining
constructs, TS-33 coverage, and measured end-to-end benchmark improvement remain
required.

## Executable boundary

- Standard Vue 3 DOM mode, no custom elements/renderer, SSR, patterned syntax,
  or inline setup mode. Both prefix-identifier settings work; binding metadata
  is admitted without prefixing (the SFC configuration).
- One native root: an element, or one conditional chain or loop. Ordinary HTML
  template elements: `div`, `span`, `main`, `section`, `article`, `header`,
  `footer`, `nav`, `aside`, `button`, `strong`, `em`, `b`, `i`, `small`, `label`,
  `input`, `img`, `br`, `hr`, `ul`, `ol`, and `li`. A button or list item nested
  in another within one template string is refused because the HTML parser
  repairs that structure; a control-flow body is a separate template.
- Static attributes/text, and JavaScript prop, interpolation, handler,
  branch-condition, loop-source and loop-key operands: direct references, or
  expressions whose retained S2 AST the generator consumes. Static event names
  with modifiers, `v-show`, `v-html`, `v-text`, and a static `class` merged
  into `:class`. Native binding targets, child regions, unique operand roles,
  effect classification, and explicit DOM/effect order must agree with the
  checked projection.
- Scoped-style attributes and the existing source-map generator remain in the
  shared emitter. This does not expand the current source-map precision claim.

Adjacent static text and direct-reference interpolations retain S2's validated
compound parts as S3 operands. The emitter coalesces each text run into one DOM
address and preserves the static template bytes and following sibling offsets.
Missing, stale or misaligned compound facts are rejected; opaque display strings
are not reparsed. Static event names use the same modifier/delegation policy as
the legacy route, including non-delegated events and once/capture/passive options.

Components, slots, template-wrapped or directly nested control flow, models,
custom and memo/once directives, dynamic event names, multi-statement handlers,
TS-dialect or opaque/foreign values, context-reserved roots (`_ctx`, `$props`,
`$attrs`, `$slots`, `$emit`), entity-encoded literals, other prop merging,
runtime refs, fragments, parser-context elements, and other option shapes
explicitly select `Legacy(reason)`; `legacy.selected` counts explicit
retained-lane selection for baselines and A/B runs. S2 diagnostics and unconsumed surface
provenance also select that route. The legacy parser still preflights diagnostics
for both routes; recoverable diagnostics retain legacy behavior.

A rejected graph, stale/misclassified partition, missing/duplicate required
operand, or broken ordering contract produces no code. Acceptance cannot be
constructed from a boolean or subsequently fall through to legacy lowering.
Selection counters distinguish `accepted`, `rejected`, and each `legacy.*`
reason under `davinci.s3_vapor`.

## Control-flow slice

S3 `If` and `For` ops now project natively to the shared `If`/`For` IR:
`v-if`/`v-else-if`/`v-else` chains with direct-reference conditions, and
element-carried `v-for` over a direct-reference or integer-range source with
plain-identifier value/key/index aliases and an optional direct-reference
`:key`. The loop body's `:key` binding is lifted into the loop; `key` anywhere
else selects `legacy.binding`. Each branch or loop body is exactly one native
element instantiated from its own template, so control flow nests inside
admitted elements to any depth, and a chain or loop may be the template root.
A controlled-region closure requires every op inside a branch or loop body to
carry its dynamic partition; a missing one, a branch region without its
condition, a duplicated or non-trailing unconditional branch, or a missing loop
position is rejected rather than rerouted.

`davinci.s3_vapor.legacy.control_flow` counts the refused control-flow shapes:
`<template>` wrappers and carrier branch keys (S2 side facts that S3 does not
carry), branch or loop bodies that are fragments, text, or directly nested
control flow, and aliases that are destructured (S2 enumerates no names for
them), duplicated, underscore/dollar-prefixed, or template globals. Compound
conditions, sources, and keys select `legacy.expression_or_encoding`.

Block node ids reserve one id per branch/loop block exactly as upstream (and
the retained lane) do, so the published Vapor fixture corpus stays at 116/117
(the tracked #1161 failure) with these shapes on the native route. Templates
are byte-identical to the retained lane for every admitted probe source.

Mounted traces exposed a shared fast-removal defect: the retained lane marked
any single-element loop inside a branch or loop as its parent's only child, so
emptying it cleared siblings (for example a title beside the rows). Both lanes
now set the flag only when the loop is its parent element's sole child. The
test runtime (`@vue/runtime-vapor` 3.6.0-beta.10) also leaves key/index refs
stale on unkeyed updates; rc.6 fixes that in `updateAt`, so the object-loop
scenario is keyed to observe compiler behavior rather than that runtime gap.

## Expression and attribute slice

S2 parses every template expression once. For admitted non-reference
operands, the bridge copies that retained oxc AST structurally into the output
arena (`CloneIn`, not a parse) and attaches it as the generator node's `js_ast`;
the shared retained resolver then rewrites from the tree. S2 never parses
compound text parts, so each non-reference part takes its single parse at the
bridge through `JsExpr::parse_in`, S2's own admission rule. An AST is attached
only when its text is exactly the operand text and `js_module_compatible`
holds, so the generator never falls back to a counted reparse; replacing an
operand's text orphans its AST and selects `legacy.expression_or_encoding`.
Loop keys now resolve node-aware in the shared generator (byte-identical for
the retained lane, which also carries P1-5 ASTs).

Handlers keep the generator's reference/function/inline classification, so
`count++`, assignments, calls with `$event`, and arrow or function callbacks
share the retained lane's code. `v-show` lowers to the builtin directive,
`v-html`/`v-text` to element effects on childless elements, and a valued static
`class` merges ahead of its `:class` as the retained lane does; static `style`
beside `:style` stays legacy (the lanes do not merge it). Binding metadata is
admitted when identifiers are not prefixed: the retained lane then leaves
expression text as authored and metadata only steers the shared generator
(`$props` resolution), which both lanes share. `VaporCompilerOptions::
davinci_retained_lane` replaces the former empty-metadata trick for baselines.

A lane comparison over compound props, text, handlers, loops, branches,
directives and metadata found identical code modulo node numbering, except
for context-reserved roots: prefixing rewrites `$attrs.x` onto `_ctx` while the
generator leaves it bare, so those roots stay legacy. Mounted traces cover
compound classes/styles/titles/text, five handler shapes including `$event`,
and `v-show`/`v-text`/`v-html` updates, for VDOM, native and retained Vapor.
Two reviewed snapshots differ only in parent-first node numbering, and fixture
parity stays at 116/117.

## Evidence and remaining limits

- Graph payload mutation changes attributes, text references, and event handlers
  in emitted code even with a decoy source. Scratch source/arena lifetime tests
  prevent accidental reuse of an earlier AST. Replacing an ordering edge with a
  duplicate is rejected; permuting the serialized edge list remains valid.
- Production probe tests pin zero legacy core/Vapor walks and zero expression
  reparses for admitted native shapes. Explicit legacy selection retains the
  P2-12a ladder's two walks and exact visit counts; the production reparse floor
  remains unchanged. These are structural measurements, not a latency claim.
- The text/event expansion covers mixed and adjacent interpolations, sibling
  identity through Unicode/null/number updates, focus/custom/non-bubbling events,
  keyboard versus mouse modifiers, composed key/DOM guards and combined listener
  options. Mounted tests caught two shared
  generator defects: key filters were dropped when DOM modifiers were present,
  and multiple listener options lacked separating commas. Both are now covered
  by independent expected delivery traces as well as VDOM/Vapor agreement.
  Mouse-only modifiers normalize click to contextmenu/mouseup, keyboard aliases
  and arbitrary key names stay in key filters, and non-bubbling events attach
  directly rather than relying on document-level delegation.
- The Rust-owned static/dynamic scenario still matches the independent expected
  mounted DOM/Vapor traces. Nested/separated native nodes additionally preserve
  measured DOM identities across object replacement, prop/text updates, disabled
  clicks, and unmount, with exactly two delivered events.
- Testing the fallback exposed nontermination on rejected JS such as `(`. The
  recursive text-scanning rewrite was removed: failed parses terminate with
  opaque passthrough in the existing tolerant mode; prefixing-enabled expression
  validation still reports errors and emits no code.
- Control-flow evidence: an exact-reason refusal table, payload mutations that
  change conditions, loop sources and keys in emitted code, and five corrupt
  graphs that pass the generic verifier but are rejected. Branch toggles,
  keyed reorder/insert/delete, unkeyed in-place patching, nested loops inside
  branches, object/range loops and root-level chains/loops all have
  independently specified mounted DOM, event and identity traces for VDOM and
  Vapor; the nested scenario also runs over the retained lane. Every mounted
  and benchmark source is pinned to zero legacy walks and reparses.
- Four reviewed output snapshots reflect parent-before-child node numbering and
  equivalent child-index navigation. The adjacent dynamic-child fixture also has
  an independently specified mounted update trace.
- References beginning with `$event` remain in the legacy lane. Their handler
  semantics follow Vue: a reference names a component/setup binding; only an
  inline statement receives the implicit event parameter. The Chromium contract
  in #6261 corrects the earlier no-op callback assumption and checks both VDOM
  and Vapor against official Vue 3.5/3.6 and independent expected traces. The
  expression lanes share retained-AST declaration ownership; five pinned
  upstream scope differences also execute authored JavaScript as an independent
  oracle, with the original official output and observations retained.

## Mechanical witnesses

- `cargo test -p vize_atelier_vapor --lib`
- `cargo test -p vize_atelier_vapor --test davinci_vapor_artifact --test davinci_walk_baseline --test davinci_expr_reparse_floor`
- `cargo test -p vize_atelier_vapor --test davinci_mounted_behavior --test davinci_s3_compiled_trace`
- `cargo test -p vize_atelier_vapor --test davinci_event_handlers -- --ignored --nocapture` (Chromium)
- `cargo clippy -p vize_atelier_vapor --lib -- -D warnings`
- `cargo run -p vize_test_runner --bin coverage` (published fixture parity)
- `cargo bench -p vize_atelier_vapor --bench davinci -- vapor_native_pair` compares
  the native/default and explicitly retained legacy routes on identical text,
  event, and control-flow fixtures. The same benchmark can be applied to a pinned base checkout to
  measure the former S3-attempt/fallback cost independently of the direct legacy
  floor. These microbenchmarks do not replace the full corpus promotion budget.
- The full Check and Davinci Lean Actions lanes; the umbrella's remaining
  backend, corpus, performance, and release gates remain independent.

Local smoke measurement on 2026-09-21 (Nix toolchain, ten Criterion samples,
one-second warmup, two-second measurement) put the admitted text fixture at
9.56–9.68 μs and the event fixture at 10.30–10.55 μs. Explicit legacy selection
on the same build remained faster at 7.45–7.58 μs and 8.02–8.08 μs respectively.
The default route at base `a8b17f73b` selected fallback on these fixtures and
measured 11.24–11.75 μs and 11.68–11.93 μs. These sequential local observations
are provisional, not isolated repeated A/B evidence or a promotion pass. The
base/head builds reused a target directory, so the changed crate was cleaned
and rebuilt before measuring the final head to avoid stale artifact reuse;
the Actions A/B lane uses isolated build graphs.

The control-flow slice's same-session smoke run (ten samples, one-second
warmup, two-second measurement, other agents sharing the host) measured the
`control_flow` fixture at 23.38–24.14 μs native versus 16.74–18.21 μs on the
retained lane; `text_runs` 10.45–10.92 μs versus 7.90–8.09 μs and `events`
11.64–12.21 μs versus 8.66–9.12 μs. The native route remains slower at this
fixture size: S1/S2/S3 construction plus admission costs more than the retained
parse/transform/lower on small templates. No promotion claim follows from it.

The expression slice's run (same settings, host heavily shared) measured the
new `expressions` fixture at 17.03–19.51 μs native versus 14.32–14.48 μs
retained, and `control_flow` at 27.49–32.34 μs versus 17.75–20.21 μs; the
spread reflects host contention, and the native gap remains.
