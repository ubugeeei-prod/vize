# P3-13 — Optimization remarks

Contract and vocabulary: [remarks-format.md](../remarks-format.md). JSON
schema: [remarks.schema.json](../remarks.schema.json).

## Slice 1 — the remark substrate (2026-09-21)

**The channel is the observer.** `PassObserver` gains the remark hook
(`on_remark`) beside its seven MLIR instrumentation hooks, plus an associated
const `REMARKS` (default `false`). `run_pipeline_remarked` hands each pass
body a `PassRemarks` bound to the running pass's `PassEvent`, so the `pass` a
remark carries is the pass manager's attribution, never the body's say-so;
`run_pipeline` is that driver with the channel unused, so every existing
caller is untouched. `Pair` forwards to exactly the members that consume
remarks. The P2-3 `CountingRemarkSink` placeholder is replaced: its channel
role is `PassRemarks`, its counting role is `RemarkCounter`.

**Zero cost when detached, measured.** Because `REMARKS` is a const, a pass
guards blocker classification and argument construction on
`RemarkSink::ENABLED` and the path is compiled out under `NoObserver`,
`BudgetObserver`, `TimingObserver` and their compositions.
`crates/vize_davinci/tests/remark_zero_cost.rs` runs a body that allocates
one label per remark under the counting allocator: **0** allocations
detached, **0** under `Pair<Timing, Budget>`, and exactly **3** (one per
pass) under a non-allocating counter — the control that proves the zero is
the observer's absence. The production DOM path calls the hoist body with
the detached `NoRemarks` sink, so shipped output and allocation budgets are
unchanged by construction.

**Structured, ordered, serialized twice.** A remark is
`{stage, pass, kind: applied|missed|analysis, name, span, args}` with typed
args (string / integer / bool, unique static keys). `RemarkCollector`
records owned remarks and finishes them in a walk-independent canonical
order (pass run position, span start, outer span first, name). One
`RemarkLog` prints as the `[remarks]` folio page (both round-trip laws,
`Display` span elision, every rejection message pinned) and as the
schema-versioned JSON document validated against the committed schema by
the strict TS-15 validator. `davinci-opt --remarks <path>` writes the run's
document (empty for the catalogue-free no-op passes, and the file says so),
and `davinci-opt --roundtrip --stage remarks` checks a page's canonicity.

**First real emitter: `s2.hoist-static`.** The pass runs under the remark
channel inside `run_transform`. It explains every element's whole-subtree
eligibility (`static-subtree`) and every non-whole-hoistable owner's props
surface (`static-props`), naming the first blocker in the lattice's own
order: the svg quirk, a `ref` attribute, the first unhoistable binding (with
the failed `ui.bind` gate: `dynamic-name`, `modifier`, `reserved-key`,
`no-value`, `non-constant`), or the first child op making the subtree
dynamic. The blocker functions _are_ the rule — `props_all_hoistable` is now
`props_blocker(..).is_none()` and the binding predicate is
`binding_blocker(..).is_none()` — so a remark cannot explain a decision the
analysis did not make. `crates/vize_s1_to_s2/tests/hoist_pass_remarks.rs`
pins the full page for the `levels`, `positions` and new `blockers`
fixtures (7 applied / 20 missed on `blockers.vue`, every blocker and `ui.bind` rule), and
re-derives every remark's kind from the published `StaticFacts` plus an
owner census walked over the S2 folio — a separate tree and a separate walk.
Facts under a collector equal facts under `NoObserver`.

## Slice 2 — TS-32 corpus remarks-diff (2026-09-21)

`crates/vize_s1_to_s2/tests/davinci_remarks_corpus.rs` sweeps the 433
in-repo `.vue` fixtures under `tests/_fixtures` (`_git` submodules and
`node_modules` excluded), runs each inline HTML template through lowering
and the S2 transform pipeline under a `RemarkCollector`, and requires the
resulting `[remarks-corpus]` page to equal the committed
`tests/_fixtures/davinci-remarks-baseline.folio` exactly: 433 files, 1001
remarks, 138 applied / 863 missed at the first bless. A difference fails
with the keyed remarks-diff (`vize_davinci::folio::remarks::diff`:
`regressed` / `improved` / `rekinded` / `reargued` / `added` / `removed`).
The `UPDATE_REMARKS_BASELINE=1` bless **refuses** any `applied → missed`
transition that the baseline's `[remarks-corpus.explained]` ledger does not
list with a reason, and a plain run rejects a ledger entry naming no
baseline `missed` remark. Both directions were exercised by hand-edited
baselines: a flipped entry fails the plain run as `improved`, and a forged
`applied` entry makes the bless refuse the resulting `regressed` identity.

The lane is feature-gated like its siblings and runs in the required
`clippy-and-test` job right after the DOM corpus.
`tests/tooling/davinci-remarks-diff-lane.test.ts` pins the manifest entry,
the CI command and the TS-32 suite row.

## Slice 3 — remarks in the Spolvero feed, and the C-13 backlog (2026-09-21)

The feed gains a `remarks` member: remark document items plus `path`, spans
in file byte offsets. It is additive to feed v1, optional in the schema so
earlier documents stay valid, and emitted by every producer.
`vize_curator::inspector::template_remarks` lowers each inline HTML
template and runs the S2 transform pipeline under a collector. The
inspector payload, the wasm `analyzeSfc` result, and the `vize inspector`
agent report now carry the decision explanations beside the S1 pages.
`davinci-opt --folio-dir` adds the run's own log. The curator and vitrine
tests derive the expected spans from the source text, not from the
producer. A pre-P3-13 v1 feed still validates.

C-13's first version mines the TS-32 corpus. `mine_missed` groups missed
remarks by reason: the arguments after the subject, which is the
vocabulary's first argument. The groups are ranked by hits, and the TS-32
test pins the rendered [remarks-backlog.md](../remarks-backlog.md). The
first pass reports 24 reasons. The top items are dynamic-text children
(185 hits), `v-on` on the props surface (151), and non-constant `v-bind`
values (98).
