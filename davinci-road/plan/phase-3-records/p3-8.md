# P3-8 - SSR S4 string-plan path

The SSR thin path (charter #9) reads the static partition as facts: supported
SSR compiles build S1, lower S1 to S2, lower S2 to S3, verify the S3 artifact,
and consume the exported partition facts while building the S4 string plan.
Since the third slice the plan is also the **emitter input** for the admitted
surface; everything else selects the legacy AST walker under a typed reason.

## Boundary

The bridge is selected for standard Vue 3 SSR templates with no preserved
comments, no custom renderer, no patterned-template desugaring, and no
custom-element matcher. Those shapes are the option subset where the S2 source
view and existing SSR transform view currently agree without an extra recovery
policy.

Plan emission additionally requires no Croquis analysis, no inline render
closure, the Vue 3 dialect, and no experimental in-tag comments (the same
option firewall the S2 DOM lane keeps). Binding metadata (non-inline
`$setup.` / `$props.` / `$data.` / `$options.` prefixes), `is_ts`,
`scope_id`, SSR CSS variables, and the opt-in single-anchor source map are
admitted.

This does not close P3-8. The remaining work is to consume Croquis-informed
rewrites once the shared transform door publishes them, record the canonical
Real Project Matrix run as the TS-11 witness, and delete the legacy walker
per charter #26.

The 2026-09-13 second slice made segment payloads typed before SSR code
generation. `SsrStringSegment` carries `SsrStringPayload` values such as tag
names, attribute names, expressions, slot names, comments, and loop bindings
instead of an ambiguous optional source string.

## Third slice: plan emission for plain elements (2026-09-21)

`vize_atelier_ssr::s4::select_ssr_lane` is the production selector. It returns
`Emitted(SsrCodegenResult)`, `Legacy(reason)`, or `Rejected(diagnostics)`; the
compile path runs the legacy walker only for the latter two. The emitter
(`s4/emit*`) walks plan segments in order and never reads the legacy template
AST; the legacy parse and transform still run because the public API returns
their tree and diagnostics.

Owned surface: native elements (minus raw-text / RCDATA parents, `<template>`,
`<select>` / `<option>`), static attributes, static-name `v-bind` without
modifiers (including the same-name shorthand), object-spread `v-bind`,
`v-on` (dropped by SSR), static text, `{{ }}` including S2's merged
text/interpolation runs, the fragment markers, and the single fallthrough root
(`_ssrRenderAttrs(_mergeProps(..., _attrs))`). Dropped comments follow S2's
`drop.comment` condensing, which is the shipped parser's.

| subject         | decision                                                                                                  |
| --------------- | --------------------------------------------------------------------------------------------------------- |
| Emitter input   | Plan segments carry their S2 operand (`SsrSegmentSource`) and the fact index (the S2 page-order id).      |
| Attached order  | An element's attributes and bindings interleave in authored order; binding facts stay in page order.      |
| Expressions     | `vize_s1_to_s2::TransformExpressions` runs the byte-proven transform rewrite without DOM consumption.     |
| Partition facts | An expression segment must read a dynamic fact; a static fact on one is a rejection, never a guess.       |
| Entities        | Text whose entities decode to whitespace keeps legacy: the shipped parser condenses after decoding.       |
| Output framing  | `SsrCodegenContext::begin_render` / `finish_render` are shared, so signature and preamble cannot diverge. |
| Failure mode    | Unowned shapes return a typed legacy reason; broken plan invariants become `ExtendPoint` diagnostics.     |

Selection counters (profiler): `davinci.s4_ssr.accepted`,
`davinci.s4_ssr.rejected`, and `davinci.s4_ssr.legacy.<reason>` for `options`,
`surface_semantics`, `operation`, `element`, `binding`,
`expression_or_encoding`, and `structure`; the witness counters
(`davinci.s4_ssr.files`, `segments`, `static_segments`, `dynamic_segments`,
`partition_facts`, `s2_diagnostics`) are unchanged.

The differential battery (`s4/differential_tests.rs`) compiles every fixture on
the selected lane and with the legacy walker pinned, under four option sets
(default, scoped + CSS vars, bindings + TS, source map), and requires
byte-identical code, preamble, map, and diagnostics. Admitted fixtures must be
emitted from the plan (so a silent fallback cannot make the battery vacuous);
refused fixtures must stay legacy; TypeScript fixtures are owned exactly when
`is_ts` is set. The existing SSR snapshot suite runs through the production
selector unchanged.

The traversal recorder now pins a production floor beside the fixed pre-S2
baseline: `small`, `stress-wide`, and `stress-interp` drop the SSR codegen
walk (2 -> 1 walks; 16 -> 8, 4 -> 2, 2002 -> 1001 visits).

## Fourth slice: control flow and element directives (2026-09-21)

The plan now carries region boundaries: `If` / `Branch` / `CloseBranch` /
`CloseIf` and `For` / `CloseFor` (branches are regions, not ops, so they read
the chain's fact). The emitter ports the legacy child-list walk over those
regions: fragment markers from the legacy child count (S2's merged text runs
count one child per part), the single fallthrough candidate among elements and
`v-if` chains, `disable_nested_fragments` inside loops, the empty-comment
`else`, and the keyed `<template v-for>` fragment rule read from S2's
`for_wrappers` fact.

`v-for` bodies enter the transform scope through
`TransformExpressions::enter_for` and push the legacy codegen's destructure
params, so every emitted expression goes through the same `_ctx.` strip the
legacy walker applies. Element directives now owned: `v-show` (inline toggle,
static-style merge, bound-style merge, root `style` entry), `v-html`,
`v-text`, and native `v-model` (text / checkbox / radio / dynamic `:type`
inputs, `<textarea>`, `<select>` with `selected` on nested options). Every
directive value is transform-rewritten from its entity-decoded attribute
text, which is what the shipped parser hands the transform; interpolations
stay undecoded. The traversal floor adds `stress-deep` (2/144 -> 1/72).

## Fifth slice: SSR corpus gate (2026-09-21)

`tests/davinci_ssr_corpus.rs` (feature `davinci-differential`, doc-hidden
`vize_atelier_ssr::differential::compare_ssr_lanes`) compiles every SFC
template on the selected lane and with the legacy walker pinned, under the
options the production SFC compile derives (script binding metadata, `is_ts`,
the scoped-style id, the component name). Code, preamble, map, and
diagnostics must be byte-identical, a `rejected` plan fails the gate, and a
sweep that never emits from the plan fails too. The required
`clippy-and-test` job sweeps the checkout (smoke scope) with
`VIZE_DAVINCI_DIFFERENTIAL_CORPUS="$PWD"`; a bare `.` resolves against the
crate directory `cargo test` runs in, which holds no SFCs. The Real Project
Matrix DOM corpus job runs the same gate over the hydrated canonical
fixtures.

Measured 2026-09-21 (smoke scope, not closure evidence): the checkout's 823
SFCs give 717 compared templates, 274 emitted from the plan, 0 divergences,
0 rejected (legacy: `surface_semantics` 431, `element` 8, `binding` 4); a
1,406-file vendor sample from installed UI packages gives 1,279 compared,
71 emitted, 0 divergences. Components and slots are the dominant remaining
refusal. The canonical Real Project Matrix run remains the open TS-11 witness.

## Sixth slice: components, built-ins, and slot outlets (2026-09-22)

The plan closes components and outlets (`CloseComponent`, `CloseSlot`) so the
emitter can own them. Components without slot content emit
`_push(_ssrRenderComponent(callee, props, null, _parent))`: the legacy
source-ordered prop bag (segments split at spreads and dynamic keys, `v-on`
as `on*` props through the transform's `process_inline_handler`, which
`TransformExpressions::handler` now publishes, `v-model` as
`modelValue` / `onUpdate:modelValue`, `v-show` as a style entry), the
scoped-style prop, `_attrs` fallthrough, and setup-binding /
`resolveComponent` callees. `<Teleport>`, `<Suspense>`, and the transparent `<Transition>` /
`<KeepAlive>` wrappers, and `<slot>` outlets (`_ssrRenderSlot` with name,
camelized props, spreads, and a fallback closure) are owned too. Components
and outlets are fallthrough candidates like elements. Still refused:
component slot content (the VNode fallback), `<component :is>`, component
`v-model` arguments or modifiers, dynamic outlet prop keys, and a second
outlet `name` source.

Measured (smoke): the checkout now emits 494 of 717 compared templates from
the plan and the vendor sample 167 of 1,279, both with 0 divergences; slot
content (`legacy.operation`: 78 and 850) is the dominant remaining refusal.

## Seventh slice: slot content and the VNode fallback (2026-09-22)

A new `SlotContent` segment kind carries `v-slot` bindings so region depth
pairing stays exact. Component slot content emits the legacy static slots
object: `default` plus `<template #name>` / `v-slot` entries, each a
`_withCtx((params, _push, _parent, _scopeId) => ...)` whose push branch
re-emits the plan ranges and whose `else` branch returns the VNode fallback
(`_createElementVNode` / `_createVNode` / `_createTextVNode`, `_renderSlot`,
conditional chains, `_renderList` blocks, keyed `<template v-for>`
fragments), with `_: 1`, `_: 3 FORWARDED` (an outlet in the content), or
`_: 2 DYNAMIC` (inside scoped params). Slot params enter the transform scope
and the codegen strip, and the props pattern is the whole quoted text the
legacy lane reads. Two legacy transforms are mirrored exactly: a `v-if`
branch root drops its `:key` (the branch-key fact span names the segment),
and component `v-model` binds the trimmed value while its update handler is
spelled over the raw attribute text and processed whole
(`TransformExpressions::model_update`), so TypeScript erasure reprints it.
Still refused: `createSlots` shapes (slots under `v-if` / `v-for`, dynamic
slot names), `<component :is>`, custom directives, and the option refusals.

Measured (smoke): the checkout emits 523 of 717 compared templates from the
plan (legacy: `operation` 76, `surface_semantics` 67, `binding` 37,
`element` 14) and the vendor sample 1,034 of 1,279 (`surface_semantics`
149, `operation` 57, `binding` 39), both with 0 divergences. The traversal
floor adds `medium` (2/118 -> 1/33); `large` stays on the legacy walker
behind dynamic components and conditional slots.

## Eighth slice: dynamic components, model arguments, branch gaps (2026-09-22)

`<component :is>` emits `_ssrRenderVNode(_push, _createVNode(
_resolveDynamicComponent(is), props, vnodeSlots), _parent)` (and
`_createVNode(_resolveDynamicComponent(is), ...)` inside a VNode fallback):
the static-name `is` spellings leave the prop bag, the slots are the VNode
slots object, and `ssrRenderComponent` stays registered as the legacy lane
registers it before branching. Component `v-model` arguments and modifiers
follow the transform's expansion: the raw argument keys the trimmed value,
the update listener is `create_on_name("update:<arg>")`, and modifiers add
`<arg>Modifiers` (`modelModifiers` for the default model) as
`{ name: true, ... }`; a dynamic argument stays refused. `drop.branch-gap`
(whitespace and comments between `v-if` branches) is admitted, except that
any dropped `@vize:` directive comment refuses the template: the legacy
parser keeps those comments with `comments` off and its walker renders them.

Measured (smoke): the checkout emits 643 of 717 compared templates from the
plan (legacy: `binding` 31, `element` 19, `surface_semantics` 14,
`operation` 10) and the vendor sample 1,207 of 1,279 (`operation` 44 -
`createSlots` shapes; `binding` 28 - custom directives, `v-once`,
`v-cloak`), both with 0 divergences.

## Ninth slice: `createSlots` (2026-09-22)

Slot templates directly under a `v-if` branch or a `v-for` region, and
`<template #[name]>` carriers, emit the legacy `_createSlots({ default,
named, _: 2 /* DYNAMIC */ }, [entries])` in both the push form and the VNode
fallback: conditional entries `(cond) ? { name, fn, key: "N" } : ... :
undefined`, looped entries `_renderList(source, (aliases) => { return {
name, fn } })` inside the aliases' transform and strip scope, and dynamic
names as the legacy `_ctx.<identifier>` spelling after the scoped-param
strip. The push form keeps the legacy quirk of spelling `_renderList`
while registering `ssrRenderList`. A slot carrier nested below plain
content (outside nested components) and non-identifier dynamic names stay
refused. Every ladder fixture now emits from the plan: the traversal floor
moves `large` 2/106 -> 1/57, so the SSR codegen walk is gone from the whole
ladder.

Measured (smoke): the checkout emits 650 of 717 compared templates (legacy:
`binding` 31, `element` 19, `surface_semantics` 14, `operation` 3) and the
vendor sample 1,242 of 1,279 (`binding` 37: custom directives, `v-once`,
`v-cloak`), both with 0 divergences.

## Tenth slice: plain `<template>` and non-raw-text tags (2026-09-22)

Neither parser special-cases `iframe`, `noembed`, `noframes`, `noscript`,
`xmp`, or `plaintext` (only `script`, `style`, `textarea`, and `title` are
raw text), so the defensive refusal is lifted; a plain `<template>` (no
`v-if` / `v-for` / `v-slot`) renders as an ordinary element on both lanes,
including inside a slot's VNode fallback. Measured (smoke): the checkout
emits 663 of 717 compared templates (legacy: `binding` 37,
`surface_semantics` 14, `operation` 3; `element` is empty) and the vendor
sample 1,242 of 1,279, both with 0 divergences.

**Element directives (resolved by the `fix(ssr)!` alignment below).** The
tenth slice left custom directives and `v-once` / `v-cloak` / `v-memo`
refused: the legacy lane rendered them through an unbound `_directives` (a
`ReferenceError` at render time) and treated the built-ins as custom
directives, and inline `.camel`, inline `:[key]`, and `<slot :[k]>` were
likewise known-wrong against `@vue/compiler-ssr` 3.5. Byte parity would have
ported those bugs into the plan, so legacy was fixed first.

## Production sweep and reach (2026-09-22)

The corpus gate now also drives the real SFC adapter entry point
(`compile_sfc_for_adapter_with_experimental_options`, `SeparateTemplate`,
template id = filename, `is_ts` from the script lang, scoped styles, SSR
on), once on the selected lane and once with the legacy walker pinned through
the `davinci-differential` thread-local hook
(`vize_atelier_ssr::differential::{record_lanes, with_legacy_lane}`). The
whole SFC output (code, CSS, map, errors, warnings) must be byte-identical,
and each production SSR compile's lane verdict is recorded, so the reach
number reflects every option the SFC compiler adds. A Croquis summary is now
its own reason, `davinci.s4_ssr.legacy.croquis` (lane label
`legacy.croquis`), because it is the production-reach gate: the SFC compiler
passes one for every `<script setup>` block, and the shared transform door
does not publish Croquis-informed rewrites yet (owned by the cross-backend
production-reach task; the DOM S2 lane refuses them the same way).

Measured (smoke, 0 divergences, 0 rejected on both sweeps):

| corpus         | production reach (`s4`) | `legacy.croquis` | other legacy                         | emitter sweep  |
| -------------- | ----------------------- | ---------------- | ------------------------------------ | -------------- |
| checkout (722) | 112 (15.5%)             | 571              | `binding` 26, `surface_semantics` 11 | 663 of 717     |
| vendor (1,279) | 171 (13.4%)             | 1,071            | `binding` 37                         | 1,242 of 1,279 |

The vendor `legacy.croquis` count equals its `<script setup>` file count, so
Croquis is the whole production gap beyond the element-directive refusals.

## JSX SSR on the plan (2026-09-22)

JSX/TSX SSR (`vize_atelier_jsx::compile_to_ssr` and the `ssr` compile config)
now enters the plan lane first. `vize_atelier_ssr::compile_s2_to_ssr` takes
the JSX S2 projection (`LoweredRoot::s2`) and runs the same S3 lowering and
verification, partition facts, string plan, and plan emitter as the template
path (`s4/select.rs` is the shared half), with the transform door's
`prefix_identifiers` off (`TransformExpressions::unprefixed`) because JSX
render functions close over their setup scope. The legacy transform and
walker run only when the plan does not own the root: `v-once` / `v-memo`
on a JSX element, or another root the S2 projection refuses. Custom
directives (with their value and argument) and a lowercase
`<component is={...}>` project to S2 (`VueDirectiveOp`, `ComponentOp`); the
walker and the Relief VDOM codegen already treat the latter as a dynamic
component, and the VDOM S2 differential covers the lowercase spelling.

The witness (`ssr/s4_differential.rs`) compiles each case on the plan lane
and with the walker pinned and requires byte-identical output: 33 admitted
cases (elements, attributes, spreads, events, text, interpolation, ternaries,
`&&`, `.map` lists, fragments, components, scoped and named slots,
`<Teleport>`, `<component is>` and member-expression tags, custom
directives, `v-show`, `v-html`, `v-model`, scoped styles, TSX, and two-root
modules) must be plan-emitted, and `v-once` must stay on the walker. Every existing JSX SSR snapshot is unchanged with the plan in
production.

## Vue 3.5 alignment, `fix(ssr)!` (2026-09-22)

The element-directive refusal above is resolved by fixing legacy first,
approved by the maintainer. Every changed shape is an entry in the
[compile waiver ledger](../compile-waivers.md) (W-SSR-1..16) and is pinned
two ways by `tests/vue_ssr_render.rs`: the compiled module equals the pinned
aligned bytes, and the real Vue 3.5 server renderer renders it exactly like
`@vue/compiler-ssr` 3.5's output while the pinned pre-fix output threw or
rendered different HTML.

The legacy walker now follows Vue's `needMergeProps` path whenever an
element carries a spread, a dynamic key, or a custom directive (or is the
fallthrough root): source-ordered segments, a spread flushes the pending
object, `_attrs` joins as an injected bind, `v-show` merges last, and
`_ssrGetDirectiveProps(_ctx, dir, value, arg, modifiers)` resolves `dir`
through `$setup["vX"]`, the inline binding, or `_resolveDirective("x")`. A
custom directive on an empty element or a `<textarea>` owns the content
through a `_temp` binding declared at the top of `ssrRender`. `v-once`,
`v-cloak`, and `v-memo` are dropped, as upstream.

The plan mirrors each shape (`s4/emit/merged.rs`), including the
binding-metadata split the legacy transform makes: a custom directive's
dynamic argument is prefixed like a value (`$setup.x`, `$props.x`), while a
`v-bind` / `v-on` dynamic key stays `_ctx.<key>` (or the scope local).
Non-identifier dynamic keys and arguments (`:[a + b]`) stay refused under
`binding`, beside `v-model` on non-form elements and a second outlet `name`
source. Measured (smoke emitter sweep, 0 divergences, 0 rejected): the
checkout emits 709 of 736 compared templates from the plan (legacy:
`binding` 10, `surface_semantics` 14, `operation` 3) and the vendor sample 1,279 of 1,279.

## Eleventh slice: implicit `<tbody>` (2026-09-22)

A `<tr>` placed directly under `<table>` emits the `tbody` both parsers
insert. The synthesized open tag is anchored one byte past the triggering
child's tag name, matching the legacy walker's zero-width loc. A direct
cell still needs `lower.table.implicit-tr`, which stays refused.

## Decisions

| subject        | decision                                                                                           |
| -------------- | -------------------------------------------------------------------------------------------------- |
| Bridge home    | `vize_atelier_ssr::s4` owns the production-path bridge so S2, S3, and partition facts stay shared. |
| Fact contract  | `SsrStringPlan` consumes `vize_s2_to_s3::PartitionFacts` in the same S2 page order as S3 lowering. |
| Failure mode   | Stale or mismatched partition facts become SSR transform diagnostics instead of guessed output.    |
| Payload policy | The plan owns output for the admitted surface; the legacy walker remains for every other shape.    |
| Counters       | Profiling records witness counts plus `accepted` / `rejected` / `legacy.<reason>` selection.       |
| Legacy bugs    | Parity never ports known-wrong output; fix legacy first, under a compile-waiver ledger entry.      |
