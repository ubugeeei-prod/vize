# P3-8 - SSR S4 string-plan first slice

This slice starts the SSR thin path without claiming that the current SSR
generator has been deleted. Supported SSR compiles now build S1, lower S1 to
S2, lower S2 to S3, verify the S3 artifact, and consume the exported partition
facts while building a preliminary S4 string plan beside the existing emitter.

## Boundary

The bridge is selected for standard Vue 3 SSR templates with no preserved
comments, no custom renderer, no patterned-template desugaring, and no
custom-element matcher. Those shapes are the option subset where the S2 source
view and existing SSR transform view currently agree without an extra recovery
policy.

This does not close P3-8. The remaining work is to move concrete SSR payload
generation from `codegen/` onto `SsrStringPlan`, then run the SSR corpus
byte-parity gate as the required TS-11 witness.

## Decisions

| subject        | decision                                                                                               |
| -------------- | ------------------------------------------------------------------------------------------------------ |
| Bridge home    | `vize_atelier_ssr::s4` owns the production-path bridge so S2, S3, and partition facts stay shared.     |
| Fact contract  | `SsrStringPlan` consumes `vize_s2_to_s3::PartitionFacts` in the same S2 page order as S3 lowering.     |
| Failure mode   | Stale or mismatched partition facts become SSR transform diagnostics instead of guessed output.        |
| Payload policy | Existing SSR codegen remains the output source until the S4 plan owns node-specific payloads.          |
| Counters       | Profiling records S4 SSR file, segment, static/dynamic segment, partition-fact, and diagnostic counts. |
