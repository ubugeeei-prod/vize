# P3-15 - Lean theorems

P3-15 proves small, closed statements about the S3 models in the
`formal/impeto` package. All proofs live in the CI-lenient Davinci Lean lane
(charter #39): the workflow's path filters cover S3, the lattice and the Lean
package, so a failing theorem blocks S3-semantics changes, not unrelated PRs.

## Proof hygiene

- `Impeto.Audit` defines `#audit_impeto_theorems`. `Impeto/Theorems.lean`
  imports every theorem module and runs it during `lake build`: each theorem
  from an `Impeto.*` module may depend only on `propext`, `Quot.sound` and
  `Classical.choice`. A proof hole, a compiler-trusted decision
  (`native_decide`) or a new postulate fails the build. Both failure modes were
  probed locally before landing. After slice 3 the audit covers 367 theorem
  declarations, including generated equation lemmas, and requires at least 200.
- The workflow also scans every `.lean` source for the four escape words and
  fails closed on a scanner error. `davinci-lean-workflow.test.ts` pins the
  step, repeats the scan and requires the named laws below.

## Slice 1 (2026-09-21): reactivity lattice laws

`Impeto.Lattice` is an independent model of the [P3-2](./p3-2.md) rule table:
every origin, effect and escape premise demands a lower bound, and a
provide/inject origin demands at least `reactive`. `Impeto.LatticeLaws` proves:

| theorem                                               | statement                                                                      |
| ----------------------------------------------------- | ------------------------------------------------------------------------------ |
| `Class.le_*`, `Class.chain`                           | `static < props-stable < reactive < unstable` is a total order                 |
| `Class.join_*`, `join_le_iff`                         | the table `join` is the least upper bound; commutative, associative            |
| `Class.rank_join`                                     | the table join equals the rank maximum a bit-rank evaluator computes           |
| `effectsFloor_append`, `effectsFloor_mono`            | the effect floor is a union-to-join homomorphism and monotone                  |
| `effectsFloor_eq_tier`                                | the first-matching-tier reading of the rule table is the same floor            |
| `classify_admissible`, `classify_least`               | the naive evaluator meets every demand and is below every solution             |
| `classify_spec`                                       | `classify i <= c` iff `c` satisfies the declarative spec                       |
| `classify_monotone`, `classify_add_effect`            | weaker origins, more effects and wider escapes never stabilize                 |
| `classify_escape_demotes`                             | escape analysis only demotes                                                   |
| `classify_effects_extensional`                        | effect order and duplicates are unobservable                                   |
| `classify_verdict_orthogonal`, `fires_iff`            | verdicts never change the value; consumers fire only on `proven`               |
| `provideInject_capped`, `provideInject_cap_redundant` | provide/inject is never above `reactive`; today's origin floor implies the cap |
| `classify_static_iff`                                 | `static` exactly for an inert local binding                                    |

### Rust differential

`fixtures/reactivity-lattice.folio` is the exact `[s3-reactivity-folio]` page
that the Rust `evaluate` prints for 400 enumerated inputs: all 256 effect sets
for an inert local binding, then every origin/escape pair with no effect and
with each single effect (all 48 origin/effect/escape floor combinations). The
verdict cycles through all three values. `cargo test -p vize_impeto --test
lattice_reference_fixture` checks byte provenance;
`VIZE_UPDATE_LATTICE_REFERENCE_FIXTURE=1` regenerates it.

`lake exe impetoRef --check-lattice-fixtures` parses the page without Rust
code, requires the canonical print form, re-enumerates the same matrix, checks
the powerset and floor-combination coverage and recomputes every class with
the proved classifier. It also rejects eight damaged pages (promoted class,
dropped or duplicated row, effect order, duplicate effect, unknown spelling,
extra field, changed verdict) and five wrong classifiers (ignoring escapes,
effects or origins, allocation as static, capture as props-stable). Both
commands run in the Davinci Lean workflow.

## Slice 2 (2026-09-21): effect grouping preserves dependency edges

S3 has no separate grouping pass yet. Every grouping or scheduling pass must
leave an artifact that the TS-27 validator accepts in the `scheduled` phase.
`Impeto.Schedule` restates that contract without Rust code. It checks
duplicate op ids (S3V001), unresolved endpoints (S3V004), effect-scoped
edges that leave their scope region (S3V007) and backward or self edges
(S3V008). It uses the validator's first-position and bounded parent-walk rules.
`Impeto.ScheduleLaws` proves:

| theorem                               | statement                                                                                                                     |
| ------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `run_opId`                            | the P3-4 small-step trace executes ops in list order under both backends                                                      |
| `accepted_schedule_orders_edges`      | acceptance implies every edge's source event precedes every target event in the VDOM and Vapor traces                         |
| `accepted_edges_stay_in_scope`        | acceptance keeps both endpoints of each effect-scoped edge inside that effect's region                                        |
| `accepted_regrouping_preserves_edges` | an accepted regrouping of the same ops and edges executes a permutation of the original events and orders every original edge |

The theorem covers DOM-order, effect-order and data-dependency edges alike.
It is stated against the executable P3-4 trace semantics, not a separate
abstraction.

`fixtures/schedule-contract.txt` records the exact Rust validator codes for 45
cases: five Rust-lowered reference templates under nine scenarios. The
scenarios are as-built, promoted to `scheduled`, reversed op order, one reversed
edge, a self edge, a dangling target, a duplicated op, an edge scoped to a
foreign effect, and an edge scoped to a missing effect. The Rust bridge
(`lean_reference_fixture::schedule`) regenerates it with
`VIZE_UPDATE_SCHEDULE_CONTRACT_FIXTURE=1`.
`lake exe impetoRef --check-schedule-fixtures` applies the same scenarios to the
committed graph Folios. It requires every negative scenario to be rejected,
recomputes all codes, and executes accepted scheduled programs under both
backends to observe the proved ordering. Every Rust-lowered reference template
is already accepted when promoted to `scheduled`, so current lowering order
satisfies the contract.

## Slice 3 (2026-09-21): keyed `v-for` IVM linearity

The reference update machine that TS-29 executes (`Impeto.Incremental`) is
now written as total structural recursion over sibling lists with explicit
fuel. The output of every update is unchanged: all stateful and loop fixtures,
plus the 512 ordered-subset reconciliation pairs, still pass. That form lets
`Impeto.IncrementalLaws` prove, for every successful update:

| theorem                     | statement                                                                                                                     |
| --------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| `reconcile_erase`           | the patched tree, identities erased, is exactly the freshly rendered view                                                     |
| `update_tree`               | an accepted update's observed tree equals the from-scratch tree, so incremental maintenance is recompute-from-scratch         |
| `siblings_identity`         | each top-level element keeps the identity of the previous sibling with its S3 address, or gets a fresh one in `[next, after)` |
| `reconcile_allocations`     | the allocator advances by exactly the number of elements with no retained address, recursively                                |
| `update_without_insertions` | a keyed reorder or payload patch in which every address survives allocates nothing                                            |

Keyed and positional `v-for` differ only in the S3 address that
`Impeto.Iteration` assigns: key-derived or index-derived. The theorems
therefore cover both identity policies and nested scopes. Work is linear in
the inserted delta: surviving keys are patched in place and only inserted
elements are allocated. This is a property of the reference machine. It makes
no claim about the time complexity of the production runtimes, which the
mounted TS-29 gate compares observationally.

## Status

_Closed 2026-09-21:_ the lattice laws, the effect-grouping edge-preservation
theorem and the keyed `v-for` IVM theorems are proved against the current
P3-4 reference semantics. They run in the CI-lenient Davinci Lean lane, whose
path filters make them block S3-semantics changes but not unrelated PRs. The
audit rejects holes and non-standard foundations. The TS-29 fixture matrix
belongs to [P3-11](./p3-11.md). Later S3 semantics must extend these theorems
in the same lane (continuous C-24). The lattice model covers the P3-2 summary
boundary, not the retained-AST analysis that will produce those summaries. A
future grouping pass must be accepted by the validator before the grouping
theorem applies to it.
