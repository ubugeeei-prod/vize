# P3-17 — Production SFC reach

**Status:** open. Slice 1 (2026-09-22) measures the reach and pins it as a
ratcheted floor; the Croquis-informed S2 rewrites, the module-hoisting entry
and the backend option refusals remain open (see _Remaining work_).

## Why this task exists

Phase 2 exited with "DOM on S2" (P2-11, P2-20). The evidence behind that line
is the template-compiler corpus lane: `davinci_dom_corpus` compares
`compile_template` in its default shape (function mode, no
`prefix_identifiers`, no binding metadata) against the legacy lane, and the
Real Project Matrix runs exactly that lane over the hydrated corpus. The
sibling `Prefixed` / `Bindings` lanes run on committed batteries only.

None of those lanes is the shape a real component compiles in. `compile_sfc`
attaches a Croquis summary to every `<script setup>` template, inlines the
render function into `setup()` (`vize build`) or emits module-mode render
functions with static hoisting (the Vite plugin), and the DOM selector
refused both:

- `stage_options::s2_emit_supported` required `!has_croquis`, and
  `compile_sfc` passes `croquis: Some(croquis)` for every script-setup
  template (`vize_atelier_sfc/src/compile.rs`, the non-Vapor
  `compile_template_block` call).
- `compile_template_block` routes a non-inline compile with
  `hoist_static: true` (the `DomCompilerOptions` default, and what the Vite
  plugin's NAPI `compileSfc` passes) through the compatibility entry, whose
  pipeline selection is `Disabled` — S2 is never attempted.

The SSR S4 plan (`emission_supported`: `croquis.is_none() && !inline`) and the
native Vapor S3 lane (`has_binding_metadata || inline` → `legacy.options`)
refuse the same inputs.

## Slice 1 — measurement, parity oracle and floors (2026-09-22)

- **DOM selection counters.** `vize_atelier_dom/src/compile/selection.rs`
  records exactly one counter per DOM template compile while the global
  profiler is enabled: `davinci.s2_dom.accepted`, or
  `davinci.s2_dom.legacy.<reason>` for the first gate that kept the compile
  on the legacy lane (`parse_error`, `entry`, `emit_refused`, `ssr`,
  `patterned_template`, `self_component`, `custom_renderer`, `dialect`,
  `template_syntax`, `croquis`, `patterned_source`). The SFC fast path's own
  S2 refusal now reaches the shared pipeline as `S2EmitSelection::Refused`,
  so it is counted as `emit_refused` rather than as the entry. Nothing is
  recorded while the profiler is off (the P2-12b no-observer cost law). The
  SSR (`davinci.s4_ssr.*`, P3-8) and Vapor (`davinci.s3_vapor.*`, P3-6)
  selectors already record the same accepted/legacy/rejected shape.
- **Production-reach gate.**
  `cargo test -p vize_atelier_sfc --features davinci-dom-differential --test davinci_production_reach -- --nocapture`
  compiles every `.vue` under `tests/_fixtures` (the `_git` corpus excluded)
  through four shipping shapes, each built the way its adapter builds it:
  `dom_inline` (`vize build` / Rust `compile_sfc`), `dom_module` (the Vite
  plugin's NAPI default), `ssr` (the Vite SSR build) and `vapor`. It clears
  the profiler around each compile, classifies the compile from its
  backend's selection counters, and fails when a DOM compile records zero or
  several counters. The step rides the required `clippy-and-test` job.
- **Production parity oracle.** The `davinci-dom-differential` feature arms
  `vize_atelier_dom::differential::with_legacy_lane`, a thread-local override
  that sends every DOM compile on the thread to the legacy lane. Every DOM
  template the S2 emitter accepts on a production shape is compiled again
  under the override and the complete `compile_sfc` results — code, CSS,
  error and warning messages — must be byte-equal (TS-11 over the production
  path, charter #23). Slice 1 compares nothing, because nothing is accepted;
  the oracle is in place before any refusal is lifted.
- **Floors.** `reach-budgets.toml [reach]` pins `accepted_min` and
  `templates_min` per shape. The gate fails below a floor and prints when a
  run exceeds one, so the PR that raises reach raises the floor.
- **Hydrated corpus.** The Real Project Matrix `s2 dom corpus` job runs the
  same test with `VIZE_DAVINCI_DIFFERENTIAL_CORPUS=tests/_fixtures/_git`
  before dehydrating: reach is reported and parity enforced there, floors
  are not.

### Measured baseline (committed fixtures, 433 files, 342 templates)

| Shape        | Stage     | Accepted | Reach | Legacy reasons                                                                                                                                |
| ------------ | --------- | -------: | ----: | --------------------------------------------------------------------------------------------------------------------------------------------- |
| `dom_inline` | S2        |        0 |  0.0% | `croquis` 294, `entry` 47, `parse_error` 1                                                                                                    |
| `dom_module` | S2        |        0 |  0.0% | `entry` 341, `parse_error` 1                                                                                                                  |
| `ssr`        | S4 plan   |       29 |  8.5% | `options` 294, `surface_semantics` 18, unrecorded 1 (fatal parse)                                                                             |
| `vapor`      | native S3 |        3 |  0.9% | `options` 300, `surface_semantics` 13, `structure` 10, `operation` 8, `expression_or_encoding` 3, `control_flow` 2, `element` 2, unrecorded 1 |

_Update 2026-09-22 (rebase onto #6308):_ the native Vapor lane no longer
refuses binding metadata or inline mode; `vapor` now accepts 151/342
(44.2%; `element` 46, `expression_or_encoding` 46, `component` 27,
`surface_semantics` 22, `binding` 19, `operation` 16, `control_flow` 12,
`structure` 2, unrecorded 1) and its floor is 151. After #6337 (S4 plan
components and slots) `ssr` accepts 44/342 (12.9%; `options` 294,
`binding` 3, unrecorded 1) and its floor is 44.

One fixture (`V_MATCH_SYNTAX`) fails `compile_sfc` on every shape and is not
a template compile; 90 files carry no `<template>`.

**Reading the table honestly:** on the committed fixtures no production DOM
compile reaches S2. `dom_inline`'s `entry` rows are the SFCs without
`<script setup>`: they compile non-inline with static hoisting and take the
compatibility entry exactly like `dom_module`. The phase-2 corpus evidence
remains true for `compile_template` callers; it did not cover SFCs.

## Remaining work

1. **Croquis-informed rewrites on S2.** The legacy transform consumes the
   Croquis summary in exactly two places: the reactivity tracker
   (`get_reactive_kind`: inline-mode `.value` / `_unref` decisions in the
   identifier collector and the simple-identifier fallback) and component
   registration (`used_components` plus Croquis `SetupConst` bindings). Both
   become binding facts on the shared `BindingTable` that the S2 transform
   rewrite (and through it the SSR plan's `TransformExpressions`) consults,
   leaving the codegen-side rewrites on binding metadata alone as the shipped
   codegen does. Then the `croquis` refusal is lifted on the production-path
   parity oracle above.
2. **Module-mode hoisting entry.** Prove S2 parity for non-inline,
   `hoist_static` module compiles on the same oracle and route them through
   the sections entry; this is what moves `dom_module` and the non-script
   `dom_inline` rows.
3. **SSR and Vapor option refusals.** P3-8 consumes the shared Croquis facts
   for the S4 plan; P3-6 lifted the native lane's binding-metadata / inline
   refusal (#6308) and owns its remaining buckets. Floors rise in their PRs.
4. **Hydrated-corpus numbers.** Record the Real Project Matrix reach table
   here once a dispatch runs with this step.
5. **Performance.** A script-setup SFC DOM bench with a pinned budget before
   the croquis refusal is lifted (charter #22: the S2 path may not be slower
   than the legacy lane it replaces).
