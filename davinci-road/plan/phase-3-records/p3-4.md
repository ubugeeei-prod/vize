# P3-4 - Lean reference semantics first slice

This slice starts the P3-4 executable reference without pulling Lean into the
runtime dependency graph. The new `formal/impeto/` Lake package is pinned by
`lean-toolchain` and exercised only by the dedicated Davinci Lean workflow, in
the CI-lenient supply-chain lane allowed by charter #39.

## Contract boundary

- Input is the existing S3 Folio text contract: `phase`, `regions`, `ops`,
  `edges`, and `effects`.
- The Lean side owns a small, independent syntax model instead of importing Rust
  code or regenerated bindings.
- Fixture traces are observable semantics, not emitted-code byte shape, matching
  TS-28 and the Vapor experimental policy.

## First semantics

The first small-step machine executes the committed op sequence once under two
interpretations:

- VDOM: `insert-node` becomes `create-element`, property/event ops become patch
  events, and structural control ops become branch/list/slot observations.
- Vapor: the same S3 ops become effect-oriented observations such as
  `create-node`, `assign-prop`, `listen`, and `conditional-effect`.

Effect ids remain visible in the trace. That deliberately makes effect-scope
drift observable before optional scheduling or extraction passes land.

## Fixtures

The initial ladder covers:

- `static-text.s3.folio` - static element plus text.
- `dynamic-button.s3.folio` - prop, event, interpolation, and effect order.
- `control-flow.s3.folio` - branch-owned region and child ops.

## Validation

- `lake build` over `formal/impeto/`.
- `lake exe impetoRef --check-fixtures`, comparing the Lean reference trace to
  the committed `.trace` files.
- `tests/tooling/davinci-lean-reference.test.ts`, keeping the workflow, pinned
  toolchain, fixture declarations, and TS-28 command in sync.

This does not close P3-4. The remaining work is to feed generated S3 fixtures
from the Rust lowering path and then compare compiled backend behavior traces
against this reference runner.
