# P3-11 - Array-loop incremental reference slice

Issue [#6251](https://github.com/ubugeeei-prod/vize/issues/6251) connects one
array-loop subset across Rust S3 lowering, independent Lean execution and
mounted VDOM/Vapor output. P3-11 remains open.

`Impeto.Iteration` executes the source/alias operands using lexical JSON
environments. The second `for-key` alias is the array index; reconciliation
identity comes separately from the repeated-root key binding. Nested aliases
shadow and restore their enclosing environment.

`Impeto.Incremental` owns the previous materialized tree and a monotonically
allocated element lifetime. Updates preserve keyed or positional identities,
patch payloads, insert elements and retire removed subtrees. Its resulting tree
must equal a fresh S3 render after every update. All ordered-subset transitions
over three keys are exercised under both identity policies, with explicit
allocation and event-value expectations. The matcher's equivalence with fresh
rendering, keyed retention and exact allocation count are proved in
[P3-15](./p3-15.md); it makes no production time-complexity claim.

Three Rust-owned fixtures share their exact authored source, graph/value Folios,
scenario and complete expected tree/event/lifetime observations with the
mounted runtime. They exercise reorder, front insertion, middle deletion,
same-key object replacement, empty/refill, nested alias shadowing, cross-parent
movement and parent removal/recreation. Expected lifetime numbers are authored;
the DOM runner observes actual objects through a WeakMap, not key spelling.

The event traces exposed a production defect: the native Vapor event generator
wrapped an already transformed arrow a second time, so clicking returned a
function and delivered no event. It now uses the shared retained-AST function
classifier before choosing a wrapper, matching component-event handling.
Supplemental mounted cases cover authored arrow/function and optional-call
handlers without changing the reference fixture's expression subset.

The exact supported subset, failure boundaries and lifetime rationale are in
[`loop-reference.md`](../../../formal/impeto/fixtures/loop-reference.md).
The existing Davinci Lean workflow runs the stateful reference, Rust provenance
and mounted gates. The default Cargo suite also executes both Rust gates.

Remaining work includes object/range and multi-root iteration, general
expressions, model/supplied-slot reference semantics and the full TS-29
matrix. P3-4, P3-12 and the Phase 3 exit also remain open.
