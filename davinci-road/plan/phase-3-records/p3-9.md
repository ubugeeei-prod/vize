# P3-9 — S4 Structured Emitter + Universal Source Maps

## Slice 1: TS-31 Budget Pin

This slice establishes the numeric gate before changing emitters.

`davinci-road/plan/budgets.toml` now carries `[sourcemap]` rows for the
required P3-9 backend/category matrix:

| Backend | Categories                                                    |
| ------- | ------------------------------------------------------------- |
| DOM     | `static-template`, `rewritten-identifier`, `section-boundary` |
| Vapor   | `static-template`, `rewritten-identifier`, `section-boundary` |
| SSR     | `static-template`, `rewritten-identifier`, `section-boundary` |

Each row pins a minimum authored-anchor count, a minimum coverage percentage,
and an exact span-accuracy floor. Rewritten identifiers stay at 100% coverage
and 100% span accuracy because TS-31 calls them out as exact assertions.

The legacy SFC text-matching source-map recovery is also recorded as
`legacy_sfc_text_matching_recovery`, so deleting
`crates/vize_atelier_sfc/src/source_map.rs` has a visible floor: a future S4
path must show coverage at least as good as this legacy row before removal.

The checker lives in `tests/tooling/davinci-sourcemap-budgets.test.ts`; it
keeps `[sourcemap]` non-empty, verifies every DOM/Vapor/SSR category cell, and
rejects malformed or non-numeric budget rows.

## Slice 2: SSR/Vapor Map Entry Points

This slice wires the shared Source Map v3 builder contract into non-DOM
backends without changing generated JavaScript bytes.

- `vize_atelier_core::codegen::source_map::build_single_anchor_source_map`
  exposes a minimal one-source map helper for backends that have not migrated
  every emitted token onto structured span segments yet.
- `vize_atelier_ssr` now carries `SsrCodegenResult::map` and an opt-in
  `SsrCompilerExperimentalOptions::source_map` gate.
- `vize_atelier_vapor` now carries `VaporCompileResult::map`,
  `VaporGenerateResult::map`, and an opt-in
  `VaporCompilerExperimentalOptions::source_map` gate.
- NAPI/WASM direct template compilation now preserves source maps for DOM,
  SSR, and Vapor when `sourceMap: true` is requested.

This is intentionally not the P3-9 finish line. The map currently records the
module-start anchor so consumers can rely on result shape, `sources`, and
`sourcesContent` across all three backends. Later P3-9 slices must replace
these minimum anchors with token-level structured emission and then retire the
legacy SFC text-matching recovery once TS-31 coverage proves the new path is at
least as strong.

## Slice 3: TS-31 Measurement Harness

TS-31 is now measured, not asserted by hand.
`cargo test -p vize_atelier_sfc --test davinci_ts31_sourcemap` compiles the
fixture battery in `crates/vize_atelier_sfc/tests/fixtures/ts31/` with source
maps on for DOM, Vapor and SSR (templates) and for the SFC module (the legacy
recovery row), decodes every map with an independent v3 decoder, and keeps
[`ts31-sourcemap-coverage.json`](../ts31-sourcemap-coverage.json) equal to the
measurement (`VIZE_UPDATE_TS31_REPORT=1` rewrites it for review). The same test
compiles every fixture with maps off and asserts byte-identical emitted
JavaScript, so maps stay additive and TS-11 stays empty.

The oracle is the fixture file: each anchor names its authored token by text
and occurrence, so its byte span never comes from the map under test. An
anchor is `exact` when a segment maps generated bytes carrying the anchor's
emitted form to the token's first authored byte, `covered` when a segment
lands inside the authored span without meeting that rule, and `unmapped`
otherwise. Emitted forms per category:

| Category                 | Authored token                          | Emitted form at the mapping                                |
| ------------------------ | --------------------------------------- | ---------------------------------------------------------- |
| `static-template`        | tag name, attribute name/value, text    | the same bytes                                             |
| `rewritten-identifier`   | template identifier the compiler scopes | the identifier behind an optional `_ctx.`-style rewrite    |
| `section-boundary`       | the structural unit's opening `<`       | the backend construct opening the unit's code (per anchor) |
| `text-matching-recovery` | authored script statement               | the same statement                                         |

Coverage is `(exact + covered) / authored`, span accuracy is
`exact / (exact + covered)`, and `anchors_min` is enforced against `exact`.
`tests/tooling/davinci-sourcemap-coverage.test.ts` compares the report with the
pinned budgets: every row meets its budget or appears below with its exact
measured counts, so an improving slice must shrink this ledger and a
regression cannot hide in it.

The legacy row measures 11/11 exact anchors over the SFC battery, which covers
the recovery's documented domain (verbatim, unique JavaScript statements).
Deleting `crates/vize_atelier_sfc/src/source_map.rs` stays blocked by the gate
until a structured SFC path is measured over the same battery at or above
that row.

## Slice 4: DOM Span-Carrying Emission

The DOM codegen now writes every mapped token through span-carrying methods on
`CodegenContext` (`codegen/context/spans.rs`): each call appends the generated
bytes and records the authored span in the same step, so the map is a property
of emission rather than a side call before a string append. The shared
`SourceMapBuilder` still assembles the document, and the code buffer receives
exactly the bytes a plain append would, which the TS-31 harness re-checks with
maps off.

- The render function opens at the template section start; every block
  (`(_openBlock(`: elements, components, `v-if`/`v-else-if`/`v-else`
  branches, `<template>` branch fragments, `v-for` fragments) opens at its
  authored unit's `<`; slot functions (`_withCtx(`) open at their
  `<template #slot>` (or the component carrying root `v-slot`).
- Tag names map to the authored tag name (the byte after `<`) instead of the
  `<`; component resolution names map to the first element authoring that
  tag; slot names map to their `v-slot` argument; static text maps from every
  children, branch, slot and `v-once` path.
- Expressions keep their whole-expression anchor, and every identifier the
  rewrite scoped (`_ctx.x`, `$setup.x`, `$props.x`, `__props.x`, `_unref(x)`)
  gets its own named segment. `codegen::rewrite_spans` recovers the insertion
  points only when the emitted text decomposes exactly into the authored text
  plus the rewrite alphabet, preferring authored bytes; TypeScript stripping,
  comment rewriting and alias renames produce no identifier segments. Event
  handlers and slot content now flow through the same emission.
- Synthesized expressions with the empty stub span are no longer anchored at
  the template start.

`codegen/span_tests.rs` pins the full code and every decoded segment for a
rewrite/tag fixture and a branch/loop/slot fixture. DOM now meets every TS-31
budget (28/28 static-template, 10/10 rewritten-identifier, 10/10
section-boundary, all byte-exact).

## Slice 5: SSR Span-Carrying Emission

`vize_atelier_core::codegen::spanned` adds the shared S4 primitive for
emitters that assemble code before writing it: `SpannedText` is generated text
plus the authored anchors of the tokens it copies, rebased onto the generated
offset when the piece is written, and `expression_anchors` gives any backend
the DOM's whole-expression plus named rewritten-identifier anchors. DOM now
uses the same helper, so every backend feeds one `SourceMapBuilder` through
one anchor model.

The SSR generator carries spans through both of its write paths: template
literal parts are `SpannedText` (coalescing keeps anchors; `` ` `` and `${`
escaping rebases them), and direct writes record as they happen. The render
function, `if`/`else if`/`else` branches, `_ssrRenderList` loops and
`_withCtx` slot functions open at their authored units; tag names, static
attributes (including the fallthrough `_mergeProps` object of a root element),
bound attribute keys, component resolution names, slot names and text map to
their authored tokens; interpolations, conditions, loop sources and bound
values carry expression anchors. The single-anchor fallback is gone.

The harness now accepts an `absent` backend list for tokens a backend emits no
code for by design (SSR drops event listeners): the harness asserts the token
really is absent from that backend's output and does not count the anchor as
authored there. SSR meets every TS-31 budget (28/28 static-template, 9/9
rewritten-identifier with `increment` verified absent, 10/10
section-boundary, all byte-exact), and `source_map_tests.rs` pins the full
SSR code and every decoded segment.

## Slice 6: Structured Emission Document

`vize_atelier_core::codegen::document::EmitDocument` is the one S4 emission
document. It holds the generated text and `SpanLink`s, each pairing a
generated byte range with the authored byte range it comes from, an optional
authored symbol, and whether the link contributes a v3 segment. The document
is target-neutral:

- `EmitDocument::source_map` serializes the segment-bearing links through the
  shared `SourceMapBuilder`, in emission order.
- `vize_canon`'s `ProjectionMapping::from_emit_document` reads the same links
  as P4-5a projection rows: a range link is a row, and a link nested in the
  preceding row (a rewritten identifier inside its expression) refines it as a
  sub-span. Unit anchors (a block or slot function opening its authored unit)
  carry no authored extent and yield no row.

The DOM `CodegenContext` and the SSR context no longer own a code string plus a
side `SourceMapBuilder`: both write into an `EmitDocument` that records only
when a map is requested. Pieces assembled before their position is known are
recording documents; appending one rebases its links, and SSR's template
literal escaping is the document's `push_escaped`, which rebases links onto
the escaped output. `SpannedText` is gone. Tokens that copy authored bytes now
record their authored extent (tag names, text, static attribute names and
values, slot names, comments, component names, expressions and rewritten
identifiers). The DOM and SSR maps and emitted bytes are unchanged: the pinned
span tests, the S4 differential battery and TS-31 pass unmodified.

## Slice 7: Vapor Span-Carrying Emission

Both Vapor lanes emit token-level maps through the Slice 6 emission document:

- The Vapor generate context writes its render code into an `EmitDocument`,
  and the module (imports, `_template` declarations, delegated events, render
  function) is assembled as one document whose links serialize the map.
- Template strings carry links from lowering: the template builder writes
  into an `EmitDocument` that records only for a map-requesting compile, so
  both paths produce the same bytes by construction. Each `_template("...")`
  line writes its template through `push_escaped` with the `escape_template`
  replacements, which rebases the links onto the escaped literal.
- Generation looks up authored units by exact span identity: for a
  map-requesting legacy-lane compile, `VaporSourceSpans` is collected once
  from the transformed template and keys every `v-if`/`v-else-if` branch,
  `v-else`, `v-for` and `<template #slot>` by the authored span of the
  expression the IR keeps for it (condition, loop source, slot name; the IR
  slot name now keeps its `v-slot` argument span). `_createIf(`,
  `_createFor(`, the `v-else` closure and slot closures open at their
  authored units; component resolution names map to the authored tag.
- `SetProp`/`SetText` calls are built once as document fragments for
  statement and inline-effect emission alike, carrying key, static-text and
  expression links; handler references and callbacks keep expression links.
- The native S3 lane carries authored spans in its checked payload (element,
  attribute, binding, text, branch and loop spans from the S3 operands). The
  tag name, attribute value and directive argument inside those spans are
  located by the authored HTML/Vue syntax, and each locator verifies the
  token it found before linking it. Payload expressions keep their spans, and
  branches and loops key their units like the legacy walk, so both lanes emit
  the same map for the same template. Native component and outlet props
  (admitted since #6308) carry no spans yet.
- Public Vapor APIs are unchanged; a map requested without the lowering side
  table (direct `generate_vapor_*` callers) still carries the render entry and
  every IR expression link.

The battery gains `native-direct-bindings`, a single-line native HTML fixture
the Vapor compile admits through the native S3 lane, so that emitter is
measured too. Vapor now meets every TS-31 budget (35/35 static-template,
13/13 rewritten-identifier, 11/11 section-boundary, all byte-exact), and
`tests_source_map.rs` pins the full code and every decoded segment for both
lanes.

## Slice 8: Structured SFC Module Map

`compile_sfc` attaches a structured module map instead of recovering one by
text matching:

- Each stage that copies authored script text records the copy as byte runs
  (`module_map::Runs`), and a stage that regenerates text from a known
  authored construct records a point anchor at it. The stages are statement
  sectioning, destructured-prop rewrites, hoisting, `await` expansion, import
  dedupe, `export default` rewriting, lazy-hydration and artifact-macro
  erasure, v-model demotion, standalone output rewriting, and macro bindings
  such as `const props = __props`.
- A TypeScript re-print into JavaScript is composed through the token
  provenance that oxc's codegen records. The napi boundary's TypeScript strip
  carries the map the same way (`finalize_module_output_with_map`).
- Runs compose stage to stage into `.vue` offsets. They are verified byte for
  byte against the source before emission, and emit one segment per token
  start. A construction defect therefore drops a mapping instead of
  publishing a wrong one. Emitted bytes are unchanged with maps on or off.
- The napi `compileSfc` / batch paths request the compiler's map in place of
  `build_sfc_source_map`.

TS-31 now measures the structured map (`sfc`) and the legacy recovery
(`legacy-sfc`) over the same `sfc.toml` battery. The structured map is 11/11
exact, and the gate requires it to be no worse than the legacy on any
anchor. A new `sfc-rewrites.toml` battery pins statements that the pipeline
rewrites; the structured map is 19/19 exact there. Its fixtures cover
TypeScript re-prints, destructured props, top-level `await`,
`export default`, and macro bindings. Both structured rows meet their new
budgets, so neither enters the ledger above. Deleting the recovery remains
open for the next slice.
