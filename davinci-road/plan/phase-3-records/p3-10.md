# P3-10 - Try-measure-commit extraction

P3-10 lands in slices. The budget contract came first so no extraction pass
could choose winners before the metric rule was pinned; placement alternatives
came next so the pass has explicit, verified shapes to choose among, and the
pass itself chooses among them.

## Slice 1 - Budget Contract (2026-09-13)

`davinci-road/plan/budgets.toml` now carries:

- `[optimization]` rows for `-O0` through `-O3`.
- `candidate_budget`, the per-component decrementing budget for trying
  hoist/cache/inline/group placements.
- Per-metric epsilons for emitted size, reactive-edge count, and update-path
  length.
- `required_improvements_min`, which keeps `-O1` and above from committing a
  tie.
- `tie_policy = "reject"` on every tier.
- `[target.p3-10]`, which records the task-start revision and the metric roles.

The starting policy is intentionally strict: `reactive-edge` and `update-path`
are correctness-adjacent constraints, emitted size is the objective, and all
epsilons begin at zero. Loosening any value must go through the existing budget
ratchet process.

## Slice 2 - Placement Alternatives (2026-09-21)

Placements are explicit data on S3 ops and do not change behavior yet.

| subject    | decision                                                                                                                                                                 |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Home       | `vize_impeto::placement`; `Program::placements` holds one record per op that has more than the canonical `inline` shape, in op order.                                    |
| Overlay    | Records never rewrite ops, regions, edges, effect scopes, or operands, so the P3-3 partition export keeps describing canonical S3 without revalidation.                  |
| `hoist`    | Outermost literal element of a subtree owned by an `if`, `for`, slot, or component region; `ref`, `ref_for`, `ref_key`, `key`, and `is` pin instance identity and block. |
| `cache`    | Dynamic `set-event` with one plain JS handler under a static name and no `for`, slot, or component scope above it.                                                       |
| `group`    | Leaf update reading one direct reference that its keyed effect-order predecessor reads in the same root, `if` branch, or `for` item; the run joins its first op's unit.  |
| Verifier   | `S3V010` re-derives every alternative and committed choice; a chosen group stays contiguous with its committed unit and a chosen hoist never nests in another.           |
| Folio      | `S3PlacementFolio` (`[s3-placement-folio]`) is a companion page; the graph page and its Lean parser are unchanged.                                                       |
| Production | Nothing calls `annotate` outside tests and fuzzing yet, so backend output is unchanged.                                                                                  |

The group rule is deliberately narrow. Direct references (`a`, `a.b`) carry no
call, operator, or assignment; one lexical scope makes identical text name one
binding; and contiguity in the keyed effect chain means no other reactive op
can be reordered. Keyless dynamic ops are skipped because they re-run only when
their controlling region re-renders, where op order is fixed. Slot and
component content can mix scopes and never groups.

## Slice 3 - Try-Measure-Commit Pass (2026-09-21)

| subject      | decision                                                                                                                                             |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| Home         | `vize_impeto::extract`; `vize_s2_to_s3::optimize` runs annotation plus extraction beside the exported partition facts.                               |
| Loop         | From the all-inline plan, each candidate in record order is performed on a trial plan, simplified locally, measured, and committed or rolled back.   |
| Metrics      | Reactive edges and update path are constraints, emitted size is the objective; the model and byte constants are in `impeto-ops.md`.                  |
| Rule         | Constraints judged first; no metric beyond its epsilon; `required_improvements_min` strict gains; ties keep the simpler shape.                       |
| Budget       | Each measured trial spends one unit of the tier's `candidate_budget`; blocked or unreached candidates are recorded without measuring.                |
| Tiers        | `OptTier::budget()` equals `[optimization]` field for field (`tests/optimization_budgets.rs`); metric order equals `[target.p3-10]`.                 |
| Decisions    | One `{pass, kind, span, args}` row per candidate on `S3ExtractionFolio`, also sent through the counting `RemarkSink` until P3-13 structures remarks. |
| Partition    | The pass writes only `chosen` (`EXTRACT` is `Preserved::ALL`); `PartitionFacts::stale` stays `None` at every tier in tests and fuzzing.              |
| Measurements | A static `<p>` subtree under `v-if` hoists (-55 bytes, -3 path steps); identical direct reads group (-21 bytes, -1 edge per member).                 |

Under the zero epsilons pinned in slice 1, a cached handler costs 27 guard bytes
against the 21-byte effect unit it removes, so every cache candidate is
recorded as `regressed-emitted-size` (+6) even though it removes one edge and
one update step. That is the rule working as pinned; changing it is a budget
ratchet decision, not a pass change. A lone static node under a control region
is recorded the same way (+8).
