# P2-11 — DOM backend on S2 (series record)

**An explicitly marked small series** (the plan README's permitted
exception): one reviewable PR per emit increment, all under this ID.
This record grows one installment file per landed PR; the task's box
in `phase-2.md` stays **unticked** until the series completes the
acceptance gate. Do not invent installments that have not merged to
`origin/main`.

The S1-to-S2 emit test-consumer import path is `vize_s1_to_s2::emit`;
the physical package and directory now use `vize_s1_to_s2`; Ricalco remains
only the codename. `vize_atelier_dom` is published and cannot name unpublished
Davinci crates in its release graph. The current decision is a firewall: S2 DOM
witnesses live in atelier_dom **test space** through dev-dependencies that are
stripped on publish, and the tooling gate rejects any unstripped edge from a
publishable crate into an unpublished stage crate. The old DOM lane is still
the shipped compile path. The exit gate is unchanged.

The `emit.rs` module docs keep a running capability list. **This
record's landed numbers are the sixty-seven `origin/main` PRs**, not that
comment.

## Current named remainder

Installments 45-64 close the late P2-11 witness backlog that remained after
the single nested slot wrapper fix. Event/model/slot residuals, `v-if` branches
that contain `v-for`, hardened handler bodies, static class flags, keyed slot
template forwarding, component `v-once` wrappers, opaque bind values, empty
text edges, trailing block comments, line-comment expressions and slot text
fact alignment now have direct S2-vs-shipped coverage. The latest reduced
real-project cases keep nested interactive-content recovery in the comparison
lane through S0, S1 and S1-to-S2 lowering, and keep authored event handler
expressions raw where the shipped DOM lane does.

Installments 65-67 extend that late patch and wrapper program: dynamic
components with runtime custom directives keep `NEED_PATCH`, and component
props emitted through template wrappers now have reduced S2-vs-shipped
witnesses for static hoists, branch keys, scoped-slot inline props and class
binds that must stay inline.

The patch-site program is also now explicit for the surfaces that were still
named after #5363: `v-memo`, `v-once`, slot outlet and `createSlots` cases join
the late directive and object-spread patch witnesses, and #5401 wires the
committed DOM corpus lane into the required Rust test job. #5387 remains the
corpus-runnable entry; it runs the committed battery by default and expands to
the hydrated fixture tree when `VIZE_DAVINCI_DIFFERENTIAL_CORPUS` is set.

The series is not done. Waiver budget remains zero, and the old DOM lane remains
the shipped path. The current blockers are the canonical hydrated
zero-divergence evidence run and the deliberate production-lane switch / flag
deletion, which still needs the release-graph decision recorded by installment
40 rather than an accidental dependency edge.

## Hydrated corpus differential count contract

The P2-11 TS-25 corpus record counts project rows, not hydrated checkout
directories. On the current `tests/_fixtures/vue-ecosystem-fixtures.json`
manifest, the full compiler-surface lane is **144 DOM-output comparisons**:
one comparison per project row. Those rows sit under **142 ecosystem fixture
paths** because `tests/_fixtures/_git/primevue` contributes three project rows:
`primevue`, `primevue-volt`, and `primevue-showcase`. A run that records
142 DOM-output comparisons is stale even if every fixture path is hydrated.

The comparison-count contract is no longer a blocker:
[#5359](https://github.com/ubugeeei-prod/vize/pull/5359) pins it in tooling and
in this record. The hydrated zero-divergence corpus run is still a blocker.
The landed P2-11 witnesses are direct S2-vs-shipped fixture comparisons; the
task is not complete until a clean hydrated corpus run records 144
zero-divergence DOM-output comparisons for the P2-11 differential lane.
