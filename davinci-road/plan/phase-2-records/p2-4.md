# P2-4 — Folio derive + `davinci-opt` pipelines

**`#[derive(Folio)]` and the two-mode `davinci-opt`. Landed 2026-08-20;
every acceptance clause met, with the CLI-surface deviations the
"alternatives" requirement forces itemized below.**

## The line this task exists to draw

**The derive owns the mechanical trio — print, parse, field order — and
nothing that is a decision.** The generated grammar (now written down in
[`folio-format.md`](../folio-format.md), "Derived pages") is computable
from the type shape alone: a `[kebab-case-type-name]` header, `name=value`
scalars in declaration order, a `[page.field]` section per `Vec` (order
preserved) or `FxHashMap` field (entries sorted by printed key, rule 1),
empty sections omitted, LF, 1-based error lines. `Display` on a derived
page prints the `Full` text: eliding is a decision, so the derive makes
none, and `Display` carries no round-trip law regardless.

Of the folio-format normalization rules, one is recorded as **not
applicable** rather than silently skipped: stable sequential ids (rule 2)
require knowing which field _is_ an id, which is semantic. A derived type
carrying id references needs a hand-written page, and the format doc says
so.

## Why `CroquisFolio` did not move to the derive

The contract asked for the check, and the answer is measured, not argued:
the croquis page's every byte is a semantic decision — `{name}{!|?}` prop
markers, ` @{start}:{end}` span tails, `^` type-only/hoisted flags,
verbatim multi-line sections, span elision in `Display`, scope-id
renumbering. The mechanical grammar for the same fields would share not
even the header line (`[vir]` is not the kebab-case of anything). So the
hand impl stays, the fixtures stay byte-frozen, and the derive lands on a
**real type with a mechanical dump**: `BudgetObserver`, whose
`[budget-observer]` page makes a run's walk counts a parseable artifact —
exactly what P2-12b's gate will want to read — and is reachable as
`davinci-opt --stage budget-observer`, which is the `--stage`
generalization the contract asked for.

## The host `std` edge, for P2-14's audit

`vize_davinci_derive` is a proc-macro crate: it runs on the **host** at
build time and is never linked into any target, so it is `std` by nature
while everything it _generates_ names only `::core` and `vize_davinci`
support paths (`folio::page`, `folio::value`) — the generated impls
compile inside the `no_std + alloc` crate and through the wasm32-wasip2
lane. It sits in `vize_davinci`'s `[dependencies]` (that is where a derive
used by library types goes), which does not widen any release graph:
`cargo tree -i vize_davinci_derive --workspace --edges normal` prints
exactly `vize_davinci` and nothing else; the wider default view fans out
only through the backends' **dev**-dependencies on `vize_davinci`, which
are not compile paths of published artifacts (TS-11's concern). Two
consequences worth recording:

- `vize_davinci` gained `extern crate self as vize_davinci;` so the
  expansion's absolute paths resolve inside the defining crate too.
- The derive crate carries a crate-level allow for the house string lints
  (`disallowed_types` / `disallowed_methods` / `disallowed_macros`): those
  rules exist for the compiler's hot paths, and a host-only build
  dependency speaking syn/quote's std-String API is the one place pulling
  `vize_carton` in to satisfy them would invert their point.
- **Lane note for P2-14:** the nix flake's toolchain carries only
  `wasm32-unknown-unknown`, so the wasip2 acceptance build ran against the
  upstream `rust-std-1.95.0-wasm32-wasip2` component (same commit,
  `59807616e`) in a sysroot overlay. The machine recipe P2-14 lands in CI
  should install the target properly; until then this is what "green" was
  measured with.

## `davinci-opt`: what stayed frozen, what the contract forced

`--roundtrip` and `--pipeline` are now alternatives (exactly one). The
frozen part is pinned by `tests/davinci_opt_cli.rs`: all 14 committed
P0-10 croquis fixtures round-trip byte-identically through the extended
binary under the default stage and `--stage croquis`, with stdout
(`roundtrip OK: {path} ({n} bytes)`), empty stderr, the mismatch report,
and exit codes 0/1/2 asserted exactly. The deviations, each forced by the
contract's own "becomes one of two alternatives" and "beyond croquis":

- the usage string gained a **second line** for `--pipeline`; the first
  line is byte-identical to P0-10's,
- `--roundtrip <file> is required` became `--roundtrip <file> or
--pipeline "<syntax>" is required` (a required flag cannot stay required
  once it is an alternative),
- the unknown-stage list reads `(available: budget-observer, croquis)`,
- stdin that is not UTF-8 is reported as its own error rather than through
  `read_to_string`'s message (the house lint bans `std::string::String`,
  so the binary reads bytes and converts explicitly).

`--pipeline "<syntax>"` reads a folio from stdin, parses the string with
the P2-2 parser (**no second grammar**; the ten documented rejections
surface verbatim as `davinci-opt: --pipeline: {message}`, exit 2), runs
each segment as a `Pipeline` plan, and prints the full normalized folio to
stdout — stdout stays pure folio, parseable by `--roundtrip`, while a
`walks=/passes=` summary goes to stderr through the budget observer.
Binding names to descriptions is the caller's step by `pipeline.rs`'s own
design and there is no catalogue until P2-9, so **every named pass runs as
an optional, fusable no-op** — stated in the binary's docs, not implied.
Per-pass folio printing is deliberately absent: that is P2-13's
`--folio-after-change`, and this task's non-goal list says so.

## TS-16 and TS-17, established

- **TS-16 per derived type** (`tests/folio_derive_laws.rs`): byte-exact
  `print(parse(t)) == t` and structural `parse(print(v)) == v` for
  `BudgetObserver` and for a local type covering every supported field
  kind; normalization-by-first-print on scrambled input; `Display == Full`
  stated as a fact about the derive, not a law; and all fifteen parse
  rejections asserted on exact `FolioError`s (TS-13 green, allowlist
  untouched).
- **TS-17** (`tests/pipeline_snapshot.rs`): folio in → pipeline →
  `assert_folio_snapshot!` out, over a committed croquis fixture and a
  fused-plus-barrier plan, with the walk accounting pinned as the
  structural supplement _through the budget observer's own derived page_ —
  the run's counts are themselves a TS-16 artifact. The binary-level twin
  drives the same fixture through `davinci-opt --pipeline` on stdin. Until
  P2-9 lands pass bodies the snapshot pins the harness shape, not a
  transformation; the first real pass test replaces the no-op step and
  keeps everything else.
