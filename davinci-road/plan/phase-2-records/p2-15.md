# P2-15 — Metamorphic suite v1

**Four justified mutators, a per-mutator declared normalization, the
matrix fixture plane committed, and TS-21 running over both sources with
the scope proof. Landed 2026-08-21; every acceptance clause met, the
full-corpus widening run twice at 12,215 files × 179,992 mutations with
zero divergences, and one pre-existing staleness (croquis-consumption)
absorbed rather than left red.**

## The home: `vize_ricalco` test space (the decision)

The suite lives at `crates/vize_ricalco/tests/metamorphic/` (`main.rs` +
five modules, each ≤ 350 lines). Dependency direction decided it: the
pipeline under test is sinopia parse → ricalco lower → disegno folio,
which is exactly ricalco's dependency set — no crate gains an edge, no
`no_std` surface changes (test space compiles `std`; the arena crates'
`src/` is untouched), and the string discipline (`vize_carton::String`,
`cstr!`/`append!`) holds even there because the clippy disallowed-lists
apply to tests. No new dependency was added: the condense mirror is
justified by citation into `vize_armature`, not by a differential test
against it, because a dev-dependency on armature would put ricalco into
`cargo tree -i vize_armature` and muddy the TS-11 reading for no
assurance gain.

## Where the mutations act, and the scope rule

Three mutators act on **source text**: the S1 tree is edited (tokens are
source slices, so S1 is a lossless map of the bytes), re-rendered
through `vize_sinopia::render`, and the mutant source runs the whole
pipeline — parser included. Text split/merge acts on the **S1 tree
directly** (a deviation, owned below): no source spelling can split a
maximal text run, so the split halves stay genuine source subslices
(`Cx::offset`'s debug assert holds) and the mutant lowers in place.

Sites exist only inside an **attribute-less root-level `<template>`**
element — the SFC template block. Script/style/custom blocks are another
language's text, and `lang=`/`src=` templates are not Vue-HTML; the
walk simply does not enter them. Inside scope, `rawtext` elements ban
every mutator, `<pre>` bans the whitespace mutator, and `v-pre` subtrees
ban everything — not because the mutations are provably wrong there but
because P2-8 defers `v-pre` while lowering directives normally, so the
oracle would compare two artifacts that are wrong the same way. The
predicate module (`predicates.rs`) is deliberately conservative; every
refusal is a **counted skip**.

## The justifications live beside the mutators

The contract allowed the record or the code; they landed as the module
documentation of `tests/metamorphic/mutators.rs`, where a reviewer of a
mutator change cannot miss them, and this record only summarizes:

- **Attribute reorder** — adjacent static-attribute transposition;
  HTML's attribute-map semantics plus the exclusions: directive-shaped
  names, case-insensitive duplicates, `class`/`style` in any spelling,
  a frozen tag list where DOM attribute-application order is observable
  (`input`/`img`/`iframe`/…), unquoted or hole-bearing values.
- **Pass-through `<template>` wrap** — moves a `v-if`/`v-else-if`/
  `v-else` onto a fresh wrapper (Vue's documented invisible-wrapper
  pattern; the lowering's own unwrap site is
  `crates/vize_ricalco/src/lower/structural.rs:213-217`). A _bare_
  template is a real element in Vue, so the wrapper always carries the
  moved directive. Root position is argued equivalent (the branch
  resolves to the same node); slot positions are excluded (component
  children, slot templates, `v-slot` carriers), as are `<template>`
  targets and elements with a second branch directive.
- **Text split/merge** — adjacent text nodes are one DOM text run; the
  shipped `transform_text` merge
  (`crates/vize_atelier_core/src/steps/text.rs`) is the
  in-repo statement of that semantics. Split additionally proves its
  exact inverse: re-merging reproduces the original `Full`-mode folio
  byte-for-byte.
- **Whitespace edits** — one whitespace run ↦ a different run over
  exactly Vue's alphabet `[ \t\n\f\r]`, newline-presence preserved
  (the remove-vs-condense decision at
  `crates/vize_armature/src/parser/whitespace.rs:115-118` reads it);
  Vue's condense rules are cited line by line.

## The declared normalization (the oracle)

Folios compare as **full normalized artifacts** — whole-document
`Display` prints, whole-value equality, never a substring (TS-13).
`Display` is `folio-format.md`'s declared elision (every ` @s:e` span
and nothing else), which is exactly the quotient byte-shifting
mutations need; the `ops=` header is recomputed by the printer from the
normalized tree. Each mutator then declares the _minimal_ structural
quotient its justification licenses (`normalize.rs`):

| mutator     | quotient beyond span elision                          |
| ----------- | ----------------------------------------------------- |
| reorder     | `attr` lines under one owner sorted (name, value)     |
| wrap        | none — structural identity                            |
| split/merge | adjacent `ui.text` lines concatenated                 |
| whitespace  | text merge + the mirrored condense (with `<pre>` off) |

The text rules are honest statements about P2-8's v1 scope: the
lowering carries text verbatim per node (`lower/leaf.rs:50-52`, a
recorded non-goal), so until P2-9 lands `transform_text` and the
condense as passes, the quotient _is_ the cited rule set — and when
P2-9 lands, these normalization steps should become no-ops (left open,
below). Sensitivity pins prove the quotient does not collapse real
differences (value differences under sorting, element boundaries under
merging, text differences under condensing), and a normalization
applied identically to both sides can mask but never invent one.

## Scope proof and the measured numbers

Counting is per mutator: sites, applied, predicate skips, and
beyond-cap (applied mutations are capped at 8 per mutator per file for
corpus scale; a capped-out site was safe but unattempted, which is not
a skip and is counted separately). **A run whose total mutation count
is zero fails** — `Report::verdict` — and the failure mode itself is
pinned by test (`a_zero_mutation_run_fails`: one unsplittable text
node → 1 site, 1 counted skip, 0 mutations, exact `Err` text; the
empty file list likewise).

- **Matrix plane** (90 stubs, census pinned exactly): 321 mutations —
  wrap 27/30 sites (the three `template--v-else*` targets skip), split
  102/192 (one unsplittable `"\n"` per stub skips), whitespace 192/192,
  reorder 0/0 (stubs carry one attribute each — the hand-written pins
  below carry reorder's always-on coverage), merge 0/0. Zero failures.
- **Corpus shard** (the two PR-hydrated submodules, 773 files): 10,756
  mutations, zero failures, ~5 s. Line:
  `reorder=856/3809 (skips=2679) wrap=53/218 (skips=165)
split=4736/12361 whitespace=5111/13801`.
- **Full corpus** (read-only against the main checkout's hydrated
  `tests/_fixtures/_git`, the P2-8 honest-label convention, run twice
  with identical counts): 12,215 files, **179,992 mutations, zero
  divergences**, 143 s. Whitespace skips 353 (real `pre`/rawtext
  content), reorder skips 92,268 — the conservative predicates are
  load-bearing, not decorative.
- **A finding: merge's natural census is zero.** The tokenizer emits
  maximal text runs, so parser output never carries adjacent text nodes
  (probed against the recovery shapes too — stray end tags and bogus
  declarations surface as `Unexpected` _between_ text nodes). The merge
  mutator's execution lanes are the split-inverse identity (73,790
  applications over the corpus) plus a dedicated pin that drives its
  real site-enumeration → predicate → apply path on a split tree; its
  natural lane stays armed for any future parser shape that emits
  adjacency.

Hand-written pins keep every mutator exercised independently of the
generated plane, and predicate pins assert the documented refusals
(`template-tag`, `slot-content`, `merge-order-family`,
`duplicate-name`, `v-pre-subtree`, `pre-content`, `rawtext-content`,
and the out-of-scope `lang="pug"` template block).

## CI wiring (the decision, and the reasoning)

check.yml is over the 350-line ratchet and its job list is pinned
sixfold (the P2-14 record); the P2-15 answer is **zero check.yml
growth**:

- **Matrix plane, per PR:** the `metamorphic` target is a plain
  integration test of `vize_ricalco`, so `cargo test --workspace` in
  the unconditional `clippy-and-test` job runs it — required through
  `test-report`'s existing `needs:`, no workflow edit at all.
- **Corpus shard, per PR:** `tests/tooling/davinci-metamorphic-corpus.test.ts`
  rides the `test-scripts` job's `tests/tooling/*.test.ts` glob and
  sweeps exactly the two submodules that job already hydrates for the
  CLI diagnostic fixture (`ant-design-vue`, `create-vue` — 773 real
  files), so the shard costs no extra checkout and no workflow line.
  The gate asserts exit 0 _and_ re-parses the printed scope line
  (`files>0`, `mutations>0`); unhydrated local checkouts skip loudly,
  the `vue2-render-signature` convention.
- **Full corpus:** not wired into PR CI — 143 s of oracle is fine, but
  hydrating 30+ submodules per PR is not, and there is no standing
  corpus-diff workflow to join (TS-11's corpus-diff.mjs is a
  local/release-evidence gate; the only full-hydration workflow,
  `real-project-matrix`, is a weekly CLI-exercise lane whose sharded
  jobs would each pay the test build for one shard's files). The
  full-corpus run stays the recorded recipe — the same env var pointed
  at `tests/_fixtures/_git` — executed and recorded here at land time,
  the P2-8 precedent.

## Deviations, each owned

1. **Split/merge mutate the S1 tree, not the source.** The contract's
   pipeline reads "on original vs mutant" without saying where the
   mutation happens; for these two no source spelling exists (a comment
   splice would change Vue's dev-mode output, so it would be a _wrong_
   spelling). Slices stay genuine subslices; the other three mutators
   go through render → reparse and exercise the parser too.
2. **One test binary, env-gated corpus — not P2-8's `[[test]]
required-features` shape.** The matrix plane is committed, so the
   default target must run everywhere (`cargo test --workspace` _is_
   the PR lane); only the corpus widening is env-gated, and a feature
   gate on the same binary would subtract the plane from the workspace
   run. The `davinci-differential` feature is untouched.
3. **`croquis-consumption.md` was already stale on the P2-8 base**
   (`vize_ricalco`/`vize_s2` sources counted by the naive lane;
   verified by checking with the new files stashed away), and the new
   test files move the counts further. Regenerated here so TS-12 is
   green on this branch; if P2-8's own landing regenerates it first,
   the rebase re-runs `--write` and keeps whichever byte-set the tree
   dictates.
4. **`v-for` is not a wrap source in v1.** Moving `v-for` to a wrapper
   interacts with `:key` placement (Vue wants the key on the
   `<template>`), which is a diff-semantics question, not an invisible
   wrapper — offering it would need a justification this task cannot
   write honestly. Recorded as the natural v2 candidate.
5. **Mutant soundness is not re-asserted per mutant.** The P2-8
   four-part oracle already covers every original corpus file; running
   it per mutant would triple the lane's cost to re-prove totality the
   corpus lane owns. The metamorphic oracle is the added value here.

## Acceptance, clause by clause

- **TS-21 established**: the suite runs over the committed matrix plane
  (every `cargo test --workspace`) and a corpus shard (per PR via the
  tooling gate) with the scope proof — mutations applied and skips
  counted per mutator, zero-mutation runs fail, and the failure mode is
  itself pinned. Registry row updated with the concrete commands.
- **TS-12 green** for the newly committed fixtures — all four `--check`
  entries pass — with the staleness check demonstrably failing on an
  injected edit, both as a one-time proof (performed, then reverted)
  and as a standing temp-dir test.
- **TS-13**: `assertion-lint: OK`, allowlist untouched; every oracle is
  whole-value equality (normalized folio strings, census tuples, exact
  `Err` text, `Vec::new()` failure lists).
- **House rules**: every new file ≤ 350 lines (largest: `sites.rs`
  291 after the predicate split); no `mod.rs` anywhere new; clippy
  house invocation and `--tests` clean including the disallowed-type
  lists; `cargo fmt --check` clean; markdown through oxfmt; arena
  crates untouched so `no_std` surfaces are unchanged.
- **Non-goals honored**: no S3 equivalence, no semantic-fact mutators,
  no `folio-reduce`, and the corpus submodules were never mutated —
  the full-corpus run read the main checkout's fixtures read-only,
  copies in memory only (the P0-13 convention).

## Left open, with owners

- **P2-9 should shrink the declared normalization.** When
  `transform_text` and the condense land as passes, the `merge_text`
  and `condense` rules must become no-ops; the P2-9 series should
  ratchet them out (turn them off and watch the suite stay green) —
  the normalization table above is the checklist.
- The corpus shard follows whatever submodules `test-scripts` hydrates;
  if that set grows, the shard grows for free (the gate names the dirs
  in one list).
- The per-file cap (8 per mutator) and the midpoint split choice are
  pragmatic; a seeded-random site sample under a printed seed is the
  natural widening if TS-21 ever needs more depth per file.
