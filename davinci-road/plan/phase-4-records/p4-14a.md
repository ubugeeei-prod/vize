# P4-14a — Structured diagnostic renderer

Contract: [phase-4-tasks-last.md](../phase-4-tasks-last.md#p4-14a--structured-diagnostic-renderer). Charter #42.

## What landed (2026-09-22)

**`vize_davinci::render`**, `#![no_std]` + `alloc` like the rest of the crate
(TS-24 builds it for `wasm32-wasip2 --no-default-features`). One public
entry, `Renderer<'c, C: Catalog>` — generic, so the catalog is statically
dispatched — rendering a `vize_davinci::Diagnostic` against a `SourceFile`
(path + authored text + the S0 `LineIndex`, built once per file):

```text
error[vue/require-v-for-key]: Elements in iteration expect to have `v-bind:key` directives.
 --> src/components/TodoList.vue:9:9
  |
9 |     <li v-for="todo in todos">{{ todo.title }}</li>
  |         ^^^^^^^^^^^^^^^^^^^^^ each `<li>` rendered here needs a stable key
  |
  = help: without a key, Vue reuses DOM nodes in place and can mix up item state when the list changes
help: key each item by its id
  |
9 |     <li v-for="todo in todos" :key="todo.id">{{ todo.title }}</li>
  |                              +++++++++++++++
```

- **Headline** `severity[code]: message`; continuation lines of a multi-line
  message align under its first character.
- **Location** from the primary span's start, line and column derived at
  render time from the S0 line index (P2-1). The column is in UTF-16 code
  units exactly as `LineIndex` and the LSP report it, so a terminal location
  and an editor location agree.
- **Excerpt** in rustc's layout: `^^^` primary / `---` secondary marks (a
  primary mark wins an overlap); the rightmost label inline when nothing
  extends past it, every other label hanging on its own row with `|`
  connectors, rightmost first so connectors never cross; multi-line spans in
  margin columns (`/` when a span opens at a line's content, a `__^`
  connector otherwise, `|_^ label` under its last character), with greedy
  column reuse for spans whose lines do not overlap and `|` left standing
  where a connector crosses an open span; a one-line gap is printed, a longer
  one is `...`, and a long span shows its first and last two lines.
- **Footers** `= help: …` from `PartKind::Help`, multi-line help aligned.
- **Fixes**: a run of consecutive `PartKind::Suggestion` parts (message =
  replacement) is one fix, titled by an immediately preceding help part or
  by the catalogue's "suggested fix". Insertion-only fixes print the edited
  line with `+++` under the inserted text; anything else prints the touched
  lines before (`-`, removed text red) and after (`+`, inserted text green).
  Overlapping edits cannot apply together, so an overlap starts a new fix.
- **Terminal-faithful text**: every column is a sum of display widths
  (`unicode-width`, no_std) over the same normalized glyphs the row prints —
  east-asian wide characters and emoji take two columns, a tab prints as four
  spaces, C0 controls and DEL print as their control pictures (`␛`, `␡`),
  bidirectional overrides and isolates as `�` (the Trojan Source class), a
  zero-width joiner as nothing. Producer labels and messages go through the
  same normalization, so an escape byte in a message cannot restyle the
  terminal. A `\r` pairing with `\n` is a terminator, not text.
- **Degenerate spans** are normalized exactly as `Span::slice` does (clamp,
  then snap down to a char boundary): inverted, past-the-end and mid-character
  spans render, never panic.
- **Colour**: one palette (rustc's: severity colour for the headline and
  primary marks, bright blue for the gutter and secondary marks, cyan for
  guidance, green/red for fix text). Colour off is the same bytes with the
  escapes removed — asserted for every case in every locale.

**Where messages come from.** Producer text arrives already localized — Patina
resolves its messages through `vize_carton::i18n` at report time, in the
linter's locale — so the renderer never re-translates a headline or a label.
What it resolves through the `Catalog` is its own vocabulary, a closed
`Phrase` enum (severity words, `help`, the default fix title) keyed by
`Phrase::key`, so a catalogue is total by construction. The en/ja/zh
vocabulary lives in `crates/vize_carton/src/i18n_render.rs`; `EnglishCatalog`
is the built-in English for callers without a translator, pinned equal to the
`en` column. Compiler and other producers that lack localized text are
P4-14b's.

**Codes beside the diagnostic.** `vize_davinci::Diagnostic` does not carry a
code yet — that field belongs to lane D's P4-6 work on `diagnostic*` — so
`render_into(out, file, code: Option<&str>, diagnostic)` takes it alongside.
When the diagnostic grows a code, the call sites pass it through; nothing in
the renderer changes.

**`vize lint --format rich --locale <en|ja|zh>`** (`crates/vize/src/commands/lint/rich.rs`)
is the CLI edge the contract names: `LocaleCatalog` implements `Catalog` over
the shipped translator, `--locale` also sets the linter's locale so Patina's
messages arrive translated, and the report ends with a localized summary
(`1 ファイルを検査し、エラー 2 件、警告 3 件が見つかりました`). `rich`
previously aliased Patina's `ansi` formatter at the CLI; `ansi` itself is
unchanged. The `LintDiagnostic` → `Diagnostic` mapping there is deliberately
interim: labels become secondary parts, a fix becomes a titled suggestion
run, help (rendered to plain text) becomes a footer. P4-6c's canonical
Patina conversion replaces it, and with it FP-1: until then the two rules
FP-1 names render script-block offsets against whole-file lines here as they
do in every other lint format. The adapter builds error diagnostics with
`Diagnostic::new`; when P4-6a makes errors witness-only, it moves to the
exemption constructor with the rest of Patina.

## Evidence

**TS-53**, both halves, registered in [test-suites.md](../test-suites.md):

- `cargo test -p vize_davinci --test diagnostic_render` — 14 cases (every
  layout path: inline and hanging labels, multi-line labels, slash and
  connector multi-line spans, three nested multi-line spans sharing two margin
  columns, elision inside a 13-line span with a two-digit gutter, both fix
  styles, a two-edit fix across lines, Japanese identifiers and text with
  emoji, tabs + CRLF + a bidi override, end of file, every severity, codes and
  none, and the degenerate spans) × en/ja/zh plain snapshots + an ANSI
  snapshot per case: **56 committed files**, compared byte for byte; the
  directory must hold exactly those files; colour-stripped output must equal
  plain output in all 42 case×locale renderings; `EnglishCatalog` must equal
  the shipped `en` column.
- `node --test tests/tooling/davinci-diagnostic-catalog.test.ts` — enumerates
  the `Phrase` variants, `Phrase::ALL` and the key arms from the renderer
  source and the translations from `i18n_render.rs`; fails on a phrase
  missing in any locale, an empty translation, a placeholder set that differs
  from `en`, a drifted `EnglishCatalog`, or a case without all three locale
  snapshots. Proven to fail: removing `render.help`, blanking one `zh`
  entry, dropping a `ja` placeholder and truncating `Phrase::ALL` each
  produce exactly their one pinned problem.

TS-1 `cargo test -p vize_davinci`; TS-13 assertion lint clean on the new
tests; TS-24 `cargo build -p vize_davinci --lib --target wasm32-wasip2
--no-default-features` green.
