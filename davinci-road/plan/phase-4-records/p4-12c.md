# P4-12c — Pug as an S1 dialect

Contract: [phase-4-tasks-last.md](../phase-4-tasks-last.md#p4-12c--pug-as-an-s1-dialect). Charter #12.

## Slice 1 — the lossless pug surface, its lowering, and the compile lanes (2026-09-22)

**The surface is pug's own parse, lossless.** `crates/vize_s1/src/pug/` ports `pug-lexer@5.0.1` (dispatch order, regular expressions, indentation stack, `addText`'s `#[…]` / `#{…}` / `\`-escape splitter, `pipelessText` with its retry) and `pug-parser@6.0.0`'s recursive descent (`tag()`'s head-parts / same-line / block switch, `parseText`'s newline-join rule, `parseTextBlock`, `parseTextHtml`, `: ` block expansion) and `character-parser@2.2.0` (bracket, string, template, comment and regexp-vs-divide states) over the text Vue actually hands pug: `@vue/compiler-sfc`'s `dedent` of the `lang="pug"` block, then pug's BOM strip and `\r\n`/`\r` normalization. That _logical_ view keeps an origin map, so every token is a slice of the **authored** bytes and the bytes the view drops (dedent prefix, the `\r` of a CRLF) fall into `leading`: `render(parse_pug(src)) == src` holds by construction and is debug-asserted on every parse, like the Vue surface.

**Hole policy, pug edition** (crate docs of `vize_s1::pug`): an unterminated `#[` closes with a `Missing` `]`; everything pug throws on — an unlexable line rest, a bad `.class`/`#id`, an unclosed `(`, an attribute key error, a token pug's parser rejects, an indented block no construct owns — becomes an `Unexpected` node, text piece or attribute item under a recorded `PugErrorCode` (the pug error name it mirrors). Recovery is deterministic: an inconsistent outdent keeps the line a sibling at the innermost level it does not outdent past, mixed tabs/spaces count as indentation. Unbuffered `//-` comments are **trivia**: pug strips them before parsing (`pug-strip-comments`), so they never shape the tree (two piped lines around one still join with `\n`) and ride in the next token's `leading`, the SwiftSyntax trivia model. Constructs the lowering refuses are recognised with pug's own patterns and kept verbatim as `PugNode::Refused` with their bodies.

**The lowering desugars at S1 and reuses the one Vue lowering.** `crates/vize_s1_to_s2/src/lower/pug*` replays `pug-code-gen@3.0.4` + `pug-attrs@3.0.0` + `pug-runtime@3.0.1` under the options every Vue toolchain passes (`doctype: "html"`, `pretty: false`): class shorthands and `class=` merge into one leading `class`, `pug_escape` on escaped values, `pug_attr`'s terse booleans and dropped `false`/`null`/empty `class`/`style`, `pug_style`, void elements, the `SELF_CLOSING_CONTENT` / duplicate-attribute / duplicate-id checks, the first-`html`-tag doctype, and — found by the fuzz below — the runtime path a bare attribute takes, whose key pug pastes into a JavaScript string (so it renders cooked, and a key that is no valid string body breaks pug's build). Attribute values and `=` code fold only what pug folds without an engine (string and substitution-free template literals with ECMAScript escape cooking, `true`/`false`/`null`/`undefined`, plain integers). The output is the **derived Vue template** plus a `PugSourceMap` from every derived byte to the authored pug byte it came from (verbatim copies map exactly: tag names, text, unquoted keys, literal bodies that render unchanged). `lower_pug` parses the derived template into the Vue surface and runs `vize_s1_to_s2::lower`, returning S2 over the derived template with **all diagnostics in authored pug coordinates** (the Vue lowering's own — e.g. a stray `v-else` — land on the pug attribute that wrote them).

_Why not a second S1→S2 lowering over pug nodes:_ it would re-implement the Vue lowering's decision surface (structure, `v-if` chains, `v-for`, slots, `v-model`, text condensing — thousands of lines) for a dialect whose only semantics is "render to that HTML"; that is the dual lane charter #26 forbids, and it would make the compile oracle a property to test instead of a construction. Desugaring at S1 keeps one lowering and makes pug-vs-HTML compile equality hold by construction; the source map carries provenance. Pug-specific S2 facts (none are needed today; P4-12c's non-goals exclude pug lint rules) would attach through the same map.

**Refusal** (Vue's documented pug support is a static preprocessor pass): mixins and calls, `include`, `extends`/`block`/`yield`, `if`/`unless`/`else`, `each`/`for`, `case`/`when`/`default`, `while`, filters, `-` code, `#{…}`/`!{…}`, non-constant attribute values and `=` code, `&attributes`, `doctype` — each an error diagnostic at the construct naming the Vue alternative; nothing is emitted for it. Under P4-6's witness law these errors add no exemption: pug lexer errors report through the one `surface-syntax` site beside the HTML tokenizer's, refusals through the one `lowering` site beside the structural lowering's (`vize_s1_to_s2::exemptions`), so `witness-exemptions.tsv` is unchanged.

**Compile lanes.** `vize_atelier_sfc` selects `lang="pug"` (inline templates) in the compile entry, beside the root-`v-match` view: the template content becomes the derived Vue template and DOM, Vapor and SSR compile it exactly as an authored HTML template; refused pug fails the compile with `PUG_TEMPLATE_ERROR` located in the SFC. Before this slice a pug template compiled its pug source _as HTML text_.

**Storage** ([storage boundary](../storage-boundary.md)): S1 stays free of `alloc::vec::Vec` — the lexer's token and error buffers, indentation stack, text-block scratch and the character-parser stacks all live in the parse arena (`vize_s0::Vec`), and the regexp heuristic's keyword test reads a fixed 11-byte window instead of collecting. The lowering retains four reviewed sites: diagnostics in `lower/pug.rs` and `lower/pug/emit.rs` (analysis) and the attribute worklists and source-map segments in `lower/pug/attrs.rs` / `lower/pug/map.rs` (lower); every row and aggregate is in `storage-inventory.tsv`.

## Slice 2 — the corpus compile oracle with scope proof (2026-09-22)

**Baseline.** `tests/_fixtures/davinci-pug/corpus-baseline.tsv` pins one row per inline `<template lang="pug">` SFC of the registered corpus at its pinned revision — 498 rows over 7 projects (wave-ui 219, dho-web-client 211, lx-music-desktop 30, vue-cal-v4 16, vuelidate 14, splitpanes 7, vux 1; vux's one `src=` template is out of scope) — holding the sha256 of the pinned `pug@3.0.4` rendering of the content `@vue/compiler-sfc` extracts. `tests/tooling/davinci-pug-corpus-oracle.test.ts` recomputes the rows for every hydrated project and requires exact equality (a missing, extra or drifted SFC fails), and reports which projects it proved; it runs in the real-project matrix beside the glyph pug oracle.

**Lane.** `davinci_pug_corpus` (feature `davinci-differential`) pins the baseline's 498-row scope on every pull request (clippy-and-test) and, over a hydrated corpus, requires for every pug SFC: TS-19 fidelity, TS-20 totality and soundness, the derived template's sha256 equal to the pinned pug's, and the SFC compiling **byte-identically to its twin whose template is that HTML** in the DOM, SSR and Vapor lanes; every baseline row of a present project must be visited. It runs on the fully hydrated corpus in the real-project matrix's `davinci-dom-corpus` job, before the corpus is dehydrated. Measured locally over the pinned-revision corpus: 498 SFCs, 0 refused, **1,494 of 1,494 lane compiles identical**.

**Provenance.** The source map now records verbatim-ness explicitly (a synthesized run that happens to equal its construct's length no longer maps byte-for-byte), a span ending in synthesized bytes widens to the whole construct, and an attribute's synthesized bytes map to the whole authored `name=value`.

## Slice 3 — pug templates lint (2026-09-22)

**Selector.** Patina's `lint_sfc` routes an SFC whose inline template is pug through `PugBlockView` (`vize_s1_to_s2::lower::pug::view`): the block is swapped for its derived template, the SFC lints through the one template lane, and every diagnostic, label and fix range maps back onto the authored host; a fix that would edit the swapped block is dropped (its diagnostic stays) because derived HTML has no pug spelling. A refused template keeps the pre-dialect behaviour — its compile reports the refusal.

**Authored order.** pug hoists the merged `class` attribute to the front, so linting pug's exact rendering reported `vue/attribute-order` for what pug did (3,647 of the corpus findings) rather than what the author wrote. The view uses `PugRendering::AuthoredOrder` — the same elements, attributes, values and text with the class attribute at its authored position; compile keeps the exact rendering.

**Comparison surface.** vue-eslint-parser does not parse pug, so the ESLint baseline of the real-project lint-divergence gate cannot see inside a pug template. `lint-divergence-report.rs` reports Patina findings inside an inline pug template body as `patinaOutsideBaselineSurface` (counted, hashed, not scored) instead of false positives; findings elsewhere in the SFC are compared as before.

**Evidence.** `cargo test -p vize_patina --test pug_template_lint`: a pug SFC reports exactly its HTML twin's diagnostics with every range on the authored pug bytes (`v-for="item in items"` for `vue/require-v-for-key`); all 26 matrix fixtures lint like their pug-rendered HTML for every rule but attribute order, which is pinned separately against the authored order. `node --test tests/tooling/lint-divergence-pug-surface.test.ts` runs the real runner (pinned ESLint baseline) on a pug SFC: 0 false positives, 1 finding outside the surface, budget passed.
