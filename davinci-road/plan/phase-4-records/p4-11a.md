# P4-11a — Content-model tables and exact per-file checker

**Acceptance evidence is complete; the box stays open until P4-6a lands.**
The contract depends on P4-6a because the `exact` tier this checker claims
has to be declared through P4-6a's precision-tier types, which have not
landed yet. When they do, registering `vue/permitted-contents` as `exact`
is the only step left.

## Boundary

`crates/vize_patina/src/html_content_model/` decides, for every element and
text node of a template as authored, whether the HTML parser keeps it where
Vue's virtual DOM puts it (parser family) and whether the content model
permits it (content-model family). The checker covers 21 classes and is
three-valued: a finding is reported only when it holds in every context
consistent with the template, and anything unknown stays silent.
`vue/permitted-contents` reports exactly what the checker proves.

## Acceptance

- **`--check` fails on an injected edit.** `tests/tooling/davinci-matrices.test.ts` regenerates the table into a scratch copy, removes one `void` member and asserts exit 1 naming the row.
- **TS-37, 100% recall, count-exact by identity.** `seed-defects.rs --html-nesting` (`tools/support/davinci/seed_html.rs`) appends one snippet per checker class to every eligible template. For each class it expects exact identities (file, rule, span), and it asserts the seeded lint equals the baseline moved through the insertions plus the injections. `tests/tooling/davinci-html-nesting-seeds.test.ts` pins the committed miniature set at 45/45, checks that the seeded classes equal `ViolationClass::id` (plus the P4-11b class), and proves the assertion fails against a linter that finds nothing. The injections include one P4-11b cross-component injection per file that has a `<script setup>` block. A file is seeded only when its name appears in no other source file, because a seeded root inside an imported child would add composed findings at the parent that no manifest row names. That rule is why eligibility is low in auto-import projects.
