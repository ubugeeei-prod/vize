# P4-14b — Catalog completeness for every producer

Contract: [phase-4-tasks-last.md](../phase-4-tasks-last.md#p4-14b--catalog-completeness-for-every-producer). In progress; the TODO box stays open until every producer is catalogued and P4-6c has landed.

## Slice 1 — the template compiler's 56 codes (2026-09-22)

**Stable codes.** `vize_relief::ErrorCode` gains `ALL` (the 56 variants in
declaration order), `code()` — the user-facing name, `compiler/<variant in
kebab case>`, e.g. `compiler/v-if-no-expression` — and `from_code()`. The name
is what a rendered diagnostic shows (`error[compiler/v-if-no-expression]`) and
what `vize explain` (P4-14c) will accept, so it is a published surface.

**Catalogue.** Every code has `compiler/<name>.message` and
`compiler/<name>.help` in en, ja and zh — 112 entries in three per-section
Rust tables (`crates/vize_carton/src/i18n_compiler{,_template,_directive}.rs`),
not in the over-budget JSON files. The `en` message is byte-identical to
`ErrorCode::message()`, so no English output moves. The Japanese and Chinese
are written for the reader, not glossed from the English — the HTML tokenizer
errors say what went wrong and where (`タグ名の前でファイルが終わっています。`
for `EofBeforeTagName`, where the English reads only "Unexpected EOF in tag."),
and each help names the concrete fix with the Vue syntax it needs.

**Adapter.** `CompilerError::to_diagnostic(locale)` is the one route from the
compiler's error type onto the unified `vize_davinci::Diagnostic`: a warning
when the compiler recovers (`is_recoverable`), an error otherwise; stage from
the code (tokenizer and Vue syntax → Surface, transforms → Lowered, modes →
Emit); the location's byte span (the file start when there is none); the
headline in the requested locale when the error carries its code's standard
message, its own call-site message otherwise (the `with_message` sites
are not catalogued yet); the code's help as a part (not for `ExtendPoint`,
whose meaning is its message); and errors built with
`Diagnostic::legacy_error` under the inventoried `vize_relief/compiler-error`
exemption (P4-6a) until the compiler produces witnesses. `vize_relief` takes a runtime dependency on `vize_davinci` for it.

**Checks.** `tests/tooling/davinci-diagnostic-catalog.test.ts` now also parses
the `ErrorCode` enum, `ALL`, `code()` and `message()` from source and fails
when a variant is missing from `ALL`, is not named `compiler/<kebab>`, lacks a
message or help entry, or has an `en` message different from `message()`;
proven by a removed help entry, a reworded `en` message and a renamed code,
each producing exactly its one problem. Rust unit tests pin `to_diagnostic`
exactly (a standard error in ja, a recoverable custom-message error in zh,
`ExtendPoint`), the name round trip and uniqueness, and that every code's ja
and zh message and help differ from the English.

## Slice 2 — every lint rule described in en, ja and zh (2026-09-22)

**0 of 248 rules without a description in any locale**, down from 121. The
missing `<rule>.description` entries (a11y 4, css 10, ecosystem 9, html 7,
musea 5, nuxt 4, script 60, type 5, vapor 1, vue 16) live in four Rust tables,
`crates/vize_carton/src/i18n_rules_{markup,script,script_more,ecosystem}.rs`,
whose `en` column is each rule's own `RuleMeta`-family description byte for
byte. Japanese uses the register rule catalogues read in
(〜を禁止する / 〜を必須にする / 〜を推奨する, 非推奨とする for "discourage");
Chinese the matching 禁止 / 要求 / 推荐 / 不建议.

The catalog check enumerates the rules mechanically — every `RuleMeta`,
`ScriptRuleMeta`, `CssRuleMeta` and `MuseaRuleMeta` declaration under
`crates/vize_patina/src/rules`, 248 names — and fails on a rule with no
description in some locale (JSON files, supplemental tables and the new
tables together), a new description whose `en` drifts from its rule, one that
names no rule, or one catalogued twice. Proven by a removed entry (three
problems, one per locale), a drifted `en`, and a blanked `ja` in the JSON
source. The 45 pre-existing JSON `en` descriptions that differ from their
`RuleMeta` text are left as they are: nothing reads them at runtime, and the
over-budget JSON files are not rewritten here.
