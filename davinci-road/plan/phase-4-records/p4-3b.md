The index is checked. External reads of `component_usages` and
`used_components`, including lane C, go through `ComponentUsages`.

## Group

`ComponentUsages` in `crates/vize_croquis/src/facts/components.rs`
records each template use with its source index, then the
used-component names in that set's iteration order. Readers call
`component_usage_list`, `used_component_name_list`,
`used_components_empty`, and `used_component_contains`. Test writes
call `Croquis::note_component_usage` and `Croquis::note_used_component`.
Field storage stays in this crate.

`RenderTree` in `crates/vize_croquis_cf/src/facts/render_tree.rs` is
keyed by the caller file, the component file the module graph resolves,
and the name that file exports. A local alias is not the key. A
re-export is followed to the original file. A missing import falls
back only when one component in the project has that name, so two
same-basename files do not depend on registration order. Recomputing
the table drops an edge the current files no longer support.
