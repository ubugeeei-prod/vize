# P4-7b — Facade switch (slice 1: the SFC markup lane)

**The SFC template lane now runs every markup-capable rule through its
`MarkupRule` body over the markup facade, in one fused walk, and no longer
through its legacy `Rule` hooks. A three-lane switch oracle proves each body
reproduces its hooks exactly, on the Relief backend (production) and on the S2
backend. Slice 1 landed 2026-09-22; the S2-backend swap and the variant
deletion moved to P4-8c (below).**

## What landed

- `crates/vize_patina/src/linter/engine/template.rs` (split out of
  `engine.rs`): a template runs through two lanes over one `LintContext`, and
  a rule runs in exactly one of them — its markup body when it has one, its
  directive hooks otherwise. The directive lane still registers every
  suppression comment before either lane reports. The two lanes' reports are
  interleaved in source order (a stable merge on the start offset), so a
  template reports in the one-walk order it did before the switch; the
  type-aware diagnostics snapshot is unchanged.
- `markup/hooks.rs`, `markup/dispatch.rs` (+ `dispatch/layout.rs`): a rule
  declares the hooks it implements (`MarkupRule::hooks`, default all); a fused
  `MarkupRuleSet` calls each rule only at its hooks, in registration order,
  and the facade walk skips a binding / directive / scope walk nobody listens
  to. `MarkupDocument::visit_rules` drives the set; `visit_with` keeps the
  one-rule form.
- `linter/engine/lane_plan.rs`: which rule runs in which lane, and each markup
  rule's subscription laid out per hook, is computed once per `Linter` (a
  `OnceLock` dropped whenever the registry changes) instead of per template.
- `visitor.rs`: `LintVisitor` dispatches a prepared list of the rules it runs;
  a rule another lane owns is never visited, not even to be skipped, and a
  walk with no rule left only serves the comment directives.
- Hot facade queries (`tag`, `kind`, `range`, `is_unqualified_tag_exact`)
  inline their Relief arm and keep the other backends out of line
  (`markup/element/projected.rs`).
- `Rule::markup_on_templates` (default `true`) lets a rule keep its template
  hooks: `vue/permitted-contents` (lane I, P4-11a) re-reads the template as
  authored in `run_on_template`, which the facade over the repaired lint
  parse is not, so templates keep that entry and the oracle covers the other
  39 rules.
- All 40 markup rules declare their hooks. The oracle's findings brought nine
  bodies to exact parity with their hooks (`require-v-for-key`,
  `no-access-key`, `no-autofocus`, `interactive-supports-focus`,
  `no-redundant-roles`, `html-button-has-type`, `img-alt`,
  `no-unsandboxed-iframe`, `prefer-static-class`, the shared
  `markup_helpers`); `mouse-events-have-key-events` reads its handlers in one
  binding pass. One behaviour change, a bug fix: `vapor/prefer-static-class`'s
  fix edit for `<div :class="'a'">` ended one byte late and swallowed the
  tag's `>`; it now ends at the attribute (its unit snapshot moves 29 → 28).

## The switch oracle

`markup/differential/switch.rs` runs every markup rule three ways over one
template: **legacy** (its hooks over the lint parse — the pre-switch lane),
**relief** (its body, fused, over the Relief facade — the production lane) and
**s2** (the same bodies over the S2 facade). The relief lane must reproduce
the legacy diagnostic set — rule, severity, message, span, help, labels, fix —
on every template; the s2 lane too, except where the lint parse restructured
the authored tree (HTML tree construction; `differential/nesting.rs`), where
the two backends present different documents by design and the template is
counted, never compared.

| Surface                                                    | Templates | Restructured | Relief-agreed | S2-agreed | Divergences |
| ---------------------------------------------------------- | --------: | -----------: | ------------: | --------: | ----------: |
| Committed planes + every rule's fixture SFC (plain suite)  |     1,068 |            0 |           825 |       825 |           0 |
| Repo corpus (`davinci_markup_differential`, scope `smoke`) |       737 |            — |         1,178 |         — |           0 |

The plain-suite census is pinned (`markup_bodies_reproduce_their_legacy_hooks`),
so the oracle cannot silently compare an empty set; the corpus entry panics on
the first divergence.

## Performance (charter #22)

Instructions retired per `lint_template` call (`proc_pid_rusage`, Apple
silicon, release), `origin/main` against this branch built back to back:

| Case                                                    |   main | branch |      Δ |
| ------------------------------------------------------- | -----: | -----: | -----: |
| `lint_large` — 100 `v-if` blocks, default preset        | 7.059M | 6.963M | −1.4 % |
| `lint_small` — 7 elements, default preset               | 197.2k | 199.1k | +1.0 % |
| `markup_ir/template_only` — 80-figure gallery, one rule | 2.052M | 2.044M | −0.4 % |

Rebuilding identical code moved these counts by up to ±1 % (code layout), so
`lint_small` is at the noise floor rather than a measured slowdown. Wall-clock
Criterion on the shared 17-agent host swung ±10 % between identical runs and is
not quoted; CI's `pr-benchmark` A/B is the gate.

How the gap closed, for the record: the first cut (per-rule traversal over the
S2 facade) ran `lint_large` 4× slower — lowering an S2 tree per template
beside the Relief parse costs more than the parse itself (S1 + S2 lowering
199 µs against the Relief parse's 117 µs). Moving the lane onto the Relief
facade and fusing the walk left it +26 %; hook subscriptions, the active-rule
list, the cached lane plan and the inline Relief arms took `lint_large` below
main.

## Re-cut: why the S2 backend waits for P4-8c

P4-7b's original deliverable — "markup rules over the S2 facade only; the
Relief and JSX variants deleted" — needs the S2 artifact per template. While
the directive lane still runs the remaining rules over the Relief parse,
lowering S2 next to it is a second, costlier parse on every template (above),
which the perf gate forbids. The directive lane empties at P4-8c, where the
legacy hooks are deleted, so the SFC lane's move onto the S2 backend and the
variant deletion (with its `grep` acceptance) moved into P4-8c. The switch
oracle already proves the S2 backend exact outside the restructured bucket,
so that move is a backend change, not a behaviour change. P4-7b keeps the
switch itself: this slice, and `lint_jsx` onto the P2-16 projection.
