# P4-10a — Provider contract and Vue Router provider

**`vize_croquis_cf::providers` lands the app-level fact provider contract the
open question recommended — a provider is a project-level population pass
that declares its ambient inputs and exclusively owns its output groups — with
the in-tree `VueRouterProvider` producing `route-tree` and `route-params`, a
witness-carrying route-typing consumer in `vize lint --cross-file`, and Maestro
route-name completions read off the same groups. Landed 2026-09-22.**

## Boundary

In: `createRouter({ routes })` routers (named and namespace `vue-router`
imports), `routes`/`children` as array literals, `const` bindings and relative
imports of them (named, default, re-exported), nested path joining, the full
param grammar (`:id(\\d+)`, `?`, `+`, `*`, `\\:`), route components (default
imports and `() => import('./X.vue')`). Navigation sites: `push`, `replace`
and `resolve` on a proven router receiver, `$router.…` in template
expressions, `<RouterLink :to>`. Out, by the contract's non-goals: Nuxt and
file-based routes (P4-10b), path-string navigations, external providers
(P6-7), type information for non-literal param values (P4-5b's projection).

## Decisions

| subject        | decision                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Contract       | `trait Provider { NAME, INPUTS: &[AmbientInput], OUTPUTS: Demand, DESC }`. A provider's groups are ordinary `FactGroup`s with `FactProducer<ProjectSources>` impls registered in the const `PROJECT_FACTS` registry, so stratification and the TS-35 detector apply unchanged.                                                                                                                                                                                                          |
| Single writer  | `check_providers(&[ProviderDesc], Demand) -> Result<(), ProviderError>` is a `const fn`; `ProviderRegistry::new` panics on any error, so a second writer is E0080 in a `const` item (doctest). Errors: `NoInputs`, `NoOutputs`, `UnproducedOutput`, `SecondWriter { group, owner, writer }` — each asserted exactly.                                                                                                                                                                    |
| Ambient inputs | `AmbientInput::{ScriptModules, SfcTemplates, Glob, Config}`; `ProviderRegistry::inputs(demand)` folds the inputs of every provider owning a group in the demand's closure — the P5-1 key-manifest entry. The Vue Router provider reads `ScriptModules`.                                                                                                                                                                                                                                 |
| Identity       | Provider groups take ids from the reserved `40..48` block (`route-tree` = 40, `route-params` = 41), disjoint from per-artifact groups, so a witness link's group id is program-unique.                                                                                                                                                                                                                                                                                                  |
| Features       | `provider-vue-router` (default) compiles the provider and its registry entries in (charter #15's first tier).                                                                                                                                                                                                                                                                                                                                                                           |
| Artifact       | `ProjectSources`: whole script modules plus SFCs split once into script/template blocks by the parse-only splitter; every span is a whole-file offset. Relative imports resolve with extensions and `index` files; aliases are never guessed.                                                                                                                                                                                                                                           |
| Soundness      | Bindings resolve through OXC semantic scoping only, so a parameter named `router`, a local `useRouter`, a shadowed `undefined` or a rebound `RouterLink` is never mistaken for Vue Router's. A router whose records are not all static is **open** (`DynamicRoutes`, `DynamicRecord`, `AddRoute`, and any `createRouter` occurrence the finder cannot account for); `route-tree`'s witness verdict is `Proven` only while closed, `route-params`' only for a static path declared once. |
| Diagnostics    | On the unified channel (`vize_davinci::Diagnostic`, P4-6a): `ecosystem/vue-router-unknown-route`, `-extra-param`, `-param-type` are `Diagnostic::proven` errors whose chains cite `route-tree` / `route-params` facts; `-missing-param` is a warning, because Vue Router fills missing required params from the current location — only a runtime-location fact could prove the throw. Rule contract: `Tier::Sound` over the declared domain.                                           |
| Maestro        | Route-name completions list the project's `route-params` names (with the static path as detail) before same-file `<route>`/`definePage` names; the Maestro path-param parser is deleted in favour of the provider's one path grammar (`parse_route_params`). File-name params stay until P4-10b.                                                                                                                                                                                        |

## Demo

`tests/_fixtures/davinci-routes/demo-app` is the Vue Fes demo: nested named
routes, an imported admin module and a component misusing them. Run
`vize lint --cross-file` inside it for 4 errors and 2 warnings, each with the
route's declaration site, its params and their accepted types in the help.

## Mechanical witnesses

- `cargo test -p vize_croquis_cf --test davinci_routes` — the TS-9 lane: five
  fixture projects (`demo-app`, `multi-router`, `open-tree`, `param-types`,
  `shadowing`) rendered exactly (facts, then diagnostics with parts and
  witness links) against their `expected.txt`; every witness re-verified by
  `vize_davinci::witness::verify` (TS-36); a forged witness citing an open tree
  fails with the exact `WitnessError::NotProven`; `undeclared_accesses() == 0`
  (TS-35)
- `cargo test -p vize_croquis_cf --lib providers` — the exact `ProviderError`
  for every violation class, the input manifest, module resolution, the path
  grammar
- `cargo test -p vize_croquis_cf --doc providers` — the second-writer
  `compile_fail,E0080` registry and its compiling twin
- `cargo test -p vize_maestro --lib -- provider_groups ecosystem::router` —
  exact route-name completion rows from the provider

## Follow-up

P4-10b adds `NuxtProvider` (the `pages/` tree, `definePageMeta`) as a second
provider in the same registry and flows `route-params` into the P4-5b
projection for `useRoute()` / `navigateTo`. Route typing joins the default
lint lane once TS-38 corpus triage has run over it.
