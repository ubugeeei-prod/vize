# P4-9a — Template CFG complexity facts and metric spec

**Landed 2026-09-22.** The metric is decided and written down
([complexity-metrics.md](../complexity-metrics.md)). The `template-complexity`
pass computes it over S2 regions, and an independent naive evaluator agrees
with it over the matrix plane, a CI corpus shard and the full corpus. The pass
is also registered as the `TemplateComplexityGroup`
[fact group](../phase-4-tasks.md#p4-1a--fact-api-core), which every consumer
reads under a declared demand.

## Boundary

The pass produces facts and nothing reads them yet. Replacing the string
counting in `vize_croquis_cf/src/rules/complexity.rs`, rendered (cross-file)
complexity, the `vue/max-template-complexity` rule and the Doctor finding are
[P4-9b](../phase-4-tasks-later.md#p4-9b--cross-file-complexity-rule-and-doctor-finding).
Script-side complexity is a non-goal.

## Decisions

| subject             | decision                                                                                                                                                                                                                                                          |
| ------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Metric              | Both families per component; the rules, evaluated positions, exclusions and the five amendments to the open-question recommendation are in the spec.                                                                                                              |
| No materialized CFG | Structured S2 regions make `E − N + 2 = 1 + decisions`; the pass counts decisions, the oracle builds the graph and measures `E − N + 2` (connectivity checked first).                                                                                             |
| Classification      | `Optional`, `Fusable`, `Preserved::ALL`: a shared-borrow pre-order visit with an inherited nesting depth, no provenance, no diagnostic. Name `template-complexity`.                                                                                               |
| Fusion              | Appended to `TRANSFORM` after `hoist-static`; the two analyses form one non-barrier group — the S2 pipeline's first real fusion (four passes, three walks, pinned as `const` assertions and by the budget observer in TS-17).                                     |
| Planning            | A fifth selectable mask bit; `TransformProfile::without_complexity_analysis()`. No emitter plans it: the DOM product path never ran optional passes through the planner, and the JSX S2 emit declines it next to `hoist-static`.                                  |
| Product             | `S2Facts.complexity: Option<ComplexityFacts>` (`None` when declined): totals, `unknown`, `max_nesting` and the breakdown rows (kind, file span, carrying op's page-order id, nesting, both increments) in source order; `print_facts` is the canonical text form. |
| Thresholds          | Warn strictly above the full-corpus p95: cyclomatic > 11, cognitive > 16.                                                                                                                                                                                         |

## Measurements

- TS-34 (`cargo test -p vize_s1_to_s2 --test cfg_complexity_oracle`): 17
  hand-computed pins (both implementations equal the hand value), the matrix
  plane (90 files, 90 templates, 36 rows, 0 unknown — census pinned), and the
  CI shard `ant-design-vue` + `create-vue` (773 templates, 515 rows, 49
  unknown) wired as `tests/tooling/davinci-complexity-corpus.test.ts`.
- Full corpus, run locally: 41,580 files, 40,724 templates, 124,732 rows,
  zero disagreements; the distribution table and its reproducing command are
  in the spec.
- TS-17 (`cargo test -p vize_s1_to_s2 --test cfg_pass_snapshot`): full
  post-pass folio and full breakdown snapshots for `constructs.vue` (every
  rule, cyclomatic 15 / cognitive 18, hand-checked) and `dashboard.vue` (the
  demo component, 13 / 18); budget observer `walks=3 passes=4`.
- TS-22: the atelier walk probes do not run the S2 transform planner, and the
  S2 pipeline gains a pass without a walk; the traversal ceilings are
  untouched.
- TS-10: `s1_to_s2_pass_template_complexity` = 3 allocations (the breakdown
  vector growing 4 → 8 → 16 rows over the demo component), wall report-only;
  registered in `budgets.toml [bench]` and the CI allocation gate.

## The fact group (on P4-1a)

| subject  | decision                                                                                                                                                                                                                                             |
| -------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Group    | `pass::cfg::TemplateComplexityGroup`: id 48, stratum 0, no dependencies, `Key = ()`, `Value = ComplexityFacts`. The S2 analyses of this crate take the upper quarter of the 64-id space, away from the pass manager's own ids and the Croquis waves. |
| Artifact | One template block's text (`str`), with no copy. Its facts use block-relative spans; `template_facts::<C>(source, start, end)` computes through `TEMPLATE_FACTS`, reads under `C`'s view and shifts the spans into the file.                         |
| Readers  | `vue/max-template-complexity` and the cross-file analyzer (`croquis-cf/template-complexity`) each declare exactly this group. `run_template_range`, which bypassed the API, is gone.                                                                 |

`cargo test -p vize_s1_to_s2 --test cfg_fact_group` is TS-35 for the group:

- two consumers on one artifact produce the group once, with zero undeclared accesses;
- an undeclared reader gets the exact `FactError::Undeclared`;
- the table equals the pass run directly, and once placed in its file it equals the file-absolute lowering.
