# P4-11b — Composed cross-component conformance

**In progress (not yet claimed): the composed check, the CLI rule and the
runnable example are on `main` once the first slice merges; the acceptance
items still open are listed under "Open".**

## Boundary

`html/cross-component-nesting` is the check no per-file tool can make: every
template is valid on its own, and the collision appears only where a parent
renders a child. `vize lint --cross-file` resolves each component usage
through the parent's imports, re-checks the child's whole template in the
parent's open-element chain with the P4-11a checker
(`crates/vize_patina/src/html_content_model/composed.rs`), and reports at the
usage site every verdict that differs from the child's standalone check.

## Decisions

| subject            | decision                                                                                                                                                                                                    |
| ------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Resolution         | Imports only (`CrossFileAnalyzer::resolve_imported_component`); an alias follows its import, a same-basename file elsewhere is never picked.                                                                |
| Roots              | Single roots, every `v-if`/`v-else` alternative and every fragment root; nested component roots are followed while the chain reaches the parent.                                                            |
| Unknown is silent  | Unresolved tags, dynamic `:is`, `<slot>` pass-through, recursion (revisited file) and depth > 16 stop the chain.                                                                                            |
| Branch feasibility | `v-if` conditions are not evaluated (same domain as P4-11a): every branch is assumed reachable. Prop-sensitive feasibility is FP-3.                                                                         |
| No duplicates      | A child verdict equal to its standalone verdict is left to the per-file `vue/permitted-contents`.                                                                                                           |
| Witness            | The message names the child element, the component chain and the child position (`<div> (rendered by <InfoCard> at src/components/InfoCard.vue:6:3)`); the label marks the parent element it collides with. |
