# P4-1b — Fact preservation and recompute mode

**Facts are wired to the P2-2 pass manager: after a pass,
`FactManager::after_pass` drops every group outside the pass's post-hoc
`Preserved` set (the LLVM new-PM import), the named preservation groups are
`const Preserved` values over a single fact-id table, and the verify mode
recomputes every kept group and rejects a pass lying about what it preserves
with the exact `FactError::StalePreserved`. Landed 2026-09-22.**

## Boundary

No production producer exists yet (P4-3 registers them), so the named groups
are defined over the reserved ids of the P4-3 groups. Caching facts across
compiles (P5-1) and S3 phase ordering are out of scope.

## Decisions

| subject                  | decision                                                                                                                                                                                                                                                                                 |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Artifact borrowing       | `FactManager` no longer holds the artifact: passes mutate it between queries, so `compute`, `prepare` and `after_pass` take its current state. Every group is produced at most once per artifact **state**; `after_pass` is the only way a group goes away.                              |
| Invalidation             | `after_pass::<V>(&artifact, &PassDesc)` keeps `computed ∩ desc.preserved` and drops the rest (returned as a `Demand`). Preserved means kept as-is; there is no cascade — verify mode is what catches a kept group whose inputs changed.                                                  |
| Named groups             | `PRESERVE_STRUCTURE = {ComponentUsages, RenderTree}` (a pass rewriting only expressions keeps them); `PRESERVE_BINDINGS = {Bindings, UndefinedRefs, UnusedBindings, Reactivity}` (a pass moving template structure without touching an expression keeps them). Disjoint, pinned.         |
| Id table                 | `fact::ids` is the single allocation point of production `AnalysisId`s (`0..32`: the nine P4-3 groups today); `32..64` stay free for fixtures and benches. A const block asserts unique, ascending, below the fixture range. The P4-1a fixtures moved to `32..64`.                       |
| Verify mode              | `FactVerify` policy types (static dispatch, P2-3): `FactVerifyObserver` (`ENABLED = cfg!(debug_assertions)`) and `NoFactVerify`, both const-asserted ZSTs. On a mismatch every stale group is dropped and the first in stratum order is reported.                                        |
| Exact comparison         | `FactGroup::Value: PartialEq` (every fact oracle is exact equality); each `ProducerEntry` carries a type-erased table equality next to its producer, so recomputation compares the kept and fresh tables exactly. Verification recomputes are not productions.                           |
| Why not a `PassObserver` | A `PassObserver` hook sees only the `PassEvent`, while the pass body holds `&mut` to the artifact, so an observer cannot recompute on the pass's output. The verify policy is therefore a type parameter of `after_pass`, which the pass body calls — the same zero-cost-when-off shape. |

## Mechanical witnesses

- `cargo test -p vize_davinci --test fact_preserve` — an honest `Preserved::ALL`
  pass keeps every table; `double` drops exactly `{values, total}` and the next
  demand recomputes only those (production counter delta pinned); the lying
  pass is rejected with `StalePreserved { pass: "lying-double", group: values }`
  and every stale table dropped; trusting mode keeps the stale total (6, not
  12); the named groups are exact id sets and a `PRESERVE_BINDINGS` pass keeps
  exactly its member
- `cargo test -p vize_davinci --test fact_demand --test fact_manager --doc` (P4-1a lanes on the new API)
- `cargo bench -p vize_davinci --bench davinci_fact -- --quick` —
  `davinci_fact_query_observed` and `davinci_fact_query_unobserved` both a
  measured **19 allocations**, registered in `budgets.toml [bench]` (TS-10);
  TS-22 walk counts are untouched (no walker changed)
- TS-24 (`--target wasm32-wasip2`, with and without default features), release
  build (ZST assertions), TS-13 assertion lint, `davinci-budgets` /
  `davinci-storage-policy` / `davinci-module-layout` checkers

## Follow-up

P4-2 adds the α form (`AlphaExport`) beside `FactTable`. P4-3 waves register
producers under `fact::ids` and give their passes real `Preserved` sets built
from the named groups.
