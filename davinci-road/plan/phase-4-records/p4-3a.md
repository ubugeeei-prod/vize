## Decisions

| subject         | decision                                                                                                                                                                                                                                                                                                                                                                            |
| --------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Artifact        | Producers read the drawn `Croquis`: the tracker code stays the population pass and the struct fields stay producer storage until P4-5c. `vize_croquis::facts::CROQUIS_FACTS` is the const, stratified registry; `CroquisFacts` pairs one artifact with one `FactManager`, so a group is produced once per artifact however many demands reach it.                                   |
| Ids             | `fact::ids::BINDINGS` (1) and `UNDEFINED_REFS` (2) from the P4-1b table; no literal minted here.                                                                                                                                                                                                                                                                                    |
| `Bindings`      | One relation for three fields: key `BindingKey::{ScriptSetup, Name(name)}` (the nullary marker is a presence fact and sorts first), value `BindingFact { kind, span, prop_key }` — the exact union of `bindings`, `binding_spans` and `props_aliases`, nothing inferred. `BindingsTable` gives the name-level reads (`binding_type`, `contains_binding`, `span`, `typed`, `spans`). |
| `UndefinedRefs` | Key = walk-order ordinal, value = the `UndefinedRef`. Every occurrence is a diagnostic and consumers report in walk order, so the β table keeps occurrences and order; the α page planned in [fact-alpha-schemas.md](../fact-alpha-schemas.md) (name → count + first span) is a fold of it, registered when P5-2 needs it.                                                          |
| Consumers       | Each reader declares a `FactConsumer` with its const demand (the rule name for rules, `maestro/…`, `canon/…`, `vitrine/…` otherwise); an undeclared read panics through `expect("declared demand")` in every debug test run (TS-35).                                                                                                                                                |
| Order           | Map-iteration readers (completion lists, the Vitrine bindings array, the legacy batch generator) now iterate in name order instead of `FxHashMap` order; completion clients sort by `sort_text`, and the one pinned snapshot (`batch::virtual_ts` `generate_from_content`) moved one line. No diagnostic set or position changed.                                                   |

## TS-34 — spec and naive evaluator

`crates/vize_croquis/src/facts/spec/`:

- **`Bindings`** over `<script setup>`: an independent OXC parse reads the
  top-level declarations as syntactic forms (`bindings_extract`, which
  classifies nothing), and the rules are data — `DECLARATION_RULES`,
  `MACRO_RULES`, `REACTIVITY_RULES`, `ALIAS_APIS` — evaluated naively
  (`bindings::evaluate`: last declaration wins, including an API alias,
  and macro props bind `Props` only where no authored name exists).
  Scope: artifacts with a plain `<script>` or a JSX `<script setup>` are
  skipped by named reason, as are scripts with a parse diagnostic or a
  renamed value import from `vue`.
- **`UndefinedRefs`**: the drawer records every expression it checks
  (content, base offset, structural scope vars, scope id) into a debug-only,
  per-thread trace armed by `spec::trace::record` — the Polonius input
  relation. The naive evaluator re-extracts identifiers with no cache,
  resolves names against the **final** scope tree and the final `Bindings`
  table (the drawer uses its live cursor and the walk-time binding map), and
  applies the builtin tables; agreement therefore also proves nothing grows
  a binding or scope after a read was judged. Compared as a multiset of
  `(offset, name, context)`.
- `Agreement` counts artifacts, compared artifacts, facts and skips by
  reason; a divergence **or** a zero-fact run fails.

Mechanical witnesses (`cargo test -p vize_croquis --test fact_spec`):

| plane                                                    | bindings (artifacts / compared / facts) | undefined-refs  |
| -------------------------------------------------------- | --------------------------------------- | --------------- |
| battery (9 SFCs, one per rule family)                    | 9 / 9 / 87                              | 9 / 9 / 11      |
| P0-2 fixture ladder                                      | 6 / 5 / 80 (1 plain-script)             | 6 / 6 / 4       |
| P2-15 matrix plane (90 template-only stubs)              | 90 / 90 / 0                             | 90 / 90 / 0     |
| corpus shard (`ant-design-vue` + `create-vue`, 773 SFCs) | 773 / 670 / 3,125 (103 plain-script)    | 773 / 773 / 251 |

Zero divergences on every plane. Injecting a wrong rule
(`ConstLiteral → SetupConst`) fails the battery and the shard. The shard
runs per PR in the test-scripts job through
`tests/tooling/davinci-fact-spec-corpus.test.ts` (the P2-15 submodules, no
extra checkout); the matrix plane's `Bindings` half is empty by
construction (the stubs carry no script) and is pinned as such.
