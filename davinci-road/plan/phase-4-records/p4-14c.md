## Slice 1 — `vize explain` for every code (2026-09-22)

**The command.** `vize explain <code> [--locale en|ja|zh]`, `vize explain --list`,
and `vize --explain <code>` (rustc's spelling) print the page behind a
diagnostic code: the code and its kind, its catalogued headline or
description, its metadata (a rule's category, default severity, autofix and
docs page; a compiler code's stage and severity) and its help, markdown
rendered for the terminal (ANSI when stdout takes colour). An unknown code is
a usage error that suggests the nearest known code by edit distance
(`compiler/v-if-no-expresion` → `compiler/v-if-no-expression`), in the
requested locale.

**Generated, not written.** The page list is `explain::subjects::all()`: the
compiler's `ErrorCode::ALL` (56) and every lint rule reachable through the
rule registries, the built-in script and Musea rules and the ten CSS rules
(248), each from its own metadata. English descriptions are the rules'
`RuleMeta` text and `ErrorCode::message()`; Japanese and Chinese come from
the P4-14b catalogue. Page vocabulary (`explain.*`) lives in
`crates/vize_carton/src/i18n_explain.rs` and reuses the renderer's severity
words and `help`, so a page and a rendered diagnostic say the same thing the
same way. `LocaleCatalog` moved to `crates/vize/src/commands/explain/catalog.rs`
and is shared with `vize lint --format rich`.

**TS-53, explain half** (`cargo test -p vize --lib commands::explain`, added
to the TS-53 row): all 304 pages per locale equal
`crates/vize/src/commands/explain/snapshots/{en,ja,zh}.txt` byte for byte;
the generated list covers exactly 56 compiler codes and 248 rules, each once,
each found again by `find`; the near-miss suggestion is pinned. The node
catalog check cross-checks the snapshots against the source enumeration: each
locale's `=== <code>` headers equal the compiler codes and rule names parsed
from source, in order.

## Slice 2 — pages for cross-file and verifier codes (2026-09-22)

The 130 codes P4-14b slice 3 catalogues get pages too (`cross-file
diagnostic` with its docs page, `stage verifier invariant`, `type-check
diagnostic`, `SFC compiler diagnostic`, and `TypeScript error` pages showing
the catalogued message and help): 434 pages per locale. Their list is read
from the catalogue's `<code>.description` (and `ts/<n>.message`) keys, a
mirror the node check proves equal to the codes it parses from the producers'
sources, so it stays generated. The coverage test pins 56 compiler codes, 248
rules, 60 cross-file, 16 verifier, 18 type-checker, 14 SFC compiler and 22
TypeScript codes.
