## Decisions

| subject       | decision                                                                                                                                                                                                                                                                                                                                                                                     |
| ------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Rows          | The rows are the `VizeMapping`/`VizeSubSpan` span links the generators already emit (definitions moved into `mapping/rows.rs`), so the 100 construction sites and the `sfc_typecheck` snapshot that prints `VizeMapping { … }` are untouched. Semantic links stay `VizeSemanticLink`, held by the model.                                                                                     |
| Metadata      | `ProjectionMeta { features: ProjectionFeatures (u8 bitset, 8 flags), kind: ProjectionSpanKind }` absorbs Maestro's per-row features/data and Canon's flags/kind. It is a column that stays empty while every row is default, so wrapping generator output (`from_parts`) moves the vectors without copying rows.                                                                             |
| Authored base | Rows keep block-relative authored ranges plus one `authored_base` (Maestro's old `block_offset`); lookups returning authored offsets add it, lookups taking one expect it relative — Maestro's exact contract.                                                                                                                                                                               |
| Two lookups   | Caret lookups (`to_generated`, `to_authored`, `_for` variants, `generated_range_to_authored`) map byte to byte, first containing row, clamped to the last byte — Maestro's arithmetic. Diagnostic lookups (`span_at_generated`, `diagnostic_range_to_authored`) are the narrowest-row, sub-span-first, end-clamped arithmetic the CLI and the Corsa session already shared.                  |
| Overlaps      | `to_generated` binary-searches only when authored ranges are sorted and pairwise disjoint (the unique containing row); otherwise it scans for the first containing row. The retired Maestro map binary-searched any sorted map, which could miss a containing row under nesting and picked an arbitrary copy of a repeated chunk (isolated art variants); both now resolve to the first row. |
| Order         | Maestro producers stable-sort by authored start exactly as `SourceMap::from_mappings` did (`sort_by_authored`, a no-op pass when producers emit in order), so TS-40's order-preserving Maestro record is byte-identical.                                                                                                                                                                     |
| Allocation    | Maestro generators move their row buffer into the document (`mem::take`) instead of cloning it; the retired rows also cloned one `String` per template expression for `MappingData::Expression`, which is gone.                                                                                                                                                                              |

## Finding: a fourth mapping model

Re-cut finding #1 counted three models. A fourth lives in
`vize_carton::source_range::{SourceMap, SourceMapping, MappingData}` and backs
the third generator, `vize_croquis/src/virtual_ts/`. Croquis sits below Canon
in the dependency graph, so it cannot read `ProjectionMapping`; Canon no longer
references that model, and it is deleted with the Croquis generator in P4-5c.

## Slice 2: one diagnostic assembly pass (steps 2–3, landed 2026-09-22)

`vize_canon::projection::assemble_diagnostics(authored, documents, finished,
policy)` is the single assembly point. Surfaces only decode their backend
(`vize check`: `--pretty false` lines or project-session LSP diagnostics;
Maestro: Corsa LSP diagnostics) into `FinishedDiagnostic`s in generated
coordinates, call the pass once per authored file over every projected
document of that file, and render the result. The pass owns, in order:
reportability, the keyof-assignment false positive, projection through each
document's import map and `ProjectionMapping` (plus the missing-`.vue`-import
fallback), authored-position rules, the reachability-warning downgrade, the
template-instance rewrite, authored-message restoration, deduplication (with
the #4966 widened-literal twin), authored `@ts-ignore`/`@ts-expect-error`
suppression and template diagnostic directives. Deleted: the CLI's
per-diagnostic mapper (`lsp.rs`, `skip_rules*`, `template_instance.rs`,
`type_checker/template_directives.rs`) and Maestro's `corsa/{mapping,
template_instance, template_directives}.rs` plus its JSON dedup.

### Convergence ledger (charter #23)

Every rule now runs on both surfaces. What changed per surface:

| Surface      | Now also                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Maestro      | drops TS2666 helper artifacts, the `ArrayBuffer \| SharedArrayBuffer` TS2322 lib-baseline mismatch and the keyof-indexed-assignment TS2322 false positive; collapses literal/widened TS2322 twins; honors `@ts-*` comments above multi-line calls and the `useVModel` passive-false overload; places a missing-`.vue`-import TS2307 on the authored specifier; downgrades a reachability assertion only when its elaboration is exhaustiveness chains; dedups on `(authored start, code, message, severity)` |
| `vize check` | drops TS7044 reported as a suggestion, TS5097 on generated `.vue.ts` and authored `.vue` specifiers, and unused-declaration findings naming generated bindings; the text backend gains the missing-`.vue`-import fallback; authored suppression rules read the registered snapshot instead of re-reading the file; template directives run per authored file inside the pass (a sharded run evaluates a file in the shard that owns it) instead of after the merge                                           |
| Both         | template-instance and directive rules use the SFC template _block_ (`sfc_template_block_range`, the same block `SfcBlockType::Template` reports) instead of the editor's content-only range                                                                                                                                                                                                                                                                                                                  |

Presentation stays per surface and is not a policy: `AssemblyPolicy::report_unused`
(`vize check` follows the tsconfig's `noUnused*`; an editor shows the hints
Corsa sends), private path spellings (`vize check`'s virtual root and mirror
specifiers, the editor's overlay roots), position encoding, and the editor's
original code spelling (`2322` vs `"TS2322"`).

### Decisions

| subject        | decision                                                                                                                                                                                                                          |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Unit           | One call per authored file over all its documents (Maestro: the SFC plus inline/art variants; `vize check`: the canonical file plus byte-identical package shadows), so directives and dedup see the file's complete set.         |
| Empty files    | A directive-bearing Vue file with no checker findings is still assembled (`@vue-` substring gate), so unused expectations surface exactly as before.                                                                              |
| Template range | `vize check` passes the block it already has. The editor parses lazily: for a lexical lookup failure (as the retired `template_instance::apply` did) or when a finding meets an authored `@ts-ignore`/`@ts-expect-error` comment. |
| Text backend   | Continuation lines stay a decoding concern; the reachability predicate the decoder needs is the pass's own (`is_unreachable_pattern_diagnostic`).                                                                                 |
