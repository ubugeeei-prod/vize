# P4-13 — Musea onto S0 and S1

**Slice 1 (2026-09-21): `parse_art` runs on the shared SFC splitter plus an
S1 surface tree of the `<art>` block; the old hand scanner survives only as
the test-only differential oracle. Slice 2 deletes that oracle and closes the
task.**

## Boundary

`ArtDescriptor` and every public `vize_musea` entry point keep their shape;
only how the descriptor is read from source changes. Script bodies still go
through `vize_croquis::script_parser` for `defineArt()` (that reader never
scanned blocks), and the OXC-backed lossless script wrapper stays a non-goal,
as the contract says. The Vite plugin's own JavaScript scanners
(`npm/builder/vite-musea`) and Patina's Musea rules are other lanes.

## Decisions

| subject          | decision                                                                                                                                                                                                                                                |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| S0 split         | `vize_croquis::sfc::parse_sfc` — the one SFC container splitter compile, lint and the LSP already read — yields `<script>`/`<style>` blocks and the first `<art>` custom block; the art block's whole element extent becomes an S0 `SourceBlock` frame. |
| S1 tree          | `vize_s1::parse` over that frame; its first root child is the `<art>` element. Metadata reads the open tag's attribute tokens; variants are `variant` elements found by an explicit-stack walk that does not descend into a variant.                    |
| Attribute reads  | Exact names (case-sensitive, as before); a value is the first occurrence of the name that carries one (`title` then `title="x"` answers `x`); presence reads (`default`, `skip-vrt`) count valueless occurrences. Values stay authored bytes.           |
| Offsets          | Every descriptor string is still a slice of the source (Maestro does pointer arithmetic on `variant.template`); every offset is file-absolute through the S0 frame, and `SourceLocation` keeps its `\n`-counted line and byte column.                   |
| Container errors | An `<art>` block the splitter cannot close stays `NoArtBlock` (the contract the Vite plugin reports for `<art>` alone); any other splitter failure surfaces as `ParseError` with the splitter's message and line.                                       |
| Byte scanning    | No `memchr`/`memmem` outside the oracle; `memchr` moved to `[dev-dependencies]` and leaves with the oracle. Unused `vize_relief` / `vize_atelier_sfc` dependencies dropped; `vize_s1` added (stage crates are publishable since the re-cut, item 7).    |
| Snapshots (TS-1) | Both parse snapshots are byte-unchanged at their original paths; the `find_art_block` snapshot now pins the same block geometry read off S1 tokens.                                                                                                     |

## The differential lane (TS-11 art surface)

`crates/vize_musea/src/parse/differential_tests.rs` parses every input both
ways and compares one fingerprint per file by exact equality: the full
`Debug` of the parse result, the file-absolute offset of every borrowed slice,
Storybook CSF, Vue output, component docs, catalog entry, palette, owned JSON
and the unknown-status warnings.

| lane                                                                  | files | agree | divergent                  |
| --------------------------------------------------------------------- | ----: | ----: | -------------------------- |
| committed corpus `tests/fixtures/differential` (count pinned)         |   217 |   209 | 8, all on the ledger below |
| example gallery `examples/vite-musea/src` (count pinned, no ledger)   |     7 |     7 | 0                          |
| widened: generated 240-file Musea bench corpus (`musea-corpus.mjs`)   |   240 |   240 | 0                          |
| widened: every `*.vue` in the `origin/main` tree (crates, docs, npm…) |   710 |   710 | 0                          |

The committed corpus is every source on `origin/main` (`b6d258df`) that
contains `<art`: Rust string literals, `.vue` files, TypeScript template
literals and Markdown fences, deduplicated by content hash;
`tests/fixtures/differential/MANIFEST.tsv` maps each fixture to its origin. It
deliberately includes non-art inputs (`<article>` templates, prose that
mentions `<art>`) so the error paths are compared too. Fixtures are stored as
`*.vue.txt` because many are malformed by design and must stay out of the
repository's Vue lint and format lanes. The widened lanes run
with `VIZE_MUSEA_DIFFERENTIAL_CORPUS=<dir>`; their counts are reported here,
not pinned.

## Intentional divergences

Each class is pinned exactly in `parse/divergence_tests.rs`; the four corpus
classes are the only entries of `INTENTIONAL_DIVERGENCES`.

| class | fixtures | the scanner read                                                | S0/S1 reads                                                           |
| ----- | -------: | --------------------------------------------------------------- | --------------------------------------------------------------------- |
| D1    |        5 | `<variant name="a" />` hunted for `</variant>`; the file failed | an empty variant (HTML self-closing, as Patina's Musea rules read it) |
| D2    |        1 | `title = "Button"` is no `title=` → `MissingTitle`              | the `title` attribute                                                 |
| D3    |        1 | a `<style>` inside `<art>` was an SFC style block               | art-block content, not a style block                                  |
| D4    |        1 | unsplittable input (`<article class="…` at EOF) → `NoArtBlock`  | the splitter's `ParseError`                                           |

Scanner bugs no committed fixture exercised, pinned beside them: a
commented-out `<variant>` was still a variant; an `<article>` before `<art>`
made the file `NoArtBlock`; `<art` inside script text was the art block;
`description="a > b"` cut the open tag at `>`; `name=` text inside another
value answered `name`; `default` inside a value set `is_default`; `<art`/
`<variant` followed by `\r\n` were not tags; `</variant >` was not a close
tag.

**Inherited limitation.** The shared splitter ends an unquoted block-tag
value at `/`, so `<art component=./Button.vue>` is a malformed block
(`NoArtBlock`; the scanner read `"."`). Quoted values — every fixture — are
unaffected. Fixing it changes the compile path's splitter and belongs to a
compiler-parity PR of its own.

**Tolerance.** A file the splitter rejects (an unterminated or duplicated
non-art block) now fails `parse_art` where the scanner still found the art
block. No committed or widened input flips from `Ok` to `Err`; editor
consumers already degrade on the same splitter error through `parse_sfc`.

## Cost — faster than the scanner (charter #22)

The first cut was ×1.35 slower than the scanner and was held back for it.
Per-stage timing (release, the 240-file Musea bench corpus × 100 rounds,
best of three, ns per file) located the cost, and two changes removed it
without touching what is read:

| stage                                                      | before |     after |
| ---------------------------------------------------------- | -----: | --------: |
| `defineArt()` read (full analysis → reader)                |  9,131 |     2,657 |
| SFC split (`parse_sfc`, per-style `v-bind()` scan skipped) |  2,003 |     1,360 |
| **`parse_art`, hand scanner**                              | 10,933 |    10,933 |
| **`parse_art`, S0/S1**                                     | 14,112 | **8,146** |

- **`defineArt()` reader.** Both the scanner and the first cut ran the whole
  script-setup analysis (bindings, the global scope chain, reactivity, props
  and emits) to read one macro. `vize_croquis::script_parser::parse_define_art`
  parses once and visits only the statement shapes at which that analysis
  registers `defineArt()`, with the same import bookkeeping and the same
  argument extraction (`extract_define_art`, now shared); croquis pins
  `parse_define_art(s) == parse_script_setup(s).macros.define_art()` over a
  battery of registered and ignored shapes, and the Musea differential still
  agrees with the scanner (which keeps the full analysis) on all 217 + 240 +
  710 inputs.
- **Splitter entry point.** `vize_croquis::sfc::parse_sfc_without_css_vars`
  is `parse_sfc` with `descriptor.css_vars` left empty instead of running the
  `v-bind()` scan per style block; Musea never compiles styles. It is a new
  function beside `parse_sfc` (not an `SfcParseOptions` field, which would
  break struct literals — cargo-semver-checks), so the compile path is
  unchanged; a croquis test pins that it changes nothing but `css_vars`.

**Budget.** `crates/vize_musea/benches/davinci_art.rs` measures one whole
`parse_art` over three pinned inputs (the corpus's `defineArt()` shape, the
legacy `<art title=…>` shape, the gallery's inline `<art>`), and
`budgets.toml [bench]` pins their exact allocations (14 / 15 / 10). The CI
"Davinci allocation gate" runs it through `bench-compare`, so re-introducing
the full analysis (58 / 53 allocations on the `defineArt()` cases, measured)
fails CI; wall time stays report-only until the reference runner records it.
