# P6-8 — Contract versioning and semver policy

**Landed 2026-09-22.** The extension contracts have a written compatibility
policy, machine-checked by a marquette-style classifier over canonical
contract surfaces, and the released surface history is versioned alongside
the WIT.

## What landed

- [`contracts-compat-policy.md`](../../contracts-compat-policy.md): what is
  versioned (package version, protocol version, page schema versions,
  required features), what is additive and what is breaking, how versions
  move, and how the conformance suite moves with the contracts. The WIT
  package links it from its package docs (`crates/vize_extension_sdk/wit/types.wit`).
- `crates/vize_marquette/src/contracts*`: `ContractSurface` — the canonical,
  language-neutral description of one contract version — with deterministic
  pretty-JSON serialization and a SHA-256 fingerprint (`canonical_surface_json`,
  `surface_fingerprint`); `compare_surfaces`, which classifies every change
  with marquette's existing `CompatibilityChange` records instead of a second
  classifier; `check_version_policy`, which enforces the version movement;
  and, behind the optional `wit` feature, `contracts::wit::surface_from_wit`,
  which reads a surface with the Bytecode Alliance `wit-parser` (the parser
  `wit-bindgen` and wasmtime use; `=0.259.0`, `std` only).
- `crates/vize_extension_sdk/versions/vize-contracts@0.1.0.json`: the first released surface.
  `crates/vize_extension_host/tests/contract_surface.rs` holds every released
  surface to the policy pairwise and the newest one byte for byte to
  `crates/vize_extension_sdk/wit/` plus the host's handshake constants, so a WIT change that
  does not choose a policy-conforming version fails.

## Decisions

- **Compatibility is judged from the guest's side**: additive when every guest
  built against the older version keeps working with the newer host. Where a
  value's direction is not modelled (record fields, enum and variant cases,
  flags), any change to an existing type is breaking — over-report, never
  under-report.
- **Direction matters for functions and world items**: a new function on an
  interface a guest exports is breaking (old guests lack it), on a host-only
  interface additive; a new world import is additive, a removed one breaking;
  any world export change is breaking.
- **Before 1.0 the minor number is the breaking axis**; from 1.0, semver's
  major. **A breaking change raises the protocol version by exactly one**, so
  the handshake refuses an incompatible guest before the first call.
- **A page schema bump is breaking** while the host reads exactly one version
  of each page.

## Acceptance evidence

- `cargo test -p vize_marquette --features wit --test contract_compat`: a
  deliberately breaking WIT change (a record field, an enum case, a function
  guests must now implement, a changed signature, a removed host import, a
  page schema bump and a new required feature) yields exactly eight breaking
  changes and its `0.1.1` bump is refused with
  `a breaking change needs version 0.2.0 or later, found 0.1.1` and
  `a breaking change must raise the protocol version by exactly one: 1 -> 1`;
  the same surface at `0.2.0` / protocol 2 passes. A purely additive change
  (new type, host-provided function, imported interface, world and page kind)
  yields exactly six additive changes and no violation. The base surface is
  pinned byte for byte.
- `cargo test -p vize_marquette --test contract_version`: version parsing,
  the least next version per kind, every violation's exact message, the
  canonical JSON pinned exactly with its round trip and unknown-field refusal.
- `cargo test -p vize_extension_host --test contract_surface`: the released
  history and the current WIT agree.
- All three run in the Davinci Contracts CI lane; the feature-free tests also
  run with the workspace.

## Remaining

- The expression and output worlds (P6-1b, P6-1c) enter the surface when
  they land; each is additive over `0.1.0` unless it changes an existing
  interface.
- The post-GA promise (serving the previous major's protocol for one minor
  cycle) is policy for the GA host, not yet implemented; the GA exit (P6-13)
  checks it.
