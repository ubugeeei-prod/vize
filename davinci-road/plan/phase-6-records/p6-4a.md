# P6-4a — MoonBit hosting spike

**Landed 2026-09-22.** Decision: **host the pinned native `moonc` as a
child process behind the `MooncHost` boundary**, the virtual file passed on
its command line; the `@moonbit/moonc-worker` build of the same compiler
under Node is the recorded fallback for hosts without a native toolchain;
in-process wasmtime hosting of `moonc` is not possible today because no
wasm build of `moonc` exists. The spike code is **kept, with tests**, as
`crates/vize_dialect_moonbit/` (feature `moonc`, out of every default
build): a MoonBit expression in a Vue template is projected into a virtual
`.mbt` file with span links, type-checked by the pinned `moonc`, and its
diagnostics land on the authored template columns.
**Review point (open):** the maintainer accepts the hosting choice.

## The showcase

`crates/vize_dialect_moonbit/tests/fixtures/todo-typos.vue` — a script
block with `lang="moonbit"` makes the file's template expressions MoonBit
(dialect selection is per file, like `lang="ts"`):

```vue
<script setup lang="moonbit">
struct Todo { title : String; done : Bool }   // (abridged)
let todos : Array[Todo] = [ … ]
let show_done : Ref[Bool] = { val: true }
fn remaining() -> Int { todos.filter(fn(todo) { !todo.done }).length() }
</script>

<template>
  <h1>{{ remaining() }} left</h1>
  <button @click="remaining">Toggle</button>
  <ul>
    <li v-for="todo in todos" v-show="show_done.val || !todo.done" :class="todo.done">
      {{ "✓ " + todo.titel }}
    </li>
  </ul>
  <p v-if="remaining()">Keep going</p>
  <p v-else>All done 🎉</p>
</template>
```

`cargo run -p vize_dialect_moonbit --features moonc --example moonbit_check -- crates/vize_dialect_moonbit/tests/fixtures/todo-typos.vue`
prints `moonc`'s own messages at the authored positions (excerpt of the
committed `todo-typos.diagnostics`):

```text
error[4014]: Expr Type Mismatch
        has type : () -> Int
        wanted   : () -> Unit
  --> todo-typos.vue:21:19
   |
21 |   <button @click="remaining">Toggle</button>
   |                   ^^^^^^^^^

error[4091]: The type Todo has no field titel.
  --> todo-typos.vue:24:17
   |
24 |       {{ "✓ " + todo.titel }}
   |                 ^^^^^^^^^^

error[4014]: Expr Type Mismatch
        has type : Int
        wanted   : Bool
  --> todo-typos.vue:27:12
   |
27 |   <p v-if="remaining()">Keep going</p>
   |            ^^^^^^^^^^^

todo-typos.vue: 3 error(s), 8 expression(s) checked by moonc 0.10.7+bc794d341
```

Three things a JS template cannot say: a handler must be `() -> Unit`, not
a function returning `Int`; the `v-for` alias is typed by the collection, so
the field typo is caught inside the loop scope; and `v-if` wants a `Bool` —
MoonBit has no truthiness. The typo also makes `moonc` warn that `title` is
never read, and that warning maps into the script block. The fixed file
(`todo.vue`) checks with **zero** diagnostics.

## How it works

1. **S0** (`sfc.rs`): the shared SFC container scan; a `lang="moonbit"`
   (or `"mbt"`) script block selects the dialect for the whole file.
2. **Projection** (`projection.rs`, `projection/emit.rs`): the template is
   lowered S1 → S2 like any Vue template; each S2 expression position is
   re-read as `ExprRef::Foreign { dialect: "moonbit" }` and emitted by
   `MoonBitDialect` — the **first implementor of
   `vize_s2::expr::capability::ExprDialect`** — into one virtual file: the
   script verbatim, then `fn __vize_template()` with the template's control
   structure as MoonBit control flow (`v-if` → `if`/`else if`/`else`,
   `v-for` → `for … in …`) and each other position as a typed demand
   (`{{ e }}` needs `Show`, `v-show` needs `Bool`, a handler reference needs
   `() -> Unit`, an inline handler must be a `Unit` statement, a dynamic
   argument must be a `String`). Every expression and the script are
   copied byte for byte, so each span link is one-to-one (charter #14).
   Positions outside the subset (`v-model`, slot scopes, custom directives,
   a third `v-for` alias) are reported, never dropped.
3. **Host** (`host.rs`, `native.rs`): one coarse call per SFC — the whole
   virtual file in, `moonc`'s JSON lines out — the shape of the WIT worlds.
4. **Mapping** (`diagnostic.rs`, `lines.rs`, `render.rs`): `moonc` reports
   1-based lines and end-exclusive columns in **Unicode scalar values**
   (measured: `"😀x"` advances two columns); ranges inside a link map
   offset for offset, ranges in a position's scaffolding map to its whole
   expression, and anything else would be `Origin::Projection`, which the
   fixtures pin to zero.

## Measurements

All on macOS arm64 with the pinned toolchain `moonc v0.10.7+bc794d341
(2026-08-11)` installed from `cli.moonbitlang.com` with
`MOONBIT_INSTALL_VERSION=0.10.7+bc794d341` (the `setup-moonbit` installer).

**1. A wasm `moonc` under wasmtime — no artifact exists.** `moonc` is a
native OCaml binary (`file moonc`: `Mach-O 64-bit executable arm64`). The
only in-process build MoonBit publishes is
`@moonbit/moonc-worker@0.1.202608112+bc794d341` (the exact pinned build;
tarball sha256 `0f228ae3…3e00`): `moonc-web.cjs`, 5,543,409 bytes, first
line `// Generated by js_of_ocaml` (`version=5.8.2`), zero occurrences of
`WebAssembly`. It is JavaScript, not wasm. A throwaway wasmtime 48.0.2
probe (features `cranelift runtime std gc gc-drc`; deleted after the
measurement) recorded exactly:

| Input                                                     | `wasm_gc(false)`                                                                                | `wasm_gc(true)`                                                                                                             |
| --------------------------------------------------------- | ----------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| `moonc-web.cjs`                                           | `failed to parse WebAssembly module: magic header not detected: bad magic number` (bytes `// G`) | same                                                                                                                        |
| `moonlex.wasm` (toolchain's own wasm-gc tool, 149,308 B)  | `gc proposal must be enabled to use subtypes (at offset 0xd)`                                   | compiles (385 ms); instantiation: ``unknown import: `__moonbit_fs_unstable::write_bytes_to_file_new` has not been defined`` |
| a `moon build --target wasm-gc` hello world (364 B)       | `array indexed types not supported without the gc feature (at offset 0xb)`                      | compiles (1.4 ms); instantiation: ``unknown import: `spectest::print_char` has not been defined``                           |

So wasmtime 48 _can_ run MoonBit's wasm-gc output once the gc proposal is
enabled — which the workspace's `extension-host` wasmtime does **not**
enable today — but the toolchain's own wasm tools import 20
`__moonbit_fs_unstable.*` functions plus `spectest.print_char` (the
`moonrun`/V8 host API, not WASI), and `moonc` itself has no wasm form.

**2. Node sidecar (`moonc-worker`) — works, byte-identical diagnostics.**
Its `check()` takes files as in-memory strings (a real virtual
filesystem) and the pinned core bundle's 79 `.mi` files as bytes. On an
idle machine: module load 150–172 ms, first check 135–147 ms, warm check
79–93 ms. Diagnostics equal the native ones except the `path` field
(`./app.mbt` vs `vize/app/app.mbt`) and one gap: the API has no warning
control, so `missing_priv` (warning 4) appears unless the dialect filters
it. Under a shared-machine load average of 46: load 259–909 ms, warm
check 178–602 ms.

**3. Native `moonc` child process — chosen.** `moonc check -no-mi -w -4
-pkg vize/sfc -pkg-type library -std-path <bundle> -i <bundle>/prelude/prelude.mi:prelude
-target wasm-gc -error-format json -replace-name F.mbt -replace-content <text> F.mbt`
checks a file that **does not exist on disk**: `-replace-content` is the
virtual filesystem. Exit 0 = no error, 2 = errors; diagnostics are JSON
lines on stderr. Even with `-no-mi` it writes `<pkg>.ast` and
`<pkg>.typechecked` beside `-o`, so each check runs in a private scratch
directory removed afterwards. On an idle machine: 25–28 ms per check,
process spawn included; under load average 46: 48–62 ms (the Node warm
check under the same load: 178–602 ms).

**Why native:** it is the toolchain CI already installs at the pin
(`.moonbit-version`, shared with the Nix shell), 3–10× faster than the warm
Node path with no resident process to manage, and it needs no JS engine.
The Node build stays the fallback for the wasm/browser builds of vize,
where no native toolchain exists; both answer the same JSON, so they sit
behind the same `MooncHost` trait and share one mapping.

**Limits recorded:** one argv entry is capped at 128 KiB on Linux
(`MAX_ARG_STRLEN`), so a projection over 131,071 bytes is refused with
`HostError::TooLarge` before spawning (tested); a temp-file transport lifts
it when a real template needs it.

  rewrites the goldens.

## Findings for P6-5 (the `ExprRef` report)

1. **The compound text merge erases expressions.** `{{ a }} left` lowers to
   one `ui.interpolation` whose `ExprRef` is `Opaque(Compound)` with
   rebuilt text; the per-interpolation expressions are gone from S2. The
   spike recovers them from the S1 tree; a foreign dialect needs the parts
   as `ExprRef`s in S2 itself.
2. **Foreign expressions are re-read, not lowered.** The lowering parses
   every position as JS first (`Js` or `Opaque(ParseRejected)`), then the
   dialect re-wraps the text and span. P6-4b needs the lowering to
   construct `Foreign` when the file's dialect is not JS.
3. **`emit` has no span-link channel.** `ExprDialect::emit` writes to a
   `dyn fmt::Write`; verbatim emission makes the link recoverable from
   offsets, but a transforming dialect needs `emit` to return mapping rows
   (the P4-5a `ProjectionMapping` shape).
4. **Binder positions are expressions.** The `v-for` value alias arrives as
   an `ExprRef` like a read; `enumerate_bindings` on it reports the alias as
   a reference. The contract needs a binder/reference distinction.
5. **Column units differ per consumer:** S0 bytes, LSP UTF-16, `moonc`
   Unicode scalars — the mapping model must name its unit.
6. **Warning control is host-specific** (native `-w`, none in the worker
   API): host parity needs dialect-side filtering.
