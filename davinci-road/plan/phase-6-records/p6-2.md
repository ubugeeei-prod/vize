# P6-2 — Prebuilt versioned SDK

**Landed 2026-09-22.** Guests build against a packed SDK that depends on no
vize implementation crate; CI packs it, builds a hello-world dialect from the
tarball alone and runs it through the host in both hosting modes.

## What landed

- `crates/vize_extension_sdk/` (experimental, `no_std` + alloc): the canonical WIT
  package (`wit/`) and released surfaces (`versions/`), its `wit-bindgen`
  bindings with a public `export_input_dialect!`, the handshake constants and
  `capability(langs)`, writers for the S1 page (full grammar) and the S2 page
  (elements, static attributes, text), and — with the default `runtime`
  feature, on `wasm32` only — the runtime an import-free guest provides
  itself (dlmalloc, `cabi_realloc`, `memcmp`/`bcmp`, the panic handler).
  Its dependencies are exactly `wit-bindgen =0.62.0` and `dlmalloc =0.2.14`.
- `crates/vize_extension_sdk/examples/hello-dialect/`: a `lang="hello"`
  dialect greeting one name per line, in under a hundred lines.
- `npm/extension-sdk/` (`@vizejs/extension-sdk`): the contract types in the
  component-model JavaScript mapping (`index.d.ts`) and the handshake
  constants (`index.js`), dependency-free.

## Acceptance evidence

- `cargo test -p vize_extension_host --features extension-host --test sdk_hello`:
  `cargo package -p vize_extension_sdk`, unpack the `.crate` outside the
  source tree, copy the example's sources beside it with a manifest whose
  only vize dependency is the unpacked tarball, build for `wasm32-wasip2`,
  and exchange a block in both hosting modes — the negotiated `lang:hello`,
  and the S1 and S2 pages byte-equal to pinned text.
- `node --test tests/tooling/davinci-extension-sdk.test.ts`: the SDK's direct
  dependencies are exactly the pinned pair and no workspace crate is
  reachable through its resolved graph; the same check **fails with exact
  messages on an injected `vize_s1` edge** (and an unlisted crate); the SDK's
  WIT and released surfaces live in the SDK; all eleven WIT types and both
  exported interfaces in `index.d.ts` match the released surface; the JS and
  Rust constants equal the released handshake.
- `cargo test -p vize_extension_host --test sdk_pages`: the SDK's S1 writer
  prints byte-equal pages to the host's printer over the TS-19 battery and
  all 2,148 truncations; the S2 writer's pages are canonical disegno pages;
  the SDK's capability equals the in-tree Vue offer.

## Review point: publication

The SDK is packed, not yet published: `vize_extension_sdk` is
`publish = false` and `@vizejs/extension-sdk` is `private`. A crate's first
crates.io publication and a new npm package need the maintainer's registry
registration before the release pipeline's Trusted Publishing can take them
over; the release plan forbids deferred crates (`publish_crates` must
partition every publishable crate). Flipping both, and adding them to the
release order and the support-tier table, is the maintainer's step, and P6-9
(external validation against a tagged release) depends on it.
