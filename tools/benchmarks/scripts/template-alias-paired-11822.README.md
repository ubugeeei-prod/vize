# Public mapper comparison

This controller compares an exact fixed public baseline commit (which may be historical main) with a dispatcher-admission candidate through the normal Node CLI and freshly built NAPI SDK. It creates 2,500 typed Vue components here and installs an independent public npm lock: TypeScript 7.1.0-beta, TSRS 0.21.0-ts7.1.0-beta and Vue 3.5.44. It does not inherit external private corpus results, historical package comparisons, Vue Content Mapper, Misskey or n8n results.

Pull requests run strict TypeScript and finite negative controls. The manual Blacksmith 32-CPU job requires an explicitly approved source/comparison packet before dispatch. It has a 60-minute hard limit, a shared 53-minute processing deadline and a target seven-minute artifact reserve. Child stages clamp their deadlines to the shared processing deadline; setup Actions and upload use the job hard limit. An incomplete or timed-out population cannot produce medians or an accepted conclusion. The setup/build estimate is not a proven completion budget.

The driver builds two independent source capsules with identical ci-opt features and compiler versions, verifies physical declarations and native build tokens, and rejects production differences outside dispatcher admission. Public provider, source, helper and wrapper closures must remain unchanged. Artifacts retain original streams, source/image/lock hashes, commands, statuses and generated inputs. External commands receive a restricted environment without CI credentials or loader overrides.

Runtime preflight records the runner, CPU models, affinity, available parallelism and exposed CPU controller files before the two source builds. v1/v2 hierarchy observations and file availability are distinct; missing or denied quota values stay explicitly unavailable with their cause. They never mean zero or unlimited CPU. Measurement records CPU conditions before and after, including partial failures, and rejects a changed runner, affinity or width. Dynamic CPU frequency and tick counters are evidence rather than equality conditions; unavailable controller telemetry alone does not reject the measurement.

Execution has separate populations:

- Forty primary calls: five alternating source pairs per host and cache policy. Every call starts a fresh process with normal checker defaults and incremental output disabled. Empty owned cache/temp directories are compared with an immediate repeat reusing those directories and workspace. OS page caches remain unmanaged; neither policy measures a persistent warm process or a controlled cold OS.
- Four protocol captures: backpressure-preserving raw tees outside the primary population. Every initialization/project/transform response must match ordered requests; all 2,500 authored transform texts, mappings and metadata must agree between sources.
- Four semantic calls: positive and negative template property access, consumed expect-error and unused expect-error must produce exactly the authored oracle. Whole same-host output and statuses must agree.
- Four extended-diagnostic phase calls: counters are untimed evidence. Official TypeScript performs additional GC and reports terminal allocation, which is neither peak memory nor RSS. No corresponding behavior is inferred for TSRS.
- Twelve memory calls: three source pairs per host, sampled separately at a requested 25 ms interval. Kernel PID/start identities and all thread child lists identify observed descendants. Samples retain RSS/PSS, actual sampling durations and mapper NAPI/Go checker/launcher roles. Each RSS/PSS sum is non-atomic across its retained begin/end window. Sampling skew, short-lived processes and inter-sample peaks can be missed; the result is neither an exact peak nor a guaranteed bound. Missing roles/images, read failures, survivors or diagnostic mismatches fail qualification.

Primary GNU time reports wall time, waited CPU and maximum single-process RSS; it is not process-tree RSS. Every corpus call requires all twelve authored script diagnostics with exact starts/codes and full messages. Raw output preserves order and duplicates; canonical packets preserve multiline messages. CLI end ranges and related information are unavailable, so full authored-range qualification is false. Whole projections and same-host output equality qualify the bounded dispatcher-only comparison, not arbitrary checker or SDK changes.

Results apply only to the recorded baseline/candidate SHAs; they do not qualify a later main or a rebased candidate. The controller keeps accepted-performance false even after complete populations. Source-bound peer review of raw evidence is required before interpreting a result. There is no speed or memory win until an actual campaign completes. This cohort uses normal default CPU/checker width only and does not establish scaling. Full-graph Misskey/n8n and persistent warm LSP require separate campaigns.
