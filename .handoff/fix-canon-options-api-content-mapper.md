## Divergences (vs vue-tsc)

Fixed here (both routes):
1. FP TS2588 on template assignment to `@PropSync`/`@ModelSync`/`@VModel` fields and to class `get`/`set` pairs. #13335 made them computed (Options) bindings, so canon emitted them as `const`. Fix: `options_api/class_members.rs`; `default_export.rs` adds them to `writable_computed`. Repro: `matrix/class-vue-property-decorator`.
2. FN for members inherited through `extends:`/`mixins:` of another SFC (#13270): every inherited member became `any`. Root cause in `$VueComponentOptions`: the extra `setup?: (props: Readonly<Props>)` and `__defaults?: any` break Vue's `MixinToOptionTypes` inference. Fix in `component_export.rs`: an authored component export omits both. This changes the generated export of every Options SFC. Snapshot `batch/virtual_project/snapshots/...register_vue_file_rewrites_options_api_export_default.snap` needs `cargo insta accept`. Repro: `matrix/extends-from-sfc`, `pin-2134-*`.
3. FN for template `$emit` (unknown event or wrong payload) in Options components: `$emit` came from the generic `ComponentPublicInstance`. Fix: `options_api/instance_emit.rs` plus `setup_helpers/declarations.rs` read `$emit` from the authored instance. This applies only to an Options default export without script setup whose template names `$emit`, so generated output is unchanged otherwise. Repro: `matrix/dc-emits-object`, `emits-array-template-payloads`, `plain-ts-emits-object-template`, `dc-instance-dollar-members`.

Not fixed (gaps, both routes unless noted):
- FN: JSDoc types in `<script>` + checkJs are ignored, which gives FP TS7006 and FN. Cause: the virtual file is always `.tsx` (`CONTENT_MAPPER_VIRTUAL_EXTENSION`). Fixing it needs a JS codegen, which is a design decision. Repro: `js-dc-checkjs`, `js-jsdoc-*`.
- Vue 2.7: the content mapper hardcodes `legacy_vue2: false` (`content_mapper.rs:191`), so it misses the parent prop TS2322. `vize check` uses the legacy bridge instead, which gives an FP on `this.$emit` against `$This` and an FN in filters files. Which dialect the content mapper should use is a design decision. Repro: `vue27-*`.
- FN:
  - lowercase local registration (`renamed` → `Renamed`): `dc-components-directives`, `options-component-casing-registrations`
  - `defineAsyncComponent` props: `async-and-global-components`
  - `:is="Field"` against a `components` entry (vue-tsc TS2339): `model-and-kebab-on-options-child`
  - generic function-form `defineComponent`: `generic-define-component-function`
  - `strictTemplates` unknown prop on an Options child: `strict-templates-options`
- Wrong code: template assignment to a prop reports TS2588 where vue-tsc reports TS2540. Vize also reports a getter-only computed, which vue-tsc allows: `dc-template-assignments`.
- Wrong position: an unused default import is reported at 4:8 instead of 4:1: `strict-flags-rich`.
- FP:
  - `const o: ComponentOptions = {...}; export default o`: `plain-object-generic-annotation`
  - a contextual-keyword member (`as`) inherited from an imported mixin gives TS2304, because `has_unresolved_extends` only looks at `extends`
- Not vize bugs (vue-tsc quirks or checker version):
  - vue-tsc rejects class components (TS2528) and own-template members under `expose`
  - vue-tsc reports inject members as missing
  - tsgo 7 anchors TS2769 at the first argument (TS 5.9 anchors at the callee) and orders unions differently
- Content mapper only: transient TS18069 ("failed to transform") with the unoptimized ci build under load avg 80–90. It was not seen with the published build and is unconfirmed.
