## Zero-regression rules
- Type checker precision: Vize aims to be more correct and stricter than vue-tsc, not identical. Never drop a stricter-than-vue-tsc check.
  Every change keeps existing strictness tests unchanged and adds a regression test for the behaviour it fixes.
- Performance evidence comes from Blacksmith Actions, never from local Mac timings.
  - Anything touching `vize_canon`, the content mapper, virtual_ts emitters or helper `.d.ts`: dispatch
    `gh workflow run typecheck-corpus-pair.yml --ref main -f base_sha=<40-hex merge-base> -f head_sha=<40-hex PR head> -f corpora=misskey,n8n,nuxt-ui,reka-ui`
    and read `pair-out/summary.md` from `gh run download <id>`. Required: diagnostics IDENTICAL (or a classified, more-correct change),
    tsc types/instantiations not up, generated bytes not up without reason. tsc counts are deterministic; tsrs counts jitter ~±0.5%;
    tsc wall jitters ~±6% on n8n, so judge counts and bytes first.
  - Linter/compiler/LSP perf: use the matching workflow (`benchmark.yml`, `lintfmt-bench.yml`, `compile-bench.yml`,
    `level-instruction-counts.yml`, `lsp-dual-server-benchmark.yml`, `criterion-bench.yml`); read its inputs first.
  - Prefer intrinsic wins (less work, fewer copies, less memory) over cache-dependent ones; cold numbers first.
- Edge cases: when you fix one shape, probe its neighbours (script vs script setup, Options API, generic components, pug, kebab vs Pascal,
  `.d.ts`-only packages, Windows paths) and add fixtures for the ones that matter.
